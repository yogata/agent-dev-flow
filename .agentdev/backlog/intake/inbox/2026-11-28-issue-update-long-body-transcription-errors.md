# `issue_update` で長い日本語の本文を置き換えるとき、文字の誤りで送り直しが起きる

- **課題**: `issue_update` は番号と本文を受け取り、本文のすべてを置き換える。実行する側は 180 行の本文を tool の引数へ写すことになる。1 回目と 2 回目の送信は文字の誤りを含んだ。読み戻しの差分で検出し、3 回目で一致した。GitHub の編集の履歴に修正前の版が残る。
- **期待する処分**: 書き込み系の操作が、本文をファイルのパスで受けられるようにする。または、手順に「本文はファイルから組み立てる」「送信後に読み戻して照合する」と明記する。
- **出典**: yogata/reENC の Issue #93 の本文の更新 (2026-11-28 01:39〜01:45 JST)。reENC の Root の記録。
- **実証根拠**: (1) GitHub の編集の履歴 (GraphQL の `userContentEdits`) によれば、Issue #93 の本文は 16:39:28Z、16:43:08Z、16:44:57Z の 3 回の編集がある。(2) reENC の Root の記録によれば、2 回目の送信では行 150 は元に戻ったが、行 169 に「設設計」という文字の重複が入っていた。3 回目は行 169 を元の文言へ戻して送り、意図した本文と完全に一致するまで突合を繰り返した。(3) 同じ頃に投稿した記録コメントの最後の行に「意意図」という重複があり、`comment_update` で直した (Root の記録)。
