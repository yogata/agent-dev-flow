# RU-0120: Jev 有効性評価（Issue B）

## 目的

RU-0119（Issue A）で組込んだ Jev 先行評価の実運用観測が一定量蓄積した後、6系統の観測データを分析し、判断単位ごとに Jev 単独利用可能性と LLM 維持判断を確定するための評価を実施する。評価は絶対的な正答率測定ではなく、Jev の confidence と後段 LLM による `unchanged / corrected` の実運用上の関係（実用上の信頼性）を主軸とする。

## 対象

- 6系統横断の観測データ分析（`.agentdev/jev-observations/*.json` から。分析用の派生ビュー（JSONL、table 等）は一時生成可）
- Workflow 別・判断種別別の Jev 有効性の比較
- confidence と `unchanged / corrected` の関係分析。任意の閾値 `T` を後から適用した4象限（`confidence >= T && unchanged`、`confidence >= T && corrected`、`confidence < T && unchanged`、`confidence < T && corrected`）の分析。特に「高 confidence でも corrected」（その閾値で Jev 単独判断が危険だった可能性）と「閾値未満でも unchanged」（閾値が保守的すぎる可能性）の特定
- Jev 単独判断を許容できる confidence 閾値候補の評価（判断単位ごと）
- Jev failure 率の評価（API key 未設定 `not_configured` を除く。失敗分類別）
- `learning-promote` の5主評価軸と2補助観測軸（語潰れ軸を含む）の分析
- 置換候補判断と LLM 維持判断の区別、Issue C へ渡す判断材料の作成
- 評価言語による影響（日本語主訓練でない Jev への日本語入力）が観測・分析で分離できない場合の、評価結果への制約明記
- 必要に応じた Git 履歴・`opencode.db` の補助分析（過去 LLM 判断は正解値として扱わない）
- 観測 schema が不足していた場合の最小追加項目の特定（Issue A へのフィードバック）

## 対象外

- 実際の置換実装（Issue C / RU-0121）
- 独立した正解データ・人間ラベル・Jev 結果を隠した別 LLM 評価の新規作成（置換判断の必須条件としない）
- confidence 閾値の恒久確定（Issue C の契約として引き継ぐ候補の評価まで）
- 観測 schema の恒久変更実装（不足特定まで。実装は Issue A 系の後続で扱う）
- 投機実行の評価・実装

## 決定的受け入れ条件

設計メモ §16.2 の8条がすべて評価可能であること。要点:

1. Workflow / judgment / confidence 帯ごとの unchanged / corrected 比率が比較できる
2. 高 confidence でも corrected となったケースが分析できる
3. 閾値未満でも unchanged となったケースが分析できる
4. confidence 閾値候補ごとの Jev 単独利用可能性が評価できる
5. Jev failure 率（not_configured 除く）が評価できる
6. 判断種別ごとの置換可否が区別できる
7. 過去 LLM 判断を正解値として扱わず、不確実性が明示される（unchanged は正解認定ではない）
8. 置換実装を行わず、Issue C へ渡せる判断材料が作られる
