# RU-0020: 委譲結果受領の契約完了検査（3点ゲート）と background 消失時回復手順

## Sources

- **update-delegation-result-contract-guard（委譲結果受領の契約完了検査）**: case-run は実装作業を実行担当サブエージェントへ委譲し、result 4状態契約（completed-pr / blocked / failed / delegation-unavailable）で結果を受領する設計だが、委譲の起動・応答が契約どおり受領保証されない事象が発生。(1) run_in_background=true の委譲起動が起動直後に消失しても harness からは通知されず、実行未試行（worktree クリーン・PR なし・SSoT コメントなし）と実行中断の区別が自動では付かない（case 2796/2799/2800、2026-09-14。同期実行 run_in_background=false への切替で確実に result を受領）。(2) 委譲先が実装・検証の要約を返しても commit・PR 作成と4状態結果を返さないことがあり、adapter contract の完了判定が未達のまま後続工程へ進めない（case 2805 OU-006 / PR #2819、DEL-2811-1、case-close 2026-09-15 回収。再開セッションで残りの検証・10コミット・PR 作成まで完了）。受領側（case-run / case-auto）に、委譲結果の最終ゲートとして commit hash・PR URL・4-state result の3点を必須検査する guard、および background 委譲消失時に durable state で帰属確認し未試行なら同期実行で再委譲する回復手順が明文化されていない。ギャップ分類: guardrail insufficiency。

## Source Summary

委譲の起動・応答は契約どおり受領保証されないことがあり、受領側の完了検査（commit hash・PR URL・4-state result の3点ゲート）と durable state による帰属確認・同期再委譲の回復手順が必要である。受領側の検査・回復手順の追加に限定し、result 4状態契約の意味変更と harness 側機構を前提とした変更を含まない。

## 統合理由

1:1。単一 learning 成果物の要件（委譲結果受領の guard と回復）。result 4状態契約・fan-in・adapter にまたがる手順論点であり、RU-0019（QG-4 traceability 手順）とも対象機構が異なるため単独で要件化する（RU-0010 前例: 重い workflow 論点は単独要件化）。

## 要件化の方向

委譲受領手順整備要件として要件化する:

1. 委譲結果受領時の最終ゲートとして、commit hash・PR URL・4-state result の3点を必須検査し、不足時は「要約で終了」と扱わず再開（再委譲または継続指示）する guard を受領側手順へ明文化する（反映先候補: .opencode/skills/agentdev-case-run-execution-adapter/SKILL.md、.opencode/skills/agentdev-workflow-case-run/ fan-in・result 検証）
2. background 委譲の消失を検知した場合の回復手順を明文化する: durable state（worktree git status・PR 存在・Issue コメント）で帰属を確認し、実行未試行と判定した場合は同期実行（run_in_background=false）で再委譲する
3. docs/designs/workflows/delegation-contracts.md の委譲時最小契約 output_contract に受領側検査の情報候補を整理する
4. 制約・対象外: result 4状態契約に第5の状態を追加しない（既存契約の意味を変更しない）。harness 側機構（background task の起動保証）を前提とした変更にしない。同期実行への切替は消失検知時のフォールバックに限定する（常時同期化しない）。委譲先サブエージェントのプロンプト規約全般（作業衛生）は対象外

受け入れ条件（Sources より）: 委譲応答の受領時に3点検査（4-state result・commit hash・PR URL）が手順化され、不足時は要約で完結扱いにしないことが明記されること。background 委譲消失時の durable state 帰属確認（worktree git status・PR・Issue コメント）と、実行未試行時の同期実行による再委譲手順が文書化されること。本手順により、委譲未達の未検知による case-run / case-close の停滞が防止できること。
