# traceability gate の入力で対象 REQ 集合を明示・検証する（RU-0002）

## 目的

case-open の `prepare_definition_pr` で traceability gate を有効にする入力では、判定対象 REQ 集合（`traceabilityReqIds`）を明示・検証し、gate 実行範囲と判定対象の不整合を実行前に fail-closed で検出できるようにする。

## 背景

Case #3725 の `prepare_definition_pr.ts` 入力に `traceabilityGate` は設定されていたが、gate 判定対象として使う `input.traceabilityReqIds` が未設定だった。空配列への暗黙正規化後、traceability-check は対象 REQ 行集合を得られず fail し、後続 gate も抑止された（PR #3726、inbox E40）。

## 問題

gate 実行用 `--req` 指定と、判定対象行集合 `traceabilityReqIds` が別入力なのに、組立て側で片方のみを指定しても入力検証が検出しない。対象集合の未指定が空配列へ正規化され、入力不備として検出されない。

## 合意内容

同一 traceability gate 領域の intake 2026-10-11（新規 REQ 行の構造的 fail 明文化要求）とは要求層が異なる（本件は script 入力検証、相手は reference 手順明文化）ため 1:1 分離とした（Jev 先行評価も両者 1:1 0.66）。相手側は RU-0003 として別途要件化する。既存対策確認: fix gap。

## 要件化の方向

- `prepare_definition_pr` の traceability gate 入力組立て・検証に、対象 REQ 集合の存在・有効性検証を追加する（欠落・空・不整合入力は gate 実行前に fail-closed で報告）。具体的な入力契約変更は req-define の壁打ちで決定する。
- gate 対象と判定対象集合の関係が手順（references/definition-pr-and-idempotency.md）で明確であることを確認する。
- 調整事項: RU-0003 と同一 reference ファイルに接触するため、同一 Case 内実行時の実装順調整を計画に含める。
- 制約: fail-closed gate を維持する。実行範囲の指定を判定対象集合の指定と同一視しない。
- 本 RU は agentdev_handoff: true（AgentDevFlow 本体の不具合・改善点を扱う前工程からの引き継ぎ用 RU）である。

## 対象外

- 空または欠落した対象集合を成功扱いすること。
- gate の fail-closed 性や対象範囲を無断で緩和すること。

## 受け入れ基準

- [ ] traceability gate 有効時に対象 REQ 集合が存在し、有効であることを検証する。
- [ ] 欠落・空・不整合入力を gate 実行前に fail-closed で報告する。
- [ ] gate 対象と判定対象集合の関係が手順で明確である。
