# RU-0002: Project ExtensionsのYAML解析・構造検証標準化

## 目的

Project Extensionsの入力処理から一般的なYAML構文解析と構造検証の独自実装を縮小し、YAML解析、構造検証、ADF固有状態判定の責務を分離する。

## 対象

- Project Extensionsの独自YAML構文解析を廃止し、`Bun.YAML`を使用する。
- ADFが保証するYAML機能は、Project Extensionsの現行スキーマを表現するために必要なマッピング、配列、文字列、数値、真偽値、null、入れ子構造、通常のクォート文字列に限定する。
- Project Extensionsの構造検証にはZodを限定採用し、`version`、`kind`、`id`、`context`、`rules`、`checks`、`acceptance_gates`、`must_not`および各配列要素の構造を検証する。
- YAML解析結果の型差異を構造検証または必要最小限の正規化で吸収し、既存の状態分類と外部挙動を維持する。
- YAML構文エラー、必須フィールド欠落、旧kind、未知kind、有効なextensionの各ケースを回帰検証する。

## 対象外

- 全Markdown frontmatterの一括移行。
- REQ、Decision等のID解析のZod化。
- ADF全体へのZod適用強制。
- YAML 1.2の全機能保証。
- anchor、alias、カスタムタグ、複数ドキュメントの互換性保証。
- Project Extensionsの利用者向け機能追加またはスキーマ拡張。

## 正規所有者とアンカー

- Project Extensionsの入力・状態契約: `docs/specs/foundations/project-extensions.md`。
- 決定的検査器の主要実装: `.opencode/skills/repo-agentdev-integrity/scripts/check_extensions.ts`。
- 検査器と実行時解決処理が共有すべき状態機械はProject Extensions SPECの「状態機械の共有実装」を正とする。
- Zodは構造検証のみを所有し、ADF固有の状態意味論を所有しない。

## 依存関係

- 他RUへの依存なし。
- ADFの対応Bun実行環境で`Bun.YAML`が対象YAML機能を処理できること。
- Zod依存は既存のSkill実行時パッケージ境界に従い、`package.json` / `bun.lock`で管理し、利用先側で依存解決可能であること。

## 作業仮定

- Project Extensionsは汎用YAML処理系ではなくADF設定形式として利用する。
- 独自YAML 解析器を残して二重解析経路を維持する必要はない。
- 旧kindと未知kindの区別、`malformed`時のfail-openは既存外部契約として変更しない。

## 要件化の方向

- YAML構文解析は`Bun.YAML`へ委譲し、独自`parseSimpleYaml`相当処理を削除する。
- `Bun.YAML.parse`の例外はADF状態へ変換し、実行時処理を直接異常終了させない。
- YAML解析後の値を`unknown`として受け、ZodでProject Extensionsの構造を検証する。
- `missing`、`malformed`、`migration-required`、`schema-violation`、`valid`の判定、および旧kind・未知kindの意味判定はADF側に残す。
- 既存テストデータに加え、空入力、型不正、クォート内のコロン・`#`、CRLF、入れ子、配列、構文エラーを検証する。

## 決定的受け入れ条件

1. 現在有効なProject Extensions テストデータは、変更後も同じ状態分類で`valid`となる。
2. extension不在時は標準動作を継続する。
3. YAML構文エラー時、実行時処理は当該extensionを無視して標準動作を継続し、決定的検査器は既存契約に従って不通過を報告する。
4. 必須フィールド欠落またはkind判定以前の構造破損は`malformed`となる。
5. `command-extension`または`skill-extension`は`migration-required`となり停止する。
6. 構文上有労だが公式3値以外のkindは`schema-violation`となり停止する。
7. `context`、`rules`、`checks`、`acceptance_gates`、`must_not`の型不正を構造検証で検出できる。
8. YAML値の型解釈差により、既存有効extensionの意味が意図せず変化しない。
9. Project Extensions用の独自YAML構文解析実装が残存せず、同一入力に対する二重解析器経路が存在しない。
10. anchor、alias、カスタムタグ、複数ドキュメントをADFの保証対象として扱う仕様またはテストが追加されていない。
11. 自己適用環境と利用先相当環境の双方で必要な依存を解決し、対象テストを実行できる。
12. 各受け入れ条件の検証結果を`pass` / `fail` / `blocked` / `not applicable`のいずれかで記録し、`blocked`または`fail`が残る場合は完了扱いにしない。

## Source Summary

ADF全体の独自実装再評価において、一般的なYAML構文解析を独自保守する費用が大きい一方、Project Extensions固有の状態意味論はADF側に残すべきと合意した。対論型レビュー後、`Bun.YAML`による構文解析とProject Extensionsに限定したZod構造検証を採用し、YAML全機能やADF全体への横展開は行わない方針で合意した。
