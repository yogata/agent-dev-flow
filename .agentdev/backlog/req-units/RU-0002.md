# RU-0002: verify-only case の実行証跡 SSoT 記録の標準化

## Sources

- **1-verify-only-execution-evidence-ssot（case 2768/2769）**: 変更ゼロの verify-only case（PR・carrier commit が存在しない closure）では検証完了の証跡が会話上のみで消え、QG-4 判定根拠が恒久記録から追跡不能になる。case 2769 で確立した運用は「3検査（配布依存境界・IR-055・traceability）+ integrity suite を実 case と同水準で実行し、実行コマンド列と結果（new_delta 0、新規違反 0 件、pass/fail 数等）を SSoT コメント（Issue コメント）へ記録する」。PR が存在しないため PR 本文は記録先に使えない。運用実績はあるが workflow skill 契約に明文化されていない（fix gap）。

## Source Summary

verify-only case の検証証跡の恒久記録方法が手順として明文化されておらず、個別 case の運用依存となっている。証跡不在のまま処分判断を行うと QG-4 判定根拠が再現不可能になるため、実行・記録・参照の一連の流れを case-run / case-close の契約へ標準化する必要がある。

## 統合理由

1:1。単一成果物で単一論点（verify-only case の証跡記録標準化）であり、統合・分割の必要がない。

## 要件化の方向

verify-only case の実行証跡記録要件として要件化する。反映先は case-run / case-close workflow（Design と Skill references）:

1. case-run 側: verify-only case で3検査 + integrity suite を実 case と同水準で実行し、実行コマンド列と結果を SSoT コメントへ記録する手順の明文化（実行コマンド列はそのまま再実行手順になる）
2. case-close 側: SSoT コメントを QG-4 判定根拠として参照する手順の明文化
3. 前提の継承: PR-less closure は carrier commit 捏造を却下した作業仮定（case 2769 記録）に基づく
4. 対象は verify-only case（変更ゼロ closure）および検証のみで完了する maintenance case。通常 case（PR が存在する closure）の QG-4 記録は既存契約の対象外

受け入れ条件（Sources より）: verify-only case の case-run で3検査+integrity suite が実行されること、実行コマンド列と結果が SSoT コメントへ記録されること、case-close が SSoT を QG-4 判定根拠として参照すること。
