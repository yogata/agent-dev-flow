# RU-0030: ADF-COVERS coverage 突合の役割区別必須化（implementation 集約の誤認防止）

## Sources

- **coverage 突合の役割区別必須化（Case #2824 / PR #2874）**: ADF-COVERS 宣言は role（design / implementation / verification）を持つが、REQ 行単位で宣言集合を突合する際に役割フィルタの適用を省略すると、docs 配下の verification・design 役割宣言まで implementation 集約済みと同一視され、配布物本体宣言の除去可否（cleanup）を誤判定する。Case #2824（PR #2874）の case-run・case-close 両面で、REQ ID の有無のみの初回突合が removable と判定した 2 宣言が、役割フィルタ＋docs/ パスフィルタ適用の再突合で blocked へ反転した（REQ-053-023 は docs 側に verification 宣言のみで implementation は配布物側 2 件が唯一の所有だったため）。誤って除去すると traceability check の missing-implementation が新規発生し、coverage の対応関係が喪失する。判定基準の中核は REQ-057-028 が既に所有するが、役割フィルタ適用と除去後検査という運用詳細が workflow 手順に明記されていない（fix gap / application miss）。

## Source Summary

coverage 突合（除去可否判定）における役別フィルタと後置検査を workflow 手順として必須化し、実行者ごとの判断委ねを解消する。判定基準の中核は REQ-057-028 の既存規定に従い、本要件は運用詳細の整備に留める（二重定義しない）。

## 統合理由

1:1。単一成果物・単一論点（突合手順の運用詳細整備）であり、統合・分割不要。同一観測元の宣言残務（RU-0029）とは対象が異なる（手順の標準化 vs 宣言の付与・除去実施）ため分離し、RU-0029 から依存される。

## 要件化の方向

work_type: maintenance。判定基準の中核は REQ-057-028 行に維持する（二重定義禁止）:

1. coverage 突合（除去可否判定）に役割フィルタ＋docs/ パスフィルタの適用を必須とする手順の明記（対象: case-run の cleanup 判定、case-close STEP-3 の集約突合）
2. 除去実行後に traceability check で role 別 coverage の不変（新規 missing 0）を確認する後置検査の規定
3. agentdev-traceability の coverage 利用時の注意（役割付き出力の解釈）の明記

制約: ADF-COVERS 宣言形式・3役割モデル自体の変更は対象外（traceability の正規契約が所有）。配布依存境界: 配布物本文の要件行参照は意味参照とし、具体 REQ ID は ADF-COVERS 宣言行に限定する。

受け入れ条件: coverage 突合の cleanup 判定手順に役割フィルタ＋docs/ パスフィルタの適用が必須として明記されていること、除去実行後に traceability check で新規 missing 0 を確認する後置検査が規定されていること、REQ-057-028 と手順の間で判定基準の二重定義が生じていないこと。
