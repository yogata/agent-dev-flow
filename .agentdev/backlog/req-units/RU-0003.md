配布物変更を commit 後に検査すると内部 ID・path・宣言 parser 由来の違反発見が遅れる。3検査自体は既存だが、変更直後の一括実行と新規違反確認が手順として明文化されていない。

## 統合理由

1:1。単一論点であり統合・分割不要。

## 要件化の方向

1. case-run / case-close の配布物変更手順へ、配布依存境界・IR-055・traceability の3検査を commit 前に実行する工程と実行順を追加する。
2. base 既知違反と変更起因の新規違反を分離し、新規違反を全件分類して修正後に再検証、新規違反 0 件を確認する。
3. 既知 baseline 違反の無断削除・隠蔽は許容しない。
