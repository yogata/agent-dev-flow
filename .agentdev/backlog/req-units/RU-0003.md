# case-open STEP-4 の traceability gate 判定に新規 REQ 行の構造的 fail の扱いを明文化する（RU-0003）

## 目的

新規 REQ 行を伴う Definition 変更で case-open STEP-4 の traceability gate が報告する構造的 fail（対象行の missing-implementation / missing-verification）の扱いを、case-open reference 手順（definition-pr-and-idempotency.md）の gate 判定仕様節に明文化する。

## 背景

Case #3628 / PR #3631（case-open 実行、2026-10-11）で、新規 REQ 行（REQ-035-021）追加の Definition 変更に対し traceability gate が fail を報告した（pass=9 fail=2）。fail の内訳は対象行 REQ-035-021 の missing-implementation / missing-verification であり、case-open の正規ゲートである missing-design（対象行）は pass していた。実行は gate 判定仕様の冒頭規定（case-open の正規ゲートは対象 REQ 行の missing-design 0 件）から導出して既知未完了として処理し、PR 作成へ進めた。

## 問題

新規 REQ 行を伴うすべての case-open 設計PR で同様の gate fail と意味レビューによる判断が再発する。判断根拠（case-open の正規ゲートは対象行の missing-design 0 件、新規行の missing-implementation / missing-verification は case-run / case-ready 段階の前提欠落）が手順に明文化されていない場合、各実行で解釈判断の往復が生じ、誤って gate fail を設計PR の作成停止と読み替えるリスクがある。

## 合意内容

同一 traceability gate 領域の learning（script 入力検証要求、RU-0002）とは要求層が異なるため 1:1 分離とした（Jev 先行評価 0.66）。Case #3627 が同領域の reference 明文化（traceability gate の既存債務対照救済手順等）を進行中であるため、**本件の明文化追加との統合可否（同一 reference の gate 判定仕様節への追記として統合するか、別途とするか）を req-define の壁打ちで必ず確認する義務**を本 RU に含める。

## 要件化の方向

- STEP-4 reference の gate 判定仕様節への明文化の文言と配置を req-define で確定する。
- script 側の判定対象変更（形式検査系 + missing-design 対象行への絞り込み）を行うか、reference 側の明文化のみとするかを req-define で判断する。
- **必須義務: Case #3627 の reference 明文化スコープとの統合・重複判定を実施し、その結論を記録する。**
- 調整事項: RU-0002 と同一 reference ファイルに接触するため、同一 Case 内実行時の実装順調整を計画に含める。
- 制約: gate の fail-closed 性を維持する。新規行の missing-implementation / verification を case-open で成功扱いにしない。
- 本 RU は agentdev_handoff: true（AgentDevFlow 本体の不具合・改善点を扱う前工程からの引き継ぎ用 RU）である。

## 対象外

- 新規 REQ 行の missing-implementation / verification を case-open 段階で成功扱いとすること。
