# RU-0123: 配布物 concrete-id・ADF-COVERS 予防観点の case-run 委譲 context 引き渡し手順の明示

## Sources

- learning measure-update-distribution-artifact-declaration-application-miss.md: Case #3056（REQ-090 Jev 先行評価 Stage 1）の case-run 実装で、6系統 Workflow reference と新規 .ts / README へ具体 REQ 番号と ADF-COVERS 宣言を直接記載した結果、配布依存境界 source profile で 69 failures を検出。配布物から concrete-id と宣言を除去し、traceability sidecar（7件）へ登録し直して解消（PR #3058 merge 済み）。作成先規約は case-run SKILL L120 に既存だったが、実装担当への委譲 context に「新規配布物は本文へ concrete-id・ADF-COVERS を書かず sidecar へ登録する」予防観点が引き渡されず適用漏れ（application miss）となった。検知機構（checker）は事後のみで機能済み。

## Source Summary

配布依存境界（DEC-014・REQ-029）の規約と検知機構は既存で機能したが、作成時点で違反を防ぐ予防観点の委譲手順が存在しないことが原因で手戻りが発生した。checker 実装・Design 規約・sidecar schema の変更は不要であり、委譲 context 構成・確認観点への手順明示のみで予防と事後検知の両面運用を文書化する。

## 統合理由

単一成果物の単一論点であり、特別な統合・分割判定は不要（1:1）。

## 要件化の方向

- case-run 実行系の委譲 context 構成手順・確認観点（agentdev-workflow-case-run の STEP-S2 関連手順、agentdev-case-run-execution-adapter の委譲手順）に「新規配布物（tools/plugins/skills 配下）へは concrete-id と ADF-COVERS 宣言を本文へ書かず、traceability sidecar へ対応宣言を登録する」予防観点の引き渡し手順・確認観点を追加する。
- case-run SKILL の作成先規約と予防観点の関係（事前予防と事後検知の両立）を文書上明確にする（docs/designs/integrity/distribution-boundary.md 関連運用節の追記も候補）。
- checker（check_distribution_boundary.ts --profile source）の実装変更は含まない（対象外として明確化済み。検知機構の代替にもしない）。
