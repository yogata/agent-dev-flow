# 工程駆動系操作の完了報告への必須要素の追加

## 目的

工程駆動経路のワークフロー操作が処理を完了したとき、その報告に含めるべき要素の規定がなく、監督側が報告の中身から操作の状態を誤認する事故を防ぐ。

2026-10-17〜18 の staff-schedule-cf 適用中に4事象が発生した。代表例は、`phase-artifacts-update` の実行が内部の非同期子処理(照合2件)の完了待ちのまま制御を返した(HTTP復帰)ため、監督側がこれを操作完了と誤認して後続の `phase-tasks-update` を先行投入し、反映前提のテーマ編集を実行させてしまい、後に撤回した事象である。別の事象では、処理が終了しているのに完了報告が届かず、利用者の状況照会で初めて待機中と判明した。いずれも「完了報告に何が含まれるべきか」が契約にないことが背景にある。

現状は `agentdev-workflow-phase-artifacts-update` SKILL に「反映の結果(反映した項目と反映先、衝突・未確認・保存失敗を区別した報告。外部戻り入力存在時は受領記録の保存先、直接採用時は採否記録の保存先を報告する)」があり、保存先の報告義務は存在する。不足しているのは、機械検査の結果を報告に含める義務と、未完了の内部処理の有無を明示する義務である。変更駆動経路には REQ-007-004「完了報告は検証可能な証拠を含むこと」が存在するが、工程駆動経路には適用されていない。

あわせて、検証の解釈に関する1原則(機械検査の合格は意味品質の保証ではない)と、監督側での誤認実例に基づく2つの報告要素(採用範囲と未決事項の重なり、検討方向の差し替えに伴う旧前提の行き先)を同じ報告契約へ含める。後者2つは単独の様式を作らず報告要素として扱うことが利用者の処置決定(2026-10-21)で確定している。

## 対象

- 工程駆動経路のワークフロースキル(`agentdev-workflow-phase-artifacts-update`、`agentdev-workflow-phase-tasks-create`、`agentdev-workflow-phase-tasks-update`、`agentdev-workflow-phase-review`、`agentdev-workflow-phase-transition`、`agentdev-phase-theme-collaboration`)の完了報告に関する契約への必須要素の追記。
- 必須要素は次の4点:
  1. 保存先の一覧(保存した成果物・記録の保存先)
  2. 機械検査の結果(実行した機械検証とその結果。未実行の場合はその旨)
  3. 未完了の内部処理の有無(操作の返却時点で裏で継続している処理の有無)
  4. 採用内容の範囲が未決事項と重なる場合はその旨、および検討方向の差し替えを受領する場合は旧方向が持っていた前提の行き先(継承または破棄)
- 「機械検査の合格は意味品質の保証ではない(必要条件であって十分ではない)」の明示。
- 対応する要件(REQ-110 または req-define が確定する正規所有者)への要件行の追加。

## 対象外

停滞の検知・自動回収の実行基盤側への組み込み(実行基盤側の責務という既存の境界を維持し、本RUでは対象外と明示するのみ)。検証の権威の序列および監督再検証の要求条件の列挙(監督側の運用知識として扱い、ADF の操作契約に入れない)。新しい公開コマンド、恒久的な台帳、報告様式の新設。既存の部分反映・失敗時報告・再投入の規律の変更。受領・採用根拠の既存規律の変更。

## 正規所有者とアンカー

主対象は `docs/requirements/REQ-110.md`(工程駆動経路の要件群)。アンカーは各ワークフロースキルの SKILL.md(`src/common/skills/agentdev-workflow-phase-artifacts-update/SKILL.md` ほか phase 系5スキル)および対応する command 契約(`src/common/commands/agentdev/phase-*.md`)、`traceability/` の対応する verification 宣言。

関連する既存要件はいずれも維持前提である: REQ-110-009(部分反映、失敗報告、再投入)、REQ-110-032(採用判断の成立と反映完了の区別)、REQ-110-033(明示採用範囲を超えた未決の設計事項の一括確定禁止)、REQ-007-004(変更駆動側の完了報告の証拠要件。参考)。既存要件を無条件に改訂せず、今回の要求を満たすために変更が必要な箇所に限定する。

## 依存関係

他のRUの成果を待つ作業はない(`depends_on: []`)。2026-10-21 時点で未処理draftプール(`.agentdev/backlog/req-units/`)、`.agentdev/drafts/`、実行キュー(`adf-queue.json`)はいずれも空であり、同一の正規所有領域を逆方向から変更する案件はない。同時に配置する `decision-role-reference-in-phase-workflows`(RU-0242)は正規所有者と変更対象節(報告節と参照節)が異なり、相互に独立である。同一ファイル(`src/common/skills/agentdev-workflow-phase-*/SKILL.md`)への編集が競合する可能性は case-open のスコープ判定で扱う。

## 要件化の方向

完了報告の必須要素を既存の報告契約へ追記する形で要件化する。既存の「反映の結果…報告する」(保存先の報告)を土台に、機械検査の結果と未完了の内部処理の有無を同じ報告の必須要素として加える。新しい報告様式や公開コマンドは作らない。未完了の内部処理の有無は「有/無」の明示であり、内部処理の完了待ち・回収の実行方法は規定しない(実行基盤側の責務)。機械検査の合格が意味品質の保証ではない旨は、報告を読む側が機械検査の合格だけで品質を判断しないための文言として同じ箇所へ入れる。

採用範囲と未決事項の重なり、検討方向の差し替えに伴う旧前提の行き先は、受領処理・反映処理の既存規律(REQ-110-026〜033)が判断自体を担い、本RUはその結果を完了報告へ含める義務だけを追加する。

## 決定的受け入れ条件

1. 工程駆動系ワークフロー操作の完了報告に、保存先の一覧、機械検査の結果(未実行の場合はその旨)、未完了の内部処理の有無が含まれること
2. 採用内容の範囲が未決事項と重なる場合にその旨が、検討方向の差し替えを受領する場合に旧方向が持っていた前提の行き先(継承または破棄)が、それぞれ完了報告に含まれること
3. 機械検査の合格が意味品質の保証ではない(必要条件であって十分ではない)ことが契約上明示されていること
4. 既存の部分反映・失敗時報告・再投入の規律、受領・採用根拠の既存規律、および各操作の本来の責務が変更されないこと
5. 停滞の検知と自動回復が実行基盤側の責務であり ADF の対象外であることが維持されていること
6. 新しい公開コマンド、恒久的な台帳、報告様式の新設が行われていないこと
