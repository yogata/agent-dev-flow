# RU-0010: verify-only case の PR-less closure 経路の workflow 契約明示化

## Sources

- **PR-less closure の実行時解釈依存**: case 2768（docs_chore・実装突合検証）で、検証のみで完了し PR 差分 0 件（branch = main 同一 commit、PR 未作成）の case を PR を作らずにクローズする処分が必要になった。現行は case-close workflow の PR なし特例フロー（docs_chore、main 直接 push 済み）の適用条件への解釈適合として扱われ、verify-only case を第一級 closure 経路として明示する workflow 契約は存在しない。carrier commit（差分捏造）による verify-only PR 作成は検証証跡の汚染として case-auto bounded parent decision で明示却下済み（case 2768 前例実績）。
- **証拠ソース契約の未定義**: PR-less 完了時の証拠ソース契約（PR 本文代替の検証証跡コメント等）が品質ゲート契約に未定義（quality-gates「verify-only PR」節は PR 本文を証拠ソースとする前提）。

## Source Summary

verify-only completion の closure が実行時解釈に委ねられ、適用条件の恒久性・再現性が保証されない。第一級 closure 経路としての契約明示化が必要。

## 統合理由

1:1。workflow 契約の新規明示化という重い論点であり、単独で要件化する。

## 要件化の方向

workflow 契約明示化の要件として要件化する。明示化に含める要素:

1. 適用条件（verify-only case: case-run 委譲結果が全 success criteria 充足・branch = main 差分ゼロ・PR 未作成で終わるケース。docs_chore 特例フローとの関係整理を含む）
2. 証拠ソース契約（PR 本文代替の検証証跡コメント等）
3. carrier commit 捏造の禁止

受け入れ条件（Sources より）: case-close workflow 契約・quality-gates 契約に verify-only closure 経路が明示されること、証拠ソース契約が定義されること、carrier commit 捏造禁止が明記されること。
