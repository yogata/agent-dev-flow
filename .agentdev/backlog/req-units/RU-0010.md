# GitHub 本文の更新前に workflow extension rules を確認する（RU-0010）

## 目的

Case / Issue / PR 本文の書込み手順に、適用される workflow extension の rules を書込み前に解決・適用する必須工程を明示する。

## 背景

case-ready が Root Case 本文を更新した際、適用対象の workflow extension rules（GitHub 本文を agentdev_gh へ渡す前に yomiyasu 推敲する規則。`.agentdev/extensions/skills/agentdev-workflow-case-ready.yaml`）を確認せず投稿した。投稿後の散文検査で補完したが、前置手順の欠落は残った（Issue #3674、inbox E9）。既存対策確認: application miss（`agentdev-project-extensions` の runtime rules 読込能力はあるが、本文書込み直前の必須確認として更新操作に結び付いていなかった）。

## 問題

Issue / PR 本文の書込み手順に、適用される workflow extension の rules を書込み前に解決・適用する必須工程が明示されていない。

## 合意内容

1:1 とした（Jev 先行評価 1:1 0.95）。

## 要件化の方向

- case-ready（references/execution-contract.md）および同様に GitHub 本文を更新する case-open / case-run 手順に、書込み直前の extension rules 確認工程を追加する候補を req-define で確定する。
- `agentdev-project-extensions` の実行時 rules 解決契約との接続候補を req-define で確定する。
- 制約: extension から適用される規則を削除・弱化しない。書込み後の検査を前置規律の代替として扱わない。
- 本 RU は agentdev_handoff: true（AgentDevFlow 本体の不具合・改善点を扱う前工程からの引き継ぎ用 RU）である。

## 対象外

- extension の適用を無条件に省略すること。
- 既に実行された投稿を根拠に前置規律を不要とみなすこと。
