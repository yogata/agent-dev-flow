## Source Summary

worktree・branch 操作と worktree 検証の実行前提差に関する前置ガードの整備であり、両者とも「手順の前置確認・環境前提の明文化」で吸収する予防策ベースの改善である。誤配置 commit の修復（Case #3169）は既に自律対応済みで対象外。

## 統合理由

同一の worktree 検証・git 操作安全手順（worktree-operations.md を中心とする前置ガード）への整備であり、検証環境前提（projection・依存）と操作前提（operation in progress・current branch）を統一的に前置ガードとして位置づけられるため N:1 統合する。

## 要件化の方向

- req-define により、次を AC とする要件として定義する:
  - worktree・branch 作成を伴う workflow の前置確認に「長形式 git status で operation in progress 表示確認（検出時: porcelain 確認 → abort 判定 → 解除後再確認）」が追加されること
  - main 永続化 commit 前の current branch 確認（main 以外なら主ツリー commit 不実施・worktree 経由へ切替）が標準手順として明文化されること
  - worktree の bun test 実行契約に projection 伝播前提（commands / skills のみ・plugins / tools 不在・bun test 無言欠落）と補完手順（main root 読取専用実行または src 配下直指定）が明記されること
  - worktree の typecheck 手順に「package 単位 bun install の前置」が明記されること
  - 実施範囲の環境ラベル（junction 伝播状態・依存パッケージ状態）記録が運用に組み込まれること
- 対象外: revert 残骸根本原因の究明（未特定・観測限界）、REQ-030-017 worktree 隔離要件自体の変更、projection 機構自体の変更、bun test の外部ツール仕様変更
