# RU-0130: worktree 型検証の依存整備手段判定補助（bun install 一意化）

## Sources

- `existing-countermeasure-update-worktree-bun-install-decision-aid.md`: Case #3103（PR #3130）の worktree 内 tsc 型検証（DEL-3103-2）で bun types 解決失敗（TS2688）。worktree には main 側 node_modules が自動伝播せず、main 側 node_modules 不在時は junction による依存共有が成立せず worktree 内 bun install へ決定的に切替。agentdev-git-worktree の bun test 実行環境前提に従い解消した実績（tsconfig 書き戻しなしを git status 確認済み）。

## Source Summary

worktree での型検証・テスト時の依存整備手段選択基準（junction 共有 / worktree 内 bun install）は存在するが、「main 側 node_modules 不在時は worktree 内 bun install へ一意に決まる」という判定補助の明示がない。junction 未伝播かつ main 側 node_modules 不在の条件で手段選択に迷う余地が残る。検証前の node_modules 伝播状態確認手順の明示もセットのギャップ（選択基準表への追記で閉じる）。

## 統合理由

1:1。依存整備手段の判定補助という独立した関心領域。RU-0131（workspace 外一時ファイルの置き場所・標準手段切替）は同じ worktree-operations.md を集約先候補に共有するのみで、懸念は依存解決手段と書込み場所/guard 迂回禁止で無関係なため分離する（承認済み構成案の分割判定）。

## 要件化の方向

- agentdev-git-worktree の worktree-operations.md「bun test 実行の環境前提」節の選択基準表に、main 側 node_modules 不在時の判定補助（worktree 内 bun install へ一意決定）を追記する
- 検証前の node_modules 伝播状態確認手順（junction 成立・main 側存否）を明示する
- 対象外: worktree junction 機構自体の変更、bun install 実行手順自体の変更、REQ-018（worktree 構造的制約とテスト fallback）の契約変更
- 暫定分類は挙動Design。req-define で最終確定する
