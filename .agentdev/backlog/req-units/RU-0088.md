# RU-0088: worktree 検証時の外部依存パッケージ解決整備（選択基準の明文化と恒久整備の検討）

## Sources

- **learning: 依存解決2手法の選択基準不在**: worktree は gitignore 対象の node_modules を継承せず、bun のモジュール解決は実行 cwd の node_modules を辿るため、外部パッケージ依存テストが環境依存 fail（Case #2890/PR #2892 で junction 前置、Case #2904/PR #2934 で bun install）。2許容手段（main 側 node_modules への junction 前置＝検証後削除、package 単位の bun install --frozen-lockfile）に先行適用例が両方あるが選択基準が agentdev-git-worktree/references/worktree-operations.md（依存整備節）に未明文化。基準案: 一回限り検証なら junction、繰り返し実行する worktree なら install。制約: junction は検証後削除、install は --frozen-lockfile 维持。

- **intake: integrity suite の zod 依存解決**: Case #2893（PR #2924）case-run で integrity suite と src 側 skill script テストが zod 解決不能で fail。zod 直接依存は agentdev-project-extensions/scripts の package.json のみ、integrity 側は extension_state.ts 経由の間接依存。case-close で bun install --cwd 前置により解消（分割1 2566 pass / 0 fail、分割2 102 pass / 0 fail）。検討事項: (1) worktree 検証時の導入手順強化 (2) 依存の配布・取得機構への組込みまたは依存除去・標準 API 置換 (3) bun install 前置が必要なパッケージ境界の checker による恒久強制。

## Source Summary

worktree の node_modules 未伝播によるテスト環境依存 fail について、learning は手順面（2手法の選択基準の未明文化）、intake は構造面（依存の配布・除去・前置強制の恒久整備）から観測した同一事象の統合である。

## 統合理由

N:1 統合。intake 側に「本 item と学習成果物の統合判定を backlog-review で実施すること」の明示注記があり、同一事象（Case #2890/#2893/#2904 の zod 系 fail）の別観測。adversarial-review で統合維持、ただし学習側の対象外指定（node_modules のリポジトリ管理化）と intake 側の恒久整備検討のスコープ緊張が指摘され、要件化の方向への階層明記を反映した。

## 要件化の方向

第一対応は worktree 検証手順への依存解決2手法の選択基準の明文化（agentdev-git-worktree/references/worktree-operations.md 依存整備節、qg-4-final-acceptance.md への言及候補）。依存配布・除去・checker 強制の恒久整備は req-define が対象範囲に含めるか別 Case とするかを判断する候補（learning 側の対象外: node_modules をリポジトリ管理化に置く構成変更）。受け入れ条件: 新規 worktree で bun test を実行する作業者が検証前に依存前置を計画に含められること。
