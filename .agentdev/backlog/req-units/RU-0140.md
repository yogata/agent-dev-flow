# RU-0140: infra-transient（ツール基盤故障）停止分類と回復経路の明示

## Sources

- `2026-09-25-agentdev-gh-spawn-infra-transient.md`: 長寿命 OpenCode プロセス（opencode serve）内で agentdev_gh の gh spawn が恒常失敗（gh exited with 66）し、プロセス生存・HTTP API 応答下で GitHub 読み書きのみ全滅。case-auto #3123 再開監視（Hermes supervisor）が 2026-09-25 08:57 に fail-closed 停止を観測。serve 再起動で即回復し、durable state（staging 済み Issue 本文・draft・git）は完全保持で冪等再開が成立（09:12:01 再開 relay 受理）。gh spawn 環境劣化はインフラ（harness）層 transient 障害だが、正規書込経路が agentdev_gh に限定され代替が契約禁止のため、現行では Case 側 blocker（workflow 停止）と同形に分類される問題。

## Source Summary

ツール基盤故障は ADF の停止条件（HITL・CI 失敗・構成不備等）のいずれの本質でもないのに Case 失敗扱いで停止し、supervisor が気づいて再起動するまで pipeline が前進しない。ADF 側の機構改善として、停止分類に「infra-transient（ツール基盤故障）」を追加し、単一ツール恒常失敗 × プロセス生存 × 再試行無効 × 他経路正常（git・DB・ローカル FS）を判定条件に、停止報告へ「supervisor による harness 再起動で回復可・durable state から冪等再開」の回復経路を明記する方向を提案として整理する。本採用は後続分析対象への振り分けを示すものであり、提案の実装承認を意味しない（転記）。harness 側修正（fresh process 分離・自動再初期化）は ADF リポジトリの対象外として明記する。

## 統合理由

1:1。停止分類と回復経路の機構改善という独立した関心領域であり統合・分割不要。I1（IR-055 warning 継続観察・保留中）とは gh 関連という背景を共有する補完関係（観察 vs 機構改善）であり矛盾しない。

- 停止報告形式に回復経路（harness 再起動で回復可・durable state から冪等再開）の記載を追加する
