# Wave構成の単一Wave前提・依存DAGレベル導出への是正と機械的強制

## 目的

Epic の Wave 構成について「1つの Wave で全子 Issue を並列処理することを大前提とし、意味的必須依存が存在する場合にのみやむなく複数 Wave 構成とする」ことを契約の明文要件とし、Wave 割当が依存 DAG からの決定的導出（トポロジカルレベル割当・最小性）に一致することを機械的判断により強制する仕組みを実装する。

Epic #3507（2026-10-07 実行、16 RU 一括統合）で観測された実挙動はこの前提に反する: operation_units 21 件の depends_on が全件空（必須依存エッジ 0 本・実行構成節自ら「必須順序制約はなし」と記録）であるにもかかわらず、子 Issue 9 件が機能的主題（参照整合・カタログ系 / 検査・受入契約系 / 運用・実装系）ごとの 3 Wave に分割された。Epic 本文は「Wave 構成は意味的依存のみから構成され」と記述しつつ、実際の Wave は主題グルーピングであり、決定的導出と矛盾する。結果として Wave 境界が実行順序の意味を持たず、横断補充（REQ-034-040）により Wave-1 収束前に Wave-2/3 が着手され、「Wave-1 群を完遂する前に Wave-2/3 が着手されている」状態が生じた（実測: 初期アドミッション 5 件 = Wave-1 3 件 + Wave-2 2 件の混成、07:09〜07:13）。

## 要件化の方向

work_type: bugfix。観測された実挙動（0 辺 DAG から 3 Wave 生成）は「決定的導出」契約の違反であり、契約文と実行手順の両面で次を確立する:

1. 単一 Wave 前提の明文化: 依存エッジが存在しない子 Issue 集合はすべて同一 Wave に割り当てる
2. Wave 割当の決定的導出の定義: Wave 割当は子 Issue 間意味的依存 DAG のトポロジカルレベル割当（各子 Issue の Wave 番号 = 前提列 DAG における最長経路深さ）と一致すること。この定義により、依存 0 件なら Wave 数 1 が機械的に導出される
3. 機械的強制: 構成検証（決定的検証）に「Wave 割当とトポロジカルレベル割当の一致」検査を追加し、不一致を fail-closed で停止させる。主題的近さ・ファイル重複・マージ順序の望ましさを Wave 分割理由として採用した構成はこの検査で拒否される
4. Wave 構成判断（boolean 並列可否）の質問・判断基準から「主題的グルーピング」を読み取れる文言を排除する

## 決定的受け入れ条件

1. 依存エッジ 0 件の子 Issue 集合を与えた場合、Wave 構成が必ず 1 Wave となること（機械検査で検証可能な形）
2. 依存エッジが存在する場合、Wave 割当がトポロジカルレベル割当（最長経路深さ）と完全一致すること。過剰な Wave 分割（辺を保存するがレベルを超えて分割する構成）が検査で拒否されること
3. 本 RU の契機となった #3507 型の入力（主題別 3 Wave・0 辺 DAG）を機械検査に通した場合、fail として停止すること（再発防止の回帰条件）
4. 既存の検証項目（Epic サイズ上限・DAG 整合・全割当完了）が維持されること
5. Wave 構成判断の質問文・Jev 観測スキーマの識別子互換性: 判断単位・質問形式の意味を変えない範囲での基準更新であること（観測識別子 workflow/evaluationKind/questionId の維持）
