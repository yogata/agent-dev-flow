# RU-0124: 委譲時の観測証跡の永続チャネル記録手順

## Sources

- `existing-countermeasure-update-delegation-evidence-persistent-channel.md`: Case #3123（PR #3138）の TS-006 統合検証で、子 task の観測証跡（REQ-034-045 型）が background_output 等の一時 session 通信のみに依存し、driver の blocked 報告が SSoT コメント不能となった実例。record-in-findings 契約による PR 本文 Findings 記録と case-close Capture 回収で事後回収したが、委譲契約時に証跡の永続チャネル経路を同時に用意する手順が存在しない。

## Source Summary

親子間の観測証跡引き継ぎが一時 session 通信に依存しており、子が証跡を永続チャネル（PR 本文・Issue コメント・durable state ファイル）へ書込む受領経路が委譲契約に明示されていない。証跡を要求する検証を委譲する場合、一時出力のみで完結すると後工程での引用・監査が不能になる。record-in-findings という実績ある記録形式は既存であり、契約自体の変更ではなく「検証契約と同時に受領経路を用意する」手順の明示がギャップである（ギャップ分類: application miss）。

## 統合理由

1:1。委譲契約の観測証跡記録という独立した関心領域。RU-0125（Case Issue 本文の evidence path 記録規約）は証跡の参照側の話であり、本 RU の委譲時の受領経路（記録側）とは問題型・反映先が異なるため統合しない。

## 要件化の方向

- case-run 委譲契約の reference（agentdev-case-run-execution-adapter の harness-delegation.md 等）に、観測証跡の永続チャネル記録手順（record-in-findings 形式の明示的な記録・PR 本文指定セクション / Issue コメント / durable state ファイルの受領経路）を追記する
- v4-delegation-contracts Design への記載要否は req-define が判断する
- 対象外: record-in-findings 契約自体の変更、background_output 等の一時 session 通信機構の変更、REQ-034-045 自体の変更
- 暫定分類は挙動Design。req-define で最終確定する
