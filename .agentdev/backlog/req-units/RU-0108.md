# RU-0108: tracking Issue 本文更新時の agentdev_gh labels 省略規則と verification-incomplete 復帰手順の明記

## Sources

- **learning: agentdev_gh tracking Issue の labels 明示渡しによる read-back 検証失敗（通算 3 回・2 Case）**: tracking role の Issue へ本文のみを更新する際 labels を現行値どおり明示渡すと、GitHub 側には本文が正しく反映されているにもかかわらず Tool の read-back 検証が verification-incomplete（fail-closed・retryable false）を返す。Case #3036（第13段・#2966 段階一覧表 13 行更新）と Case #3038（第14段・14 行更新）で同一現象が再発。同セッション内の case role 本文更新（labels 明示渡し）では発生せず tracking 軸特有。labels 省略の冪等再実行で検証付き成功を取得済み。

## Source Summary

tracking 軸の物理ラベル写像を Tool 内部で管理する構成において、本文のみの更新で labels を渡すと検証だけが失敗する運用上の失敗形式。呼出形式の規約化（labels 省略・論理値指定）と検証失敗時の復帰手順で予防・復帰できる。

## 統合理由

1:1。単一成果物・単一問題クラス（tracking 軸の labels 干渉）であり、予防規則と復帰手順は同一操作知識の表裏のため分割しない。

## 要件化の方向

agentdev-issue-tracking SKILL.md の操作表・操作知識へ (1) 本文のみを更新する issue_update では labels 引数を省略する（不変ラベルは Tool が保持する）規則、(2) verification-incomplete 応答時の復帰手順（独立 issue_read で GitHub 側適用状態を確認 → 適用済みなら再実行せず完了・未適用なら labels 省略で冪等再実行）、(3) ラベル操作が必要な場合は labels 引数ではなく trackingState / kind の論理値で指示する原則、を tracking 軸限定の例外として明記する。agentdev-issue-management references issue-operation-safety.md の操作後 VERIFY 手順への注記候補を含む。agentdev_gh Tool 内部の検証実装（物理ラベル写像）は対象外・fail-closed 挙動は維持する（迂回ではなく呼出形式の規約化）。
