# RU-20261003-18: worktree 削除の Filename too long 部分失敗時 robocopy 掃除手順の追記

## Sources

- **Windows worktree remove 部分失敗の掃除実績**（learning U11・fix gap）: Case #3304 STEP-6-1 で git worktree remove が Filename too long で部分失敗。robocopy /MIR（空 dir ミラー・rc 0-7 成功・残存 0 件検証後 rmdir・git worktree prune）で完遂。worktree-operations.md 削除手順に代替掃除手順の記載なし（部分失敗放置は worktree 登録残存・ディレクトリ残存で後続操作を失敗させる）

## Source Summary

Windows パス長制限による worktree 削除の部分失敗時の代替掃除手順が運用文書にない。

## 統合理由

単一成果物・独立した手順追記。

## 要件化の方向

- worktree-operations.md 削除手順へ「Filename too long 等で部分失敗した場合の robocopy /MIR 手順」を追記: (1) 空ディレクトリを準備し robocopy <空dir> <残存worktree dir> /MIR でミラー削除、(2) robocopy 終了コード 0-7 を成功と見なす、(3) 残存ファイル 0 件を検証してから rmdir、(4) git worktree prune で登録整理
- robocopy /MIR は方向誤りで実ファイルを消すため、空ディレクトリ→残存ディレクトリの方向を明記。AGENTS.md の Windows ファイル操作規律に抵触しない手順とする
