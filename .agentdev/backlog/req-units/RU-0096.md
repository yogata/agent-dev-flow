# RU-0096: verification/implementation 宣言の同一論理関係は inline 既存宣言への集約を優先する運用規則の明文化

## Sources

- **learning: 宣言配置先の判断規則不在**: Case #2936/PR #2953（REQ-012-054 の missing-verification 解消）で、traceability_coverage.test.ts への verification 登録を sidecar 新設ではなく既存 inline 宣言への追記で行う判断を要した。sidecar 新設ルート（inline 宣言の sidecar 移行）も論理的に成立するため配置先の優先順位が規則化されておらず、優先順位不明のまま作業すると duplicate-inconsistencies が発火し差し戻しコストが生じる。同一論理関係（artifact パス × verification role）の宣言を1情報源に集約する duplicate-inconsistencies 規則は既存だが、発火前の配置先判断規則（inline 既存宣言優先、sidecar は inline 宣言がない場合の選択肢）が agentdev-traceability の運用知識に未明文化。対象外: duplicate-inconsistencies 検出ロジック自体の変更、既存 sidecar 宣言の inline 移行（既存配置の正規性は個別判断）。

## Source Summary

重複検出規則（事後）は存在するが配置先判断規則（事前予防）がなく、同一論理関係の対応追加のたびに都度判断と差し戻しリスクが発生する。

## 統合理由

1:1（統合・分割不要）。単一論点（宣言配置先の運用規則明文化）。

## 要件化の方向

agentdev-traceability（SKILL.md または references の運用知識）へ「同一論理関係（artifact パス × role）の追加対応は、該当 artifact が既存 inline 宣言を保持する場合は inline 宣言への追記を優先し、sidecar 新設は inline 宣言がない場合の選択肢とする」運用規則を追記。制約: repo-local artifact は inline 保持が正規配置先規則に適合する既存判断を前提、duplicate-inconsistencies 検出規則との整合を維持。
