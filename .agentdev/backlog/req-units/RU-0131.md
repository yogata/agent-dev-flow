# RU-0131: 同一ファイル複数 edit の順次実行規律と guard ブロック後の実取得再 edit 手順

## Sources

- **learning update-edit-parallel-application-guard-residue**（根拠: #3193）: req-impact-map.md への 7 edit 同時並行実行で 1 件が guard に fail-closed 拒否され、grep で newString 一部のみ反映の部分適用残骸が残存。guard の oldString verbatim 照合は他 edit の適用結果に依存して成立し得ず、拒否時点の状態は「完全未適用」ではない。既存対策は worktree-operations.md L248（再読取再試行）で、同時並行禁止・部分適用残骸の機構説明が fix gap

## Source Summary

edit ツールの同時並行適用が部分適用残骸を残し得る機構と、ブロック後の安全な再適用手順（grep 実取得→再 oldString→単発再 edit）が編集規律文書に未明文化である。guard 本体（agentdev-textlint-guard）は不改。

## 統合理由

単一成果物・単一関心（編集適用規律の明文化）のため 1:1（統合・分割不要）。

## 要件化の方向

- AGENTS.md 編集規律節と worktree-operations.md 書込み guard 運用指針節（L248 の再読取規則の拡張）へ、(1) 同一ファイルへの複数 edit は相互非依存の oldString 選択または順次実行に限定する規律、(2) guard ブロック後は grep 実取得で現在状態を確認してから oldString を組み立てる手順を追記する
- guard の fail-closed 維持原則は不変（解除・迂回ではなく規律と手順の追記）
