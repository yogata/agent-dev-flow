# RU-0131: workspace 外一時ファイルの置き場所指針と標準手段切替の集約

## Sources

- `existing-countermeasure-update-worktree-write-guard-temp-path.md`: case-open STEP-5 横断依存検査（Case #3101・PR #3102、Case #3139 で再発）で、検査入力 JSON を harness が pre-approved と明示する一時ディレクトリ（C:\WINDOWS\TEMP\opencode）へ write ツールで保存しようと agentdev-textlint-guard Plugin に fail-closed ブロック。harness 側の事前承認表示は repo 側 guard 判定に反映されない。deferred.md に同種 3件の記録あり。guard 自体は AGENTS.md 行動規範と整合した正しい動作で、一時ファイルの置き場所指針が機械的検査エンジンの README に定められていないことが問題。node writeFileSync 経由で同一 workspace 外パスへの書込みが可能だった実観測は API 固有の挙動の観察であり、運用上の選択肢としては採用しない（guard 迂回にあたる）。

## Source Summary

- 機械的検査エンジン（横断依存検査等）の検査入力 JSON 等の一時ファイル置き場所が scripts/README.md に規定されず、実行のたびに「harness 提示 temp への書込み試行 → guard ブロック → 代替切替」が繰り返される
- worktree-operations.md「書込み guard 運用指針」節の集約範囲に workspace 外 write ブロック事例（harness 提示 temp の project root 外扱い・project root 内配置への切替・別 API 経路迂回の非採用）が含まれない
- 8軸評価 29/40・発生 5件（inbox 2 + deferred 3）の繰返し問題クラス

## 統合理由

1:1。書込み場所と標準手段切替という独立した関心領域。RU-0130（依存整備手段の判定補助）と集約先 reference を共有するのみで問題型が無関係なため分離する（承認済み構成案の分割判定）。

## 要件化の方向

- 機械的検査エンジンの scripts/README.md に検査入力 JSON の置き場所指針（workspace 外 temp 禁止・project root 内〔worktree 配下の明示的一時パス・gitignore 領域〕限定・commit 対象外・検査後削除）を追記する
- worktree-operations.md「書込み guard 運用指針」節へ workspace 外 write ブロック事例と標準手段切替の知見を集約する
- guard ブロック後の別 API 経路（node writeFileSync 等）による workspace 外書込みを迂回として採用しない旨を明記する（fail-closed 維持・迂回ではなく標準手段への切替が正規）
- 対象外: guard（agentdev-textlint-guard、distribution-boundary-guard）の fail-closed 動作自体の変更、AGENTS.md 行動規範の変更、既存 deferred エントリの移動・prune
- 暫定分類は挙動Design。req-define で最終確定する
