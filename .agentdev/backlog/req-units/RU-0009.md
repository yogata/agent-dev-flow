# REQ 追加時の手動件数記述と派生物の同期（RU-0009）

## 目的

REQ 追加を伴う Definition 変更で、docs/README.md 手動管理区間の件数記述と REQ 行数由来の派生物が、初回の変更・検証範囲から漏れないようにする。

## 背景

REQ-112 の追加時、`generate_indexes` は `docs/README.md` の AUTOGEN 件数を 70 へ更新したが、手動管理区間の「現行要件は 69 件である。」は更新されなかった。その結果、`check_integrity` の `req-range-staleness` が exit 1 となり、`req-health-metrics.md` を含む補正 commit も必要になった（PR #3690、Issue #3681、commit e43bb977、inbox E3）。既存対策確認: application miss（AUTOGEN 外の手動件数記述は generator の更新対象外であり、REQ 追加時の編集範囲に含める手順が不足）。

## 問題

REQ 追加を伴う Definition 変更で、手動管理区間の件数記述と REQ 行数由来の派生物が事前に stage paths へ含められず、既存 integrity gate が不整合を検出して後追い補正が必要になる。

## 合意内容

1:1 とした（Jev 先行評価 1:1 0.88）。

## 要件化の方向

- REQ 追加時の Definition 編集範囲に、手動管理区間の件数記述の照合を含める手順候補を req-define で確定する（反映先候補: `agentdev-workflow-case-open/references/definition-pr-and-idempotency.md`、prepare_definition_pr）。
- REQ 行数由来の派生物が stage paths に事前包含できない場合の検出・補正・証跡の手順候補を req-define で確定する。
- 制約: 既存の整合性 gate を維持し、件数不一致を成功扱いにしない。対象文書・派生物の実際の更新範囲は下流の変更影響分析で確定する。
- 本 RU は agentdev_handoff: true（AgentDevFlow 本体の不具合・改善点を扱う前工程からの引き継ぎ用 RU）である。

## 対象外

- AUTOGEN の手動編集や REQ 件数の推測。
