# case-close 取り込み確認手順への merge 後重複行実検査の明記（RU-0009）

## 目的

同一ファイル接触 PR を直列に連続マージした場合に、GitHub squash merge の無音畳み込み（trivial 重複 auto-resolve）による本文重複の混入を検出できるよう、case-close の取り込み確認手順に merge 後重複行実検査を明記する。

## 背景

同一スクリプト接触 PR（#3747 型エラー修正 → #3751 入力検証追加、3 行重複見込み）を直列化してマージした結果、2 つ目の PR は mergeStateStatus CLEAN のままマージ成功し、重複行混入は発生しなかった（Case #3729、merge commit 0026aefc → 29ae287f）。GitHub の merge 機構が同一変更内容の行を畳み込む（trivial 重複の auto-resolve）platform 挙動が観測された。本件は実害が発生しなかった正常系の観測であるが、CLEAN 判定でも重複行が無音に畳み込まれ得ることが実証され、マージ後の取り込み実在確認で重複行なしを検査して受理した運用が有効だった。既存対策確認は fix gap（GitHub 版 STEP-4 に merge 後重複行実検査の規定なし）。

## 問題

case-close の GitHub 版 STEP-4（`pr-merge-and-conflict.md`）は mergeable ポーリング・CONFLICTING 遷移の自動分岐・STEP-4-4 ローカル先行 commit 処理・STEP-4-5 コンフリクト解消 rebase パスを規定するが、同一ファイル接触 PR を直列に連続マージした場合の merge 後の重複行実検査（マージ後 main で該当行カウントを grep 等で確認する等）を規定する条項がない。CLEAN 判定は CONFLICTING を検出しないため、無音の重複混入または無音の畳み込みを検査せずに受理するリスクが残る。
