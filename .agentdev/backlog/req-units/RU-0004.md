# 既存 fail を前提とする子 Issue の着手時再計測前置（RU-0004）

## 目的

起票源の計測前提が陳腐化した子 Issue が着手される前に、現行 main での再計測によって陳腐化を検知できる運用を導入する。

## 背景

Issue #3741 の起票源 learning 記録は Case #3674 時点（baseline f6a842da）の計測に基づいていたが、追跡Issue #3702 / PR #3720（462074e9）での修復後にその前提は陳腐化していた（発見元: PR #3750、子 Issue #3741 / OU-005 / DEL-3741-2 回収検証、Case #3729 / Epic #3732）。既存 fail を前提とする子 Issue は、着手時に現行 main での再計測を前置すると、起票前提の陳腐化を着手前に検知できる運用改善候補である。

## 問題

既存 fail を前提とする子 Issue が、起票時の計測前提の陳腐化を検知しないまま着手され得る。

- 既に解消済みの問題への無効作業や、誤った前提での実装・検証が発生する。
- 委譲プロンプトの前提記述が古い計測に基づく場合、実行担当サブエージェントの判断を歪める。
- learning-capture の記録側にも、計測前提を含む記録に採番時点の baseline を明示する規律がなく、陳腐化の判定材料が不足する。
