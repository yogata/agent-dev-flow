# RU-0004: baseline 未整備環境での対照実行 delta 0 実証による gate 合格判定の標準化

## Sources

- **baseline-comparison-delta-zero（case 2787、発生4件相当）**: baseline ファイル不在環境（worktree、新環境）では baseline 保持型 gate/checker が既存違反を新規違反と区別できず failure 化する。case 2787 では (a) `check_distribution_boundary.ts --profile source` が baseline 不在で delta 計算不能となり既存 violation を `ok: false` で報告、(b) worktree で self-sync 適用後の走査対象切替により NG baseline 未整備環境で既知 NG が新規 unmanaged NG として顕在化、の2系統が同時発生した。確立した判定手順は「同一 detector・同一引数を main HEAD（PR 変更未適用）と変更 HEAD（worktree）で同一環境再実行し、同一 signature を確認して新規違反 delta 0 を実証して合格扱い」（baseline policy: baseline 超過分のみ gate 失敗）。対照実行は stash ではなく detached worktree を使う（既存規約）。

## Source Summary

baseline 未整備環境での gate 実行が機械的に failure となる問題と、対照実行による合格判定の判定根拠記録が契約化されていない。baseline 整備（IR-059）は別課題として、未整備環境での判定手順を Design へ標準化する必要がある。

## 統合理由

1:1。単一成果物で単一論点（baseline 未整備環境での gate 合格判定手順）であり、統合・分割の必要がない。

## 要件化の方向

検証契約への追記として要件化する。反映先は `docs/designs/integrity/distribution-boundary.md`（baseline policy 節）と `docs/designs/integrity/checker-execution-contracts.md`:

1. baseline 未整備環境での gate 実行時、対照実行（同一 detector・同一引数を main HEAD と変更 HEAD で同一環境再実行）による同一 signature 確認 → 新規違反 delta 0 実証 → 合格扱い、の判定手順を追記する
2. 判定根拠（baseline policy 準拠）を記録形式に含める
3. 対照実行は detached worktree を使う（stash 往復リスク回避の既存規約に従う。worktree-operations.md の baseline 比較手順と矛盾しない）
4. delta 0 実証は同一環境での再実行に基づく（異なる環境間の結果比較で代替しない）
5. 対象外: baseline ファイルの整備自体（IR-059 baseline 整備は別課題）、checker 実装の変更

受け入れ条件（Sources より）: baseline 未整備環境での対照実行 delta 0 判定手順が文書化されていること、判定根拠（baseline policy 準拠）が記録形式に含まれること、detached worktree による baseline 比較の既存手順と矛盾しないこと。
