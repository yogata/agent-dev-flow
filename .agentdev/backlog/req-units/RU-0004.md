# case-autoの評価ブランチ・実証対応

## 目的

RU-0003で成立させる手動の実証・評価ワークフローを、同じ契約のまま `case-auto` から自走可能にする。

実証と正式実装は異なる開発サイクルとして維持し、実証完了後に同一の `case-auto` 呼び出し内で正式化や本実装へ自動継続しない。

## 対象

- `case-auto` が通常Caseと実証Caseを区別できるようにする。
- 通常Caseの既存挙動を維持する。
- 実証Caseでは当該実証専用の評価ブランチを利用する。
- 同時に複数実証を処理する場合、それぞれ異なる評価ブランチを利用する。
- Issue等の永続情報から評価ブランチを復元し、全工程へ一貫して伝播する。
- 評価ブランチ上で必要な `req-save`、`spec-save`、`case-open`、`case-run`、`case-close` を実行する。
- 実証であることだけを理由に `req-save` / `spec-save` を省略しない。
- Standard / Epic双方を扱う。
- Epicでは各Waveの `case-run → case-close` を同じ評価ブランチ上で反復する。
- 評価ブランチへのsquash mergeを正常なCase完了として扱う。
- Case実行状態と評価結果を混同しない。
- 採用でも評価ブランチを `main` へmergeしない。
- 採用でも同一実行内で正式化・本実装を開始しない。
- 実証全体の最終 `case-close` を当該 `case-auto` 実行の正常終了点とする。
- Epic中間Waveでは正式化案内を出さない。
- blocked / failed / 中断時に再開可能なら評価ブランチを保持する。
- 実証が明示的に終了・放棄された場合のみ、必要な記録後に評価ブランチを破棄する。
- 評価契約を自律変更しない。
- ユーザーが評価契約変更を明示した場合は、変更履歴と既存結果への影響を保持し、必要な再評価または再実行を行う。
- 最終出力に、評価結果、実証Issue、主要PRまたは証拠、`main` 未反映であること、次の `req-define <実証Issue>` を示す。

## 対象外

- 実証後の自動 `req-define`。
- 自動正式実装。
- 評価ブランチの `main` へのmerge。
- `case-auto` 専用の実証公開コマンド。
- `case-auto` 専用の新しい評価状態ファイル。

## 依存関係

- RU-0003: 評価ブランチを用いた実証・評価・正式化ワークフロー。
- RU-0003はRU-0002に依存するため、本RUもCase統合先一般化を前提とする。

## 要件化の方向

- `case-auto` は独自の実証判定・評価判定を所有せず、上流で確定した実証Case契約とIssueの永続情報を利用する。
- `case-auto` の既存工程を評価ブランチ上でも同じ責務境界で実行できるようにする。
- 実証完了を当該自動実行の終端とし、正式化は次の独立サイクルへ明示的に引き継ぐ。

### 作業仮定

以下は公開要件ではない。

- `case-auto` 専用の評価状態ファイルは作成せず、RU-0003で定義するIssue/PRの永続情報を利用する。
- 評価ブランチの具体的な伝播形式は実装設計で決定する。

## 決定的受け入れ条件

1. 通常 `case-auto` の既存挙動に回帰がない。
2. Standard実証を評価ブランチ上で完遂できる。
3. Epic実証を複数Waveにわたり同一評価ブランチ上で完遂できる。
4. 独立した複数実証を別々の評価ブランチで扱える。
5. `req-save` / `spec-save` が実証であることを理由に省略されず、評価ブランチ上で正しく実行される。
6. 各PRが対応する評価ブランチへsquash mergeされる。
7. 採用・不採用・判定不能を正常な評価結果として扱い、blocked / failed を実証完了扱いしない。
8. 中断・再実行時にIssue等から正しい評価ブランチを復元し、再開可能な評価ブランチを保持する。
9. 明示的な終了・放棄時のみ必要な記録後に評価ブランチを破棄できる。
10. 評価契約を自律変更せず、ユーザー指示による変更後は必要な再評価または再実行を継続できる。
11. 評価ブランチを `main` へmergeしない。
12. 実証完了後に本実装または `req-define` へ自動継続しない。
13. 最終出力から評価結果、証拠、`main` 未反映、次の `req-define <実証Issue>` が分かる。
14. Epic中間Waveを実証全体完了と誤認せず、正式化案内を出さない。

## 検証方法

RU-0003で定義する主要なStandard / Epic、採用 / 不採用 / 判定不能、blocked / failed、中断・再開、評価契約変更、複数実証並行の各シナリオを `case-auto` 経由でも実行し、手動ワークフローと最終状態、副作用、Issue/PR証跡、`main` 非反映が一致することを確認する。
