# RU-0004: 既存要件の対応付け移行と旧Artifact Graph撤去

## 1. 背景

新しい最小 TIM と `agentdev-traceability` を導入しても、既存の現行要件には新しい実装対応・検証対応が存在しない。移行前に旧 Artifact Graph を撤去すると、既存の明示参照や正規成果物の探索に使える情報まで失われ、棚卸し作業が不必要に難しくなる。

一方、旧 Artifact Graph を互換層や恒久的な補助機構として残すと、今回廃止する汎用グラフ、派生索引、旧公開API、鮮度管理等が残存する。したがって、旧 Artifact Graph は移行時の候補探索に限定して利用し、全現行要件の対応付け完了後に撤去する。

## 2. 目的

既存の全現行要件へ実装成果物・検証手段を明示的に対応付け、新しいトレーサビリティ機能へ完全移行した後、旧 Artifact Graph と旧要件体系を残さず撤去する。

## 3. 要件

### 移行順序

1. RU-0001 に基づく最小 TIM を先に確定すること。
2. RU-0002 に基づく `agentdev-traceability` の基礎機能を先に利用可能にすること。
3. 旧 Artifact Graph、通常のファイル探索、`rg`、既存文書参照等を、既存要件の対応候補を見つけるための補助手段として利用できること。
4. 旧 Artifact Graph の結果だけから、実装対応または検証対応を正規情報として自動確定しないこと。
5. 各現行要件について、実際に要件を実現する実装成果物を確認し、正規成果物側へ実装対応を保存すること。
6. 各現行要件について、実際に要件を検証する永続的な検証手段を確認し、正規成果物側へ検証対応を保存すること。
7. 全現行要件について `check` を実行し、実装対応・検証対応・対応宣言の整合性に未解決の不合格がないことを確認すること。
8. 全現行要件の要件対応が成立した後に、case-close / QG-4 の強制検査を有効化すること。
9. 標準ワークフローの旧 Artifact Graph 利用箇所を `agentdev-traceability` または本来の正規所有機能へ切り替えること。
10. 切替完了後に旧 Artifact Graph のスキル、設定、生成処理、派生生成物、旧公開APIを撤去すること。
11. 移行完了後に、旧 Artifact Graph の互換層、移行専用の恒久例外台帳、旧要件だけを除外する legacy モードを残さないこと。

### REQ再編

12. REQ-012 は全面更新して存続させ、Artifact Graph 標準化ではなく成果物トレーサビリティの正規要件を所有させること。
13. REQ-020 は独立REQとして廃止し、解析品質・試験設計として必要な内容のみ、新しい Design またはテストへ移すこと。
14. REQ-021 は存続させるが、ADF ワークフローのどこでトレーサビリティ能力を利用・検査するかだけを所有する内容へ大幅に縮小すること。
15. REQ-040 は独立REQとして廃止し、必要な `coverage`、`impact`、`check` の外部能力を REQ-012 へ統合すること。

### Decision再編

16. DEC-017 は、今回の最小 TIM、要件中心の対応モデル、Artifact Graph を必須としない構造、正規成果物の直接走査を中心とする方針へ全面再構成すること。
17. 現行 DEC-017 の4層分離、Decision の TIM 必須参加、多数の関係意味を前提とする決定は新方針へ置き換えること。
18. DEC-007 は、新DEC-017が承認された時点で置換済みとして扱い、Artifact Graph を標準探索モデルとする決定を並立させないこと。
19. DEC-019 の「一般処理は標準APIへ委譲し、ADF固有意味だけを所有する」という原則は維持し、Artifact Graph 固有参照のみ後継機能へ追従させること。

### 既存Design・実装の扱い

20. `docs/designs/foundations/traceability-model.md` を新しい最小 TIM に合わせて再設計すること。
21. `docs/designs/skills/agentdev-artifact-graph.md` は、後継 `agentdev-traceability` の Design へ置換または廃止すること。
22. 現行 `tim.ts`、`profiles.ts`、`edges.ts`、Graph生成、問い合わせ、拡張、鮮度管理等の実装は、新Designへの適合性を個別に評価し、必要な小規模資産だけ再利用すること。
23. `.agentdev/artifact-graph.yaml` および `.agentdev/graph/` を標準運用から除去すること。
24. 過去の Artifact Graph 効果評価 Report は履歴上の非規範資料として保持できること。

## 4. 作業仮定

- 既存要件の棚卸しでは旧 Artifact Graph の探索結果を候補として利用するが、最終判断は正規成果物本文・実装・検証手段を確認して行う。
- 既存要件の対応付けは、移行専用Caseとして分割実行できる。
- 移行中は旧機能と新機能が一時的に共存し得るが、最終状態では旧機能を残さない。

## 5. 対象範囲

- 全現行要件の実装対応・検証対応の棚卸しと保存
- REQ-012 / REQ-020 / REQ-021 / REQ-040 の再編
- DEC-007 / DEC-017 / DEC-019 の整合
- Traceability関連Designの再設計
- 旧 Artifact Graph の標準ワークフロー依存除去
- 旧スキル、設定、生成処理、派生生成物の撤去

## 6. 対象外

- 過去の非規範Reportの削除
- 旧公開APIの互換維持
- 恒久的な legacy モード
- 移行用例外台帳の恒久運用
- Graph DBへの移行
- OpenFastTraceの本番導入
- 性能最適化

## 8. 検証方法

- 棚卸し: 現行要件一覧を正規情報源から取得し、各要件の実装対応・検証対応を全件検査する。
- 正確性: 旧 Artifact Graph が提示した候補について、正規成果物または実装を確認せず対応関係が確定されていないことを標本確認する。
- 全件検査: `check` の全件結果を受け入れ条件単位に記録する。
- 依存除去: リポジトリ全体から旧スキル名、旧 Graph 設定、`.agentdev/graph/`、旧公開APIの実行時参照を検索する。
- 文書整合: REQ-012 / 020 / 021 / 040、DEC-007 / 017 / 019、Traceability関連Designの現行・廃止・置換関係を確認する。
- 再実行: 旧 Graph 生成物が存在しない状態で標準ワークフローのトレーサビリティ利用が成立することを確認する。
- 状態遷移: 移行途中では QG-4 強制前、全件移行後では QG-4 強制後となることを確認する。

検証結果は各受け入れ条件ごとに `pass` / `fail` / `blocked` / `not applicable` で記録する。未検証、`blocked`、`fail` が残る場合は移行完了と断定しない。

## 9. 未決事項

要件化を妨げる未決事項はない。既存要件の棚卸しをどの処理単位へ分割するかは、case-open の実行計画で決定する。
