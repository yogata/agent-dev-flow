# RU-0098: check_distribution_boundary link profile の junction 走査除外（Windows 環境で skills 投影を実質走査しない）

## Sources

- **intake: Dirent.isDirectory() フィルタの junction 除外**: Case #2903（実装 PR #2922）の case-run 配布依存境界 gate で、Windows 環境の check_distribution_boundary.ts --profile link が collectTargets の Dirent.isDirectory() フィルタにより junction エントリ（isSymbolicLink=true / isDirectory=false）を走査対象から除外することを確認。結果、skills 投影（.opencode/skills/agentdev-*）が link 走査対象に含まれず実質 commands 投影のみの走査（scanned 39 files）。main・worktree 共通の環境特性で、契約の fallback（junction 構成が維持された root 指定）でも同一挙動。実装実体は scripts/lib/distribution-boundary-fs.ts L126/L158-159（isSymbolicLink 分岐なし、item 本文と機能的に同一チェーンを intake-promote review でコード実読み確認済み）。影響: link profile の「双方反映の存在検査」が skills 投影側で機能せず、配置先投影の欠落・link 切れを検出できない（source profile が部分的に代替）。選択肢: (1) Dirent 判定に isSymbolicLink() または実体解決後 stat を併用し junction を link 走査対象に含める checker 実装修正 (2) Windows 環境特性として既知制限を checker 実行契約 Design（docs/designs/integrity/distribution-boundary.md 系）へ明記。

## Source Summary

Windows の junction ディレクトリ形式のスキル投影が link profile の走査対象から構造的に除外されており、検出の網羅性が環境依存で低下している。checker 実装修正または既知制限の文書化のいずれかで対応方針を確定する必要がある。

## 統合理由

1:1（統合・分割不要）。単一論点（link profile の走査対象）。
