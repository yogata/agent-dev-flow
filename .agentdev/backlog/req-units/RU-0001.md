# RU-0001: OpenCode同一セッションのモデル昇格とADF共通設定

## 目的

### 背景

OpenCode上で、通常は比較的軽量なモデルを利用し、通常モデルでは解決困難とモデル自身が判断した場合だけ、同一セッションのまま高能力モデルへ切り替えて処理を継続したい。

今回の利用例では通常時に GLM-5.3-Flash(high)、必要時のみ GLM-5.3(max) を利用する。ただし、この仕組み自体は特定のProviderやモデルへ固定せず、ADFの汎用的な実行時機能として扱う。

また、モデル昇格用Pluginだけの専用設定ファイルを増やすのではなく、ADF全体で利用する共通設定を単一ファイルへ集約する。

対象実行環境は OpenCode v1.18.23 とする。

### 問題

現在は、通常モデルが処理中に「この問題はより高能力なモデルが必要」と判断しても、同じ会話履歴を保持した同一セッションのまま、次ターンから別モデルへ昇格し、その後元のモデルへ復帰するADF共通機構がない。

また、今後ADFのPlugin、Tool等が利用者設定を必要とする場合の共通設定場所も定義されていない。個々の機能が専用設定ファイルを持つ方式では設定ファイルが増殖し、ADF全体としての設定責務が分散する。

### 統合理由

モデル昇格機構は昇格先モデルの利用者設定を必要とするため、ADF共通設定契約と切り離すことができない。

一方、今回の昇格機能専用設定ファイルを作成すると、今後PluginやToolごとに設定ファイルが増える構造となる。

そのため、ADF全体の共通設定ファイル、その最初の利用項目としてのモデル昇格設定、同一セッションのモデル昇格・復帰を一つのRequirement Unitとして扱う。

## 要件化の方向

### ADF共通設定

ADFのプロジェクト単位の共通設定ファイルを `.agentdev/agentdev.jsonc` に統一する。このファイルはADF全体で共有する設定ファイルであり、特定のPlugin、Tool、command、skill専用にはしない。

今回のモデル昇格では、概念的に次の設定を持つ。

```jsonc
{
  "modelEscalation": {
    "model": "zai-coding-plan/glm-5.3",
    "variant": "max"
  }
}
```

`modelEscalation` が存在しない場合、モデル昇格機能は無効とする。

通常モデルは設定項目として持たない。昇格要求を受けた時点で実際に利用しているモデルとvariantを復帰先として保持する。

### モデル昇格と復帰

通常モデル自身が現在の課題を解決困難と判断した場合、明示的に昇格を要求できるようにする。

昇格要求を受けた実行制御は、現在ターン終了後、同一 `sessionID` の次ターンを `.agentdev/agentdev.jsonc` に指定された昇格先モデルで開始する。

昇格後は、昇格モデル自身が課題解決を判断して明示的に復帰を要求するまで昇格状態を維持する。復帰時は、昇格直前に利用していたモデルおよびvariantへ戻す。

昇格・復帰時は、切替前モデルと切替後モデルを利用者へ一行で通知する。

### 責務分離

モデルは、現在のモデルでは解決困難か、および昇格後の課題が解決したか、という意味的判断のみを行う。

ADFの実行機構は、同一セッションの識別、昇格前モデルの保持、ターン境界でのモデル切替、昇格状態の保持、元モデルへの復帰、切替結果の通知、切替失敗時の正確な状態報告、無限反復の防止を担当する。

モデルからの明示的な昇格・復帰要求の受付と、決定論的なセッション制御は分離する。

本機能はomoに依存せず、ADF導入Consumerにも配布する。

## 決定的受け入れ条件

1. `.agentdev/agentdev.jsonc` がADF共通設定ファイルとして定義され、Git管理対象となっている。
2. モデル昇格機能専用の別設定ファイルを必要としない。
3. `modelEscalation` が存在しない場合、モデル昇格機能が発動しない。
4. 昇格先としてモデルとvariantを指定できる。
5. ADF設定へ通常モデルを固定しなくても動作する。
6. 通常モデルが明示的に昇格を要求しない限り、昇格モデルが利用されない。
7. 昇格要求後、現在進行中の推論ではなく次ターンから昇格モデルが利用される。
8. 昇格前後で `sessionID` が変化しない。
9. 昇格によって新しいサブエージェントまたは別セッションが生成されない。
10. 昇格モデルは同一セッションのそれまでの会話履歴を利用して処理を継続できる。
11. 昇格状態は、昇格モデルが解決を判断して復帰を明示要求するまで維持される。
12. 復帰時、昇格直前に実際に使用していたモデルとvariantへ戻る。
13. 昇格時に、切替前モデルと切替後モデルを利用者へ一行で通知する。
14. 復帰時に、切替前モデルと切替後モデルを利用者へ一行で通知する。
15. モデル切替に失敗した場合、昇格または復帰に成功したものとして表示・記録されない。
16. 昇格・復帰処理が無限反復しない。
17. 本機能が特定のメインエージェントだけに固定されず、ADFが動作するOpenCodeセッションで利用できる。
18. 本機能の動作にomoを必要としない。
19. ADF導入Consumerへ、本機能の動作に必要な実行時構成が配布される。
20. `.agentdev/agentdev.jsonc` にProvider認証情報やAPIキーを保存する必要がない。
21. OpenCode v1.18.23上で、昇格・継続・復帰の一連の状態遷移が実動作として確認できる。

### 検証方法

- 通常モデルで解決可能なケースを実行し、昇格が発生しないことを確認する。
- 通常モデルから明示的に昇格要求を行い、次ターンが指定モデル・variantかつ同一 `sessionID` であることを確認する。
- 昇格モデルで複数ターン継続し、途中で通常モデルへ戻らないことを確認する。
- 昇格モデルから復帰要求を行い、昇格直前のモデル・variantへ戻ることを確認する。
- 昇格・復帰時の通知を確認する。
- 昇格先モデルが利用不能なケースで、成功扱いされないことを確認する。
- `modelEscalation` を設定しないケースで、本機能が無効となることを確認する。
- メインセッションとサブエージェントセッションの双方で、同一セッション内切替が成立することを確認する。
- ADF Consumer環境で、配布後に同じ契約が成立することを確認する。
