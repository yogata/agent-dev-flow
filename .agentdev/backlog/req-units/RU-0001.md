# RU-0001: scripts 公開入口の self / consumer 二系統化

## 背景

AgentDevFlow の `scripts/` 直下には、利用者が直接実行するスクリプト、内部共通処理、配布成果物生成、信頼境界検証、保守処理が混在している。

利用者視点で通常必要な操作対象は大きく次の2系統である。

1. AgentDevFlow を導入先リポジトリで利用する consumer 向け操作
2. AgentDevFlow 本体リポジトリ自身へ実行時成果物を反映する self-hosting 向け操作

一方、現状の consumer 操作では、導入・再同期・変更予測を担うスクリプトと状態確認専用スクリプトが別入口となっており、状態確認機能も一部重複している。

配布成果物生成、archive 専用 installer、信頼境界検証、機械置換等は通常利用者が `scripts/` 直下から選択する用途ではない。

## 問題

`scripts/` 直下のファイル名を見ただけでは、利用者がどれを実行すべきか判断しなければならない。

特に以下の問題がある。

- consumer の導入と状態確認が複数の公開入口に分かれている。
- 単体実行しない内部共通スクリプトが公開入口と同じ階層に存在する。
- release 作成、信頼境界検証、保守処理が通常利用者向けスクリプトと同列に並ぶ。
- 公開入口名に `consumer` や `opencode` 等の実装・利用形態上の情報が入り、利用者が内部構造を理解する必要がある。
- スクリプトの固定パスが配布 manifest、信頼ルート、文書、検証処理等にも組み込まれており、単純なファイル移動では整合性を維持できない。

## Source Summary

本セッションで以下を合意した。

- `scripts/` 直下は通常利用者向けの安定した公開入口だけに限定する。
- 公開入口は consumer 用と self-hosting 用の2本とする。
- consumer 用公開入口名は `scripts/install.ps1` とする。
- self-hosting 用公開入口名は `scripts/self-sync.ps1` とする。
- 公開入口名には `opencode` を含めない。
- consumer の状態確認専用公開入口は廃止し、`install.ps1 -Mode check` へ統合する。
- 旧状態確認処理が持つ検査能力は統合後も失わない。
- 旧スクリプト名の互換ラッパーは残さない。
- consumer 内部処理は `scripts/consumer/` 配下へ移す。
- self-hosting 固有の配布、検証、保守処理は `scripts/self/` 配下へ移す。
- release archive に同梱する consumer 向け installer の公開名も `scripts/install.ps1` とする。
- repository 上では archive 専用 installer の原本を通常 consumer installer と分離して保持する。
- 通常 checkout 版と release archive 版の `install.ps1` は同名の公開入口とするが、異なる installation projection として扱う。
- consumer 用入口と self-hosting 用入口は実行対象を判定し、誤った環境では停止する。
- 配布 manifest、信頼ルート、固定パス参照、文書等も同一変更単位で更新する。
- 公開入口が依存する内部スクリプトも配布・検証対象として完全性を保証する。
- provisioning と install の責務分離、および install が provisioning や network access を行わない既存原則は維持する。

## 統合理由

本変更は「`scripts/` 配下のファイル整理」ではなく、利用者向けスクリプトの公開インターフェース境界を再定義する変更である。

ファイル移動のみを実施すると、次の問題が残る。

- consumer の複数入口が維持される。
- 利用者が内部スクリプトを選択できてしまう。
- 配布 manifest や信頼ルートが旧パスを参照し続ける。
- archive installer と通常 installer の利用者向け命名が分裂する。
- 文書上の導線と実装上の公開入口が一致しない。

したがって、公開入口、内部配置、consumer の状態確認統合、archive 配布、信頼境界、参照更新を1つの Requirement Unit として扱う。

## 要件化の方向

### 1. 公開入口境界

`scripts/` 直下に置く通常利用者向け公開スクリプトを次の2本に限定する。

```text
scripts/
├── install.ps1
└── self-sync.ps1
```

内部処理、配布生成、検証、保守処理は `scripts/` 直下へ配置しない。

### 2. consumer 公開入口

`scripts/install.ps1` を AgentDevFlow consumer 向けの唯一の通常公開入口とする。

少なくとも次のモードを提供する。

- `apply`: 導入または再同期を実行する。
- `check`: 現在の導入状態を検査する。
- `dry-run`: 変更内容を予測し、変更しない。

`check` は旧状態確認専用スクリプトが提供していた検査能力を包含する。既存の orphan 検出等を、入口統合を理由に失ってはならない。

既存の `-LocalMode`、`-PluginDir` 等、現行要件で有効な consumer 向け契約は新入口へ継承する。

### 3. self-hosting 公開入口

`scripts/self-sync.ps1` を AgentDevFlow 本体リポジトリ専用の通常公開入口とする。

少なくとも次のモードを提供する。

- `apply`
- `check`
- `dry-run`

責務は AgentDevFlow 本体の原本と実行時配置先の同期、乖離確認、変更予測とする。

### 4. 誤実行防止

`install.ps1` は AgentDevFlow 本体リポジトリを consumer として変更してはならない。

`self-sync.ps1` は consumer リポジトリで self-hosting 同期を実行してはならない。

各入口は対象環境を機械的に判定し、誤った環境では変更前に停止して、適切な入口を案内する。

### 5. 内部配置

内部実装の基本構造を次の方向で整理する。

```text
scripts/
├── install.ps1
├── self-sync.ps1
├── consumer/
│   ├── common.ps1
│   └── archive/
│       └── install.ps1
└── self/
    ├── release/
    │   ├── package-release-archive.ps1
    │   ├── trusted-distribution-gate.ps1
    │   ├── publish-hard-link.ts
    │   └── publish-hard-link.test.ts
    └── maintenance/
        └── apply-mechanical-replacement.ps1
```

具体的な内部ファイル分割は、公開契約と依存境界を変えない範囲で実装時に調整可能とする。

ただし次の分類は維持する。

- consumer 専用内部処理: `scripts/consumer/`
- self-hosting 専用内部処理: `scripts/self/`
- release 生成・検証: `scripts/self/release/`
- self-hosting 保守処理: `scripts/self/maintenance/`

### 6. release archive

repository 上の archive 専用 installer 原本は、通常 consumer installer と分離して保持する。

基本配置は次とする。

```text
scripts/consumer/archive/install.ps1
```

release archive 内では consumer が実行する公開入口として次の名前で配置する。

```text
scripts/install.ps1
```

通常 checkout 版の `scripts/install.ps1` と release archive 版の `scripts/install.ps1` は同一ファイルである必要はない。

両者は異なる installation projection として扱い、それぞれの導入方式の契約を維持する。

### 7. 配布・信頼境界

スクリプト再配置に伴い、旧固定パスを参照する次の仕組みを新構造へ同期する。

- 配布 manifest
- protected path / trust root
- release archive 構成
- 配布境界検査
- archive-installed 検査
- 関連テスト
- その他、スクリプトパスを契約として保持する検証処理

公開入口のみを配布・信頼対象として列挙して終えてはならない。

公開入口が実行時に必要とする内部スクリプト、モジュール、設定等を含む実行依存集合について、欠落や未検証状態が生じないことを保証する。

### 8. 旧入口の廃止

次の旧公開入口は廃止する。

- `scripts/install-consumer-opencode.ps1`
- `scripts/check-consumer-opencode.ps1`
- `scripts/sync-self-opencode.ps1`

旧名を維持する互換ラッパーは設けない。

現行文書、検証処理、manifest、テスト等に残る現役の旧パス参照は新しい入口または内部配置へ更新する。

歴史記録として旧名称を記録する必要がある文書は、現行入口として誤認されない限り削除対象としない。

### 9. 既存原則の維持

本変更は provisioning と install の責務分離を変更しない。

consumer の `install.ps1` は次を行わない。

- `git clone`
- `git fetch`
- `git reset`
- その他の checkout 取得・更新
- network access

checkout の取得・更新は引き続き利用者の責務とする。

`apply` の既存冪等性、安全な cwd 検査、`#Requires`、comment-based help 等の既存有効契約も維持する。

## 主対象REQまたは変更対象候補

### 主対象REQ

- `REQ-009 配布基盤と導入モデル`
  - 旧3スクリプト前提を2公開入口へ更新する。
  - consumer の状態確認入口を `install.ps1 -Mode check` へ統合する。
  - `scripts/` 公開入口境界を利用者向け安定契約として定義する。

### 変更対象候補

- 導入スクリプトの使いやすさを所有する Design
- 実行時パッケージ境界を所有する Design
- 配布依存境界を所有する Design
- trust root / protected path / manifest を所有する実装・テスト
- consumer 導入 Guide
- repository README
- ローカル版導入 README
- DEC-016 の旧スクリプト名参照

DEC-016 の「導入系スクリプトは provisioning と network access を行わない」という決定内容自体は変更しない。

配布依存境界の意味モデル自体も変更対象外とし、新しいスクリプト配置への追従を行う。

## 対象範囲

- `scripts/` 直下の公開入口再編
- consumer install/check の公開入口統合
- self-hosting 同期入口の改名
- consumer 内部スクリプトの再配置
- self-hosting 配布・検証・保守スクリプトの再配置
- release archive installer の原本配置と archive 内公開名の整理
- 配布 manifest のパス更新
- trust root / protected path のパス更新
- スクリプトの実行依存集合の配布・検証完全性確保
- README、Guide、REQ、Design、Decision 等の現役参照更新
- 関連する自動検証、テストの更新

## 対象外

- provisioning を install 側へ取り込むこと
- network access の追加
- npm/package/plugin 配布方式の新設
- release archive と通常 link mode の統合
- `.opencode/` の実行時パッケージ構造自体の再設計
- consumer のリポジトリ種別体系の2種類への縮小
- `consumer-with-agentdev`、`consumer-generated` 等の既存リポジトリ種別の廃止
- AgentDevFlow の command / skill 自体の公開インターフェース変更
- 本変更と無関係な scripts 内部実装のリファクタリング
- 歴史資料に記録された旧スクリプト名の機械的削除

## 受け入れ条件

1. `scripts/install.ps1` が consumer 向け通常公開入口として存在する。
2. `scripts/self-sync.ps1` が self-hosting 向け通常公開入口として存在する。
3. `scripts/` 直下に、通常利用者が直接選択する必要のある第三の運用スクリプトが存在しない。
4. `install.ps1` が `apply`、`check`、`dry-run` を提供する。
5. `self-sync.ps1` が `apply`、`check`、`dry-run` を提供する。
6. `install.ps1 -Mode check` が旧状態確認専用スクリプトの検査能力を包含し、orphan 等の既存検出能力が欠落しない。
7. `install.ps1 -Mode check` は consumer の管理対象ファイルを変更しない。
8. `install.ps1 -Mode dry-run` は consumer の管理対象ファイルを変更しない。
9. `install.ps1 -Mode apply` の既存冪等性が維持される。
10. `self-sync.ps1 -Mode check` と `-Mode dry-run` は同期対象を変更しない。
11. `install.ps1` を AgentDevFlow 本体リポジトリで誤実行した場合、変更前に停止する。
12. `self-sync.ps1` を consumer リポジトリで誤実行した場合、変更前に停止する。
13. 誤実行停止時に、利用者へ適切な公開入口が案内される。
14. `-LocalMode` を必要とする既存 consumer 利用形態が `install.ps1` から利用できる。
15. `-PluginDir` 等の現行有効な consumer 向け公開オプションが、要件上不要と判断されない限り維持される。
16. `install-consumer-opencode.ps1`、`check-consumer-opencode.ps1`、`sync-self-opencode.ps1` が現行公開入口として残っていない。
17. 旧公開入口名の互換ラッパーが `scripts/` 直下に存在しない。
18. 単体実行しない consumer 共通処理が `scripts/` 直下に存在しない。
19. release 生成、信頼境界検証、self-hosting 保守処理が `scripts/` 直下に存在しない。
20. repository 上で archive 専用 installer の原本が通常 consumer installer と分離されている。
21. 生成された release archive では consumer 向け installer が `scripts/install.ps1` として利用できる。
22. release archive 版 `install.ps1` が archive installation projection の既存契約を維持する。
23. 通常 checkout 版と release archive 版を同一実装へ無理に統合しない。
24. 新しい公開入口およびその実行依存集合が配布 manifest の対象として完全に表現される。
25. trust root / protected path が新しい信頼対象パスを保護し、移動後の旧パスだけを保護する状態にならない。
26. 公開入口が依存する内部ファイルを欠落させた配布成果物が正常扱いされない。
27. release archive の生成前・生成後検査が新しいパス構成でも正常に機能する。
28. 現行 README、Guide、REQ、Design、Decision、実行手順から、旧3公開入口を現行手順として参照する記述が除去または更新される。
29. 歴史的説明を除き、旧公開入口名を利用者へ実行させる現役導線が残らない。
30. `install.ps1` は provisioning を実行しない。
31. `install.ps1` は network access を行わない。
32. git clone checkout と、既存要件で許容される source ZIP checkout の双方で consumer 導入契約が維持される。
33. 通常 consumer と `-LocalMode` consumer の双方で `apply`、`check` の主要経路を検証できる。
34. PowerShell の comment-based help と `#Requires` の既存契約が新しい2公開入口で維持される。
35. 公開入口名に `opencode` を含めない。
36. 本変更によって `.opencode/` の内部構造そのものを新たな利用者公開契約へ昇格させない。

## 検証方法

実装後、少なくとも次を検証する。

- `scripts/` 直下のファイル構成確認
- consumer の `apply / check / dry-run`
- self-hosting の `apply / check / dry-run`
- consumer / self-hosting の相互誤実行
- 通常 consumer と `-LocalMode` consumer
- git clone checkout と source ZIP checkout
- consumer `check` の旧検査能力との同等性
- apply の再実行
- release archive 生成
- release archive 内の `scripts/install.ps1` 実行
- source / link / archive / archive-installed の各配布境界検査
- trust root / protected path の新パス保護
- 公開入口から内部依存を1件欠落させた場合に配布検証が失敗すること
- 現役文書・コードにおける旧公開入口参照の残存確認
- `Get-Help` による comment-based help 確認
- provisioning および network access が install 処理に再導入されていないこと
