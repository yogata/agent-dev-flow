# 配布物内部参照の一般化・是正

本 RU は AgentDevFlow 本体向けの引き継ぎ RU である（本体リポジトリでは通常の req/case workflow 入力として扱う）。

## Sources

- procedure-distribution-comment-id-reference（learning）: 配布ソースコメントへの REQ/Design ID 直接記載が配布依存境界違反になる。対応関係は ADF-COVERS 宣言行へ集約し、本文は設計契約や節名などの一般化表現にする（PR #2745）。
- procedure-distribution-concrete-id-generalization（learning）: 配布手順本文の REQ/DEC/IR concrete ID が consumer 側で解決不能。Design 節名と内容説明へ集約し、正規の対応宣言は許可された宣言行に置く（PR #2748/#2761）。
- project-knowledge-distribution-id-generalization（learning）: 配布物 reference 側の内部 ID、docs/designs パス、括弧付き宣言表記の回避規則。「Design一覧」等の一般名詞へ置換する（PR #2760）。
- worktree-operations-docs-designs-reference-removal（intake）: `src/opencode/skills/agentdev-git-worktree/references/worktree-operations.md` L146 が `docs/designs/local/runtime-package-boundary.md` を参照し IR-055 既知 delta として baseline 登録済み。是正には表現解消と baseline エントリ除去が要る。
- distribution-artifact-existing-findings-remediation-candidates #1（intake）: 既存配布物 10 ファイルに残存する本体内部 ID（REQ-NNN-NNN、IR-NNN）・docs/designs/ パス表記の段階的概念語化。

## Source Summary

配布物本文・コメント・reference に残る内部 concrete ID / docs 内部パス参照は consumer で解決できず、配布依存境界（IR-055）違反の反復原因である（PR #2745/#2748/#2760/#2761 で 4 度検出・是正を経験）。規則そのもの（宣言行集約、一般名詞化）は運用で確立済みだが、正規文書への明文化がなく、残存箇所 11 件以上が既知 delta として baseline 登録されたまま残る。

## 統合理由

N:1 統合。5 成果物は同一関心領域（配布物本文の内部 ID / パス参照の回避規則）について、規則の学習側（3件）と既存残存箇所の是正側（2件）が補完関係にある。規則明文化と残存解消を同一要件単位とすることで再発と既知 delta 残存を同時に閉じる。

## 要件化の方向

1. 配布依存境界系契約（distribution-boundary 系 Design）へ「対応関係は宣言行へ集約、本文は節名・一般名詞で記述、docs 内部パスを配布物へ残さない」規則を明文化する。
2. worktree-operations.md L146 の参照表現を解消し、IR-055 baseline の該当エントリを併せて除去する。
3. 既存配布物 10 ファイルの残存 ID・パス表記を段階的に概念語化する。
4. 受け入れ条件は配布依存境界・IR-055・traceability 検査の新規違反 0 件とする。
