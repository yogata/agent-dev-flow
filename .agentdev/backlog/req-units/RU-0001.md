# 複数委譲の中断→回収時における PR 本文への両委譲記録と機械確認の条項化（RU-0001）

## 目的

同一 worktree への複数委譲（中断 → 回収）において、回収側の完了扱いを重複 PR から守り、中断→回収の同一性を後続工程（case-close の完了判定・Capture 回収）が機械的に確認できるようにする。

## 背景

同一 worktree への複数委譲（DEL-3741-1 中断 → DEL-3741-2 回収）では、回収側の検証完了後に別主体が commit/push/PR 作成まで進行し得る実測がある（PR #3750、子 Issue #3741 / OU-005、merge commit 8c3e1d56、Case #3729 / Epic #3732）。回収側の完了扱いを重複 PR から守る運用として、「PR 本文の実行識別情報・検証差分に両委譲の記録を併記し、内容同一性を機械確認（diff 空）してから完了扱いとする」ことが候補として検討されていた。

## 問題

case-run 委譲・回収手順（`docs/designs/foundations/v4-delegation-contracts.md` と `agentdev-workflow-case-run` / `agentdev-workflow-orchestration` の管理領域）に、次の規定が存在しない（rg 実測・回収/中断/PR 本文の関連条項 0 件）。

- PR 本文の実行識別情報（DEL 識別子）・検証差分への両委譲の記録併記
- 内容同一性の機械確認（diff 空）を完了扱いの前置条件とする規律

実行識別情報が PR 本文に記録されないと、中断→回収の同一性を後続工程が機械確認できず、重複 PR による完了扱いの二重化を検出できない。

## 要件化の方向

- `docs/designs/foundations/v4-delegation-contracts.md` および case-run 関連 workflow（agentdev-workflow-case-run / agentdev-workflow-orchestration）の手順への条項化候補を req-define で確定する。
- 条項内容候補: 回収側は PR 本文の実行識別情報・検証差分に両委譲（中断側・回収側）の記録を併記する。完了扱いの前に内容同一性の機械確認（diff 空）を実施する。
- 反映先の選択（Design 追記のみ、配布 skill references への手順明記、両方）は req-define の変更影響分析で確定する。

## 対象外

- 委譲中断の検知機構そのものの新設。
- 単一委譲の通常フローの変更。
- case-close Capture 回収手順・完了判定ロジックの変更（本 RU はその前提となる記録整備のみを扱う）。
