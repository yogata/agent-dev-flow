# backlog 一括整理コマンド

## 目的

`inspect-docs` による文書診断、learning / intake / inspect の各昇格処理、`backlog-review` による統合と RU 生成までを1回の公開コマンド起動で一巡させ、蓄積された改善候補を RU 候補まで整理できる標準的な backlog 整理サイクルを提供する。

公開コマンド名は `/agentdev/backlog-auto` とする。既存の個別コマンドは置換せず、既存 Workflow Skill に処理を委譲する薄いオーケストレータとして追加する。

## 対象

- `/agentdev/backlog-auto` 公開コマンドの追加。
- 対応する Workflow Skill の追加。
- 実行順序は `inspect-docs` → 昇格3系統 → `backlog-review` とする。
- `inspect-docs` の正常終了後に `learning-promote`、`intake-promote`、`inspect-promote` を開始する。
- 3つの昇格系統には相互の先行依存関係を設けず、安全に並行可能な処理は並行実行する。
- Git 同期、commit、push、共有成果物への競合書き込み、ユーザー対話など排他性が必要な処理は安全に直列化する。
- 3つの昇格系統がすべて正常完了または「対象なし」で終了した場合のみ `backlog-review` を開始する。
- 一部の昇格系統が `blocked` または `failed` になっても、独立して進行可能な他系統は継続する。
- 1系統でも `blocked`、`failed`、未完了が残る場合は `backlog-review` を開始せず、`backlog-auto` 全体を完了扱いにしない。
- 各子ワークフローの既存 HITL 境界を維持し、複数系統が判断待ちとなった場合はユーザー対話のみを安全に直列化する。
- 3つの昇格系統で新しい採用済み成果物が生成されなかった場合でも、全系統正常終了後は `backlog-review` を実行し、実行前から存在する promoted artifact を処理対象にできるようにする。
- 中断・再実行時は子ワークフローの既存再開契約を利用し、完了済み工程を不必要に重複実行せず、未完了工程を完了済みと誤認しない。
- `inspect-docs` は既存契約どおり STEP model 対象外とし、実行途中で中断した場合は先頭から再実行する。
- `inspect-promote --auto` は通常の `backlog-auto` 実行から暗黙的に有効化しない。

## 対象外

- `inspect-docs`、`learning-promote`、`intake-promote`、`inspect-promote`、`backlog-review` の既存業務ロジックの再実装。
- learning / intake / inspect の分類基準、評価基準、昇格基準の変更。
- 既存5コマンドの廃止、置換、単独実行契約の変更。
- `intake-promote` 自身からの `backlog-review` 自動起動。
- `inspect-skills` の一括処理への追加。
- `learning-capture`、`intake-capture`、`intake-from-github` の自動起動。
- `req-define`、`req-save`、GitHub Issue / PR 作成までの自動化。
- `inspect-promote --auto` の暗黙的有効化、または本 RU での新規公開オプション追加。
- 並列化だけを目的とした複数 worktree 方式への既存ワークフロー全面再設計。
- 並行実行数、スレッド数など内部実装パラメータの固定。

## 依存関係

依存する別 RU はない。

既存公開契約として、次を前提とする。

- `inspect-docs` は診断結果を `.agentdev/inspect/inbox/` に生成し、検査対象自体を変更しない。
- `learning-promote`、`intake-promote`、`inspect-promote` はそれぞれの採用済み成果物を生成し、各自の HITL と停止条件を所有する。
- `backlog-review` は intake / learning / inspect の promoted artifact を統合して RU を生成する。
- ワークフロー横断契約は `blocked` / `failed` / resume / no-op を区別し、並列 child task を持つ workflow の fan-in 判定を扱う。

## 要件化の方向

### 利用者から見える要件

- `/agentdev/backlog-auto` を、既存個別コマンドを置換しない追加の一括入口として提供する。
- 一括入口から `inspect-docs`、昇格3系統、`backlog-review` までを一連の操作として実行できること。
- 昇格3系統は論理的に独立して進行し、安全に並行可能な範囲では並行実行できること。
- `backlog-review` の開始には昇格3系統すべての正常終了を要求すること。
- 一部系統の停止・失敗時でも独立系統を不要に停止させず、一方で部分的な状態を一括処理全体の成功として報告しないこと。
- 既存子コマンドの HITL、安全境界、停止条件、自動昇格 opt-in を維持すること。
- 中断・再実行時に既存の durable state と再開契約を利用して安全に継続できること。

### 作業仮定

以下は公開要件ではなく、利用者可視契約を変更しない範囲で実装時に変更可能な仮定とする。

- 新 Workflow Skill の実装分類は既存の `manager-orchestrator` を利用する。
- トップレベル状態は概ね「文書診断」「昇格3系統」「backlog-review」の段階で管理する。
- 排他制御、child task 管理、再開情報の具体的な保存方式は既存 STEP model / durable state 契約を再利用する。
- 「並行実行」は3コマンド全体を無条件に同時起動する意味ではなく、安全に独立実行できる処理の並行化を意味する。

## 決定的受け入れ条件

1. `/agentdev/backlog-auto` を1回起動すると、`inspect-docs` → 昇格3系統 → `backlog-review` の順序関係で処理される。
2. `inspect-docs` が正常終了する前に `learning-promote`、`intake-promote`、`inspect-promote` が開始されない。
3. `learning-promote`、`intake-promote`、`inspect-promote` 間に不要な先行依存がなく、安全に並行可能な処理を独立して進められる。
4. 同一作業ツリーに対する競合する Git 操作または共有成果物への競合書き込みが同時実行されない。
5. 複数系統が HITL 待ちとなってもユーザー対話が混線せず、どの子ワークフローに対する判断か識別でき、各既存 HITL 契約が維持される。
6. 1つの昇格系統が `blocked` になっても、独立して実行可能な他系統は継続する。
7. 1つの昇格系統が `failed` の場合、他系統が正常終了していても `backlog-review` は開始されない。
8. 昇格3系統すべてが正常完了または「対象なし」で終了した場合のみ `backlog-review` が開始される。
9. 昇格3系統の一部または全部に新規処理対象がなくても、「対象なし」が正常終了である限り一括処理の失敗として扱わない。
10. 昇格3系統で新規 promoted artifact が0件でも、全系統正常終了後に `backlog-review` が実行され、開始前から存在する promoted artifact を処理できる。
11. `inspect-docs` が `blocked` または `failed` となった場合、昇格3系統および `backlog-review` が開始されない。
12. 中断後に再実行した場合、未完了工程を完了済みと誤認せず、子ワークフローの再開契約に従って安全に継続できる。中断した `inspect-docs` は既存契約どおり先頭から再実行される。
13. 新コマンド追加後も `inspect-docs`、`learning-promote`、`intake-promote`、`inspect-promote`、`backlog-review` を従来どおり単独実行でき、各公開契約が変更されない。
14. 通常の `/agentdev/backlog-auto` 実行によって `inspect-promote --auto` が暗黙的に有効化されない。
15. `blocked`、`failed`、未完了の子ワークフローが1つでも残る場合、`backlog-auto` が全体完了を報告しない。

## Source Summary

チャット内で、`inspect-docs` の後に `learning-promote`、`intake-promote`、`inspect-promote` を論理的に並列実行し、3系統の正常終了後に `backlog-review` を実行する一括コマンドを追加する方針を合意した。

並行実行については、既存コマンドが同一作業ツリーで Git 同期、commit、push や共有領域への書き込みを行うため、コマンド全体の無条件同時実行ではなく、安全な処理だけを並行化し、競合処理とユーザー対話は直列化する方針とした。

一部の昇格系統が停止または失敗した場合は、他の独立系統は進める一方、3系統すべてが正常終了するまで `backlog-review` を開始しない。既存各子ワークフローの HITL、停止条件、再開規則を維持し、新コマンドは工程間制御だけを担う薄いオーケストレータとする。公開コマンド名は `/agentdev/backlog-auto` とする。

## 検証方法

実装後は上記受け入れ条件ごとに `pass` / `fail` / `blocked` / `not applicable` で結果を記録する。

最低限、全系統に対象がある正常系、一部または全部が空の状態、`inspect-docs` 停止、各昇格系統それぞれの `blocked` / `failed`、複数 HITL 同時待ち、Git 排他が必要な条件、既存 promoted artifact のみが存在する状態、中断後再実行、個別コマンド単独実行、`inspect-promote --auto` 非暗黙有効化を検証する。
