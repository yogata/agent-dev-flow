# ADF 管理投影物の廃止時クリーンアップ契約

## 背景

AgentDevFlow の consumer 向け `install.ps1` および self-hosting 向け `self-sync.ps1` は、正本と `.opencode/` 配置先との差異を検出し、再同期する役割を持つ。

現行では、正本から削除された `agentdev-*` junction を `check` が orphan として検出できる。一方、`apply` を実行しても orphan junction が削除されず、再度 `check` を実行すると同じ乖離が残る。

Plugin loader shim については正本から消えたものを `apply` が削除する処理が存在するため、管理対象投影物の種類によって再同期時の廃止処理が不統一になっている。

## 問題

`check` が検出した「正本から消えた ADF 管理下の投影物」を `apply` が解消しないため、再同期操作が正本と配置先の一致状態へ収束しない。

特に、`check` が orphan を乖離として報告し `apply` による修正を案内するにもかかわらず、その `apply` が orphan junction を削除しないため、利用者から見た操作契約と実際の挙動が一致していない。

この問題は `install.ps1` の junction 削除処理だけの局所的な欠落ではなく、ADF 管理下の投影物が正本から除外・削除された際の共通同期契約が十分に定義・実装・検証されていないことに起因する。

## Source Summary

チャット上で以下を確認し、合意した。

- `install.ps1` の `check` は正本に存在しない `agentdev-*` junction を orphan として検出する。
- 現行 `apply` は orphan junction を削除しない。
- `self-sync.ps1` にも同じ構造がある。
- Plugin loader shim には stale な生成物を削除する処理があり、投影物種別間で挙動が統一されていない。
- ADF 管理下の投影物が正本から除外・削除された場合、`apply` は配置先の旧投影物も除去する。
- `apply` 後は `check` が orphan を検出しない状態へ収束させる。
- この契約は junction のみに限定せず、同じ「正本から消えた ADF 管理下の投影物」という性質を持つ生成物へ適用する。
- repo-local など ADF 管理対象外の成果物は削除しない。
- `check` は検出のみ、`dry-run` は変更予測のみ、`apply` のみ実際の削除を行う。
- `install.ps1` と `self-sync.ps1` の双方を対象とする。
- archive installer は junction 方式ではないため今回の直接対象外とする。

## 統合理由

orphan junction の削除だけを `install.ps1` へ追加すると、同じ同期責務を持つ `self-sync.ps1` や、Plugin loader shim 等の他の管理投影物との契約差が残る。

本件の変更単位は個別ファイルや junction 種別ではなく、

「ADF が管理する投影物について、正本から消えたものを再同期時に配置先から除去し、正本と配置先を一致状態へ収束させる」

という共通同期契約である。

そのため、検出・変更予測・適用・完了検証までを一つの Requirement Unit として扱う。

## 要件化の方向

ADF 管理下の投影物について、正本と配置先の同期を次の状態遷移として定義する。

1. 正本に存在し配置先に存在しないものは、追加対象とする。
2. 正本と配置先の対応が不正なものは、修復対象とする。
3. 配置先に存在するが正本の管理対象から外れたものは、削除対象とする。
4. ADF 管理対象外の成果物は同期処理による削除対象にしない。
5. `check` はこれらの乖離を検出・報告するだけで変更しない。
6. `dry-run` は `apply` が実施する追加・修復・削除を予測表示するだけで変更しない。
7. `apply` は必要な追加・修復・削除を実行する。
8. `apply` 完了後、同一条件で `check` を再実行した際に、処理対象となった乖離が残存しないことを同期完了条件とする。

正本から削除されたディレクトリ名だけでなく、配布対象から明示的に除外されたことによって管理対象外となった ADF 投影物も同じ削除契約の対象とする。

## 主対象REQまたは変更対象候補

### 主対象候補

- `REQ-009`
  - 原本と配置先の乖離検出および同期の共通契約
  - 同期完了時の収束条件
  - 正本から消えた管理対象投影物の除去

### 関連変更候補

- `REQ-050`
  - `install.ps1` / `self-sync.ps1` の `check`、`dry-run`、`apply` のモード契約
  - `apply` が検出済み乖離を解消すること
- `install-script-usability` Design
  - 再同期の意味と各モードの変更可否
- `runtime-package-boundary` Design
  - ADF 管理対象と repo-local 等の管理対象外成果物との削除境界
- `scripts/install.ps1`
- `scripts/self-sync.ps1`
- 両スクリプトの挙動テスト

REQ の最終的な所有先および Design の具体的な更新先は `req-define` で既存責務を確認して確定する。

## 対象範囲

- consumer の `.opencode/` に `install.ps1` が管理投影する ADF 成果物
- self-hosting の `.opencode/` に `self-sync.ps1` が管理投影する ADF 成果物
- 正本から削除された管理対象 junction
- 配布・投影対象から明示的に除外されたことにより不要になった管理対象 junction
- ADF が生成・管理する Plugin loader shim 等、同じ stale 管理物の性質を持つ生成物
- `check`、`dry-run`、`apply` の3モードにおける stale 管理物の扱い
- `apply` 後の再 `check` による収束確認
- 上記を保証する自動テスト

## 対象外

- repo-local command、skill、plugin その他 ADF が管理していない成果物の削除
- 利用者が独自に作成した `.opencode/` 配下の成果物の削除
- ADF 管理物であることを判定できない未知のファイル・ディレクトリを推測で削除すること
- archive installer における stale 実ファイル除去の仕様変更
- archive installer を junction 方式へ変更すること
- ADF 管理範囲そのものを新たに拡大すること

archive installer について同等の収束契約が必要かどうかの評価は、本 RU の実装対象には含めない。

## 受け入れ条件

1. `install.ps1 -Mode check` は、配置先に存在するが現在の正本で管理対象ではない ADF junction を乖離として検出し、ファイルシステムを変更しない。

2. `install.ps1 -Mode dry-run` は、受け入れ条件1の junction を削除予定として報告し、実際には削除しない。

3. `install.ps1 -Mode apply` は、受け入れ条件1の junction を削除する。

4. `install.ps1 -Mode apply` の完了後、同じ条件で `install.ps1 -Mode check` を実行すると、削除対象であった junction に起因する乖離が残らず正常状態となる。

5. `self-sync.ps1` についても受け入れ条件1〜4と同等の検出、変更予測、削除、収束が成立する。

6. 正本ディレクトリ自体が削除された場合だけでなく、配布・投影対象から明示的に除外された ADF 管理物についても、同じ stale 管理物として削除対象になる。

7. Plugin loader shim 等、ADF が生成・管理し、正本側の対象消滅によって不要となる生成物についても、`check`、`dry-run`、`apply` の役割が同じ原則に従う。

8. repo-local 成果物および ADF 管理対象外のファイル・ディレクトリは、名前や配置場所が近似しているだけでは削除されない。

9. ADF 管理物かどうかを確定できない成果物は自動削除せず、既存契約に従って非破壊的に扱う。

10. stale 管理物が複数存在する場合、`apply` は対象をすべて処理し、一部だけを残した状態で正常終了しない。

11. stale 管理物が存在しない状態で `apply` を再実行しても不要な変更を発生させず、続く `check` が正常状態を維持する。

12. stale 管理物の削除処理に失敗した場合、成功したものとして扱わず、処理失敗が利用者に判別できる終了結果となる。

13. 自動テストは少なくとも以下を個別に検証する。
    - orphan junction を `check` が検出する
    - `dry-run` が削除予定を報告するが削除しない
    - `apply` が orphan junction を削除する
    - `apply` 後の `check` が正常終了する
    - 複数 orphan がすべて削除される
    - repo-local / ADF 管理対象外成果物が削除されない
    - stale Plugin loader shim 等の既存削除契約と矛盾しない

## 検証方法

実装後、`install.ps1` と `self-sync.ps1` の実スクリプトを一時リポジトリ上で実行する挙動テストにより検証する。

各テストでは `check → dry-run → apply → check` の状態遷移を確認し、各段階で対象投影物の存在有無と終了結果を検証する。

最終 `check` が正常状態へ収束しない場合は、再同期完了とは判定しない。
