# RU-0001: adversarial-review 経路A〜H識別子の廃止

## 背景

ADFでは、`agentdev-adversarial-review` を複数のワークフローから呼び出している。

現行では、その呼出箇所を以下のように「経路A〜G」と呼称し、`case-auto` の停止伝播を「経路H」と呼称している。

- req-define: 経路A
- inspect-promote: 経路B
- intake-promote: 経路C
- learning-promote: 経路D
- backlog-review: 経路E
- case-open: 経路F
- case-run execution adapter: 経路G
- case-auto の停止伝播: 経路H

各呼出元では、レビューの挿入位置、省略条件、レビュー結果反映後の戻り先、最初の副作用との順序が異なる。

一方、対論型レビューそのものは共通の `agentdev-adversarial-review` を利用しており、A〜Gごとに異なる種類のレビューが存在するわけではない。

また、case-auto は対論型レビューを直接呼び出さず、下位工程で発生した未解決のユーザー判断を受け取り、自走を停止して上位へ伝播する責務のみを持つ。

## 問題

「経路A〜H」という識別子は、現在の責務構造に対して不要な中間概念となっている。

特に以下の問題がある。

1. `req-define`、`case-open` 等の呼出元名称だけで一意に識別できるにもかかわらず、A〜Gという別名を覚える必要がある。
2. A〜Gは対論型レビューの呼出統合を表すが、Hだけはレビューを直接呼び出さない停止伝播であり、分類の意味が揃っていない。
3. 「経路A」等の表現から、対論型レビューに複数の異なる処理方式が存在するように読める。
4. Workflow Skill、Command Design、Requirement、reference等に同じ識別子が広く伝播し、概念と参照関係を不要に増やしている。
5. 呼出元ごとの差分として本当に必要なのは、レビューの挿入位置、省略条件、戻り先、副作用との順序であり、経路文字そのものではない。

## Source Summary

チャット内で以下を合意した。

- A〜Gは異なるレビュー方式ではなく、`agentdev-adversarial-review` を呼び出す場所を識別する名称である。
- 各呼出元固有のレビュー挿入位置、省略条件、レビュー結果反映後の戻り先、副作用との順序は必要であり、維持する。
- これらの差分を識別するためにA〜Gという文字を割り当てる必然性はない。
- 各呼出元のコマンド名またはWorkflow Skill名そのものを識別子とすれば足りる。
- case-autoは対論型レビューの呼出元ではなく、下位工程から未解決ユーザー判断を受け取るオーケストレーション責務として扱う。
- 「経路A〜H」を別名称へ置換するのではなく、経路識別子という概念自体を廃止する。
- 過去の監査レポートや履歴記録は原則として書き換えず、現行の正規文書と配布実装を整合させる。

## 統合理由

本件は、req-defineの「経路A」だけを局所修正する問題ではない。

A〜Hは対論型レビューの呼出統合を横断して使用されている共通概念であり、一部だけを除去すると、Requirement、Design、Workflow Skill、reference、Command定義間に用語不整合が残る。

したがって、以下を1つの変更単位として扱う。

- 対論型レビューの共通呼出契約
- 7つの呼出元固有統合
- case-autoの停止伝播
- それらを説明する正規文書、配布Workflow Skill、reference、Command定義
- 横断整合検査・索引

## 要件化の方向

### 1. 経路A〜H識別子を廃止する

現行の正規文書および配布実装では、対論型レビューの呼出統合を「経路A」「経路B」等の文字識別子で表現しない。

各呼出元は、その固有名で識別する。

例:

- `req-define の adversarial-review 統合`
- `inspect-promote の adversarial-review 統合`
- `case-run execution adapter の adversarial-review 統合`

### 2. 呼出元固有契約は維持する

経路文字の廃止によって、以下の既存契約を変更しない。

- 発動位置
- 発動条件
- 省略条件
- レビュー対象
- 採用済み指摘の反映先
- 反映後の戻り先
- 必要な再検証
- 最初の副作用との順序
- 未解決事項の停止・伝播

### 3. case-autoを対論型レビューの呼出元として扱わない

case-autoは、下位の対論型レビュー等で発生した未解決ユーザー判断を受け取り、自走を停止し、判断内容をユーザーへ提示し、既存の再開点から処理を再開する責務として記述する。

この処理を「経路H」または対論型レビューの一経路として扱わない。

### 4. 共通契約と呼出元固有契約の分離を維持する

対論型レビュー自身の振る舞い、共通の呼出契約、各Workflow固有の挿入位置・戻り先という現在の責務分離は維持する。

経路文字の削除を理由として、対論型レビュー固有ロジックを各呼出元へ複製しない。
