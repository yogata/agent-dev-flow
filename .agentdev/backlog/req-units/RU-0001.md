# distribution-boundary-guard の Plugin パッケージ化と agentdev 命名統一

## 背景

AgentDevFlow では、OpenCode 向けの継続管理対象を `src/opencode/` 配下で管理し、インストールや自己同期によって利用側へ反映する構成を採っている。

Plugin についても、独立した機能単位は `src/opencode/plugins/<name>/` 配下に Plugin 本体、補助実装、テスト、パッケージ設定等をまとめる構成が存在する。

一方、`distribution-boundary-guard` は、この構成に揃わず、利用側の `.opencode/plugins/` 配下に Plugin 本体、補助実装、テストが配置されている。また、名称も他の AgentDevFlow 固有Pluginで採用している `agentdev-*` 命名に揃っていない。

## 問題

現状には次の問題がある。

1. `distribution-boundary-guard` の継続管理対象が、正規のソース側ではなく `.opencode/plugins/` 配下に存在している。
2. Plugin 本体、補助実装、テストが `.opencode/plugins/` 直下の共有ディレクトリ構造へ分散しており、1つのPluginとしての管理境界が不明瞭である。
3. AgentDevFlow 固有のPluginであるにもかかわらず、名称が `agentdev-*` に統一されていない。
4. この例外構造を残すと、Pluginごとの所有範囲、配布元と配布先の責務、テストや依存関係の管理方法に複数の方式が併存する。

## Source Summary

チャット上で、次の内容について合意した。

- `distribution-boundary-guard` を独立したPluginディレクトリとして管理する。
- 正規の管理場所を `src/opencode/plugins/` 配下とする。
- Plugin名を `agentdev-distribution-boundary-guard` とする。
- Plugin本体だけではなく、補助実装、テスト、パッケージ設定等を同一Pluginパッケージへまとめる。
- `.opencode/plugins/` は正本として扱わず、インストールや自己同期によって生成・反映される利用側とする。
- 本機能は Custom Tool ではないため、`src/opencode/tools/` に対応するToolは設けない。
- 旧名称・旧配置を参照する設定、テスト、文書その他の関連箇所も新しい名称・配置へ整合させる。
- 旧配置を正規構造と並存させない。

## 統合理由

今回の変更は、Plugin本体のファイル名変更だけでは完結しない。

Plugin本体、補助実装、テスト、依存関係、配布経路、名称、およびそれらを参照する箇所は同一の管理境界を構成している。そのため、これらを個別の変更として扱うと、一時的または恒久的に旧構造と新構造が併存し、どちらが正本か不明確になる。

したがって、`distribution-boundary-guard` の管理境界そのものを正規化する一つのRequirement Unitとして扱う。

## 要件化の方向

`distribution-boundary-guard` を、AgentDevFlow が管理する独立したOpenCode Pluginとして次の構造へ正規化する。

```text
src/opencode/plugins/
  agentdev-distribution-boundary-guard/
    plugin.ts
    lib/
      ...
    tests/
      ...
    package.json
    tsconfig.json
    ...
```

Plugin内部のファイル分割は、既存機能の責務を保持したうえで当該Pluginディレクトリ内へ収容する。

`.opencode/plugins/` は利用側の配置先とし、`agentdev-distribution-boundary-guard` の継続管理対象を直接所有しない。

名称は `agentdev-distribution-boundary-guard` に統一する。

## 主対象REQまたは変更対象候補

主対象は、OpenCode Plugin のソース管理境界、配布境界、およびAgentDevFlow固有コンポーネントの命名規約に関する既存REQ・Design・SPECとする。

後続の `req-define` では、既存要件に所有者が存在する場合は既存REQ等の更新を優先し、同一契約を重複して所有する新規REQは作成しない。

具体的なREQ番号および変更対象文書は、`req-define` において最新の文書体系から特定する。

## 対象範囲

- `distribution-boundary-guard` の正規ソース配置の変更
- Plugin名の `agentdev-distribution-boundary-guard` への統一
- Plugin本体の独立Pluginディレクトリへの収容
- 当該Plugin専用の補助実装の同一ディレクトリへの収容
- 当該Plugin専用テストの同一ディレクトリへの収容
- 当該Plugin固有のパッケージ設定、依存関係設定、ビルド・テスト設定の同一管理境界への収容
- インストールおよび自己同期における新しいソース配置への対応
- 配布先 `.opencode/plugins/` への必要な投影
- 旧名称および旧配置を参照する設定、文書、テスト、スクリプト等の更新
- 移行完了後の旧正本配置の除去

## 対象外

- `distribution-boundary-guard` が検出・拒否する対象そのものの変更
- 既存の境界判定規則や検出条件の追加・削除
- fail-closed 等の既存の失敗時動作の変更
- OpenCode Plugin以外の機構への置き換え
- 対応するCustom Toolの新設
- `src/opencode/plugins/` 配下に存在する他Pluginの一括再編
- 今回の整理に直接関係しない命名変更
- Plugin共通基盤そのものの新規設計

## 受け入れ条件

1. `agentdev-distribution-boundary-guard` の正規ソースが `src/opencode/plugins/agentdev-distribution-boundary-guard/` 配下に存在する。
2. 当該Pluginの実行入口が同ディレクトリ内で管理される。
3. 当該Plugin専用の補助実装が、共有の `.opencode/plugins/lib/` ではなく当該Pluginの管理境界内に存在する。
4. 当該Plugin専用のテストが、共有の `.opencode/plugins/tests/` ではなく当該Pluginの管理境界内に存在する。
5. 当該Plugin固有のパッケージ設定およびテスト実行に必要な設定が、当該Pluginの管理境界内で完結する。
6. 継続管理対象のPlugin名として `agentdev-distribution-boundary-guard` が使用され、旧名称 `distribution-boundary-guard` が独立したPlugin名として残らない。
7. インストールおよび自己同期によって、正規ソースから利用可能な `.opencode/plugins/` 側の構成を生成または更新できる。
8. `.opencode/plugins/` 配下の当該Plugin関連ファイルを直接編集することを正規の保守経路としない。
9. 旧配置と新配置の双方が正本として残る状態にならない。
10. 新しい配置・名称へ変更した後も、既存の境界検出・拒否の正常系テストが成功する。
11. 新しい配置・名称へ変更した後も、既存の境界違反を拒否する異常系テストが成功する。
12. Plugin内部で検査不能または異常が発生した場合の既存の失敗時動作が、配置変更によって変化しない。
13. 旧名称または旧ソース配置を前提とする有効な参照が、設定、文書、テスト、スクリプト等に残っていない。
14. `src/opencode/tools/` に本変更専用のCustom Toolが追加されていない。
15. 今回の変更によって、当該Pluginの既存の外部動作および検出対象が変更されていない。

## 検証方法

- 正規ソースツリーを確認し、Plugin本体、補助実装、テスト、設定の所有場所を確認する。
- リポジトリ全体から旧Plugin名および旧配置への参照を検索し、移行漏れがないことを確認する。
- 当該Plugin単体のテストを実行する。
- 正常な書き込みが従来どおり許可されることを確認する。
- 配布境界に違反する書き込みが従来どおり拒否されることを確認する。
- 検査不能時の既存の失敗時動作が維持されることを確認する。
- インストールまたは自己同期後の `.opencode/plugins/` 側を確認し、正規ソースから必要なPluginが利用可能になることを確認する。
- `src/opencode/tools/` に不要な対応Toolが追加されていないことを確認する。
