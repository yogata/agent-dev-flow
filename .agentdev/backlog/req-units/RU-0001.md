# RU-0001: worktree 運用の構造的制約（投影・依存不在）と削除完了判定の統合

## Sources

- **persistent-shell-cwd-worktree-residue（case 2791）**: bash ツールが workdir に worktree 内を指定して実行した永続シェルセッションがディレクトリハンドルを保持し続けるため、`git worktree remove` / `prune` 後も空ディレクトリが Device or resource busy で残留する。git 管理状態（worktree list からの消滅・ブランチ削除）は完了しており、物理削除だけが失敗する。既存の削除手順（worktree-operations.md）は Permission denied 時のリトライ 3 回まで規定済みだが、シェルハンドル起因の残留パターンと完了判定基準が未記載（fix gap）。
- **worktree-junction-projection（case 2766/2771/2787、計6件発生）**: worktree には git 管理外実体（`.opencode/skills/agentdev-*` junction 投影、node_modules、`.opencode/plugins`）が伝播しない。実体の存在を前提とする操作（skill スクリプト実行、src と .opencode の二重編集、依存解決）が反復 fail する。必要な運用は (1) SoT パス（`src/opencode/skills/`）起点の実行、(2) 配布ソース変更は src/ のみ編集（main では .opencode 側が同一実体のため worktree では編集対象外）、(3) 依存整備（bun install またはメイン側 node_modules への junction、検証後 junction エントリのみ削除）。既存「bun test 実行の環境前提」節に一部規定済みだが未統合（fix gap）。

## Source Summary

両成果物は worktree の git 管理外の物理・構造的制約に起因する運用障害の集約である。前者は削除時のカレントディレクトリ保持による空ディレクトリ残留（完了判定の問題）、後者は実行・編集時の投影・依存不在（検証・編集前提の問題）。いずれも worktree を利用する workflow（case-run / case-close）で反復発生しており、削除手順と環境前提を正規の手順文書（worktree-operations.md）へ統合することが求められる。

## 統合理由

N:1 統合。両者とも worktree の git 管理外実体に起因する運用制約であり、正規反映先が同一ファイル（`agentdev-git-worktree/references/worktree-operations.md`）の隣接節（削除手順・bun test 実行の環境前提）であるため、単一の要件単位として扱う方が手順の一貫性と編集効率が高い。論点は独立しているが、同一読者（worktree を操作する workflow）が同一場面で参照する知識である。

## 要件化の方向

worktree 運用手順の補強要件として要件化する。反映先は `agentdev-git-worktree` Capability Skill の references（worktree-operations.md）:

1. 削除手順へ、シェルセッション cwd 保持起因の空ディレクトリ残留パターンと対処（削除前に workdir として使用したシェルセッションの cwd をリポジトリルートへ解放する、または残留は git 管理状態のみで完了判定し警告記録して処理を完了する）を追記する
2. 環境前提節へ、SoT パス起点実行・src/ のみ編集で配布整合が成立すること・依存整備（bun install / メイン側 node_modules への junction、junction エントリのみ削除し参照先を破壊しない）を統合する
3. 既存構成（目次・節構造）を維持し、worktree 構造的制約 Design（REQ-018 系）と矛盾しないことを確認する

受け入れ条件（Sources より）: 削除手順にシェル cwd 解放または残留許容の判断基準が追記されていること、空ディレクトリ残留時の警告記録と git 管理状態による完了判定が明記されていること、SoT パス起点実行・src/ のみ編集・依存整備が worktree 運用知識に統合されていること、既存「bun test 実行の環境前提」と重複なく整理されていること。
