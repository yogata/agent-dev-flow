# promote系ワークフローの自律確定とHITL最小化

## 目的

`intake-promote`、`learning-promote`、`inspect-promote` において、取得可能な根拠から判断を確定できる事項はエージェント自身が自律確定し、人間にしか判断できない事項だけをHITLへ送る。

ユーザーに判断を委ねる実質的な必要性がない最終確認を削減しつつ、利用者固有の価値判断、安全境界、不確実な判断についてはHITLを維持する。

自律確定はユーザー承認を擬制する「自動承認」ではなく、エージェント自身による判断確定として扱う。

## 対象

- `intake-promote`、`learning-promote`、`inspect-promote` の判断確定とHITL境界。
- 上記3コマンドの単独実行、および `backlog-auto` 経由での実行。
- 各判定対象を「自律確定可能」と「ユーザー判断必要」に分ける共通原則。
- 現行REQ、Decision、SPEC、対象成果物、取得可能な証拠から一意に判断できる事項の自律確定。
- 複数項目を同時処理する場合、自律確定可能かつ未決項目に依存しない項目を先行確定し、ユーザー判断が必要な項目だけをHITL対象とすること。
- 自律確定した判断について、判定結果、主要根拠、HITL不要と判断した理由を後から確認できること。
- `REQ-003` のpromote/review系HITL横断原則、`REQ-036` のinspect-promote、`REQ-037` のintake-promote、`REQ-038` のlearning-promote、`REQ-041` のbacklog-auto接続契約との整合。

自律確定可能な判断は、少なくとも次を満たすこと。

- 適用すべき既存契約と判断根拠を特定できる。
- 選択肢間に本質的な競合が残っていない。
- ユーザー固有の目的、価値観、優先順位を推測する必要がない。
- 要件または仕様の新しい対象範囲をユーザーに代わって決定する必要がない。
- 正規情報源間に未解決の矛盾がない。
- 判断に必要な情報が欠落していない。
- 必要な対論型レビューを実施した場合、未解決の本質的争点が残っていない。
- 既存の明示的な安全境界を迂回しない。

次のいずれかに該当する場合は自律確定せず、ユーザー判断へ送ること。

- 複数の妥当な選択肢が残り、技術的根拠だけでは一意に決められない。
- ユーザー固有の目的、価値判断、優先順位が必要である。
- 要件または仕様の対象範囲を新たに決める必要がある。
- 正規情報源同士が矛盾している。
- 判断に必要な証拠または情報が不足している。
- 対論型レビューで未解決の本質的争点が残っている。
- 必須の検証または外部依存が利用不能で、自律判断に必要な根拠を取得できない。
- 既存契約が明示承認そのものを安全境界として要求している。

単なる意見差、エージェント自身の一般的な不安、形式的な最終確認だけを理由としてHITLへ送らない。

自律確定可否をモデルの自己申告による確信度、確率、固定パーセンテージだけで判定しない。

### 各promoteへの適用

- `intake-promote`: 採用・保留・却下を根拠から確定できる場合はユーザー承認なしで確定し、ユーザー判断が必要なitemだけをHITL対象とする。
- `learning-promote`: 問題クラス分類、多軸評価、廃棄判定、昇華可能性、既存対策との関係から処置を確定できる場合はユーザー承認なしで確定する。`deferred`、未処理項目を自動削除しない既存安全境界は維持する。
- `inspect-promote`: 通常の分類経路でも `promote / defer / reject` を根拠から確定できる場合はHITLを要求しない。

### backlog-autoとの関係

`backlog-auto` は自動承認機能、自律判定ロジック、独自の確信度判定を所有しない。各子promoteを通常どおり呼び出し、子ワークフロー自身が共通原則に基づき自律確定またはHITL移行を判断する。

`backlog-auto` 経由か単独実行かによって、自律確定可否の原則を変えない。

### inspect-promote --autoとの関係

既存の `inspect-promote --auto` は廃止・同義化しない。

`--auto` は、事前定義された高確信度カテゴリを通常の意味判断経路より早く処理する明示opt-in fast pathとして維持する。

今回導入する自律確定は、通常の分類、検証、必要なレビューを経た結果、ユーザー判断が不要な場合に最終確認を省略する仕組みであり、`--auto` とは別概念とする。

## 対象外

- `backlog-review` のHITL削減。
- `req-define` その他promote系以外のHITL原則変更。
- `inspect-promote --auto` の廃止、暗黙有効化、意味変更。
- モデル確信度の数値閾値導入。
- ユーザー固有の価値判断、優先順位の自動化。
- 矛盾する要件・仕様の自動解消。
- 要件・仕様スコープ変更の自動承認。
- 既存の破壊的操作に対する安全境界の解除。
- 新しい承認台帳や永続状態体系の追加。
- `backlog-auto` 自身へのpromote判定ロジックの追加。

- `REQ-003` は取得可能な証拠から判断可能な限り自律審議し、技術的に決着できない優先判断、ユーザー固有の目的・価値判断、必要情報不足等のみをユーザーへ返す原則を持つ。

## 要件化の方向

- `REQ-003` に、promote系では取得可能な根拠から判断を確定できる事項を自律確定し、自律解決できない事項のみHITLへ送る共通原則を追加する。
- `REQ-036 / 037 / 038` の「ユーザー承認を経て確定する」契約を、自律確定可能な事項はHITL不要、ユーザー判断が必要な事項だけHITLとする契約へ変更する。
- `REQ-041` の「各子ワークフローの既存HITL境界を維持する」を、新しいpromote共通HITL原則を維持する契約へ更新する。
- 対応するcommand SPECとWorkflow Skillに、自律確定可否の判定位置、HITLへのフォールバック、混在時の部分自律確定、判断根拠の報告を反映する。
- `inspect-promote --auto` のfast path契約は変更しない。
- 自律確定後の保存、移動、promoted生成、通常のprune、commit、pushは、既存契約上追加承認を要求していないものについて新たなHITLを追加しない。
- 自律確定の証跡は既存の評価レポート、分類結果、採用済み成果物、実行報告を優先利用し、新規永続成果物を必須としない。

### 作業仮定

以下は公開要件ではない。

- 自律確定可否の具体的な内部判定手順は各Workflow Skillが所有する。
- 共通する判定原則は横断契約へ集約し、3つのWorkflow Skillで同一内容を重複保持しない。
- 自律確定の証跡には既存成果物・既存レポートを優先利用する。
- `backlog-auto` の工程構造、並列・合流モデル自体は変更しない。

## 決定的受け入れ条件

1. `intake-promote` で、取得可能な根拠から採用・保留・却下を一意に確定できるitemはユーザー承認なしで確定できる。
2. `learning-promote` で、取得可能な根拠から処置を一意に確定できる学習項目はユーザー承認なしで確定できる。
3. `inspect-promote` の通常経路で、取得可能な根拠から `promote / defer / reject` を一意に確定できる検出事項はユーザー承認なしで確定できる。
4. `*-promote` の単独実行と `backlog-auto` 経由の実行で、自律確定可否の原則が変わらない。
5. `backlog-auto` 自身が子ワークフローの判定結果を承認、上書きするロジックを持たない。
6. 同一実行内に自律確定可能項目とユーザー判断必要項目が混在する場合、自律確定可能かつ未決項目へ依存しない項目までHITL待ちにしない。
7. ユーザーには自律確定できなかった項目だけが判断対象として提示される。
8. ユーザー固有の価値判断または優先順位が必要な場合、自律確定しない。
9. 正規情報源に未解決の矛盾がある場合、自律確定しない。
10. 判断に必要な情報が不足している場合、自律確定しない。
11. 対論型レビューで未解決の本質的争点が残る場合、自律確定しない。
12. 必須の検証または外部依存が利用不能で、自律判断に必要な根拠を取得できない場合、利用不能を無視して自律確定しない。
13. 要件または仕様の対象範囲を新たに決定する必要がある場合、ユーザー判断を維持する。
14. 既存契約が明示承認を安全境界として要求する操作は、自律確定によって迂回されない。
15. 自律確定可否をモデルの自己申告確信度や固定パーセンテージだけで判定しない。
16. 自律確定した項目について、結果、主要根拠、HITL不要と判断した理由を後から確認できる。
17. 処理対象が空の場合、HITLを発生させず従来どおり正常な「対象なし」として完了できる。
18. `inspect-promote --auto` が従来どおり明示opt-inであり、通常経路の自律確定とは区別される。
19. `backlog-review` のHITL契約に変更がない。
20. `REQ-003 / 036 / 037 / 038 / 041` と対応するcommand SPEC、Workflow SkillのHITL説明が相互に矛盾しない。

## Source Summary

`backlog-auto` 実行時のユーザー承認回数を減らす検討から、問題の本質は `backlog-auto` に自動承認機能を追加することではなく、`intake-promote`、`learning-promote`、`inspect-promote` 自身が客観的に判断可能な事項まで一律にユーザーへ最終確認している点にあると整理した。

promote系全体について「取得可能な根拠から判断可能な事項は自律確定し、エージェントだけでは確定できない事項のみHITLへ送る」という原則へ変更する方針で合意した。`backlog-auto` はこの判断を所有せず、改善された子ワークフローを呼び出す薄いオーケストレータのままとする。

`backlog-review` のHITL、`inspect-promote --auto` の明示opt-in fast path、破壊的変更等の既存安全境界は今回の変更対象外とする。

検証では各決定的受け入れ条件を `pass / fail / blocked / not applicable` で個別評価し、明確な採用、明確な却下・保留、判断が拮抗する事例、ユーザー固有の優先判断、正規情報源の矛盾、証拠不足、レビュー未解決、複数項目の自律/HITL混在、空入力、単独実行、`backlog-auto` 経由、`inspect-promote --auto`、既存安全境界を確認する。
