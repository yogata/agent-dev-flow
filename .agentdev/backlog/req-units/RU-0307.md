# Codex・Antigravity での AgentDevFlow 全ワークフロー実行

## 目的

Codex と Antigravity のそれぞれで、Release を含む AgentDevFlow の全ワークフローを、必要な内部工程まで完走できるようにする。

## 対象

- 両ホストの GitHub プラグインを既定の GitHub 接続とし、共通の agentdev_gh 操作契約に接続する。
- scripts/ に専用の切替スクリプトを設け、利用者の明示判断に基づいて GitHub プラグイン経由から gh CLI 経由へ切り替える。
- Issue、PR、コメント、Release の操作と読み戻し、GitHub 操作の停止・再開、ワークフローの実機検証を含める。
- case-run の実行担当サブエージェントへの委譲や終了時の品質ゲートなど、全ワークフローの完走に必要な接続を確認する。

## 対象外

- OpenCode・Senpi の現行の gh CLI 経路と、既存ローカル Issue モードへの変更。
- 4ホストの任意インストール。これは別 RU 案 consumer-host-selection で扱う。

## 正規所有者とアンカー

- docs/requirements/REQ-011.md の REQ-011-001、003、005、008、024。GitHub 操作の入口、入力・結果・失敗の意味、承認と読み戻し検証を導出する。
- docs/requirements/REQ-099.md の REQ-099-005、018、021〜026。ホスト別の接続、検証済み範囲、実機確認の分担を定義する。OpenCode への引き渡しを定める REQ-099-023 は変更候補とする。
- docs/requirements/REQ-009.md。切替スクリプトの導入・配布と設定の保存の扱いを定める。
- docs/decisions/DEC-069.md。GitHub への書き込みを OpenCode に委ねる判断を、後継 Decision で見直す。

## 依存関係

- ホスト別にプラグインの提供操作、権限、呼出経路を確認し、ワークフローが必要とする操作と照合する。未確認の組合せは実機検証の対象とする。Antigravity の実機確認の分担は REQ-099-024 を参照する。
- gh CLI 経路では対象リポジトリへの認証と必要な権限を確認する。既存の共通エンジンと gh 用 runner を再利用する。
- 単独導入と同時に受け入れる場合は、consumer-host-selection と配布検証を揃える。現時点で採番済みの必須依存 RU はない。

## 要件化の方向

1. ワークフローは共通の agentdev_gh 操作契約を使い、ホスト側の接続がプラグイン呼出と応答の変換を担当する。共通契約に従って操作前の承認と書き込み後の読み戻しを扱う。
2. プラグインの無効化または必要操作の欠落を検出したら、GitHub 操作を停止して利用者に判断を求める。一時的な場合は現在の設定を保持し、プラグインの復旧を待つ。恒久的な場合は、利用者の明示判断を受けて専用スクリプトで gh 版に切り替える。
3. 切替の承認と個別の GitHub 操作の承認は独立させる。書き込み結果が不明な場合は再開前に GitHub の状態を照合し、重複操作を防ぐ。
4. 全ワークフローへの対応はホスト単位で判定する。プラグインに必要な操作が欠ける場合は、承認済みの gh 経路で完走できればよい。

## 決定的受け入れ条件

1. Codex・Antigravity の各ホストで、全公開ワークフローと必要な内部工程について、実際に使用した GitHub 実行経路と実機検証結果を記録する。OpenCode・Senpi の GitHub 経路と既存ローカル Issue モードの回帰試験が通る。
2. Release の草稿作成、読み戻し、利用者の明示承認後の公開、公開結果の読み戻しを確認する。
3. プラグインが無効または必要操作を提供しない場合、利用者の判断まで処理が停止する。一時停止中は GitHub 操作も実行経路の設定変更も発生せず、復旧後に再開できる。
4. 恒久的な切替の承認後、専用スクリプトで設定した gh 経路が再起動後も使われる。書き込み結果が不明な操作をまたいで再開する場合は、状態照合により重複作成を防げる。
