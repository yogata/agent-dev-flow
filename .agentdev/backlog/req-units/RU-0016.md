# RU-0016: ADR から Decision への正規成果物モデル移行

## 目的

AgentDevFlow の現行判断記録を ADR から Decision へ移行し、文書モデル、ID、配置、成果物契約、保存経路、配布成果物、索引、検査、Artifact Graph を一貫した Decision モデルへ統一する。

現行体系は次の責務分界を維持する。

- REQ: 現在満たすべき要求
- Decision: 継続的な意思決定とその理由
- SPEC: 現在仕様の詳細
- Guide: 人間向けナビゲーション

Decision は Architecture Decision に限定せず、将来の設計、運用、文書体系、責務境界その他の継続的な判断を拘束する意味のある意思決定を対象とする。

## 背景

現行 REQ-001 は判断記録を抽象的な文書種別として定義している一方、文書モデル、保存経路、ID、配置、索引、Skill、Command、検証処理では `ADR` / `adr` / `docs/adr/` が具体的な正規契約として使用されている。

また REQ と判断記録では管理上の性質が異なる。REQ は現在要求の体系として意味的重複を抑制し整理された集合を維持する必要がある。一方、Decision は判断が成立した文脈や再確認の履歴にも意味があり、意味的に近い複数 Decision の存在を一律に重複違反として扱うべきではない。

このため、本 RU は ADR の単純 rename ではなく、Decision を正規の判断記録文書種別として再定義し、全関連契約を横断移行する。

## 合意済み要件

### AG-001: 正規名称

判断記録の正規文書種別名を `Decision` とする。

単一の成果物または文書種別を示す場合は `Decision` / `decision` を使用し、複数の集合を自然言語上で表す場合のみ `Decisions` を使用する。

### AG-002: 正規配置・ID

現行 Decision の正規形式を次とする。

- ディレクトリ: `docs/decisions/`
- ID: `DEC-NNN`
- ファイル名: `DEC-NNN.md`
- artifact type: `decision`

ID の番号部は3桁ゼロ埋めを正規形式とする。

### AG-003: Decision の責務

Decision は、将来の設計、運用、文書体系、責務境界その他の継続的な判断を拘束する、意味のある意思決定とその理由を保持する。

Decision は以下を正規所有しない。

- ステークホルダーが満たしたい状態そのもの
- 現在仕様の詳細
- 可逆的な作業手順
- 一時的な実装計画
- 単なる削除、移動、rename 等の移行作業そのもの
- Issue / PR 等が所有する作業履歴

これらは既存の REQ / SPEC / Guide / Issue 等の責務境界に従う。

### AG-004: REQ と Decision の管理特性分離

REQ と Decision に同一の重複排除・粒度管理規則を機械適用しない。

REQ は現在要求の体系として意味的重複を抑制し、整理された集合を維持する。

Decision は判断文脈の違い、再確認、後続判断との関係に意味があるため、意味的に近い複数 Decision の存在だけを理由として重複違反または自動統合対象としない。

### AG-005: Decision 関係モデル

複数 Decision 間の意味的関係を追跡可能にする。

少なくとも以下の意味を表現できること。

- 関連する判断
- 過去判断を置換する判断
- 過去判断を再確認する判断

具体的なフィールド名、enum、serialization 形式は SPEC の責務とする。

Artifact Graph 等による関係候補抽出は許容するが、MERGE / SPLIT / supersede / reaffirm 等の意味判断を文字列一致または類似度だけで自動確定しない。

### AG-006: Decision の粒度管理

Decision の SPLIT / MERGE は固定件数のみで判断しない。

以下の意味的健全性を評価対象とする。

- 無関係な複数判断の混在
- 責務領域の過度な混在
- 判断境界の不明瞭化
- 相互矛盾する accepted Decision
- 関係付けされていない実質的な再確認・置換候補

検出結果は意味レビューの候補とし、自動的なファイル再編成を必須としない。

### AG-007: 現行 ADR の1対1移行

移行時点で存在する現行 `ADR-NNN` は、番号部を維持して `DEC-NNN` へ1対1で移行する。

以下を同時に移行する。

- ファイルパス
- frontmatter ID
- H1 / 表題内ID
- current Decision 間の参照
- REQ / SPEC / Guide / Command / Skill 等からの参照
- README / index
- graph node / relation
- checker / validator が扱う current artifact ID

移行によって既存 Decision の判断内容、適用範囲、status、判断上の意味を変更しない。

### AG-008: ID不変原則との整合

通常運用では Decision ID を安定した識別子として不変とする。

ただし、正規文書種別そのものを ADR から Decision へ変更する今回の明示的な体系移行に限り、`ADR-NNN -> DEC-NNN` の1対1マッピングを許容する。

この例外は番号部を維持し、判断内容の意味変更を伴わない体系移行に限定する。

移行後の `DEC-NNN` は通常のID不変原則に従う。

### AG-009: accepted 判断記録の意味的不変性

accepted 状態の既存 ADR を Decision へ移行する際、artifact type、ID、パス、自己参照、索引等の体系移行に必要な変更は、判断内容の意味変更として扱わない。

以下を同じ変更に混在させない。

- 判断内容の追加または削除
- 適用範囲変更
- 制約変更
- 採用方式変更
- 正規所有者変更
- 観測可能結果の変更

意味変更が必要な既存判断は Decision 移行完了後に別の Decision 操作として扱う。

### AG-010: 過去版 ADR の履歴保持

tag `v2.11.0` に実在した `v2:ADR-*` は名称・IDとも変更しない。

現行 Decision から過去版を参照する場合も `v2:ADR-NNNN` と記述する。

`v2:DEC-*` のような過去に存在しなかった識別子を生成しない。

Decision index は、現行 Decision と過去版 ADR を明確に区別して表示できること。

### AG-011: 旧 current ADR 契約の退役

Decision 移行完了後、現行成果物を対象とする通常経路では以下を生成・要求・正規参照しない。

- `docs/adr/`
- current `ADR-NNN`
- `artifact: adr`
- ADR専用の現行 Command / Skill / Template / Script 契約
- ADR専用の current checker / index 契約

過去版 `v2:ADR-*`、Git履歴、既存の完了済み Issue / PR 内の履歴記録はこの条件の対象外とする。

### AG-012: Decision 保存経路

判断候補の生成、保存、後続工程への引き渡しは Decision artifact type を使用して完結する。

少なくとも以下の経路を Decision 化する。

- req-define における Decision 要否・候補判定
- req_draft の artifact action
- req-save における CREATE / APPEND / UPDATE
- Decision ID 採番
- Decision index 更新
- case-open への参照引き渡し
- case-run による現行根拠参照
- case-auto から利用される正規成果物参照

新規 `artifact: adr` を生成する通常経路を残さない。

### AG-013: Decision Skill

現行 ADR 固有 Skill は Decision 固有 Skill へ移行する。

正規名称は以下とする。

- `agentdev-decision-file-manager`
- `agentdev-decision-guidelines`

前者は Decision ファイル操作、採番、status、参照整合性を所有する。

後者は Decision として記録すべき判断か、REQ / SPEC / Guide 等に配置すべき内容かの意味判定を所有する。

ADR の「Architecturally Significant か」という条件だけに Decision 適格性を限定しない。

### AG-014: Decision index

`docs/decisions/README.md` を現行 Decision の正規索引とする。

索引は少なくとも以下を扱う。

- current Decision 一覧
- status 別ビュー
- topic / classification view
- Decision 間関係
- 関連 REQ
- `v2:ADR-*` との履歴関係

README は分類・探索ビューであり、個別 Decision 本文のSSoTにはしない。

### AG-015: 横断移行

Decision化の対象を `docs/adr/**` に限定しない。

現行 ADR 契約または参照を保持する以下の全領域を横断確認し、Decision モデルへ整合させる。

- REQ
- SPEC
- Guides
- root / docs README
- Command
- Skill
- Reference
- Template
- Script
- `.agentdev/extensions/**`
- repository-local inspection / validation
- Artifact Graph
- rule catalog / rule ownership
- tests / fixtures / snapshots
- generated indexes
- current repository documentation

ファイル一覧をRU作成時の固定列挙だけに限定せず、実行開始時の現行HEADに対する横断inventoryを正とする。

### AG-016: 文字列一括置換の禁止

ADR -> Decision 移行は無条件の全文字列置換として実施しない。

ADR関連ヒットを少なくとも以下へ分類してから変更する。

1. current artifact contract
2. current artifact reference
3. historical `v2:ADR-*`
4. GitHub Issue / PR 等の履歴
5. Git history
6. 実装識別子
7. prose
8. unrelated / false positive

`v2:ADR-*` や履歴情報を current Decision 表記へ誤変換しない。

### AG-017: Decision health model

Decision の健全性評価を REQ の重複・分割モデルと分離する。

Decisionについて検出・評価可能にする対象は以下とする。

- 過大な Decision
- 無関係な判断の混在
- 責務・domain の過度な混在
- 判断境界の不明瞭さ
- accepted Decision 間の矛盾
- 必要な関係の欠落
- 再確認または置換候補

類似性だけを根拠とする自動 MERGE を行わない。
