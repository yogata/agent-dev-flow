# QG-4 最終受入規範と case-close 機械工程の整合

## 目的

QG-4 最終受入（full integrity suite）の規範が定める受理経路と、case-close 機械工程の実装による判定を整合させ、規範どおりの証拠が揃った受け入れが機械的に完結する状態を実現する。

## 背景

Case #3710（RU-0223、追跡Issueラベル語彙の最小化）の case-close で、フル suite の残り 3 fail が分岐点 baseline（main `9115bbed`）で同一再現し、規範のいう pre-existing として分類・証拠保存された。しかし機械工程は分類を見ずに受理を拒否したため、PR #3713（mergeable）・Issue #3710 が完了できないまま停止した。

2026-10-15 の Epic #3717（RU-0224/0225）で bun test 全件正常化が完了したため、当面の発生は抑制されている。ただし契約上の不整合は現行 main（`465ee0c5`）にも残存し、将来の pre-existing fail や checker 環境差 fail で同一停止が再発する構造である。

規範と実装の現行差分（現行 main 実測）:

- 規範 `src/common/skills/agentdev-quality-gates/references/qg-4-final-acceptance.md`:
  - 「fail 由来分類」節: 合格判定は fail 全件の由来分類（変更由来 / pre-existing / 実行形態由来 / 不明）を前提とし、検証完了基準は由来不明 0 件。pre-existing の根拠はワークツリー変更ゼロの baseline commit での同一再現確認。
  - 受理条件 5: fail 0 件、または全 fail の由来分類・由来不明 0 件・実行形態由来の再実行記録。
  - 受理条件 7: pre-existing fail の baseline 再現確認記録（detached worktree 標準手順）。
  - 「いずれかの記録が欠落する場合、由来不明の fail が残存する場合、未登録の既知欠陥を合格の根拠にする場合は fail とする」。
- 実装 `src/common/skills/agentdev-workflow-case-close/scripts/src/close_mechanical_steps.ts`:
  - integrity gate の終了コード非 0 を分類なしに `full-integrity-suite=fail` とする。
  - step fail は `exitCategory: failure` に集約される。
  - close 許可は `acceptanceEvaluation.closeAllowed === true` であっても `exitCategory === "failure"` を機械的に拒否する。

## 問題

規範が認めた受理経路（由来分類済み pre-existing fail を含む合格）が、実装の機械判定では必ず拒否される。規範側の受理条件と機械工程の判定基準が対応しておらず、規範どおりの証拠を保存しても完了に到達できない。

また規範は「未登録の既知欠陥を合格の根拠にする場合は fail」とするが、既知欠陥の登録経路（実在・様式・所有者）が確認されていない。登録を要求する文言と登録機構の実在が対応していない可能性がある。

## 対象

- `qg-4-final-acceptance.md` の受理条件・fail 由来分類・既知欠陥登録に関する規定
- `close_mechanical_steps.ts` の integrity gate 実行・step 判定・exitCategory 集約・close 許可判定

- 上記変更に対応するテスト資産

## 対象外

## 統合理由

規範・実装・登録経路は同一の受理判断を構成する部品であり、いずれか単独の修正では「規範どおりの証拠があるのに機械が拒否する」状態を解消できない。停止事象の再発防止には受理判断の全体整合が必要である。

## 要件化の方向

**主対象: 既存契約を維持した不具合修正。**

整合の方向（規範を正として実装を分類記録の機械検証へ対応させるか、実装を正として規範が fail 0 件を要求する形へ改めるか）は正規所有者の判断事項とする。いずれの方向も、由来分類なしの合格・由来不明 fail の受理・記録欠落の黙認を許さない現行の安全条件を維持する。

既知欠陥登録については、登録機構が実在すればその様式を規範文言へ対応させる。実在しなければ、登録なしで規範が完結するよう文言を整合させるか、最小の登録経路を設けるかを判断し反映する。判断に当たって新規の恒久例外機構を追加しない。

## 決定的受け入れ条件

### A-01: 現行不一致の確定

最新 main に対し、規範・実装・登録経路の現行状態を確定する。

**合格基準:** 受理条件 5/7/8 と機械工程の判定経路（integrity gate 判定・exitCategory 集約・close 許可）の対応関係が過不足なく記録され、不一致の全体像が確定していること。Case #3710 停止時の証拠と突合していること。

### A-02: 整合方向の確定と反映

受理経路の正を確定し、文書と実装の両方へ反映する。

**合格基準:** 確定した方向が正規経路（判断記録を伴う）で確定していること。規範と実装の受理判定が同一の入力に対して同一の結果を返すこと。由来不明 fail・記録欠落・未登録既知欠陥が引き続き拒否されること。

### A-03: 既知欠陥登録経路の確定

「未登録の既知欠陥を合格の根拠にする場合は fail」の文言が機能する前提を確定する。

**合格基準:** 登録経路の実在・様式・所有者が記録され、文言と機構が対応していること。実在しない場合、文言の整合または最小登録経路のいずれかが判断記録付きで反映されていること。

### A-04: 機械判定の整合実証

修正後の機械工程が、確定した契約どおりに判定することを実証する。

**合格基準:** 由来分類・baseline 再現確認の記録が揃った pre-existing fail を含む結果が close 許可経路で機械的に通ること。由来不明・記録欠落・登録欠落を含む結果が拒否されること。両方向を既存テスト資産で検証していること。

### A-05: Case #3710 の完了

整合後、保存済み QG-4 証拠（必要な場合のみ不足分の再取得）により Case #3710 の case-close を完結する。

**合格基準:** 合格済み case-run を再実行せず、元の完了条件を変更せずに、PR #3713 の統合・Issue #3710 のクローズ・worktree 後片付けが完了し、各操作の読戻しで確認できること。
