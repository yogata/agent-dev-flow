# ADF v4 の正規モデル再確定と現行規範の全面収束

> 永続ID: `RU-0181`。レビューと追加合意を反映した session 由来 RU。生成主体の今回限りの契約差異は「承認状態」に記録する。

## 目的

合意した要求の意味・禁止・検証義務が実行と完了判定まで保持され、未達を完了として扱わないことを成立条件とする。その範囲で、機械工程のモデルによる逐次駆動、不要な二重判断、処理時間、人間介入、変更時の同期負担を最小化する。

全域を一度再評価し、必要な箇所だけ変更し、実経路で成立を確認して閉じる。文書数、要求数、検査数の削減自体は成功条件としない。

## 背景

ADF v4 は、要件に基づく継続的なソフトウェア開発のための Standard Operating Model と実行基盤として、概念と実装の分離、責務分離、内部ライフサイクルへの収斂、決定的処理と意味判断の適切な分離、過剰統制の抑制を志向してきた。

一方、v4 の継続開発と実証を通じて、現在の `docs/**` には次のような状態が生じていることが確認された。

- 新旧の設計思想・責務モデルが混在している
- 現在の正規責務へ追随していない REQ / Decision / Design / Guide が残存している
- 決定的に処理できる判断を LLM 推論へ委ねる契約が残っている
- soft contract と LLM 解釈が不必要に結び付いている
- 閉じた意味評価の後段に LLM 最終判断を必須とする実証段階の契約が現行規範として残っている
- case-open / case-ready 等のライフサイクル責務について、旧責務と現責務が混在している
- 廃止済み command や旧語彙が現行規範に残存している
- 否定的統制、停止条件、レビュー等が必要性を再評価されないまま積層している箇所がある

今回の営みは、これらを個別に表現修正する「文書クリーンアップ」ではない。

現在の ADF の目的、設計思想、判断責務、ライフサイクルを改めて全体から確定し、その正規モデルと矛盾する現行規範および実現物を、置換・統合・廃止を含めて全面的に収束させる。

今回の作業は新しい製品要求を追加するものではなく、v4 内部で蓄積した矛盾、古い設計思想、責務のずれ、および実証結果を踏まえて、v4 が本来表現すべきモデルへ再収束させるものである。

## 問題

現状には、局所修正だけでは解消できない以下の構造的問題がある。

### 1. 現行成果物を暗黙の前提としてしまう危険

既存の accepted Decision、現行 REQ、Skill 構造、Workflow 実装を維持対象として扱うと、過去の設計判断そのものに問題がある場合でも、その前提を温存したまま局所整合だけを取ることになる。

その結果、本質的な責務再編や不要な仕組みの廃止が阻害される。

### 2. 判断手段の選択原則が不十分

現行には以下の構造が残る。

- 意味判断であれば LLM へ委ねる
- soft contract であれば LLM で解釈する
- Jev 等の閉じた意味評価後にも LLM が最終判断する
- 評価器が利用不能な場合に LLM 推論へフォールバックする

これらは、決定可能な処理を機械的処理へ寄せ、LLM の利用を本当に必要な開いた推論へ限定する方向と整合しない。

### 3. 正典変更の下位文書への伝播不足

正規責務が変更された後も、Guide、Foundation Design、個別 Skill Design、旧 Decision / REQ の現行部分などに旧モデルが残存している。

そのため `docs/**` の異なる文書を読むと、同じ ADF に対して異なる現在像が得られる。

### 4. 過剰統制を残す危険

問題を発見するたびに checker、gate、禁止規則、レビュー、fallback 等を追加すると、問題解消より統制自体の維持が目的化する。

必要な安全境界は維持する一方、統制追加ではなく責務整理、決定的導出、契約縮小、重複除去を優先する必要がある。

## 統合理由

判断アーキテクチャ、soft contract、ライフサイクル責務、旧 command・旧語彙、否定的統制等を個別テーマとして修正すると、各テーマが現在の別の規範を前提として局所最適化され、再び相互矛盾が残る可能性が高い。

これらは、全体モデルを同じ基準から再評価する必要がある相互依存した問題である。ただし、規範自体の誤りと、妥当な規範の投影・履行・検証不成立を区別する。すべてが同一原因で発生したとは断定せず、規範変更が不要な問題まで再設計しない。

したがって個別修正を先行せず、まず ADF の正規モデルを再確定し、そのモデルから各成果物の正当性を再評価する一つの Requirement Unit として扱う。

## 要件化の方向

### A. v4 正規モデルの再確定

本 RU の合意済み原則から導出できる具体化は自律的に進める。新しい目的、対象範囲、外部契約、恒久規範、規範間優先順位、提供能力の廃止等の選択が必要な場合は、選択肢と影響を提示して人間判断を得る。未確定事項に依存する下流の確定・変更は開始しない。文書ごとの再承認や新しい承認ゲートを設けない。

現在の成果物配置や既存実装を前提とせず、ADF の目的と v4 の中核思想から以下を再確定する。

- Standard Operating Model と Runtime / Adapter / Project Model の責務境界
- REQ / Decision / Design / Implementation / Evidence の意味境界
- 公開入口と内部ライフサイクル
- case-open / case-ready / case-run / case-close / case-revise の責務
- Quality / Verification / Evidence / Gate の責務
- 判断方法と確定権限
- 人間判断境界
- Project Extensions と安全境界
- Intake / Learning / Backlog の責務
- durable state、再構成、再実行の原則

既存成果物は、このモデルを確定するための情報源ではあるが、維持すべき制約とはしない。

### B. 判断アーキテクチャの再確定

各判断・チェックは、まずその判断自体が必要かを評価し、不要なら廃止する。必要な判断について、決定的処理を第一選択として以下の適格性を検討する。分類を難易度順の実行段階や失敗時の代替経路としない。

判断方法とは独立して、正規契約からの導出、委譲された裁量、人間に留保された判断の確定権限を判定する。また、判断の自律確定可否と副作用実行可否を分離する。開いた推論を用いても委譲範囲内の内部判断は自律確定でき、閉じた意味評価の結果が得られても新規規範の確定や外部操作の許可が自動的に得られるわけではない。

#### 1. 決定的・機械的処理

入力と適用する確定済み規則から一意に導出でき、責務に見合う実装・維持費用で機械化できる処理は、決定的に実行する。一意に導出可能でも機械化が不相応に複雑になる場合は、次項の例外理由を説明する。

例:

- 構造検査
- 列挙値検査
- ID・参照検査
- 状態遷移条件
- 依存 DAG の計算
- 集約
- 形式変換
- 確定済みの比較規則による比較
- 完全一致等、確定済み規則による重複検出
- 機械的に評価できる明示された述語の評価

本項の適格性を満たす決定的処理の結果を、同じ命題について LLM 推論や閉じた意味評価へ二重に委ねない。異なる命題である入力の十分性・規則の妥当性の評価とは区別する。

#### 2. 閉じた意味評価

決定的処理では成立しない、または機械化すると責務に対して不相応な複雑性を生じる場合のみ候補とする。

採用するには少なくとも、

- 必要な事実
- 判断基準
- 結果空間
- 評価入力

を評価前に閉じることができ、入力構成の内部に別の未解決意味判断を隠していないことを説明できなければならない。

「機械的でない」「意味を扱う」という理由だけでは閉じた意味評価へ分類しない。結果が合否等の有限集合であることだけでも閉包性を認定しない。

不相応な複雑性を理由に採用する場合は、採らなかった決定的処理案と具体的な実装・維持負担を説明する。数値的な費用判定器や中央ルーターは新設しない。

閉包条件の成立と評価器の判定品質は別である。正規判定主体として残す各判断について、代表例・反例・判定不能例等から、その判断契約を満たす評価器の採用根拠を確認する。必要性または適格性を示せない場合は、判断の縮小・分解・廃止を含めて再検討する。廃止する評価の大規模な性能実証、Jev 全体の有効性研究、全仮説の実証は要求しない。

#### 3. 開いた LLM 推論

前二者に適合しない、本質的に結果空間を事前閉包できない問題のみ例外的に利用する。

対象例:

- 根本原因の探索
- 設計案の探索
- 未整理情報からの候補形成
- 複数文脈を統合した考察

LLM 推論は「前段が失敗した場合の一般 fallback」としない。

また、LLM 推論によって新しい目的、対象範囲、外部契約、受け入れ条件、恒久規範、規範間優先順位を自動確定しない。

### C. 閉じた意味評価の障害時契約

閉じた意味評価として分類された必須判断について、評価器が以下の状態になった場合、

- 未設定
- 利用不能
- timeout
- rate limit
- network error
- provider error
- response validation failure
- その他評価を成立させられない障害

LLM 推論へ fallback して判定を継続しない。

必要な判定を未確定とし、その判定に依存する後続処理を開始しない。

当該状態は、新しい意味判断が必要な状態ではなく、必要な評価能力の利用不能または実行前提不成立として扱う。

復旧後、正規の再実行・再開経路から評価を再実行できること。修復・再試行は判定方式の代替とは区別する。設定・認証等の運用介入も、新規規範を確定する人間判断とは区別する。

依存する処理だけを止め、無関係な独立作業まで一律に止めない。判定不能を不合格または非該当へ変換しない。再開前に入力、規則、成果物、証拠への変更影響を確認し、影響する古い判定を再利用しない。既に成功した副作用を重複実行しない。影響しない証拠は一律に破棄せず再利用する。新しい状態・台帳の追加を前提とせず、既存の再開経路で成立させる。

人間判断への移行は、その判断自体が別途人間に留保された判断である場合に限る。

### D. soft contract の再定義

soft contract は、厳格な API schema や過剰な互換維持機構を要求しないという契約特性を表すものとする。

soft contract であることを、

- LLM が読み取らなければならない理由
- 機械的処理を避ける理由
- schema validation を全面禁止する理由

として扱わない。

存在確認、型、列挙値、ID、参照関係、明示的フィールド等、決定的に扱える部分は soft contract のまま機械的に処理できる。

### E. ライフサイクル責務の再収束

現在の正規モデルを基準に、case-open / case-ready / case-run / case-close / case-revise 等の責務を再確定する。

同一責務を複数工程が所有する状態、旧工程からの移管漏れ、Guide と正規 Design の不一致を残さない。

特に以下を再評価する。

- Root Case 確立
- Definition 受入
- REQ / Decision / Design 保存
- execution contract 確定
- Standard / Epic 構成
- Child Issue 構成
- Wave / 依存 DAG
- 実装実行
- Verification / QG
- merge / close
- revise / resume

### F. 現行規範の全面再評価

正規モデル確定後、現行の REQ / Decision / Design / Guide 等をそれぞれ以下のいずれかへ分類する。

- keep
- redefine
- merge
- supersede
- retire

accepted であること、現在実装されていること、既存 workflow が依存していることだけを keep の理由としない。最近是正されたことだけでも評価を免除しない。

評価対象は全域だが、変更対象は必要と判明した箇所に限定する。keep 以外の分類は分類の記録だけで完了とせず、必要な反映、消費側・参照先・検証期待値の更新まで完了対象とする。記録は今回限りの既存成果物または検証記録でよく、恒久台帳は新設しない。

### G. 過剰統制の除去

各以下を、必要な安全境界・整合性保証として本当に必要か再評価する。

- hard gate
- fail-closed
- checker
- MUST NOT / 禁止事項
- `must_not`
- adversarial-review
- HITL
- fallback
- duplicated validation
- state
- ledger
- routing
- additional schema

必要性を説明できない統制は維持しない。

問題を統制追加で解決する前に、

- 責務削減
- 契約縮小
- 重複除去
- 決定的導出
- 所有者統合
- 不要経路廃止

で解消できないかを優先する。

### H. 歴史的成果物の保持

以下は現行規範として参照されない限り、過去時点の事実として原則保持する。

- retired REQ
- superseded Decision
- historical report
- 過去の観測記録
- 過去の release / migration 記録

現在の用語や設計思想に合わせるためだけに歴史的本文を書き換えない。

### I. v4 再収束としての実施

今回の作業は v5 新設として扱わず v4 の再収束として扱う。

現行 v4 の成果物・内部実装との互換維持は要件としない。

維持する中核は、要件に基づく継続的な開発という目的と、要求、判断権限、永続状態、実行安全、証拠連鎖の意味上の性質である。工程名・工程数・内部配置・現在の実現方式は維持制約としない。

OpenCode／Senpi、GitHub／ローカル Issue 等の現在提供する能力は維持を出発点とする。能力自体を廃止する案が簡素化に有効と判明した場合は、失う用途と効果を提示して個別の人間判断へ戻す。内部互換不要を、提供能力削減の包括承認と扱わない。

正規モデルへ収束するために必要であれば、破壊的な変更を許容する。

ただし再評価の結果、

## 決定的受け入れ条件

### AC-01 正規モデルの自足性

現在の ADF の目的、責務層、成果物モデル、判断モデル、公開入口、内部ライフサイクル、品質モデル、人間判断境界を、旧設計を前提とせず正規文書群から一意に説明できること。

本 RU の合意済み原則からの具体化と、新しい人間判断を要する選択を区別し、未確定事項に依存する下流を確定していないこと。判断方法、確定権限、副作用実行可否を独立して説明できること。

### AC-02 現行成果物の再評価完了

対象となる現行 REQ / Decision / Design / Guide について、正規モデルとの関係が keep / redefine / merge / supersede / retire のいずれかとして判定済みであり、未評価の現行規範が残っていないこと。

評価対象集合が今回の基準状態から特定され、必要な変更は分類の記録だけでなく参照・消費側・検証期待値への反映まで完了していること。妥当な既存成果を不要に作り直していないこと。

### AC-03 決定的処理優先

入力と確定済み規則から一意に導出可能で、責務に見合う実装・維持費用で機械化できる判断・チェックが、LLM 推論または閉じた意味評価を正規判定主体として使用していないこと。機械化の不相応な複雑性を理由に例外とする場合は、AC-06 の説明を満たすこと。

### AC-04 不要な二重判定の不存在

決定的に確定した結果について、意味評価または LLM による再判定を正規工程として要求していないこと。

同じ命題の再判定と、入力の十分性や規則の妥当性等の異なる命題の評価を区別していること。

### AC-05 閉じた意味評価の適格性

閉じた意味評価として残る各判断について、必要な事実、判断基準、結果空間、入力閉包性、および決定的処理ではなく閉じた意味評価を使用する理由を正規文書から確認できること。

閉包条件だけを判定品質の証明とせず、正規判定主体として残す各判断で評価器の適格性を示す根拠があること。必要性を示せない評価を、実験継続だけのために必須化していないこと。

### AC-06 機械化過剰の回避

閉じた意味評価を使用する理由として、機械化が不可能であるか、または機械化が責務に対して不相応な複雑性を生じることが説明できること。

単に「意味判断である」ことだけを理由としていないこと。

採らなかった機械化案と具体的な実装・維持負担を説明していること。結果空間が有限であることだけで閉じた意味評価の適格性を認定していないこと。

### AC-07 LLM 推論の限定

正規判定に LLM 推論を使用する箇所が、本質的に結果空間を事前閉包できない開いた問題に限定されていること。

### AC-08 LLM fallback 禁止

決定的処理または閉じた意味評価として分類された判断が、実行失敗・評価器障害・未設定等を理由として LLM 推論へ自動 fallback しないこと。

### AC-09 Semantic Evaluation 障害時停止

必須の閉じた意味評価が成立しない場合、その結果を未確定として扱い、当該結果に依存する後続の副作用または状態遷移へ進まないこと。

不合格と判定不能を区別し、依存しない独立処理を一律に停止していないこと。

### AC-10 Semantic Evaluation 再開可能性

評価器復旧後、未確定状態から正規の再実行・再開経路によって評価を再実行できること。

入力・規則・成果物・証拠の変更に影響する古い判定を再利用せず、成功済み副作用を重複実行しないこと。修復・再試行・運用介入を判定方式の代替または新規規範判断と混同しないこと。

### AC-11 人間判断境界

新しい目的、価値、優先順位、対象範囲、外部契約、受け入れ条件、恒久規範、または既存規範だけでは解決できない規範間優先順位の確定だけが、人間に留保された判断として扱われること。

評価器障害だけを理由に人間判断へ移行しないこと。

人間に留保された内容判断と運用上の介入・副作用実行の許可を混同しないこと。委譲された裁量内の具体化を、新規規範の確定と同じ承認対象にしないこと。

### AC-12 soft contract と機械処理の両立

soft contract を採用する成果物でも、存在確認、型、列挙値、ID、参照関係等の決定的処理可能な部分を機械的に扱えること。

soft contract を LLM 解釈必須の根拠としていないこと。

### AC-13 ライフサイクル責務の単一性

case-open / case-ready / case-run / case-close / case-revise 等の主要責務について正規所有者が一意であり、同一責務を複数工程が現行責務として所有していないこと。

### AC-14 Wave / dependency 責務整合

Wave、意味的依存、実行並列上限、競合情報の各概念が互いに混同されず、それぞれの正規責務と決定方法が一意であること。

### AC-15 現行規範の用語整合

廃止済み command、旧 lifecycle 名、旧成果物名等が、歴史的説明を除いて現行規範として使用されていないこと。

### AC-16 過剰統制の不存在

現行 hard gate、fail-closed、checker、禁止規則、adversarial-review、HITL、fallback 等について、正規モデル上の必要性を説明できること。

説明できない統制が残っていないこと。

### AC-17 新規統制の抑制

本変更を実現するためだけに、必要性が立証されていない中央 router、ledger、新規状態、新規 gate、新規 schema、新規 checker 等を追加していないこと。

### AC-18 歴史記録の保全

retired REQ、superseded Decision、historical report 等について、過去時点の事実を現在モデルに合わせるためだけの改変を行っていないこと。

### AC-19 現行規範と歴史記録の識別性

歴史的成果物が現行契約として誤認されず、現在の正規所有者へ到達できること。

### AC-20 `docs/**` 全体整合

現行規範として有効な `docs/**` を横断して読んだとき、ADF の設計思想、判断責務、ライフサイクル、用語、所有関係について相互矛盾する現在像が得られないこと。

### AC-21 実現物整合

Command / Skill / Script / Tool / Template / Extension / checker 等の実現物が、確定した正規モデルと矛盾する責務・判断経路を実装していないこと。

実現物同士の整合だけでなく、本 RU の合意が正規契約・実行入力・検証義務へ意味を保って届いていること。試験内の参照モデルや手順文面の存在だけを、実運用入力の検査と拒否結果による副作用抑止の証明として扱わないこと。

### AC-22 互換維持による妥協の不存在

現行 v4 の実装・文書・accepted Decision 等との互換維持だけを理由として、正規モデルと矛盾する構造を残していないこと。

提供能力の維持と内部互換の維持を区別し、能力自体の廃止を内部互換不要の合意だけで確定していないこと。

### AC-23 v4 境界

再収束後も v4 の Standard Operating Model の目的および中核モデルを維持できること。

維持できないことが判明した場合、本作業内で暗黙に v5 化せず、その理由と必要な新規判断事項を提示して停止すること。

維持する中核は、要件に基づく継続的な開発という目的と、要求・判断権限・永続状態・実行安全・証拠連鎖の意味上の性質である。工程名・工程数・内部配置の変更だけで中核放棄と判定しないこと。

### AC-24 baseline tag

再収束の変更開始前の `main` commit に、release version と混同しない非 SemVer の baseline tag が存在すること。

既存 tag を移動または再利用していないこと。

### AC-25 baseline 追跡性

再収束後の状態から、baseline tag を用いて作業前状態との差分を一意に比較できること。

### AC-26 検証結果

最終検証では、少なくとも本 AC-01〜AC-25 をそれぞれ `pass / fail / blocked / not applicable` で個別判定し、`fail` または `blocked` が残る場合に完了と報告しないこと。

非該当は正規モデル上の廃止等、適用されない根拠を説明できる場合に限る。未評価・未投影・未実装・未検証・証拠不足・検証不能を非該当としない。判定は現在の契約・対象成果物・評価範囲に有効な証拠に基づくこと。今回の条件を満たした後、新規観測の増加だけを理由に完了対象を無期限に拡張しない。
