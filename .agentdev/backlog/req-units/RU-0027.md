# RU-0027: Draft Definition PR の作成〜merge 完結契約の整備（ブランチ命名・draft フラグ・merge 経路）

## Sources

- **Draft Definition PR のブランチ命名規約が definition-readiness Design で所有されていない**: case-open の Draft Definition PR 作成に必要なブランチ命名規約が `docs/designs/workflows/definition-readiness.md`（Definition PR lifecycle、canonical Definition 判定、冪等キーの正規所有者）に定義されていない（2026-09-16 再確認: 同 Design に branch/ブランチの記述なし）。2026-09-15 の case-open Batch 1（Case #2821〜#2825、PR #2826〜#2830）では `agentdev-git-worktree` の `{type}/issue-{N}` から `definition/issue-{N}` を派生運用した。実装系ブランチ（`feature/issue-{N}`）との区別は可能だが、規約の正規所有とバッチ以降の一貫運用には Design 側の明文化が必要。Definition Amendment PR（case-revise）のブランチ命名も併せて確定対象。
- **Draft Definition PR の merge 完結経路の不在（draft 解除操作不在と draft フラグ不統一）**: case-ready STEP-1 の Definition PR 受入で、Draft Definition PR 10件（#2826〜#2830・#2851〜#2859）が draft 状態のまま作成され、pr_merge が「gh: Pull Request is still a draft (HTTP 405)」で失敗。agentdev_gh Custom Tool に draft 解除（ready 化）操作が存在せず、pr_update 契約は draft フィールドを unknown-field として拒否、gh CLI 直操作は write-guard でブロックされるため merge 前提を満たせず HITL 停止した。根本原因は (a) case-open の Definition PR 作成時の draft フラグ不統一（Batch 1/4 が draft、Batch 2/3 が非 draft）、(b) agentdev_gh 操作カタログに draft 解除操作が設計として含まれない、の複合。運用時の partial merge は不可（REQ-057 要件テーブルへの行追加連鎖により rebase 採番順序が崩壊するリスク）。write-guard 境界（raw gh WRITE のブロック）は維持する。
