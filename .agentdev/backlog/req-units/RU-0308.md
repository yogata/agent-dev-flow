# 利用先リポジトリでの4エージェント任意選択

## 目的

利用者が Codex、Antigravity、OpenCode、Senpi の4エージェントから、利用先リポジトリに AgentDevFlow を配置する対象を選べるようにする。各エージェントの単独導入と任意の複数選択を、チェックアウト版とリリース ZIP 版の両方で実現する。

## 対象

- 利用先リポジトリのエージェント選択、選択の記録、再導入、切替、選択に応じた依存検査。
- チェックアウト版の CLI と対話ウィザード、ZIP 版の CLI、ZIP の収録内容と公開前検証。
- OpenCode の `.opencode/`、Senpi の `.senpi/`、Codex と Antigravity が共有する `.agents/skills/` への配置。

## 対象外

- エージェント本体や CLI のインストール、ホーム全域への配置、本体リポジトリの `self-sync.ps1` における対応エージェントの拡張。
- Codex・Antigravity で、導入後に Issue・PR・Release を含む全ワークフローを完走させるための実行接続。これは [RU-0307](RU-0307.md) が扱う。本 RU は導入先のエージェントが対象スキルを読み込めるところまでを扱う。

## 依存関係

採番済みの必須依存 RU はない。エージェント上での全ワークフロー実行は [RU-0307](RU-0307.md) の対象であり、導入の完了条件はこの RU の受け入れ条件で判断する。

1. 選択・更新・切替と対応範囲を合意してから、状態の表現と配置規則を確定する。
2. チェックアウト版の Codex 単独導入で、選択状態とエージェント別前提検査を検証する。次に他の組み合わせと既存導入の引き継ぎを検証する。
3. Senpi の接続と共通資産が展開元から独立して読み込める構成を決め、ZIP 生成・導入と配布ゲートを揃えて更新する。
4. 両経路の回帰試験、公開前検証、利用手順を揃える。配布検査では、各エージェントに必要な資産に加えて収録禁止資産と検出すべき欠落も確認する。

## 要件化の方向

### 不足する要件

| 確定が必要な契約 | 要件候補 |
| --- | --- |
| 選択の自由度 | 両導入経路で、4エージェントの各単独と任意の組み合わせを指定できる。新規導入と更新で選択を省略した場合の挙動を定義する |
| 選択の継承と切替 | 成功した配置の選択を記録し、再実行と更新で再現できる。切替時は所有を確認できる AgentDevFlow 資産だけを変更し、利用者の設定とスキルを保持する。記録の欠落・破損・移行時の扱いを定義する |
| エージェント別の依存 | 選んだエージェントの配置に必要な資産・依存を検査する。配置検査とホスト実行の確認結果を区別する |
| ZIP の自己完結 | ZIP 版は展開元を片付けた後も、選択したエージェントの配布対象スキルと接続を読み込める。公開前検証が、選択に応じた不足・余分な配置・内容不一致を検出する |
| 共有スキルの寿命 | Codex と Antigravity の選択は個別に記録し、共有スキルはどちらかが選択されている間は維持する |

### 合意済みの方針

- 新規導入では配置先のエージェントを明示する。対話ウィザードで選択を求め、非対話 CLI で省略した場合は指定方法を案内する。更新で省略した場合は、前回の選択を維持する。
- Codex と Antigravity は `.agents/skills/` を共有できる。片方だけを選択した場合に、同じリポジトリを開いたもう片方からも共有スキルが見えることを許容する。
- 単独導入後に実際のエージェントで業務を実行して確認するのは利用者が担当する。導入側は配置と読み込みを検証し、利用者に起動方法を示す。

### 設計候補と確認事項

| 論点 | 推奨案と決定の影響 |
| --- | --- |
| 全解除と原本の保護 | 全解除を明示的な空の選択として扱い、個別解除と同じ規則を適用する案。原本、利用者の設定とスキルを保持する。チェックアウト版で除去するのは管理リンクと必要に応じて installer が生成した補助ファイル。ZIP 版は実ファイルを配置するため、所有を確認できる配布コピーを除去する案。記録上は空の選択を保存し、引数省略と区別する |
| 導入済みエージェントの判定 | 導入先の `.agentdev/install-state.json` に成功した選択を記録し、更新時の判定根拠とする案。記録がない既存導入では、所有を確認できる `.opencode/`・`.senpi/` の配置から補助的に判定する。`.agents/skills/` の存在だけでは Codex・Antigravity のどちらを選んだか確定できないため、明示選択で補う |
| Codex・Antigravity の選択単位 | 4エージェントの選択を維持し、Codex と Antigravity を配置上だけ同じグループとして扱う案。ウィザードでも1項目にまとめる場合は、利用者に見える選択が3項目になる |

## 決定的受け入れ条件

1. 空でない全15通りを、クリーンな利用先でチェックアウト版と ZIP 版それぞれに指定できる。各選択について、期待する管理対象パスの集合と実際の集合が一致する。Codex 単独、Antigravity 単独、両者のみでは `.opencode/` と `.senpi/` の管理資産が作られない。
2. OpenCode を選ばない導入は、OpenCode 用 textlint の依存実体や OpenCode 用 third-party Skill の配置を要求しない。OpenCode 選択時には既存の必要な検査が働く。
3. エージェント切替の `dry-run` が示した管理対象の変更を `apply` が反映し、その後の `check` が合格する。記録済み選択を省略で再現でき、同じ選択で再実行しても配置に差が出ない。利用者の設定・スキルと、残すエージェントの資産が保持される。
4. Codex＋Antigravity から片方を外すと記録上の選択だけが変わり、共有スキルは残る。両方を選択から外し別のエージェントに切り替えると、所有が確認できる共有配置だけが除去される。
5. 旧状態の引き継ぎでは、確定可能な選択を保持し、曖昧な場合は明示選択を案内する。所有が確認できない衝突では当該資産を保持し、処理結果に衝突を示す。
6. ZIP 展開元を除いた利用先で、配布対象スキルと Senpi 接続モジュールが読み込める。公開前検証で、欠落・余分な配置・内容不一致を個別に検出する。利用者が各エージェントで業務を開始できるよう、エージェント別の起動方法を導入手順に示す。
