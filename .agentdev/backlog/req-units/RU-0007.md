# vendored bundle 再生成時の焼き付きパス無害化自己検査

本 RU は AgentDevFlow 本体向けの引き継ぎ RU である（本体リポジトリでは通常の req/case workflow 入力として扱う）。

## Sources

- textlint-bundle-build-path-selfcheck（intake）: vendored engine bundle（`src/opencode/plugins/agentdev-textlint-guard/vendor/textlint-engine.bundle.json`）再生成時に kuromojin 既定 dicPath 用 `require.resolve` 由来の絶対パスが焼き付く。runtime は `KUROMOJIN_DIC_PATH` 固定経路で使用されるため実害はないが、ビルド時 worktree 削除後の `bun test` が環境依存 fail し得る。焼き付きパスの検出手段がなく再現時の調査コストが発生する（PR 2730 / Issue 2725 由来）。

## Source Summary

実害なしの既知現象だが、bundle 再生成後の環境で `bun test` fail の原因が判明しにくく、検出・無害化の自己検査が未整備。

## 統合理由

1:1。単一論点であり統合・分割不要。

## 要件化の方向

1. build スクリプトへ bundle 内焼き付き絶対パスの検出・除去（または無害化）自己検査を追加する。
2. 現行のまま受け入れ（実害なし）とする場合の判断は req-define で選択可能とする。
3. 配布物相対解決の運用知識は docs/knowledge/ の offline bundle 知識と相互参照する。
