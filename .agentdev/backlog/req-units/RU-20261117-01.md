# RU-20261117-01: QG-4の試験範囲適正化と正式リリース前の全試験保証

## 背景

Case #4113では、2ファイル・99行の削除という小規模な変更に対しても、case-closeでリポジトリ全体の試験が実行された。続くCase #4117・#4118でも、全試験の実行が工程費用の主要因として残った。

一方、ADFの品質モデルは、変更内容・リスク・受け入れ条件から検証義務を導出する考え方を採用している。

## 問題

通常案件の検証義務と、実際に実行する試験の範囲が十分に対応していない。変更規模や影響範囲と無関係に全試験を強制すると、小規模な変更でも大きな実行費用が生じる。

また、通常案件の全試験義務を廃止するだけでは、正式リリース前にリポジトリ全体の試験が実行される保証が不足する。

## Source Summary

本セッションで利用者は、次の方針に合意した。

1. 通常案件では、変更内容と受け入れ条件から必要な試験を決定して実行する。
2. 試験範囲を安全に限定できない場合は、リポジトリ全体の試験を実行する。
3. 利用者が全試験を明示要求した場合は、その要求を維持する。
4. 正式リリース前には、リポジトリ全体の試験を実行する。
5. 検証義務を弱めず、必要な品質保証を維持する。

## 統合理由

通常案件の試験範囲の適正化と、正式リリース前の全試験保証は、同時に成立させる必要がある。前者だけを変更すると、全試験が一度も実行されないままリリースに進める可能性が残るため、同一RUで両方を扱う。

## 要件化の方向

### 通常案件の試験選択

- 変更内容、依存関係、リスク、受け入れ条件と正規の検証義務から、必要な試験の範囲を決定する。
- 変更ファイルに直接対応する試験に加え、影響を受ける関連機能や共通基盤の試験も評価対象とする。
- 試験範囲を限定する根拠が不足する場合は、全試験を実行する。対象の一部だけを検査して全体の成立を主張しない。
- 試験以外の必須検査・実際の利用経路による検証は、試験範囲の縮小によって省略しない。

### QG-4の最終受け入れ

- QG-4は、正規契約から検証義務を独立に確認する責務を維持する。
- 全試験の一律実行を完了条件とせず、必要な試験・検査が実施され、要求範囲の成立が証明されたことを判定する。
- 検証の独立性、証拠の鮮度、変更後の再検証義務を維持する。
- 既知欠陥の由来分類と既存の受理規則は変更しない。未分類の失敗や証拠不足を合格としない。

### 正式リリース前の全試験

- ADFが管理する正式リリース工程では、リリース対象コミットについて、リポジトリ全体の試験が正規の方法で実行され、既存の受理基準を満たした証拠を確認する。
- その確認は新しい正式版タグの作成より前に完了させる。証拠不足、不合格、実行不能の場合はタグ作成とリリース完了を認めない。
- 検証後に対象コミットまたは検証条件が変わり、証拠の有効性が失われた場合は、必要な再検証を行う。
- リリース対象とは異なる案件分岐の試験結果だけを、リリース対象コミットの全試験の証拠として扱わない。

## 主対象REQまたは変更対象候補

- QG-4の正規定義：`agentdev-quality-gates`、`v4-quality-gate-model`
- case-closeの最終検証：`docs/designs/commands/case-close.md` および対応する実行主体
- 検証専用案件の試験実行：`docs/designs/commands/case-run.md`
- 正式リリース工程：`REQ-114`、`agentdev-workflow-backlog-auto` の第7段階
- 試験影響範囲の判定：`test-impact-detection-gate` と既存の変更影響判定機構

正規所有者と変更対象の確定は後続の要件定義・設計工程で行う。新しい品質ゲートや恒久台帳の追加は既定としない。

## 対象範囲

- 通常案件における試験の選択と実行
- QG-4の検証義務・試験実行義務・最終受け入れ判定
- 変更を伴わない検証専用案件の試験実行
- ADFが管理する正式リリース前の全試験保証
- 該当する工程間の接続と、正常系・異常系の回帰検証

## 対象外

- 個々の試験内容や品質ゲート体系の全面再設計
- 試験範囲の選択とは独立した全体監査などの必須検査の一律廃止
- 新規の恒久的な試験対応台帳や汎用工程管理基盤の導入
- ADFの管理外で行われる手動のタグ操作や公開操作
- 既存の既知欠陥受理規則や利用者承認境界の変更

## 受け入れ条件

| ID | 要求する結果・成立条件・検証方法・合格基準 |
|---|---|
| TS-001 | 変更範囲と依存関係を安全に特定できる通常案件で、必要な試験が選択・実行され、全試験の一律実行を要求されないこと。変更対象と関連試験を対応づけた記録、実行対象・結果・除外根拠を確認する。関連試験の欠落または根拠のない除外は不合格とする。 |
| TS-002 | 試験の影響範囲や依存関係を安全に特定できない案件では全試験が選択されること。共通基盤の変更、依存関係不明、対象抽出失敗などを反例として検証し、不明な範囲を無条件に除外した場合や0件実行を誤って成功とした場合は不合格とする。 |
| TS-003 | QG-4が正規契約から必要な検証義務を独立に導出・照合し、対象成果物に対する試験・検査の実行証拠と対応を確認すること。必要な証拠の不足、無効化された証拠の流用、未検証範囲の残存を検出した場合は完了を拒否する。 |
| TS-004 | 検証専用案件でも必要な検証が成立すること。変更がないという理由だけで全試験を無条件に強制せず、同時に、必要な検証が未実施なら完了しないことを、検証専用案件の正常系と未実施の反例で確認する。 |
| TS-005 | 正式リリースでは、リリース対象として確定したコミットに対する正規の全試験の実行・受理証拠が、正式版タグの作成前に確認されること。全試験未実施、対象コミット不一致、不合格または証拠不足を与えた場合にタグ作成を拒否することを確認する。 |
| TS-006 | 試験後に対象コミットや検証条件が変わって証拠が無効になった場合、無条件に旧証拠を再利用しないこと。同一条件で有効な証拠と、変更後に無効となる証拠の双方を与えて判定を確認する。 |
| TS-007 | 利用者または正規契約が全試験を明示要求する案件では、試験の選択機構による範囲縮小を認めないこと。全試験指定と試験選択を同時に与え、全試験の実施・受理が確認できない場合に完了を拒否する。 |

## 実装前の確認事項

- コード変更を含めた試験影響範囲の判定能力と、判定できない場合の境界を確定する。
- QG-4および検証専用案件で全試験を無条件に起動している箇所を確認する。
- 正式リリースを実行できる正規経路と、リリース対象コミットへの試験証拠の結び付けを確認する。
- 既存の試験失敗分類、既知欠陥の受理、再実行条件と矛盾しないことを確認する。

これらの技術的確認は実現方法の選定に用い、合意した検証義務を弱める理由にはしない。
