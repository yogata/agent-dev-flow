# RU-0110: case-close STEP-4-3 への branch HEAD commit message の auto-close キーワード確認前置

## Sources

- **learning: PR タイトル事前変更は 1-commit PR の squash タイトルを制御できない（Case #2954・PR #2957）**: case-close STEP-4-3 の「PR タイトル事前変更」を実施しても、本リポジトリの squash merge 設定（1-commit PR で commit message を採用）では branch HEAD の元 commit メッセージがそのまま squash タイトルになった。元 message に auto-close キーワードを含まず誤 close は未発生（保護が偶然に依存）。commit message 優先設定のリポジトリで branch HEAD message に fixes/closes/resolves + 近接参照が含まれたまま merge すると Issue の意図しない auto-close が発生する。現行 STEP-4-3 は PR タイトル変更のみを規定し commit message 確認を想定していない（guardrail insufficiency）。

## Source Summary

squash コミットタイトルの由来はリポジトリ設定に依存し、PR タイトル事前変更だけでは auto-close 回避を担保できない。merge 前の branch HEAD commit message 確認が保護の実体になるが手順に未規定である。

## 統合理由

1:1。単一成果物・単一 STEP（case-close STEP-4-3）の手順強化であり分割すべき複数論点を持たない。

## 要件化の方向

agentdev-workflow-case-close references pr-merge-and-conflict.md STEP-4-3 の前置として、branch HEAD commit message の auto-close キーワード確認（fixes/closes/resolves + Issue 近接参照なし）を merge 前チェックとして追加する。1-commit PR・commit message 採用設定環境では PR タイトル事前変更が squash タイトルを制御できない旨（補助手段である旨）を注記する。確認でキーワードを検出した場合の扱い（commit message 修正・rebase 等）を手順に含める。リポジトリ設定の差異を判定できない場合は commit message 確認を常に実施する安全側で運用する。確認対象は branch HEAD の commit message のみ（全 commit の精査は要求しない）。リポジトリ側 squash 設定変更・pr_merge Tool 実装は対象外。Issue の close は case-close の明示 close で完結する設計を維持する。
