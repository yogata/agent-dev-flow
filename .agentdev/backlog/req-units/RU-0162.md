# RU-0162: case-open/ready/close機械工程のスクリプト化とorchestration並列改善

## 目的

過去72時間（2026-10-02〜05）のOpenCode実測（268セッション、19,428ツール呼び出し）に基づく処理時間分析の合意（本セッション2026-10-05）を実装に移す。case-open（平均29分・31実施、うちツール実行32%）、case-ready（平均21分・20実施、同9%）、case-close（平均27分・30実施、同28%）の所要の大半がLLM推論ターンであり、機械的に確定した手順をLLMがbashコマンド1個ずつとして生成・実行している構造が主因である。

本RUは過去72時間の処理時間分析セッション（Hermes Supervisor）での合意に基づき、Supervisorが作成・保存した。frontmatter の `generation_actor` は session由来RU契約（REQ-008-051）の固定値 `req-define-parent` へ適合させた（2026-10-06、case-open 開始前の解決）。実作成主体が Supervisor であった事実は本記述が保持し、当該配置をもって契約改訂の承認とは扱わず、正規契約は変更していない。

変更の原則: 意味判断（停止判断、deviation分類、adversarial review、警告の重要度評価）はモデルが担当し続ける。worktree作成、テンプレート複写、索引再生成、整合検査、traceability検査、commit、PR/Issue本文の組立といった決定的処理は、各workflow skill配下のscript 1呼び出しに束ねる。GitHub I/O（issue/pr作成・マージ・クローズ）はagentdev_ghツールのまま維持し、scriptはローカル決定的処理のみとする境界を維持する。

## 対象

- case-open STEP-4（実変更判定とDefinition PR作成）の機械工程をscript化: worktree作成からREQ行編集、generate_indexes、check_integrity、traceability check、commitまでを1 script呼び出しとし、報告JSON（実行結果・差分・警告・提案するIssue/PR本文）をstdoutへ返す。モデルは報告JSONの意味レビューとagentdev_ghによるI/O実行のみ
- case-ready・case-closeの機械工程の同様のscript化（工程別の個別scriptとし、共通基盤は作らない。inspect_cross_dependencies.tsと同じ作りに従う）
- workflow skill参照文面（references/*.md）の短縮: LLMが手順を逐次実行する指示から、script呼び出しと報告JSON解釈への置換
- orchestration stage 3のWave障壁の緩和: 完了即次投入のスロット型キュー（依存関係のあるDefinition mergeのみ排他維持）。wave-gate.tsの依存充足ゲート純関数は再利用する
- 委譲プロンプト雛形（agentdev-case-run-execution-adapter）への必須契約要約の埋め込み（セッション毎の参照資料再読込削減）
- HITL question のノンブロッキング化（スキップ可能キュー）のコマンド契約変更
- bash内蔵コマンド（grep/ls）の内蔵ツール使用規律の各workflow skillへの明記

## 対象外

- case-run本体の実装変更（ユーザー指示により除外。ただし委譲プロンプト雛形・検証キャッシュの効果はcase-runにも波及する）
- コマンド公開インターフェース・ガードレールの変更（委譲先は引き続きworkflow skillのload指定）
- adversarial review、deviation capture、auto_gate停止判断の機械化
- GitHub I/Oのscript内gh CLI直接実行（agentdev_ghツール境界の維持）
- 新しい中央評価基盤・共通phase-runner基盤の作成（3工程の実測が揃ってから別途検討）
- モデルや推論強度の変更
