# GitHub 版隔離検証環境の正規構築手段不在（TS-007 / TS-008 / TS-010 統合）

## 観測内容

agentdev_gh 操作カタログには GitHub 上へのリポジトリ作成（repo create 相当）の操作が存在せず、gh-write guard（agentdev-gh-write-guard）は raw gh WRITE を cwd 非依存のコマンド文字列検査により fail-closed 拒否するため、正規手段では検証用リポジトリを構築できない。既存の隔離検証リポジトリも不在である（gh repo list 読取で一致 0 件）。このため、正規成果物ゼロの新規プロジェクト起点の GitHub 版正規利用経路の実操作検証が実施不能となっている。

本根本原因により次の検証が blocked となっている（いずれも Local 版部分は pass、代替の構造的等価性は「同等以上の証明能力を持つ代替」とは認めない〔RA-005 判断〕）:

- TS-007（REQ-110-021、Case #3779 / PR #3781 由来）: GitHub 上のリポジトリと Issue を含む正規利用経路で、正規成果物ゼロの新規プロジェクト起点の一連経路を実行する検証。Case #3779 の完了条件2 が未充足で判断待ち停止。GitHub 版相当のローカル git リポジトリ環境での実行は実施済み。
- TS-008（REQ-111、AC8）と TS-010（REQ-110、AC10・AC1/AC3 移管分）: Epic #3803（PR #3811 Findings 第1項、PR #3812 intake〔再現・拡張〕、DEL-3803-CLOSE）の該当部分が blocked として記録。gh-write guard の拒否はプロジェクト内・外の両 cwd で再現済み（PR #3812 検証差分 #15）。

## 影響

- 整備されるまで TS-007 / TS-008 / TS-010 の GitHub 版部分が継続して blocked となり、Case #3779 と Epic #3803 の完了条件が未充足のまま残る。
- 正規利用経路の GitHub 版実操作検証が恒久的に欠落したままになる（検証環境の不備の恒久化）。

## 課題

- GitHub 上に正規成果物ゼロの検証環境を用意できる正規手段が存在しない。
- 整備方針（専用検証入口の追加、または管理者事前準備の隔離検証 repo の常備）と REQ-110 / REQ-111 の検証方法・適用範囲の再評価のいずれを行うかが未決。
