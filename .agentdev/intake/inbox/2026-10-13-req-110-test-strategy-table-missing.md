# REQ-110 本体に test strategy 表が存在せず、TS 番号の解決先が不在である問題を解消する

## 観測

Epic #3653（工程駆動コラボレーション）の Wave-1（#3657）実行時、Issue 完了条件が参照する TS 番号（TS-001、TS-003、TS-004、TS-005、TS-008、TS-009、TS-011）の解決先が REQ-110 文書内に存在しなかった。REQ-110 には test strategy 表が存在せず、TS 番号が正規情報源から解決できない構造である。実行では Issue 本文に明記された合格条件（保存先実ファイルの読み戻し突合、テーマ一覧の正本導出・恒久正本不在、識別状態の別セッション復元、閲覧像の第二正本化禁止）を正に検証を実施した。REQ-110 の main 現在（commit 3f457e6f）でも test strategy 表は存在しない。Wave-2（#3658）の検証契約（TS-001〜TS-013 を GitHub 版と Local 版の両実環境で実施）も TS 番号の解決先を Issue 本文の記述で代替して実行済みである。

## 今回扱わない理由

Wave-1〜Wave-3 の実行は完了済みであり、REQ 文書の変更（test strategy 表の追加または TS 番号の別正規情報源の指定）は Definition 正規成果物の変更であって実行 Case の対象外である。

## 影響

REQ-110 を参照する将来の Case で、TS 番号が検証手順の正規情報源から解決できず、実行ごとに Issue 本文や PR 本文の記述を代替情報源として解釈判断する往復が再発する。REQ-110 の15行は既に実装・検証済みであるため、検証の再実行時に TS 番号の意味が実行記録からしか復元できない状態が続く。

## レビューで決めること

- REQ-110 への test strategy 表追加（REQ 行の APPEND/UPDATE 判定）または、TS 番号の正規情報源を別文書（Design 等へ指定する方針）のどちらで解消するか
- 既に完了済みの TS-001〜TS-013 の内容を実行記録（#3657 PR #3664、#3658 PR #3666 の検証差分）から復元して表へ起稿するか、将来検証向けに再定義するか
