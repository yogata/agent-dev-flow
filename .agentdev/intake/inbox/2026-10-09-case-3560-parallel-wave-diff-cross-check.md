# 並列 Wave の実差分交差確認を commit・push 前に検討する

## 内容

並列 Wave の変更対象管理で、宣言上は重複なしでも実差分で同一ファイル（docs/designs/commands/req-define.md）が重複した。Epic #3560 Wave-2 で Issue #3563（PR #3569）と Issue #3564（PR #3570）が req-define.md の別節を変更し、マージ順序の調整決定（#3569 先）とコンフリクト時の Level 1 rebase 担当を case-close に引き継ぐ対応が必要になった。今回の重複は親 case-run の調整決定（双方の所有正当・マージ順序 #3569 先）で処置済み。

## 影響

並列実行の子 Issue が同一ファイルを変更する場合、マージ順序の決定とコンフリクト解消の担当判断が後続工程へ引き継がれる。宣言ベースの重複前置検出では実差分の交差が検出されず、マージ直前まで衝突リスクが見えないまま残る。

## 提案

commit・push 前の実差分交差確認（並列実行中の兄弟 branch の変更ファイルとの交差チェック）を検討する。REQ/Design 変更を伴うため req-define 再合意を経る正規経路で評価する。

## 根拠

Epic #3560 Wave-2、Issue #3564（PR #3570 本文「兄弟 Issue との変更対象重複と調整記録」節・Findings の intake 候補）。
