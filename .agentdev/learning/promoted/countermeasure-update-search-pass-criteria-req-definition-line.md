# 検索型合格条件の REQ 本体定義行は正当クラスとして除外する解釈基準を整備する

## 背景

REQ-123-001 TS-001.2（Case #4167・PR #4173）の「撤去モジュール名の参照残存 0 件」検索（rg / git grep）が、撤去対象モジュール名を列挙している REQ 本体の定義行（REQ-123.md REQ-123-001 行）自体にヒットし、合格条件が字面のままでは機械的に達成不能となった。REQ は実行担当が編集不可の既確定文書である。実行担当は「dangling 参照の不在」を意味意図とする解釈で REQ 定義行と docs/reports/（完了条件の網羅範囲外と本文に明記済み）を計上対象外とし、Findings に判断根拠を記録して合格判定した（case-close QG-4 で根拠記録を確認のうえ受理）。

## 問題

「参照残存 0 件」型の検索合格条件は dangling 参照の不在を意味意図とするが、検索パターンは字面一致のため REQ 本体が撤去対象名を列挙する場合、REQ 本体の定義行にも一致する。同系問題の既存知識（docs/knowledge/grep-zero-criteria-legacy-term-quotation.md）は「執筆規約で予防」（旧語の字面引用回避・描写形への言い換え）の観点のみで、REQ 本体の列挙行のような「編集不可で回避できない正当クラス」の解釈基準が欠落している。解釈基準が明文化されていないと、解体系 REQ の合格判定が実行担当ごとにブレる。

## 望ましい変更

- 要件doc の検索型合格条件作成時に「REQ 本体の定義行・網羅範囲外領域（docs/reports/ 等・完了条件文言に従う領域）を除外」の解釈注記を事前に含める指針を整備する
- 解体系 REQ 実行時の解釈基準（REQ 本体定義行・網羅範囲外領域は stale reference の計上対象から除外）と、実行担当の Findings 根拠記録必須化（case-close で確認）の運用を既存知識へ追記する
