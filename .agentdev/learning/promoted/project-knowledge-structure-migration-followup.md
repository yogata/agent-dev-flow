# 構造移設の追随漏れ防止の 3 点セットと横断検索手順

処分区分: 4 project knowledge

## 背景

src/opencode から src/common への構造移設に伴う追随漏れが 3 件連続した: (1) 検査基盤の走査先変更での追随漏れ（baseline・除外定義・文言の更新不整合）、(2) テストの旧正本参照残存（Wave 1 共通正本化の追随漏れ・pre-existing fail）、(3) scripts/self 配下の検査テストが旧構成前提として残存（src テスト green でも潜む）。

## 問題

構造移設では移設元パスの参照が多層（src テスト、scripts、検査基盤の baseline・除外定義・文言）に分散しておおり、単一層の更新では追随漏れが残る。src テストの green が追随完了の証拠にならない。

## 望ましい変更

次の手順知見を知識文書化する（docs/knowledge/ への直接保存は backlog-review 承認後）:

1. **3 点セット同時変更**: 検査基盤の走査先変更は (a) baseline 期待値、(b) 除外定義、(c) 検査文言・メッセージの 3 点を同時変更する
2. **横断旧パス検索**: 移設完了判定は src 配下に加え scripts 配下（scripts/self 等）を含む横断検索で旧パス残存 0 件を確認する。検索語はパス区切りのバリエーション（`src/opencode`・`src\\opencode`・`opencode/skills` 等）を網羅する（TS-011 の教訓を含む）
3. **移設後の全層テスト実行**: src テストに加え scripts 配下テスト・fixture を含む全実行で追随を確認する
