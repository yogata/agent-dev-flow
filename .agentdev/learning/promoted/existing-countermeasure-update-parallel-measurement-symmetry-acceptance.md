# 既存対策の更新: 並列化比較測定の受け入れ条件への測定内容対称性確認の明示

## 背景

Case #3139 の TS-004 subset 7 ファイル比較測定で、並列側が baseline 側に無い候補検証（RA-002 由来）を含むより深い作業を実行しており測定内容が非対称、かつ subset 小規模では委譲固定 overhead が支配するため、TS-004 契約（同一候補整理・同一読み取り・同一比較対象）を満たさず評価を取り下げた。
ユーザー判断（2026-09-25）により非対称測定の成功証拠流用が不承認とされ、同条件全件再検証の指示があった。
全件対称再測定（同一 Git revision・docs corpus 同一〔diff 空〕・全件 303 ファイル/28,619 行・共通候補入力・同一委譲 prompt・同一判定基準・差は逐次か並列かのみ）で再実施し、並列 16分00秒 < 現行実行参照 21分29秒 < 全件逐次 baseline 55分47秒 の両比較対象に対する短縮を実証した（単一実行の改善率は断定しない・REQ-036-033）。

## 問題

REQ-036-032（docs/requirements/REQ-036.md:51）は同一 Git revision の診断対象 corpus と既知 finding を比較基準と規定するが、測定作業の対称性（候補検証の有無・候補入力の同一性）を測定設計段階で揃えることを明記していない。
測定設計段階で作業内容の対称性が揃っていない比較測定は、TS-004 型の契約を満たさず評価取り下げ・全面再測定のコストを生む。

## 望ましい変更

並列化の比較測定の受け入れ条件に「測定内容の対称性確認（候補検証の有無・候補入力の同一性・読み取り内容の同一性）」を明示する。

- 測定設計段階で baseline 側と並列側の作業内容の対称性を確認し、差がある場合は測定計画を修正する。
- 非対称測定は短縮証拠として採用しない（本測定で実証済みの判断基準）。

## 元learning item / 根拠

- **要約**: 並列診断の壁時計短縮比較測定は、測定内容の対称性（候補検証の有無・入力同一性）を測定設計段階で揃えることが必須。
- **根拠**: Case #3139 の TS-004 subset 7 ファイル測定の取り下げ（非対称測定・委譲固定 overhead 支配）と、ユーザー判断（2026-09-25）による同条件全件再測定指示。全件対称再測定（303 ファイル/28,619 行・差は逐次か並列かのみ）で 16分00秒 vs 21分29秒 vs 55分47秒 を実証。測定記録は PR #3141 本文。
- **再発条件**: 並列化の効果測定を subset で代用し測定内容の対称性を確認しない場合に再発。
- **横展開可能性**: LLM 意味診断の比較測定全般（モデル・構成の A/B 比較等）に適用可能な測定設計知見。
