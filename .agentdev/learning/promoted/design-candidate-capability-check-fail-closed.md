# 存在チェックと能力検証の分離原則（能力欠落時 fail-closed）

処分区分: 3 恒久契約候補（Design）

## 背景

Case #3316（PR #3332 Findings）で、投影パスによる runner 差し替え（パスの存在で runner を選択する構成）において、存在チェックだけでは能力欠落（差し替え先 runner が必要な機能を持たない）を検出できず、scripts/self 配下の検査テストが旧構成前提として残存した。存在するが能力が不足する状態が黙って受け入れられ、検証の死角が生じた。

## 問題

存在チェック（パス・ファイルの有無）は能力検証（その対象が期待する機能・契約を満たすか）の代替にならない。能力不足を検出せず暗黙にフォールバックまたは黙過する構成は、検証資産の陳腐化を静かに進行させる。

## 望ましい変更

設計原則として次を Design に反映する候補:

1. **存在チェックと能力検証の分離**: 対象の選択（存在）と対象の能力確認（契約充足）を別のチェックとして構成する
2. **能力不足時の fail-closed**: 能力検証に不合格の場合は暗黙のフォールバックをせず、明示的な失敗として停止する（fail-closed）
3. **選択判定テストに欠落環境ケース必須**: 選択ロジック（runner・実行経路の選択等）を検証するテストには「対象が存在しない」「存在するが能力不足」の両ケースを含める

この原則は Design multi-host-canonical-model の guard 分離節（存在チェックと整合性検証の分離）と同型であり、横断する設計原則として整理する価値がある。

## 対象範囲

### 対象

- パス・実行可能ファイルの存在で選択を行う構成（runner 差し替え、実行経路選択等）
- 選択ロジックのテスト設計

### 対象外

- 個別 runner の機能追加（能力そのものの実装）
