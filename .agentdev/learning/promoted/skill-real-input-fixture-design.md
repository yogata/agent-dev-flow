# 実入力構造を再現する fixture と代表入力による横断回帰検証

## 背景

agentdev-artifact-graph の関係抽出処理で、単純化したテスト fixture が実際の Project Extension の配列形式を再現しておらず、既存テストが `rules.skill` と `context.paths` の関係抽出漏れを検出できなかった（#9）。代表質問10件を従来探索と比較したところ、初回結果の10件中8件に重大な見逃しがあった。

## 問題

- テスト fixture が mapping 中心の入力だけを表現し、`- id: ...` から始まる配列要素と後続 field の親文脈を再現していなかった
- そのため、実入力では配列内 mapping と後続 field の親子関係として存在する `rules.skill` と `context.paths` の関係抽出が、fixture では再現されず関係抽出漏れがテストで検出できなかった
- 局所的な最小 fixture のみでテストを完結させたことで、実運用で重大な見逃し（10件中8件）が潜伏した

## 望ましい変更

構造化設定を独自解析するテスト設計において、実入力と同じ入れ子・配列・親子関係を含む fixture と、代表入力を使った横断回帰検証を併用する手順を確立する。

1. 対応する入力構造（平坦 mapping、配列内 mapping、入れ子親子等）ごとに実例由来の fixture を配置する
2. 代表入力（実運用の Project Extension 等の実際のデータ）を使った横断回帰検証で、局所 fixture の不足を補う
3. 代表質問・代表シナリオで従来手法と比較し、見逃し率を定期確認する

## 対象範囲

### 対象

- repo-agentdev-artifact-graph のテスト設計（fixture 構成、回帰検証手順）
- 構造化設定（YAML/JSON）を独自解析するスクリプト群のテスト設計一般

### 対象外

- artifact-graph の関係抽出ロジック自体の仕様変更（#9 で解析処理は修正済み、本件はテスト設計の知見）
- 汎用的なテストフレームワークの導入（既存 bun test を維持）

## 制約

- 既存の局所 fixture を廃止せず、実入力構造 fixture と代表入力検証を併用する形で補強すること
- 実入力（Project Extension 等）は個別プロジェクトの設定値を含み得るため、代表入力は機密性を考慮したサンプル化または構造のみ再現した合成データを使用すること
- 解析処理の仕様（関係抽出ルール）は本件の対象外とし、テスト設計原則の確立に限定すること

## 元learning item / 根拠

- **要約**: 実入力の配列形式を再現しない局所 fixture が関係抽出漏れを隠し、代表質問10件中8件に重大な見逃しを生んだ
- **根拠**: Issue #1944 の TS-013 で代表質問10件を従来探索と比較し、初回結果の10件中8件に重大な見逃しがあることを確認。fixture が mapping 中心の入力だけを表現し `- id: ...` から始まる配列要素と後続 field の親文脈を再現していなかったことが根本原因。配列要素親文脈を保持するよう解析処理を修正し、実際の拡張定義と同じ配列形式の fixture と回帰検査を追加して代表質問を再評価した（PR #1947、`.opencode/skills/repo-agentdev-artifact-graph/scripts/lib/parse.ts`）
- **再発条件**: 実入力が配列内 mapping を含む一方、fixture が平坦な mapping だけを表現する場合
- **横展開可能性**: 構造化設定（YAML/JSON）を独自解析するテスト全般で発生し得る。実入力の入れ子・配列・親子関係を再現しない fixture は見逃しを潜伏させる
