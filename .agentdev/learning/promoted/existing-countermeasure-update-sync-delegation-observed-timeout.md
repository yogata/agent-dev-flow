# 既存対策の更新: 同期委譲の実効上限判定の実観測基準（observed-time 原則）

## 背景

Case #3139 の TS-004 subset 測定（DEL-3139-1）で、全 corpus 1 単位の同期委譲が 5分 timeout で失敗（実失敗観察）した。
実装の選択基準どおり非同期委譲へ切替して完遂し（同期失敗 → 非同期切替の経路・背景子 Abort 対策経路の実証を含む）、この観察と委譲収束実績は TS-003 pass の根拠として有効のまま保持された。
同期委譲の実効上限は harness 環境の timeout 設定（本環境で 5分）に依存し、corpus 全件規模の意味診断は超過する。
REQ-036-031 は「同期委譲で完了できる単位では同期方式を利用でき、完了できない単位では非同期委譲と子の完了まで親の実行コンテキストが維持される経路を用いる」ことを既に規定する（実読確認済み）。

## 問題

「同期委譲で完了できる単位」の判定について、事前見積もりで判定する余地が残り、環境 timeout の実観測を判定基準とすることが運用文書に明示されていない。
環境依存の数値断定（固定の時間閾値）は環境が変わると陳腐化する。

## 望ましい変更

同期委譲の実効判定基準として、事前見積もりでなく環境 timeout の実観測を基準にする指針（observed-time 原則）を注記する。

- 同期失敗 → 非同期切替の経路が機能することまで含めて検証する運用を明示する。
- 同期委譲の目安時間を環境依存として注記する。固定数値閾値は定義しない（ユーザー決定〔2026-09-25〕・環境依存のため数値断定はしない）。
