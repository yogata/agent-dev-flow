# copyTree 型再帰コピーの skip 判定は root 起点の相対パスで行う

## 背景

Case #3236（PR #3238、TS-005 配布検査の fix）で、`copyTree` 型の再帰コピー実装の skip 判定が再帰先基準の相対パスで計算され、除外プレフィックス（`tests/`、`vendor/` 等）との比較が壊れるバグを検出・修正した。修正と回帰テストは完了しているが、再帰列挙実装全般に適用できる判断基準としての知識化が未実施である。

## 問題

再帰コピー・再帰列挙の実装で `path.relative` を各再帰レベルで計算すると、skip 判定のプレフィックス比較が再帰先ディレクトリ基準の相対パスになり、root 起点の除外指定（`tests/`、`vendor/` 等）と一致しない。またディレクトリ自体（末尾スラッシュなしの名前）が skip 判定に含まれていない場合も残留の原因になる。従来の `tests/` 除外は fixture に test ファイルが残留していても検査が壊れないため潜在化していた（TS-005 テスト実行時の初回 4 fail で検出）。

## 望ましい変更

再帰コピー・再帰列挙では相対パスを再帰レベルごとに計算せず、root 起点の相対パスを伝播させる。skip 判定はファイル・ディレクトリ両形式を扱う。この判断基準を docs/knowledge/ の知識文書として保存する。

## 元learning item / 根拠

- **要約**: copyTree 型再帰コピーの skip 判定は root 起点の相対パスで行う（各再帰レベル計算は壊れる）。skip 判定はファイル・ディレクトリ両形式を扱う
- **根拠**: `path.relative` を各再帰レベルで計算すると除外プレフィックス比較が再帰先基準になり `tests/`、`vendor/` と一致しない。ディレクトリ自体（末尾スラッシュなし）も skip 対象に含めていなかった。root 起点相対パス伝播方式へ修正しディレクトリ自体の除外を追加（commit ba6bc9bb、最終 HEAD で 8 pass / 0 fail 再確認）
- **再発条件**: copyTree 型の再帰コピーで exclude プレフィックス判定を各再帰レベルの相対パスで行った場合
- **横展開可能性**: 再帰列挙・再帰コピーを含む util 実装全般（TypeScript に限らない一般パターン）
