# grep 0 件基準の機械検査と旧語の字面引用の衝突を避ける執筆規約

## 背景

2 事例が同一問題クラスとして観測された:

1. v4 移行再編（Case #2979）で 4 Design の参照張替えを行う際、「v4-lifecycle-state-machine（旧 workflow-contracts「X」節を吸収）」「case-open / case-ready Design（definition-readiness 後継）」形式の注記を本文へ残したところ、TS-004 の「4 Design ファイル名 grep 0 件」検査が旧名に引っかかり 0 件にならなかった
2. 横断是正（2026-08-15・PR #2111 系）で、禁止対象の旧表現の字面をそのまま引用した禁止注記が、完了条件の再 grep で hit し「旧表現 0 件」基準と衝突した

## 問題

是正注記・「後継」注記・旧→新対応表のいずれも、旧語の字面を本文に残すため、「旧名（旧表現）が 0 件であること」を要求する grep 0 件基準の完了条件・機械検査と構造的に衝突する。この衝突は執筆時点で予見可能であり、検査設計や exemption で事後解消するより執筆規約で予防する方が低コストである。本 repo は grep 0 件基準の完了条件（TS-004 型・再 grep 0 件確認等）を多用するため再発可能性が高い。

## 望ましい変更

docs/knowledge/ への知識文書として、次の執筆規約を確立する:

1. 旧表現を禁止する是正注記は、禁止対象の字面を引用せず描写形（「X を権威情報源とする旧表現」等）で書く
2. 削除・RETIRE・supersede を伴う参照張替えでは、「旧〜の後継」形式の注記を本文に残さず、対応関係は正本（crosswalk・処遇記録）へ集約して本文は正本参照のみを持つ
3. 歴史参照テーブル（旧→新行対応表等）の旧行 ID・旧名は code span 等、検査の対象外形式で記録する
4. grep 0 件基準の完了条件を持つ Case では、注記・対応表を含む全体 grep を case-run と case-close の両方で実施する

## 対象範囲

### 対象

- 横断是正・用語統一・Design 削除（RETIRE/supersede）・参照張替えを伴う変更の執筆場面
- grep 0 件基準の完了条件・機械検査を持つ Case の検証手順

### 対象外

- 検査側（grep 0 件基準・IR）の実装変更（exemption 設計は別議論）

## 制約

- 対応関係の正本（crosswalk・処遇記録）が存在しない変更では、正本を先に確定してから本文の旧名を排除する（Case #2979 の教訓: 正本がある以上、本文は後継名のみを持つべき）
- 履歴文書の正当クラス（DEC superseded 本文・crosswalk 処遇行等）は削除対象ではない（検査側の正当クラス分類と整合させる）
- 知識文書の新設は backlog-review の利用者承認経由で行う

## 受け入れ条件

- [ ] 旧語の字面を本文に残さない執筆規約（描写形・正本集約・code span）が知識として参照可能であること
- [ ] grep 0 件基準の完了条件を持つ Case での全体 grep 実施（case-run・case-close 両方）が規約に含まれること
- [ ] 正当クラス（履歴文書）の扱いが規約と検査側の分類と矛盾しないこと
