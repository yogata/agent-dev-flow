# 契約テストが固定する配布物トークンと本文編集・完了判定の相互作用の手順化（spec 候補）

## 背景

配布物構造を固定する契約テストと、本文編集・完了条件設計の相互作用で2件の手戻りが発生した（相補ペア。両エントリが相互参照で関係を明示）:

1. **実行時手順側**: case-run Step 7-1 の手続本体圧縮（thin 化）時に、`distribution_boundary_routing_contract.test.ts` が detector entrypoint と `--profile source` を公開契約トークンとして固定していることを踏まえず圧縮し、テスト4件を一時失敗させた（PR 2117 / Issue 2107）
2. **完了条件設計側**: 構造変更（thin 化）を伴う PR の完了条件に「固定する契約テストの期待値更新」が含まれず、並列 Wave で更新が一部だけ行われ、統合状態で陳腐化期待値 24 件 fail として顕在化。Epic 差し戻しに直結した（PR #2118 / Issue #2108、OU-002〜004）

## 問題

契約テストが配布物本文のトークン・期待値を固定していることを、(a) 編集時（圧縮・リライト前の固定トークン確認）と (b) 完了条件設計時（期待値更新の明示的包含）の両面で考慮する手順が存在しない。並列 Wave では他 Wave の更新状況が見えず、部分的実施が検出できない。

## 望ましい変更

1. 本文圧縮・機械的リライトの前に、当該ファイル名・セクション名を参照する `*.test.ts` の grep 確認を thin 化手順に組み込む（固定トークン特定 → 圧縮 → テストの順序）
2. 構造変更 PR の完了条件テンプレート・ガイドラインに「当該構造を固定する契約テスト（`*.test.ts`）の期待値更新」を明示的に含める

## 対象範囲

### 対象

- thin 化・圧縮・機械的リライトを行う手順（case-run の手続本体圧縮、docs 是正等）
- 構造変更 PR の完了条件記載ガイドライン（case-open）

### 対象外

- 契約テスト自体の設計変更・削減
- 期待値の自動追従化（テスト実装の改修は別件）

## 元learning item / 根拠

- **要約**: 契約テストが固定するトークン・期待値と、本文編集・完了判定の相互作用の手順不在で、テスト一時失敗と Epic 差し戻し（陳腐化期待値 24 件）が発生
- **根拠**: PR 2117（routing contract テスト4件一時失敗、トークン復元で解消、最終 24/24 pass）、PR #2118（OU-003/004 の期待値未更新が統合で顕在化、差し戻し後 fix で解消）
- **再発条件**: 契約テストが本文トークン・期待値を固定する領域を機械的圧縮・構造変更する PR を、期待値更新なしで完了判定した場合（特に並列 Wave）
- **横展開可能性**: 高い。契約テストを持つプロジェクト・並列 Wave 構成全般
