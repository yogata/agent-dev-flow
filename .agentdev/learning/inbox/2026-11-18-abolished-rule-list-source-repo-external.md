# 廃止32 IR ルールの個別列挙の正が repo 内に存在せず、制約充足解から導出した

- 問題事象: 実行指示書に列挙された廃止32 IR ルールの個別ファイル名の正が repo 内に存在せず（実行指示書は repo 外の文書）、実装と検証がカテゴリ定義（A 旧世代監視9・B 記述スタイル過剰介入13・C 禁止用語・散文品質・残骸監視10）と残存24の内訳という制約から列挙を導出する必要があった
- 発生局面: case-run の REQ-122-001 実装・検証（Issue 4153・PR 4157）
- 検知方法: 実装側で廃止32の個別ファイル名を機械照合可能な正規列挙（repo 内参照）として解決できる箇所が存在しないことの確認
- 根本原因: 列挙の正を実行指示書（repo 外文書）に置く要件（AG-001・DEC-065 決定1）が、repo 内に機械照合可能な列挙または導出根拠を保持しておらず、判定根拠が恒久的に repo 外に依存する構造になっている
- 自律対応内容: カテゴリ定義・内訳・DEC-065 の明示（IR-016/068/055/059 残存・IR-072/073 廃止）・AG-013 の IR-024 存続参照から制約充足解として32ファイルを導出し、PR 本文へ導出根拠を記録。検証で廃止32＋残存24＝56 の過不足なしなしを機械確認（PR changed files 突合・worktree 実在確認）
- ユーザー確認有無: なし（実行指示書の列挙内容自体は受理済み合意であり、導出結果の妥当性は機械照合で立証）
- Decision/REQ/spec 影響: REQ-122-001、DEC-065 決定1、AG-001
- 横展開観点: 列挙の正が repo 外にある実行指示・合意文書を扱う場合、repo 内に導出根拠（制約と照合方法）と機械照合結果（過不足なし確認）を記録しておくと、後続 Wave や将来の検証が機械照合で再現できる。判定根拠の所在が要件行・検証列に集約される運用と相性がよい
- 再発条件: 実行指示書や外部合意文書を列挙の正とする要件を実装・検証する場合
- 予防策候補: 列挙の正を repo 外文書に置く場合、実装単位の PR 本文へ導出根拠と機械照合結果の記録を義務化する。または列挙の正を repo 内の正規文書（REQ 検証列・Decision 付録等）へ投影する
- 想定反映先: REQ-122-001 の検証運用（Wave-4 の最終検証で Phase 1〜4 のコミット存在と列挙整合を再確認する際）、実行指示書由来の実装単位の記録様式
- 関連: Case 4150、Issue 4153、PR 4157、DEC-065
- タグ: 実行指示書、列挙の正、制約充足解、機械照合、repo 外文書
