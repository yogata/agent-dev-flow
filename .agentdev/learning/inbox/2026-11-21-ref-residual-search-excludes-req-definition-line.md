# 完了条件の参照残存検索で REQ 本体の定義行（撤去対象モジュール名を列挙する行）を stale reference 除外として解釈した

- 問題事象: 解体系 REQ の完了条件「撤去モジュール名の参照残存 0 件」検索（rg/git grep）は、撤去対象モジュール名を列挙している REQ 本体の定義行（REQ-123.md REQ-123-001 行）自体にヒットする。REQ は実行担当が編集不可の既確定文書であり、ヒットしたままだと合格条件「参照残存 0 件」が機械的に達成できない
- 発生局面: case-run（PR #4173・Wave-1 #4169）TS-001.2 参照残存検索の合格判定
- 検知方法: 検索実行時のヒット行の内容点検。残存ヒットが REQ-123.md 定義行（撤去命令の記述自体）と docs/reports/（完了条件の網羅範囲外と本文に明記済み）のみであることを確認
- 根本原因: 完了条件の検索合格条件は「dangling 参照（削除済み資産への参照）の不在」を意味意図とするが、検索パターンは字面一致のため、撤去命令そのものを記述する REQ 定義行にも一致する。REQ の定義行は dangling 参照ではなく撤去命令の記述である
- 自律対応内容: 定義行と docs/reports/ を stale reference ではないと解釈し、PR 本文 Findings に判断根拠を記録した上で合格判定した。REQ 本体・完了条件文言は一切変更していない
- ユーザー確認有無: なし（実行担当の解釈判断・根拠記録のみ。case-close QG-4 で Findings の根拠記録を確認のうえ受理）
- 横展開観点: 同種の解体系 REQ（モジュール撤去・資産廃止系）の実行では、検索合格条件の解釈をこの基準で統一すべき。REQ 本体の定義行・廃止理由記述行は stale reference の計上対象から除外し、docs/reports/ 等の網羅範囲外領域も完了条件文言に従って除外する
- 再発条件: REQ 行の完了条件に「〜の参照残存 0 件」型の検索合格条件があり、当該 REQ 本体自身が撤去対象名を列挙する場合
 - 予防策候補: (a) 要件doc の検索合格条件に「REQ 本体の定義行・網羅範囲外領域を除外」の解釈注記を事前に含める、(b) 実行担当の Findings での根拠記録を必須化し case-close で確認する運用の明文化
 - 想定反映先: req-define（検索型合格条件の要件doc作成時ガイダンス）、case-run（参照残存検索の合格判定基準）
 - 関連: Case #4167、PR #4173（Findings に判断根拠記録済み）、REQ-123-001・TS-001.2
 - タグ: 検索合格条件、REQ 定義行、解釈判断、Findings 記録
