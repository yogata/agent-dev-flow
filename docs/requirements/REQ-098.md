## 目的

ADF ローカルの docs/** への変更と、ADF が GitHub へ書き込む文章（Issue/PR のタイトル・本文、説明・レビュー・完了コメント）に対し、yomiyasu による推敲・同梱 lint の実行・指摘確認を ADF の工程上必須とする。
文章表層品質の機械検査は REQ-053 が、Markdown の日本語表現と用語選択の基準は REQ-094 が、third-party Skill（yomiyasu を含む）の運用前提と導入検知は REQ-097 がそれぞれ現行どおり所有し、本要件は推敲の工程適用契約を新規に所有する。適用済み判定手順、適用の記録様式、実現方式、Python 実行詳細は project-extensions.md（yomiyasu 推敲の工程必須化節）が design 被覆する。

## 要件

| ID | 要件 |
|---|---|
| REQ-098-001 | docs/** の日本語文章を変更する工程は、変更する文章と周辺文脈を yomiyasu で推敲すること。推敲は編集前に yomiyasu を読み込んだ後、内容の変更が揃った時点で行い、同梱 lint を実行して指摘を確認してから提出すること。編集単位ごとの推敲と既存文書全体への一括推敲は要求しないこと |
| REQ-098-002 | Definition PR と実装 PR の両方を適用対象とすること。case-open は Definition 文章の編集前読込と提出前の推敲・lint、case-ready は Definition PR のマージ前に適用を確認し不足時はマージを行わず対象文章の修正へ差し戻すこと。case-run は実装に伴う docs 変更への適用、case-close は実装 PR のマージ前に適用を確認し不足時は case-run へ差し戻すこと。case-revise を含む Definition 変更の例外経路も対象から漏らさないこと |
| REQ-098-003 | ADF が作成・更新する Issue/PR のタイトル・本文と、説明・レビュー・完了の各コメントは GitHub への書込み前に推敲すること。本文は同梱 lint を実行して指摘を確認した後に agentdev_gh へ渡すこと。タイトルも推敲対象とするが、本文向けの文長・箇条書き比率をタイトルの合否条件にしないこと。書込み後の VERIFY は現行契約を維持すること |
| REQ-098-004 | Issue/PR の更新では変更する文章と周辺文脈を対象とし、他者の文章・引用・ログを無断でリライトしないこと。ラベル・状態・チェックボックスのみの変更に再推敲を要求しないこと |
| REQ-098-005 | GitHub への書込みを持つ Workflow とその実委譲先を調査して列挙し、暗黙の伝播を仮定せず、呼出経路ごとに適用を定義すること |
| REQ-098-006 | 推敲は要件の必須性、条件、責任主体、数値、否定条件を保持すること。識別子、リンク、コード、引用、固定テンプレート、表構造、AUTOGEN 部分を保護すること。既存の用語辞書と文書契約を優先し、曖昧な主体を推測で補わないこと。箇条書きの削減と否定対比の肯定化を機械的に適用しないこと |
| REQ-098-008 | yomiyasu 未導入または lint の実行失敗の場合は、対象文章の提出・投稿・マージを停止すること。適用確認は最後の文章変更の後に行うこと。再開時は既存 PR 等の記録と現在の差分から適用の有無を判定できること。親セッションが yomiyasu を読み込んだ事実のみを根拠に委譲先の適用を省略しないこと |
| REQ-098-010 | req-define 自身の適用は .agentdev/drafts/** に限定した編集スコープの現行契約を維持し、入口が req-define であることを理由に docs への書込み義務や draft への推敲義務を追加しないこと |
| REQ-098-011 | 本要件による必須化は対応する project extension が有効な場合の ADF 工程上の必須化であり、extension 不在時の継続と malformed 時の fail-open を定める現行契約（REQ-002-031）を変更しないこと。全書込みに対する機械的強制は保証しないこと |
| REQ-098-014 | 適用の実行にあたり、既存の ADF-COVERS 宣言、固定見出し、成果物配置契約、書込み guard、UTF-8/LF 保持の各規律を維持すること |

## 適用範囲

- 対象: docs/** の日本語文章の変更、ADF が作成・更新する GitHub 上の文章（Issue/PR のタイトル・本文、説明・レビュー・完了コメント）、内部 lifecycle 各工程（case-open、case-ready、case-run、case-close、case-revise）における適用とマージ前確認
- 対象外: consumer 全体への配布、過去の docs・Issue・PR の一括リライト、draft（.agentdev/drafts/**）への適用拡大、ハーネスの全書込み拒否、extension の fail-open 契約の変更（REQ-002-031 維持）、yomiyasu 本体の改変、新しい GitHub 投稿ゲートや依存の追加、REQ-053 が所有する textlint 機械検査の契約変更
- 各工程への具体配置と extension 記述の詳細は Design（docs/designs/foundations/project-extensions.md「yomiyasu 推敲の工程必須化」節）に従う
