## 目的

Case実行で作成される検証用一時資材を正式な成果物と役割で区別し、作成から回収までの登録・追跡の契約を所有する。検証用remote、clone、bare repository、退避ログ、補助スクリプト、専用server・process等がCaseやEpicの終了後に残存する状態を排除する。
完了判定工程での照合・拒否・全終了経路の強制はcase-close実行契約（REQ-032）が、worktree構造上の一時ファイル配置分類はworktree構造的制約REQ（REQ-018）が、検証証跡の必須要素と保存様式の一般契約は完了報告と成果物品質ゲートREQ（REQ-007）とCase Issue工程記録モデルREQ（REQ-101）が所有する。本REQはこれらと重複する要件行を持たず、一時資材の登録と回収のライフサイクル契約に限定する。

## 要件

| ID | 要件 |
|---|---|
| REQ-118-001 | ADFの作成・委譲入口は、Case実行で作成する一時資材の案件・種別・所在・識別情報・回収担当を実行処理の記録として登録すること。PR本文への自由文自己申告と終了時のLLM抽出のみで登録を代替しないこと（AG-002） |
| REQ-118-002 | 一時資材の登録は親・子・共通の所有区分を持つこと。子Issueの完了後も親または共通の一時資材が残る場合は全体（親の管理する終了単位）を未完了として扱うこと（AG-002） |
| REQ-118-003 | 正式な成果物（実装、テストコード、必要なテストデータ・期待結果・環境再現スクリプト、正式な手順文書）は対象repoに登録して維持し、テスト実行で生成したデータ、clone、検証用remote、ログ、専用process等は一時資材として回収対象に分類すること。拡張子、testという名前、git追跡済みという事実だけで分類しないこと（AG-001） |
| REQ-118-004 | 一時資材は案件スコープの専用領域へ配置すること。専用領域の運用と実行可能な作成経路の制限を接続し、任意のshell/Python/native/OpenCode子processを自由に実行させたまま引数のpattern検査だけで全作成物の捕捉を主張しないこと（AG-003） |
| REQ-118-005 | 未登録・範囲外の一時資材の作成を機械検出または実行制限すること。機械検出も実行制限も成立しない作成経路が残る場合は未達として報告し、解消されない限り完了扱いとしないこと。申告された集合だけの検査を成立扱いにしないこと（AG-003） |
| REQ-118-006 | 一時資材の削除は、利用者の削除確認と対象の正確な識別情報（所在、種別、内容の識別。同名別物、PID再利用、symlink/junctionの参照先を含む）との対応が確認できた場合だけ実行すること。確認なし、対象の追加変更後、別物への入替え時は削除しないこと。実行担当が生成したapproval等の機械可読値だけを利用者確認として扱わないこと。確認済み識別情報との対応を残置許容の例外として流用しないこと（AG-005） |
| REQ-118-007 | 検証の必要な結果（入力、対象版、操作、実結果、失敗、訂正、判定理由）は本体Issue/PRへ保存し、回収した一時資材へのアクセスなしで読み戻して理解できること。全生ログ、環境一式、Git bundleを別保管庫へ移して恒久保持する方式を採らないこと。機械判定のためにローカル生ログの永久保持を要求しないこと（AG-004） |
| REQ-118-008 | 一時資材の生成記録が空の場合、作成物が存在しないことと生成記録が欠落していることを区別して扱うこと。区別できない空の生成記録を作成物なしの根拠にしないこと（AG-007） |
| REQ-118-009 | 一時資材の登録・追跡に使う記録自体も一時資材とし、終了時の回収対象に含めること。保存すべき最終記録は本体Issue/PRへ収束させること（AG-008） |

## 適用範囲

- 対象: ADFの作成・委譲入口（case-open、case-runの実行委譲を含む）における一時資材の登録、正式成果物と一時資材の役割分類、案件スコープ専用領域、未登録・範囲外作成の機械検出・実行制限、削除確認と識別情報の対応、証跡の本体Issue/PR保存と読み戻し、生成記録の空状態区別、登録・追跡記録自体の回収
- 対象外: 完了判定工程での照合・拒否・全終了経路の強制の規範所有（case-close実行契約 REQ-032 が維持する。本REQは新設の要件行により REQ-032・REQ-052 への行追加で接続し、既存要件行の変更と規範所有の移動は対象外のまま。ただし当該機構の実装拡張——case-close機械工程の照合と終了判定記録の書出し、agentdev_gh issue_close の終了前提検証、作成ヘルパーと台帳、および対応する正式テスト——は本REQの要件行に基づく実装対象であり対象外としない）、worktree構造上の一時ファイル配置分類とworktree削除手順（worktree構造的制約 REQ-018）、検証証跡の必須要素と保存様式の一般契約（REQ-007、REQ-101）、未追跡残存の恒常checkerと承認一覧（自己監査コマンド REQ-010、IR-073）、Hermes固有のtool実行基盤・ToDo・Goal・自由文完了報告の配信前判定・既定profileの監督スキル（監督側で別に是正）、新規サービスの構築と常時監視、今回の旧検証資材の個別削除実行（利用者の明示確認後の監督側対応）
