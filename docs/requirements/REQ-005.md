## 目的

AgentDevFlow 開発ワークフローのマクロフェーズ構成、フェーズ間の SSoT（唯一の情報源）遷移、work_type と scale による工程分類、command 間の接続契約、宣言的定義とコマンド固有手続きの責務分界を定義する。
本 REQ は工程接続のプロトコル層を所有し、個別 command の実行オーケストレーション（Issue/PR/Case 実行、Epic/Wave 制御）は REQ-006 が所有する。

## 要件

| ID | 要件 |
|---|---|
| REQ-005-001 | ワークフローは壁打ち、構造的実行、レビュー完了の3つのマクロフェーズで構成すること |
| REQ-005-002 | 各マクロフェーズは入力 SSoT と出力 SSoT を明示すること |
| REQ-005-003 | フェーズ境界を跨ぐ場合、次フェーズが参照する成果物へ情報を永続化すること |
| REQ-005-004 | ワークフロー実行中のエラー回復はデータ損失を伴わないこと |
| REQ-005-005 | ワークフローを work_type（bugfix、feature、maintenance、docs_chore）と scale（feature のみ standard、large）で分類すること |
| REQ-005-006 | workflow_route は work_type と scale から派生する値とし、永続化対象から除外すること |
| REQ-005-007 | work_type が bugfix、maintenance、docs_chore の場合、新規 REQ 作成を要求せず Issue 本文で要件を管理すること |
| REQ-005-008 | work_type が feature の場合、現行 REQ と SPEC が現行状態に保たれること |
| REQ-005-009 | work_type 由来の label と template metadata が矛盾する場合、コマンドは停止して確認を求めること |
| REQ-005-010 | 全公開 command は主フロー、最大自走入口、補助フロー、検出フロー、repo-local 検査のいずれかに分類すること |
| REQ-005-011 | 最大自走入口は標準フローを置換せず、追加入口として位置づけること |
| REQ-005-012 | workflow-lifecycle は宣言的定義（ライフサイクル判定、work_type 判定、scale 判定、SSoT 遷移、上位への引き継ぎ判定）のみを提供し、コマンド固有手続きを含まないこと |
| REQ-005-013 | コマンド固有手続きは目的別スキル（Issue 操作手順、intake 抽出と振り分け、backlog 統合、REQ 構造診断）が分担して保持すること |
| REQ-005-014 | workflow-lifecycle の宣言（提供範囲と除外範囲）と実体は一致すること |
| REQ-005-015 | 上位への引き継ぎ共通方針はライフサイクル判定の一部として workflow-lifecycle スキルに属すること |
| REQ-005-016 | AgentDevFlow 適用プロジェクトでは AgentDevFlow 本体、配布 command、配布 skill、配布 template、配布 script を上位への引き継ぎ対象として扱うこと |
| REQ-005-017 | AgentDevFlow 適用プロジェクトで AgentDevFlow 本体の不具合または改善点を発見した場合、現在プロジェクトでは適用せず、上位への引き継ぎ用 RU として整理すること |
| REQ-005-018 | agent-dev-flow 本体リポジトリでは AgentDevFlow 本体が現在プロジェクトの成果物であり、通常の req/case workflow で改修対象にできること |
| REQ-005-019 | `agentdev_handoff: true` は AgentDevFlow 本体向けの引き継ぎ標識とし、通常 RU または要件doc の必須 frontmatter ではないこと |
| REQ-005-020 | 通常 RU には `agentdev_handoff` を記載せず、`agentdev_handoff: false` も記載しないこと |
| REQ-005-021 | 導入先リポジトリで要件doc、RU、Issue 本文に `agentdev_handoff: true` を検出した場合、コマンドは停止して agent-dev-flow repository への手動取り込み対象として報告すること |
| REQ-005-022 | agent-dev-flow 本体リポジトリでは `agentdev_handoff: true` を停止条件とせず、取り込み元の履歴メタデータとして扱い、通常の req/case workflow 入力として処理すること |
| REQ-005-023 | workflow-lifecycle の reference に SPEC 相当の詳細記述が含まれる場合、当該記述は `docs/specs/` へ配置し、実行時の command と skill は自己完結すること |

## 適用範囲

- **対象**:
  - ワークフロー3マクロフェーズ構成と SSoT 遷移、エラー回復のデータ保全
  - work_type と scale による工程分類、workflow_route の派生と非永続化、label と template の矛盾停止条件
  - 公開 command の分類（主フロー、最大自走入口、補助フロー、検出フロー、repo-local 検査）と最大自走入口の位置づけ
  - workflow-lifecycle の宣言的定義責務、コマンド固有手続きの目的別スキル分担、宣言と実体の一致
  - 上位への引き継ぎワークフロー規約、`agentdev_handoff: true` メタデータ意味論、導入先と本体リポジトリの停止条件の違い
  - workflow-lifecycle reference と SPEC の配置境界
- **対象外**:
  - 個別 command（case-open、case-run、case-close、case-update、case-auto）の内部実行手順と I/O 詳細（REQ-006）
  - Issue、PR、Case 実行オーケストレーション、Epic と Wave 制御、execution_unit 並列実行モデル（REQ-006）
  - draft、RU、要件doc の構造化契約と lifecycle（REQ-008）
  - workflow_route 派生ルールの詳細マッピング表、draft-meta の field 別格納可否一覧（SPEC）
  - 各 command の公開 API、入出力、Guardrails 詳細（SPEC）
  - REQ と SPEC の責務分離の一般原則、文書種別配置基準（REQ-001）
