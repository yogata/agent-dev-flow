## 目的

Custom Tool agentdev_gh の起票（issue_create）・読取補完操作を、受理フィールドの操作・role 別差異による初回失敗なしに使用するための呼出側規律を運用文書へ明記する。

agentdev_gh の受理フィールドは操作・role 別に異なる。role: case では kind が不受理（kind requires role 'tracking'）であり、Case Issue の work_type は物理ラベル（bug、maintenance、enhancement 等）を labels へ指定する運用である。Case Issue は "case" ラベルを持たないため、gh issue list --label case 等のラベルフィルタは機能しない。

Tool 側の入力契約は受理仕様が REQ-011-028、失敗分類が REQ-011-029 がそれぞれ所有し、issue_list のサーバ側絞り込み推送契約は REQ-011-033 が所有する。物理ラベル写像の機械適用は Tool 内実装（REQ-049-008）が所有する。本 REQ は呼出側の運用規律のみを所有し、Tool 実装・操作契約の変更を要求しない。

## 要件

| ID | 要件 |
|---|---|
| REQ-095-001 | agentdev_gh の起票・読取操作の呼出側は、操作・role 別の受理フィールド対応表（role は issue_create/issue_list 専用、kind は role 'tracking' 専用で role: case では不受理、Case Issue の work_type は物理ラベルを labels へ指定）を運用文書（配布 skill reference issue-operation-safety.md、agentdev-issue-tracking SKILL.md）から参照できること |
| REQ-095-002 | gh CLI による読取補完は、ラベルなし列挙＋タイトル・本文確認で行う規律を運用文書から参照できること（Case Issue は "case" ラベルを持たずラベルフィルタが機能しないため） |
| REQ-095-003 | issue_list の server-side search 利用時は、ハイフン入り識別子等のトークン正規化不一致による偽陰性の可能性を考慮し、空の検索結果応答を対象 Issue の不存在の証拠としないこと。重複起票判定ではフィルタを外した一覧取得で再確認できる手段を要求すること（使用手順の詳細は配布 skill reference issue-operation-safety.md が所有） |

## 適用範囲

- **対象**: agentdev_gh の起票（issue_create）・読取補完操作の呼出側運用規律とその運用文書への明記
- **対象外**: agentdev_gh の入力契約・操作契約自体の変更（REQ-011-033）、物理ラベル写像の Tool 内実装の変更（REQ-049-008）、issue_list 使用手順の詳細（issue-operation-safety.md 所有。旧 REQ-092 から分離済み）、REQ-093 が所有する起動環境障害の予防・診断・回復、REQ-049 が所有する追跡Issue論理スキーマ
