## 目的

ADF の6系統 Workflow の意味判断に typesafe/Jev による先行評価を逐次経路で組み込み、Jev と LLM 最終判断の関係を実運用で観測可能にすること。Jev は最終判断者ではなく、後段の LLM 推論への追加情報として扱うこと。本要件は観測可能化（Stage 1 / Issue A）までを対象とし、有効性の最終結論（Issue B）と LLM 推論の Jev 置換（Issue C）を含まないこと。

## 要件

| ID | 要件 |
|---|---|
| REQ-090-001 | ADF は Jev 先行評価を提供する Custom Tool を備えること。Tool の公開契約は provider・SDK のいずれにも依存せず、初期実装の Vercel AI Gateway 接続（model ID typesafe-ai/jev、credential AI_GATEWAY_API_KEY）は adapter 内部実装として隠蔽し、SDK 固有の名称・型・格納位置を Workflow 層と公開スキーマへ漏らさないこと。Tool は API 呼出し、入出力形式の検証、provider・接続設定の解決、結果・確率分布・確実性の正規化、呼出し失敗の構造化、機械的処理時間の計測を担い、判断対象の意味、評価基準、Jev を呼ぶべき箇所、最終判断を所有しないこと。質問型と boolean/choice/score の対応づけは adapter mapping であり意味契約の変更としないこと。 |
| REQ-090-002 | Jev 先行評価はデフォルトで有効であり、feature flag や opt-in 手続きを必要としないこと。利用可否は AI_GATEWAY_API_KEY の設定有無で決まること。API key 未設定時は Jev を呼び出さず従来 LLM 経路のみで Workflow を完了させ、未設定を Jev API 失敗に含めず、観測上 not_configured に相当する区分として記録すること。 |
| REQ-090-003 | Jev API 呼出し後の失敗（timeout、429、5xx、network error、response validation error 等）に対して自動 retry を行わず即座に従来 LLM 経路へ fallback し、失敗分類を観測として記録すること。観測 JSON の保存のみに失敗した場合、Workflow は success とし、正規成果物を有効とし、rollback・再実行・擬似再生成を行わず、完了報告で識別可能な warning として通知すること。Jev 経路の障害によって既存 ADF の正規状態を破損しないこと。 |
| REQ-090-004 | learning-promote、req-define、Epic/Wave 構成判断、intake-promote、inspect-promote、backlog-review の6系統 Workflow は、閉じた意味判断ごとに「Jev 先行評価 → Jev 結果と confidence を情報として含む LLM 推論 → LLM による最終判断 → unchanged/corrected の記録」の逐次経路を実行できること。LLM 推論は Jev 結果だけでなく従来の判断材料も参照して最終判断すること。判断単位と質問形式の割当ては各 Workflow/Capability Skill が所有し、その初期割当て（適用対象19件）と適用可否を本 Case 内で確定する3件の判断結論を該当 Workflow の reference へ文書化すること。Jev へ渡す state は Workflow が構成した閉じた判断入力とし、候補探索用の repository 全文を渡さないこと。 |
| REQ-090-005 | Jev 判断ごとに、Jev 結果、候補別確率分布、confidence、LLM 最終判断、llm_treatment（unchanged/corrected）を観測として記録できること。confidence と llm_treatment は独立した一次観測値として保存し、観測時に confidence 閾値を固定しないこと。unchanged は LLM が判断を変更しなかったという観測事実とし、評価カテゴリを混入させないこと。初期 Vercel adapter では inputTokens を取得して記録すること。 |
| REQ-090-006 | 観測記録は .agentdev/jev-observations/ を正式な永続 domain state（git 管理対象）として保存先とし、1 Workflow 実行につき 1 JSON ファイルとして保存すること（1実行の複数 Jev 判断は同一 JSON 内に格納し、JSONL は正本としない）。観測必須項目は provider、requested model、source revision、Workflow と判断種別、判断対象の最小識別情報、Jev 結果、候補別確率分布、confidence、LLM 最終判断、llm_treatment、outcome、Jev 呼出し時間とすること（resolved model は provider が返せる場合のみ、inputTokens は初期 Vercel adapter で記録）。観測入力は再構成可能な入力について判断入力全文を保存せず参照と request/input digest で保持し、再構成不能な入力のみ最小 input_snapshot として保存すること。観測記録は Workflow の正規状態と混在しないこと。観測 JSON の filename、個別 field 名、snapshot 物理表現は実装設計時の自由度として合意済みであり、本項の意味契約を変更しない範囲で定めること。 |
| REQ-090-007 | Epic/Wave 構成の正規判断所有者は case-ready であり、docs/designs/workflows/references/execution-unit-construction.md 内の旧 case-open 所有表現（6箇所）および docs/designs/README.md 横断 Design 一覧の当該行が case-ready 実行契約へ整合して更新されていること。 |
| REQ-090-008 | Jev 実装開始直前の最新 main に v4.0.2 tag が存在すること。Jev を無効化した場合（API key 未設定を含む）、既存 Workflow の挙動を基準点時点と同等に維持できること。 |
| REQ-090-009 | Jev 導入のために、投機実行、background LLM 化、rollback 機構、投機状態管理、Jev 専用の durable state、汎用意味判断基盤、汎用依存グラフ基盤、汎用 provenance graph、汎用 replay engine、Jev 専用サブエージェントを新設しないこと。 |
| REQ-090-010 | 既存 Command / Workflow Skill / Capability Skill の責務境界を維持すること。Custom Tool は機械処理のみを担い、判断の意味・基準・Jev 呼出し位置・LLM 最終判断は Workflow/Capability Skill が所有すること。Command は公開契約上必要な範囲のみを更新し、Jev 固有の手順を不必要に重複記述しないこと。 |

## 適用範囲

### 対象
- Jev 先行評価 Custom Tool（provider・SDK 非依存の公開契約、初期 Vercel adapter、失敗の構造化、confidence 正規化）
- 6系統 Workflow（learning-promote、req-define、Epic/Wave 構成判断、intake-promote、inspect-promote、backlog-review）への逐次経路追加
- 観測 domain state .agentdev/jev-observations/（1実行1 JSON、必須観測項目、入力再構成）
- Epic/Wave 所有表現の case-ready 整合修正（execution-unit-construction.md、docs/designs/README.md）
- v4.0.2 tag 基準点の作成
- REQ-089 欠番に伴う採番整合（欠番記録3ファイル、採番スクリプトの最小修正、新規 REQ は REQ-090）

### 対象外
- Jev 有効性の最終結論（Issue B: 一定量観測後の評価）
- LLM 推論の Jev 置換（Issue C: confidence 閾値に基づく最終判断の置換）
- 投機実行、background LLM 化、rollback 機構、投機状態管理
- 汎用意味判断基盤、汎用依存グラフ基盤、汎用 provenance graph、汎用 replay engine の新設
- opencode.db を使った本格分析
- Jev だけを理由とする独自外部送信制限の新設
- 観測 JSON の filename、個別 field 名、snapshot 物理表現などの具体 schema 規定（実装設計時の自由度として合意済み）
- 課金開始後の実験継続条件の判断（本 Case の失敗条件としない）
