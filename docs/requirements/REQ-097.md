## 目的

third-party 成果物（Skill 形式と package 形式）の包括定義と、宣言された third-party Skill を全環境で導入済みとする運用前提契約を所有する。取得機構の実行面（OpenCode セッションと LLM 不要の一括実行面）、宣言ファイルの配置と解決（本体管理と consumer 管理）、導入系スクリプトによる drift 検知と案内の責務を確定する。
third-party Skill の所有区分（第三区分）は REQ-002-042〜044 が、配布依存境界としての解決は REQ-029-009/012 が、導入系スクリプトの network access 禁止と取得不実施は REQ-009-046/050 が所有し、本 REQ はそれらを維持した上で運用前提の契約を所有する。

## 要件

| ID | 要件 |
|---|---|
| REQ-097-001 | third-party 成果物を Skill 形式（宣言の正は skills.yaml、取得機構による解決、配置先はホスト別に third-party-skill-management.md が所有）と package 形式（宣言の正は版固定情報〔依存宣言と lockfile〕、導入時生成による解決、配置先は plugin 配下の依存成果物領域）の2形態として定義すること。環境ツール（bun、git、gh、OpenCode 自身等）は動作環境であって依存ではないため対象外とすること。包括定義の正は third-party Skill 管理 Design と用語集が担い、README-INSTALL は consumer 向け案内としてこれを引用すること。統一宣言ファイルを作らないこと。通知文書（THIRD-PARTY-NOTICES、REQ-029-013）の通知対象は版固定情報解決する package 形式の依存と解釈すること（Skill 形式の本体は配布物へ含めないため通知を要しない） |
| REQ-097-002 | 宣言された third-party Skill は consumer を含む全環境で導入済みであることを前提とすること。導入系スクリプト（install.ps1、self-sync.ps1、consumer archive installer の3経路）は network access 禁止（REQ-009-046）と取得不実施（REQ-009-050）を維持したまま、宣言ファイルが解決できた環境において宣言と配置の drift（宣言済みで配置欠落）を検知した場合に ERROR 停止し取得手段を案内すること。宣言ファイルが解決できない環境は検査対象外として正常に扱うこと。drift 検知は3経路で同期して追加・維持すること |
| REQ-097-003 | third-party Skill の取得機構は OpenCode セッションを介さない一括実行面（tool package 内 CLI）を持つこと。CLI の dry-run 指定・終了コード等の実行面の詳細は third-party-skill-management.md が所有する。CLI は scripts/ 直下の公開入口（REQ-050-001）に該当せず、公開入口2本の境界は維持すること |
| REQ-097-004 | 宣言ファイルの解決は worktree の src/third-party/skills.yaml（本体管理）を優先し、不在時は .agentdev/third-party/skills.yaml（consumer 管理）へフォールバックすること。取得機構の全実行面（OpenCode セッションの Custom Tool と CLI）は同一の解決を使用し、両候補が不在の場合は fail-closed で停止して案内すること |

## 適用範囲

- **対象**: third-party 成果物の包括定義と文書化（glossary、third-party Skill 管理 Design、README-INSTALL）、取得機構の一括実行面（共通原本側 Tool engine 領域内の agentdev-third-party CLI）、宣言ファイルの2候補解決、導入系3経路（scripts/install.ps1、scripts/self-sync.ps1、scripts/consumer/archive/install.ps1）の drift 検知、最初の実宣言（yomiyasu）と実証
- **対象外**: 環境ツール（bun、git、gh、OpenCode）の検知・宣言・インストール支援、release archive への skills.yaml 収録（consumer は .agentdev/third-party/ で自己宣言するため）、宣言の自動生成・自動取得（REQ-009-050 維持）、Provenance 履歴の拡張、package 形式の新たな検知（既存 textlint vendor 検知のまま）、複数 third-party Skill 運用への拡張（1エントリで機構を固める。2つ目以降は後続要件）、package-release-archive.ps1 への skills.yaml 収録要否検証の新規実装
- **制約**: REQ-009-046（導入系 network access 禁止）、REQ-009-050（導入系の取得不実施）、REQ-002-042〜044（third-party Skill の宣言・取得・配布契約）を維持する。Design「third-party-skill-management.md」の既存節は不変とする。Windows UTF-8 編集規律（per-line string replace、PowerShell リダイレクト禁止）を遵守する。ADF-COVERS 宣言行を編集時に保持する
