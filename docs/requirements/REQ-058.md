## 目的

ADF が管理する投影物（管理対象 junction、Plugin loader shim 等の ADF 生成物）が正本から除外・削除された際に、再同期操作が正本と配置先の一致状態へ収束する共通契約を所有する。
配布基盤と導入モデルは REQ-009 が所有し、scripts 公開入口の境界は REQ-050 が所有する。本 REQ は、正本から消えた管理対象投影物を再同期時に配置先から除去し、正本と配置先を一致状態へ収束させる同期完了条件を所有することで、投影物種別間で不統一だった廃止時処理を共通化し、check が検出した乖離を apply が解消するという操作契約と実際の挙動の一致を保証する。

## 要件

| ID | 要件 |
|---|---|
| REQ-058-001 | 再同期手段は、正本と配置先の ADF 管理対象投影物の対応を、正本に存在し配置先に存在しない追加対象、対応が不正な修復対象、配置先に存在するが正本の管理対象から外れた削除対象へ分類すること |
| REQ-058-002 | 正本から削除された、または配布・投影対象から明示的に除外されたことにより管理対象から外れた ADF 管理投影物は、再同期時に配置先から除去されること |
| REQ-058-003 | 検出モード（check）は管理対象から外れた投影物の乖離を検出・報告するだけで、ファイルシステムを変更しないこと |
| REQ-058-004 | 予測モード（dry-run）は適用モード（apply）が実施する追加、修復、削除を予測表示するだけで、変更しないこと |
| REQ-058-005 | 適用モード（apply）のみが実際の追加、修復、削除を実行すること |
| REQ-058-006 | 適用モードの完了後、同一条件で検出モードを再実行した際に、処理対象となった乖離が残存しないことを同期完了条件とすること。最終 check が正常状態へ収束しない場合は再同期完了と判定しないこと |
| REQ-058-007 | Plugin loader shim 等、ADF が生成・管理し正本側の対象消滅によって不要となる生成物についても、検出、変更予測、適用、完了検証が同一の原則に従うこと |
| REQ-058-008 | ADF 管理対象外の成果物（repo-local 成果物、利用者が独自に作成した成果物、管理物判定が不能な成果物）は、名前や配置場所が近似しているだけでは同期処理による削除対象にしないこと。管理物かどうかを確定できない成果物は自動削除せず、非破壊的に扱うこと |
| REQ-058-009 | 複数の stale 管理投影物が存在する場合、適用モードは対象をすべて処理し、一部だけを残した状態で正常終了しないこと |
| REQ-058-010 | stale 管理投影物が存在しない状態での適用モード再実行は不要な変更を発生させず、続く検出モードが正常状態を維持すること |
| REQ-058-011 | stale 管理投影物の削除処理に失敗した場合、成功したものとして扱わず、処理失敗が利用者に判別できる終了結果となること |
| REQ-058-012 | 本契約の同期・検出・適用の収束契約は、consumer 向けと self-hosting 向けの両公開入口に同一構成で適用すること。archive installer は junction 方式ではないため本契約の直接対象外とすること |

## 適用範囲

- **対象**:
  - 正本と配置先の ADF 管理対象投影物の同期状態分類（追加・修復・削除）と、検出、変更予測、適用、完了検証の4段階の収束契約
  - 正本から削除された管理対象投影物、配布・投影対象から明示的に除外された管理対象投影物、正本側の対象消滅により不要となる ADF 生成物（Plugin loader shim 等）の廃止時処理
  - ADF 管理対象外の成果物の非破壊境界と、管理物判定不能な成果物の扱い
  - 適用モードの完全性（全対象処理）、冪等性（再実行で不要変更なし）、失敗報告
- **対象外**:
  - 配布基盤と導入モデルそのもの（REQ-009）、scripts 公開入口の境界・モード構成・命名（REQ-050）
  - archive installer における stale 実ファイル除去の仕様変更、archive installer を junction 方式へ変更すること
  - ADF 管理範囲そのものの新たな拡大、利用者が独自に作成した成果物の管理化
  - repo-local 成果物の削除、複数利用者の同時実行排他制御
