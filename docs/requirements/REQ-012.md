## 目的

REQ-013 により廃止された旧文書探索経路インデックスに代わる標準探索モデルとして、現行 repo-local の Artifact Graph を consumer でも利用可能な標準配布スキルへ昇格する。標準コアと augmentation を分離し、open extensibility によって self-hosting 固有知識を標準契約から除外する。

## 要件

| ID | 要件 |
|---|---|
| REQ-012-001 | agentdev-artifact-graph 標準配布スキルが consumer 環境で self-hosting 固有 path なしに動作すること |
| REQ-012-002 | 標準スキルのデフォルト indexed_paths は docs/requirements, docs/decisions, docs/specs の3種のみとし、self-hosting 固有 path（src/opencode, .opencode, .agentdev/extensions, scripts, tests）を含まないこと |
| REQ-012-003 | 標準 node_types デフォルトは requirement, decision, specification の3種とし、command, skill, integrity_rule, extension, source_file は augmentation が追加すること |
| REQ-012-004 | node_types, relation_types は closed-enum ではなく augmentation から追加可能な open extension point として実装すること |
| REQ-012-005 | project augmentation が存在しなくても標準動作すること |
| REQ-012-006 | project augmentation により project 固有正規成果物を node_types, relation_types へ追加できること |
| REQ-012-007 | project-owned source（src/tests/scripts/config 等）を固定 directory 知識なしに必要時探索できること（discovery_roots + query 時 rg/filesystem 補完） |
| REQ-012-008 | consumer 環境で AgentDevFlow 配布物（.opencode/commands/agentdev/, .opencode/skills/agentdev-*/, .agentdev-plugin/**）を indexed_paths に含めず、生成 Graph にこれらパターンのノードが0件であること |
| REQ-012-009 | self-hosting augmentation は command, skill, integrity_rule, extension, source_file の node_type と delegates_to, governs の relation_type を追加し、indexed_paths デフォルトへ src/opencode, .opencode, .agentdev/extensions, scripts, tests を追加することで現行 repo-local と同等の探索能力を維持すること |
| REQ-012-010 | Graph 不在・stale・生成失敗でも代替探索へ fallback し、標準 workflow を恒常停止しないこと（fail-open） |
| REQ-012-011 | Graph と rg 等の独立確認結果の差異を検出・分類・是正・回帰検証する verification feedback 機構を持つこと |
| REQ-012-012 | Graph は SSoT ではなく、正規成果物での確認を常時実施すること。差異は原因分類（canonical defect / graph defect）し、Graph を直接手編集せず原因側を修正して再生成すること |
| REQ-012-013 | 同一入力（input_digest, indexed_paths, excluded_paths, schema_version, generator_version が同一）から生成した5ファイル（manifest.json, nodes.jsonl, edges.jsonl, provenance.jsonl, diagnostics.json）がバイト単位で同一であること |
| REQ-012-014 | consumer が AgentDevFlow運用（REQ/Decision/SPEC）を採用しない場合、Graph は空で生成され正常状態であること |
| REQ-012-015 | Artifact Graph を利用する command, skill, Project Extension は廃止済み repo-agentdev-artifact-graph を実行時委譲先として参照せず、現行標準 skill agentdev-artifact-graph へ統一すること。廃止済み skill への実行時依存および superseded SPEC パスの実行時 context 参照を残さないこと。委譲先 skill の不存在を正常な Artifact Graph 利用状態として扱わないこと |
| REQ-012-016 | すべての Graph consumer は Graph 不在を関連なしまたは影響なしの根拠にせず、意味的類似および意味的責務重複を Graph の明示関係と同一視しないこと。Graph 取得結果の根拠となる canonical source を確認可能とし、必要に応じて独立手段で補完または反証すること |
| REQ-012-017 | Artifact Graph が missing, stale, invalid, regeneration failure, consumer に対象 node type または relation type が存在しない状態であっても、Graph failure 自体を停止条件としない consumer では代替探索へ移行できること。Artifact Graph を使用しない consumer、AgentDevFlow 正規成果物モデルを採用しない consumer が異常終了しないこと |

## 適用範囲

**対象**: agentdev-artifact-graph 標準配布スキル、open extensibility モデル、project augmentation、self-hosting augmentation、fail-open、決定論性、provenance、verification feedback

**対象外**: 旧文書探索経路インデックス依存除去（REQ-013）、AgentDevFlow 以外のプロジェクト固有 Graph 実装の強制、embeddings 生成と外部ベクトルストア、Neo4j 等の専用グラフDB、LLM による全面的な関係抽出、文章の意味が類似する責務重複の決定論的確定、明示参照が存在しない影響の網羅保証
