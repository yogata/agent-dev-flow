## 目的

ADF が起票する GitHub Issue・ローカル版 Issue のタイトルに、役割・計画上の位置・主題を一覧で把握できる統一された記述規則を適用する。起票する担当エージェントによる表記の揺れを防ぎ、タイトルを表示用の情報に徹させる。

タイトルの具体書式（書式の文字列表記、役割から書式への判定、主題原則、Wave 投影規則、除外情報一覧、付与と更新の場面、生成例）は workflows/issue-title-policy Design が単一参照点として所有する。本 REQ は必須条件のみを所有し、Design の内容を複製しない。件名を論理スキーマ項目として保持する構造（REQ-049-007）は変更しない。

## 要件

| ID | 要件 |
|---|---|
| REQ-100-001 | ADF が起票する Issue（GitHub・ローカル版 agentdev_gh local の両経路）のタイトルは、Issue の役割に応じた書式（Root Case または Standard Case は `Case: 主題`、Epic として確定した管理 Issue は `Epic: 主題`、Epic 配下の子 Issue は `[Wave N] Task: 主題`、追跡Issueは `Tracking: 主題`）に従うこと。具体書式の正は workflows/issue-title-policy Design が単一参照点として所有すること |
| REQ-100-002 | 主題は、合意済みの開発・修正作業では対象と達成する変更を、Epic 管理では作業群で達成する成果を、問題追跡では対象と観測された問題を、案・リスク等の追跡では検討する案・懸念・判断対象を表すこと。未確定の原因や未合意の解決策を確定事項として書かないこと |
| REQ-100-003 | タイトルの主題は対象と方向を具体化すること（「整備」「改善」「対応」のみで主題を完結させない）。REQ 行追加・APPEND・ファイル更新といった編集操作ではなく実現する変更を優先して表すこと。類似 Issue を対象・範囲・期待成果で識別できることを損なう短縮をしないこと |
| REQ-100-004 | 子 Issue のタイトルは確定済みの所属 Wave を先頭に置くこと。Wave 番号は所属 Epic 内でのみ有効とし、正規の構成変更で所属 Wave が変わった場合はタイトルを同期すること。タイトル解析から実行順序を決定しないこと（構成の基準は Epic 本文） |
| REQ-100-005 | タイトルから工程名・現在状態・OU/RA/AG/ACT/TS の羅列・REQ/Decision 番号の羅列・親 Issue 番号・投入識別子・topic_slug・ファイル一覧・検証件数・実測値を除き、これらを本文の既存の対応欄へ保持すること。除外情報の除去で再開・冪等照合を壊さないこと |
| REQ-100-006 | case-open は合意済みの対象・目的から Case のタイトルを生成し、case-ready は確定構造に沿って接頭辞を更新し子 Issue へ Wave 付きタイトルを付与すること。case-run / case-close は状態の進行・停止・完了のみではタイトルを変更しないこと。追跡Issueの起票・更新は確認された主題に基づいてタイトルを生成すること |
| REQ-100-007 | タイトルの更新理由は誤記・曖昧さの修正、合意済み対象・目的の変更、役割 / Wave 構成の確定または変更に限定すること。タイトルの書換えで未合意の範囲変更を隠さないこと。同じ対象の再利用は安定識別情報で行い、タイトル修正を理由に新規 Issue を作らないこと |
| REQ-100-008 | タイトル規則の適用は既存の role/kind・Issue 本文テンプレート・work_type 判定・推敲工程・Custom Tool による書込み経路を再利用すること。タイトル規則のために新しい論理 role・kind・Issue 構造・管理サービス・専用 Plugin・意味評価器・独自ワークフローを追加しないこと。Tool に新しい意味判断を持たせないこと |

## 適用範囲

- **対象**: ADF が起票・更新する GitHub Issue・ローカル版 Issue のタイトル（役割別書式、主題原則、Wave 投影、除外情報、工程別の付与・更新責任）と、その単一参照点としての workflows/issue-title-policy Design
- **対象外**: ラベル体系の改変、既存 Issue の一括改名・更新、閉鎖済み Issue 階層の移行、Root Case と別 Epic の統合、case-auto 起動単位の Epic 化、GitHub 親子機能の導入、Conventional Commits 変更（PR タイトルは対象外）、新規タイトル規則のための既存 role/kind 追加。追跡Issueの論理スキーマ構成（REQ-049-007）、agentdev_gh 起票・読取操作の呼出側規律（REQ-095）、タイトル・本文の推敲（REQ-098）は各 REQ のまま変更しない
