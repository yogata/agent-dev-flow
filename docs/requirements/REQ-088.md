## 目的

ADF v4 Standard Operating Model の基盤となる責務構造と情報モデルが、正規成果物として
所有され続ける。三層責務モデル、情報寿命モデルと昇格ガード、Project Contract の論理的
再構成、中核文書モデルの意味境界が、定義と実装の対応関係とともに維持される。

## 要件

| ID | 要件 |
|---|---|
| REQ-088-001 | ADF の責務は ADF Runtime、ADF Standard Operating Model、Project Model の三層に分離され、各層の責務と層間契約が Design により正規定義されること |
| REQ-088-002 | ルールと情報の寿命を少なくとも 8 種で区別し、各寿命について artifact 種別、canonical owner、昇格条件が Design により定義されること |
| REQ-088-003 | Learning と Observation が無条件に REQ へ昇格しない昇格ガードが、評価・昇格の正規経路に組み込まれること |
| REQ-088-004 | Project Contract は単一の巨大文書に依存せず、定義済みの再構成要素の集合と各要素の canonical owner から論理的に再構成できること |
| REQ-088-005 | 新規 session が永続的な正規成果物から Project の現在契約を再構成できること |
| REQ-088-006 | REQ、Decision、Design、Implementation、Evidence の意味境界（何が成立しなければならないか、なぜその選択か、どの構造・実現方式で成立させるか、実体、根拠）が v4 モデル定義として正規所有されること |
| REQ-088-007 | Decision の結果を REQ/Design の現行状態へ反映することと、Decision 自体を履歴的根拠として保持することが両立されること |

## 適用範囲

- **対象**: 三層責務モデル、情報寿命モデルと昇格ガード、Project Contract の論理ビュー、中核文書モデルの意味境界
- **対象外**: Implementation/Evidence の文書種としての配置・採番・検査の詳細（実装段階の APPEND で確定）、各層の実装（各担当段階）、work_type/scale/Epic/Wave の語彙再定義（第5段）、Quality/Verification/Evidence/Gate モデルの分解（第6段）
