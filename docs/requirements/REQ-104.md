## 目的

ADF v5 の共通責務を要件定義・設計・実装・構築と各段階の検証として所有し、詳細工程を参照モデルとして
プロジェクト方針による採用に委ねる。小規模開発と段階開発の双方を、不要な成果物や恒久的な工程進捗
管理の強制なしで成立させる。

## 要件

| ID | 要件 |
|---|---|
| REQ-104-001 | ADF の共通責務は要件定義、設計、実装・構築、および各段階の検証とし、全プロジェクトに適用される必須基準として正規所有されること |
| REQ-104-002 | 基本設計、詳細設計、環境定義等の詳細工程は任意の参照モデルであり、ADF が全プロジェクトに必須工程として強制しないこと |
| REQ-104-003 | プロジェクトが詳細工程と必須成果物を採用した場合、ADF は採用済みの工程、工程間関係、必須成果物を対象作業の基準として参照して解決・保持できること |
| REQ-104-004 | 採用されていない参照例の工程・成果物を欠落として誤判定せず、採用済みで必須の成果物が存在しない場合はファイル不在だけを根拠に工程省略として合格させないこと |
| REQ-104-005 | 工程の分割・統合・省略に際して、元の要求、制約、受け入れ条件、必要な検証義務が失われないこと |
| REQ-104-006 | 共通責務モデルは単独工程の実施と一気通貫の実施の双方を扱えること。工程進捗の恒久管理を ADF の共通中核の必須要件としないこと |
| REQ-104-007 | 工程構成の説明（プロセスモデル）と対象システムの設計内容（システムモデル）を別の関心として区別し、混同しないこと |
| REQ-104-008 | 採用規約の解決は、採用宣言あり、宣言なしでも有効な既存運用あり、両方なし、宣言が存在するが読取不能の各状態を区別して扱うこと。既存の有効規約を優先し、基準がないときだけ標準案を未採用候補として提示し、読取不能時は判断を留保すること（REQ-105-008 の移行期規約を包含する） |
| REQ-104-009 | 採用規約の解決は、対象作業（工程駆動の各操作、変更駆動の workflow、Case 実行、品質ゲート等、工程構成に基づいて成果物の有無・成立を判定する作業）の実行経路から参照され、解決結果（採用済み工程、工程間関係、必須成果物）が当該作業の判定基準として使われること。読取不能時の判断留保を、宣言なしの移行期デフォルト接続と区別して扱うこと |
| REQ-104-010 | 採用規約の解決結果は、対象作業の実際の実行とその証拠（正規成果物、操作結果、Git 履歴、検証証拠）とともに確認することで、単独工程・一気通貫実行・両経路共存の成立を判定すること。解決の成立だけを成立判定の根拠としないこと |
| REQ-104-011 | 採用した工程構成に応じた判定として、詳細工程を採用しない案件では標準案を未採用候補として扱い、複数の詳細工程を採用した案件では採用済み各工程を単独の作業単位として解決できること。未採用の参照工程を判定基準へ含めないこと |
| REQ-104-012 | 採用済みで必須の成果物の欠落を検出結果として提示し、作成・採用外明示・省略明示のいずれかに分類する根拠確認の実行経路を利用者が辿れること。根拠確認を経ない欠落を工程省略として合格させないこと |
| REQ-104-013 | 工程の分割・統合・省略の再構成宣言には元の要求・制約・受け入れ条件・検証義務の継承を必須とし、継承宣言なし・空宣言の再構成宣言を受理しないこと |
| REQ-104-014 | 採用規約の解決と判定の検証は、4状態（有効採用宣言あり、宣言なしで有効運用あり、両方なし、宣言ありで読取不能）と判定規則（未採用参照工程の基準外扱い、採用済み必須成果物の欠落検出、継承宣言必須化）の代表事例を実際の解決経路（公開操作・公開 script CLI）で実行して確認すること。解決器の実装や試験ファイルの存在を合格証拠としないこと |

## 適用範囲

- **対象**: 共通責務の必須基準化、詳細工程の参照モデル化と採用、採用済み工程・成果物の解決と保持、単独実行と一気通貫実行の双方
- **対象外**: 工程構成の具体的な保存形式・解析方式・設定ファイル名、WBS・工数・要員・予算・進捗率の管理、参照モデルに示す全工程・全成果物の一律必須化
