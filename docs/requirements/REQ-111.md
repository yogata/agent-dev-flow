## 目的

工程駆動における利用者判断による工程遷移、独立レビュー、確定済み設計からの実装接続、および変更駆動経路の維持・接続の利用契約を所有する。工程の進捗と完了の判断は利用者が担い、ADF は工程全体の完了認定を行わない。

## 要件

| ID | 要件 |
|---|---|
| REQ-111-001 | 独立レビューは単独で起動でき、既定要求・成果物・検証証拠と照合し、テーマ一覧の解消状態だけを根拠に問題なしと判定しないこと。所見は確定違反・証拠不足・推測・未採用改善候補を区別し、工程全体の完了を認定しないこと |
| REQ-111-002 | 工程の完了・遷移は利用者の判断による単独操作とし、参考の懸念は具体的な事実と推測を区別して必要な場合のみ再確認し、利用者が続行を選べば推論だけで止めないこと。遷移は前工程を完了済みの過去工程として一回だけ実行し、取消の場合は現在工程を維持すること |
| REQ-111-003 | 対象工程の解決不能・永続切替の書込失敗・中断後の同一要求再実行では、利用者の工程完了判断と技術的切替を分離し、未成立部分を報告し、確定した遷移だけを復元して二重実行を防ぐこと。書込み・工程特定の技術的失敗を成功扱いしないこと |
| REQ-111-004 | 採用済みの工程関係が後続0件・1件・複数件、前置工程が複数件の各条件に対し、終端で架空の工程を作らず、後続1件では一意に解決し、複数候補では利用者選択を求め、前置工程の既知義務と未確認範囲を欠落させずに伝えること |
| REQ-111-005 | 工程遷移の成立後、現在工程と既知義務は次工程の初回テーマ形成が未実施・失敗でも参照を維持し、初回形成の成否が遷移の完了を取り消さないこと |
| REQ-111-006 | 利用者が要件の確定だけまたは設計の確定だけを指示した場合、対象の有限作業を適切な正規成果物・技術的根拠とともに独立して終了でき、Issue・PR・後続実装を一律に要求しないこと |
| REQ-111-007 | 利用者が確定済み詳細設計と有限な実装対象・既存検証条件を指示した場合、要件定義へ無条件に戻らず、最新の実リポジトリの実装対象・依存・証拠を確認して実装・検証に接続すること。未検証の結果は未検証として扱うこと |
| REQ-111-008 | 完了済み過去工程の正規改訂は、下流が実際に依拠した版と現行版の差を起点に必要な下流更新・再検証へ接続し、現在工程を巻き戻さないこと。中間工程の更新必要・不要・作成・未確認の区別と理由を残し、処理失敗時は現在工程までの全反映完了を宣言せず再開可能な情報を示すこと。対応関係・正味差分のゼロを無影響の証明とせず、実在成果物・途中版への実依拠と再利用する旧証拠の現行適用可能性を確認し、比較不能な対象は未確認とすること。差分・影響評価の一般義務は REQ-106 に従うこと |
| REQ-111-009 | 機能追加・バグ報告・エラーログの直接入力、RU を経由する要件化、意味的依存を持つ複数作業・Epic/Wave、工程駆動で形成した成果物への後続変更の各経路を、工程駆動の操作・工程遷移を前置必須とせずに実行できること。旧コマンド名・旧内部構造の一致を合否条件としないこと |
| REQ-111-010 | v4 で有効な変更駆動の能力群（直接要求・障害からの要件化、発見・学習から RU を経た入口、小規模/Epic/Wave の依存実行、既存合意の正規改訂、実変更・証拠・安全境界、中断・失敗・再開、GitHub/Local・工程駆動成果物の再利用）の外部的結果と検証義務を、v5.1.0 の正規経路でも成立させること。各能力群の検証は実装着手時の有効な正規契約の外部的結果を基準とすること |
| REQ-111-011 | 工程駆動の4操作と工程遷移は、GitHub 版と Local 版の両方の正規利用経路から実行できること。Local 版で実装作業を伴う場合は、ローカル記録と実 Git 取り込み結果を独立して突合でき、成功報告だけでは確定しないこと |
| REQ-111-012 | 中断した有限作業の再開は、実際の未完了を識別して必要な範囲だけ継続し、実装・検証の未成立を成功として報告しないこと（REQ-108-006 の既有義務に従い、工程駆動経路での適用を明示する） |
| REQ-111-013 | 意味を引き継ぐ後継経路が実現・採用されるまで旧経路を失効させないこと。移行期は REQ-108-012 に従い現行利用経路を正として維持し、REQ-005-001/010/011 の改訂は後継経路の実現・採用と同じ変更セットで確定すること |
| REQ-111-014 | 独立レビューの所見のうち利用者が明示的に採用した対象のみを、採用範囲と判断根拠を維持して成果物更新の正規経路へ引き継ぐこと。未採用または採否不明の所見を修正確定済みの要求として扱わないこと |
| REQ-111-015 | 採用された所見の引き継ぎでは、対象成果物、参照する要求、元の指摘内容、判断根拠を誤転記や意味変更なく利用し、対象箇所の特定に行番号だけを依存条件としないこと。実際の修正前に最新の正規成果物を照合して指摘内容が現在も成立することを確認し、誤所見、既に解消済みの所見、対象を一意に特定できない所見をそのまま修正に使わないこと。一部が不成立・衝突・未確認でも独立して安全に修正できる部分を反映し、保留部分の理由と必要な確認を区別して報告すること |
| REQ-111-016 | 採用された各所見について実際の成果物変更と照合し、反映済み・未反映・保留を確認できること。修正指示の生成、作業開始、保存操作の成功だけを反映完了の証拠としないこと。一部が反映された後に中断した場合は、現在の成果物と採用済み所見を照合して残る必要な修正だけを継続し、成立済み修正の再適用による内容の重複を生じないこと |
| REQ-111-017 | 工程駆動と変更駆動のいずれの正規利用経路でも、実装の開始境界において、実装に必要な確定事項、未決事項、採用判断を失わないこと。同じ有効な判断・依存条件に基づいて実行を進められる部分と保留すべき部分を区別できること。GitHub版とLocal版のそれぞれの処理境界でも同一の要求が成立することを確認できること |
| REQ-111-018 | 採用・未決・試作の区別は、中断や再実行によって失われないこと。再開時は実際の正規情報と有効な判断から必要な状態を再構成し、未決事項を無断で解決済みにせず、試作を正式採用へ変化させず、実施済みの独立作業を不当に重複実行したり完了扱いを消失させたりしないこと（REQ-108-006、REQ-111-012 の既有義務の、採用・未決・試作の状態維持への適用） |

## 適用範囲

- **対象**: 独立レビューの所見区分と所見の成果物修正への引き継ぎ、利用者判断による工程遷移とその技術的分離、工程関係の解決、有限作業の独立終了、確定済み設計からの実装・検証接続、完了済み過去工程の改訂と影響伝播、変更駆動経路の独立維持と能力群の意味保存、4操作と工程遷移の GitHub/Local 両対応、移行期の権威継続、実装開始境界での確定事項・未決事項・採用判断の維持と、中断・再実行時の採用・未決・試作状態の維持
- **対象外**: ADF による工程全体の完了・深度の採点、新しい工程進捗台帳、独立レビューの必須ゲート化、旧 phase-plan 第5操作や遷移直後の自動補助起動、全成果物の再生成・汎用依存グラフ、v4 の公開APIの恒久的互換保証、旧コマンドAPIを再現する無制限な互換開発、要件定義・Definition 整備段階での Local 通し動作・v4→v5 移行実証の実施（当該段階の実施制約であり Case 全体の対象外ではない。B15／TS-012 の GitHub・Local 両版実経路検証、新4操作への Local 適用義務、既存 REQ-009/109 の証明義務は維持する）
