## 目的

本 REQ は、検出コマンド群（inspect-docs、inspect-skills、inspect-promote）と検出ドメインの命名・用語基盤を所有し、docs と配布物の意味診断、検出事項の分類・昇格の実行責務を担う。
3 command は DEC-006（inspect 3-command 構成への正規化）が定める単一の正規化単位であり、本 REQ の関心単位とする。
機械的検査は docs-check（REQ-010）が担当し、本系 command は対象を直接修正せず機械的検出と意味診断を分離して候補報告に徹する。
検出事項の分類と採用済み成果物への昇格は REQ-003-055 の共通原則に基づき（一意に確定できる事項は自律確定し、ユーザー判断が必要な事項のみ HITL を経る）、自動的な要件化を行わない。
検出事項の inbox、採用済み成果物の配置とライフサイクルは REQ-008 が、パイプライン全体の共通契約は v4-lifecycle-state-machine Designが、採用済み成果物の RU 化は backlog-review を所有する REQ が所有する。

| REQ-036-029 | inspect-docs の STEP-2 の意味診断（REQ 体系/6観点、Design、Decision/guides/README）は、範囲が重複しない診断担当へ分割して並列に実行できること。配布物診断は並列化の対象外とし、STEP-2 完了後の後続工程で従来どおり実行して結果品質を維持すること。大きすぎる範囲は完了できる単位に切り分けること。各診断担当は検査対象ファイルを変更せず、候補・file:line 形式の根拠・正規情報源・不確実性を返すこと。現行の工程順序と read-only-diagnostic 型（REQ-027-003）を維持し、工程間の横断並列化は行わないこと |
| REQ-036-030 | 横断矛盾判定、候補の重複排除、既知 defer/false positive 照合、6観点の網羅確認、finding の生成と git 永続化は、意味診断の並列化後も親の単一 writer として維持されること。source-of-truth priority（現行 REQ > 承認済み Decision > Design > guides）を維持すること |
| REQ-036-031 | 並列診断の委譲は、同期委譲で完了できる単位では同期方式を利用でき、完了できない単位では非同期委譲と子の完了まで親の実行コンテキストが維持される経路を用いること。失敗した診断担当だけを識別して再実行または取得済みの結果から回収し、親による全系統の全面再診断を行わないこと。並列性を失敗回避のために全体逐次化しないこと |
| REQ-036-032 | 並列化の変更前後に、同一 Git revision の診断対象 corpus と既知 finding を比較基準として、壁時計時間、意味診断工程の時間、各診断担当の開始・完了・待機、委譲の失敗と再実行、モデル呼出とツール呼出を測定し、検出漏れと過剰検出の有無を確認すること。比較測定の測定内容は両系統で対称であること（候補検証の有無・候補入力の同一性・読み取り内容の同一性が揃っていること）を測定設計時に確認すること。手動検証した対照例を含めて確認し、finding 差分には全件に正当理由を付すこと |
| REQ-036-033 | 並列化により短縮効果が得られない場合または診断品質が劣化する場合は成功扱いにせず、原因を評価して採否を判断すること。測定内容が非対称な比較測定を短縮効果の成功証拠として採用しないこと（subset 測定自体は禁止しない）。単一実行の測定値から改善率を断定しないこと。計測条件と結果を Case の検証証拠として残すこと |

## 適用範囲

- **対象**:
  - 検出コマンド群の命名統一、ドメイン状態、検出事項用語とファイル名接頭辞、diagnostics 命名の許容境界
  - inspect-extensions の公開 command 廃止と extension 検査の3層責務分離（決定的検査を IR-056 / docs-check、意味診断を inspect-skills、finding 処分を inspect-promote へ移管）
  - inspect-docs の REQ 体系意味診断、診断観点、機械検査の委譲、出力範囲、diagnostics 系 skill へのルーティング
  - inspect-skills の command と skill 参照妥当性診断、診断観点、skill 集約、副作用範囲、推奨経路提示
  - inspect-promote の分類、HITL 承認、promote と reject と defer の処理、明確な不整合の直接要件化、高確信度検出事項の自動昇格
  - severity・gate_level 軸の維持（baseline_status は IR スキーマから除外済み）
  - 実装・検証との整合を評価できる段階に達した draft Design の状態乖離 DRIFT 診断（読み取り限定）
  - 関連 REQ の実装 Case 進行と Decision 状態の乖離 DRIFT 診断（読み取り限定）
  - inspect-docs の意味診断の並列実行、診断担当への委譲と結果回収、並列化の評価・受入れ条件
- **対象外**:
  - docs-check の検査責務と配布境界（REQ-010）
  - 一時成果物の配置、ライフサイクル、構造化契約（REQ-008）
  - REQ と Design の健全性指標と分割予兆の定量定義（REQ-001）
  - IR 体系の実効性監査と存在条件厳格化（REQ-028、retired。恒常契約は DEC-013 と本 REQ の移管受入れ行が所有）
  - 取り込みパイプライン（intake）、学習パイプライン（learning）、バックログ統合（backlog-review）の各責務（各分割先 REQ）
  - 個別検出事項の修正実行
