## 目的

draft、RU、取り込み項目、学習エントリ、検出事項として command 間で引き渡される中間成果物は一時的な位置づけであり、docs/ 配下の REQ、Decision、Design、guide、索引が永続基準である。
本 REQ はこれら一時成果物の配置、ライフサイクル、構造化契約を所有し、永続文書と一時成果物の境界を明確にする。
要件定義プロセス（req-define、req-save、design-save）の実行契約は REQ-004 が所有し、本 REQ は当該プロセスが生み出し消費する一時成果物の契約を定義する。

### REQ-008-059: 未確定内容の auto_ready 抑止

req-define は、後続工程で決定する必要がある未確定事項、必須内容の欠落、暫定プレースホルダーが agreed_items または
artifact_actions に残る場合、auto_gate.auto_ready を true にしないこと。

判定は決定的マーカー検査（"TBD"、"TODO"、"未定"、"後続工程で確定"、"case-run で確定" 等の代表 fixture）と
QG-1 の意味判定（必須フィールド欠落、曖昧要件、測定不能条件）を組み合わせる。禁止事項や過去事例として当該文字列を
引用した文を誤検知しないこと。
停止時に該当 AG-ID または ACT-ID と理由を auto_gate.stop_reasons へ記録すること。

## 適用範囲

- **対象**:
  - 一時成果物（draft、RU、取り込み項目、学習エントリ、検出事項）の位置づけと永続文書との境界
  - .agentdev/drafts/ 配置規約と draft type registry（標準 draft type を req_draft のみに限定する制約を含む）
  - RU ライフサイクル（配置、削除タイミング、失敗時残存、永続文書の根拠参照対象外、セッション由来 RU の自足性と採否確定済み要件）
  - 取り込み、学習、診断の promoted/ ディレクトリの統一意味
  - req_draft の構造化契約（soft contract、標準フィールド、artifact_actions、operation_units、test_strategy、case_open_hints、content 完全確定、target_area 必須出力）
  - req_draft の停止条件と SSoT 遷移（case-open 成功を境界とする Issue/Epic SSoT 化）
  - 最終 REQ ファイルの必須セクション維持
- **対象外**:
  - req-define、req-save、design-save の実行プロセス、ユーザー合意形成プロセス（REQ-004）
  - 委譲時の判断、承認、副作用発動の境界、外部実行手段の中間成果物の取り扱い（REQ-003）
  - 取り込み、学習、検出の各 command 群の実行手順と分類判定（REQ-036〜038）
  - case-open の Issue 作成、VERIFY、RU 削除実行責務（REQ-006）
  - draft、RU の frontmatter、フィールド名、値一覧の詳細スキーマ（Design）
  - OU、artifact_actions、test_strategy のフィールド単位の詳細定義（Design）
