## 目的

case-open の実行契約を所有する。
合意済み要件doc からの GitHub Issue 本文生成、Standard flow と Epic flow のルーティング、Epic/Wave/Issue 構成の自律生成、構成検証、RU 削除と同期確認を扱う。
マクロフェーズ構成と work_type 分類は REQ-005 が、execution contract の境界定義は REQ-017 が、Epic Issue を実行順序 SSoT とする実行モデルは Epic と Wave 実行モデル REQ が所有し、本 REQ は case-open の実行オーケストレーションを所有する。

## 要件

| ID | 要件 |
|---|---|
| REQ-030-001 | case-open は合意済み要件doc を入力とし GitHub Issue 本文を生成して対象 REQ 番号を埋め込むこと |
| REQ-030-002 | case-open は入力要件doc 数、scale、operation_unit 構成に基づき Standard flow と Epic flow をルーティングすること |
| REQ-030-003 | case-open は合意済み要件doc 全体を入力とし Epic、Wave、Issue、依存関係、初期 status を自律生成すること |
| REQ-030-004 | case-open は機能要件、非機能要件、制約、対象外、受け入れ条件を新規に作成せず合意済み入力を反映すること |
| REQ-030-005 | case-open は実装順序、Issue 分解、Wave 構成をユーザー確認事項とせず自律生成すること |
| REQ-030-006 | case-open は要件が曖昧で Issue 構造を生成できない場合、停止すること |
| REQ-030-007 | case-open は依存グラフの連結成分（必須依存のみをエッジとする）を Epic 候補の出発点とすること |
| REQ-030-008 | case-open は依存強度、Epic サイズ、機能的一貫性の3軸で最終 Issue 構成を自律生成し複数 Standard、複数 Epic、混在のいずれも作成できること |
| REQ-030-009 | case-open は単独根（1 operation_unit だけの連結成分）を Epic 化せず Standard flow として扱うこと |
| REQ-030-010 | case-open は Epic サイズ上限と Wave 同時実行上限を実行安全境界として遵守すること（数値の詳細は Design） |
| REQ-030-011 | case-open は無関係な operation_unit 群を単一 Epic へ機械的に集約しないこと |
| REQ-030-012 | case-open は Epic 構成推論の根拠を Epic Issue 本文に記録すること |
| REQ-030-013 | case-open は Epic Issue 本文の Wave テーブルに各子 Issue の実行方法（並列、直列）を技術的依存関係に基づいて明記すること |
| REQ-030-014 | case-open は Epic 分解時に既存オープン Issue とのスコープ重複を検知し重複する子 Issue 生成をスキップまたはユーザー確認すること |
| REQ-030-015 | case-open は完了条件と事前状態の記載を識別子中心とし変動しやすい実測値スナップショットは補助値とすること |
| REQ-030-016 | case-open は完了条件を Issue 本文に展開する前に最新状態を再確認し差異がある場合は最新状態を優先すること |
| REQ-030-017 | case-open は Issue 本文をファイル経由で扱い Markdown 行構造を保持すること（詳細は Design） |
| REQ-030-018 | case-open は構成確定後かつ GitHub Issue 作成前に構成検証（上限、依存維持、全割当）を実行し上限超過または構成不備を検出した場合停止すること |
| REQ-030-019 | case-open は Issue 作成と VERIFY 成功後に RU を削除する唯一のコマンドであること |
| REQ-030-020 | case-open は RU ファイル削除後に統合先ブランチ（REQ-042 の定義による、既定 main）の作業ディレクトリとリモートの同期を確認し不一致を検出した場合停止すること |
| REQ-030-021 | case-open は自工程で実観測した deviation を Split Rule で分類して intake/learning のいずれかへ保存すること（case-close への capture 委譲は廃止） |

## 適用範囲

- 対象: case-open（Issue 本文生成、REQ 番号埋め込み、Standard と Epic flow ルーティング、Epic/Wave/Issue 構成の自律生成、連結成分と3軸判断、スコープ重複検知、完了条件記載、構成検証、RU 削除と同期確認）
- 対象外: マクロフェーズ構成と work_type 分類（REQ-005）、委譲時の判断と承認（REQ-003）、execution contract の境界定義（REQ-017）、Epic/Wave 実行モデルの実行規則（Epic と Wave 実行モデル REQ）、Epic サイズ上限等の数値（Design）、harness 固有詳細の配布物からの除去一般原則（REQ-002）
