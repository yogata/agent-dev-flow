## 目的

agentdev_gh 操作カタログには GitHub 上へのリポジトリ作成（repo create 相当）の操作が存在せず、gh-write guard は raw gh WRITE を fail-closed 拒否するため、正規手段では検証用リポジトリを構築できない。この結果、GitHub 版正規利用経路の実操作検証（REQ-110 / REQ-111 の TS-007・TS-008・TS-010 の GitHub 版部分）が継続 blocked となり、検証環境の不備が恒久化している。整備方針を決定として記録する。

## 要件

| ID | 要件 |
|---|---|
| REQ-116-001 | 検証環境の正規構築手段の方針として、agentdev_gh 操作カタログの拡張（repo create 相当操作の追加）ではなく、管理者事前準備による隔離検証リポジトリの常備を採用すること。agentdev_gh 操作カタログ不拡張（DEC-045 決定3前半）を維持すること |
| REQ-116-002 | REQ-110 / REQ-111 の検証方法・適用範囲は再評価しない（変更しない）ことを記録すること。検証方法の格下げは REQ-032-037（検証方法変更は同等以上の観測能力と未証明範囲不増を条件）、REQ-055（production-equivalent verification）、RA-005 判断（代替の構造的等価性は同等以上と認めない）と整合しないため選択しないことを判断根拠として記録すること |
| REQ-116-003 | gh-write guard の fail-closed 拒否自体の緩和は解決手段としないこと |
| REQ-116-004 | 隔離検証リポジトリの用意前提（構築・運用・クリーンアップの手順と責務）を検証環境前提として文書化すること |
| REQ-116-005 | 判断後の処置経路を併記すること: 検証環境の用意後に case-close を再開入口として、Case #3779 完了条件2（TS-007）と Epic #3803 の TS-008・TS-010 の GitHub 版部分の検証を再開する。検証環境の用意が外部要因で不能な場合は req-define 差し戻しとして再評価する |

## 適用範囲

- **対象**: GitHub 版正規利用経路の実操作検証環境（隔離検証リポジトリ）の構築手段の方針と処置経路の記録
- **対象外**: agentdev_gh 操作カタログの拡張、gh-write guard の緩和、REQ-110 / REQ-111 の検証方法・適用範囲の変更、plugin ホスト環境差等の環境要因の技術調査（Problem 管理として別途）
