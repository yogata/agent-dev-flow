## 目的

Git 操作（ドメイン状態永続化の push を含む）が対話認証の待機で停止・反復しないことを保証する。認証の失敗、対話要求、タイムアウトを識別して報告し、必要な人間の認証操作の境界を維持する。

## 要件

| ID | 要件 |
|---|---|
| REQ-102-001 | Git 操作は非対話で使用できる正規の認証経路を確認してから実行すること。認証済み実行環境では対話認証の待機なしに対象の Git 操作が完了すること |
| REQ-102-002 | 認証失敗、対話要求、タイムアウトを識別可能にし、認証支援の待機を正常実行として扱わないこと。認証不成立時は失敗、必要な処置、再開条件を報告すること |
| REQ-102-003 | 認証条件を変更しない同一条件での長時間待機を無条件に再試行しないこと。認証方式を変更して再試行する場合は変更内容と結果を識別できること。認証方式を特定のコマンドに固定しないこと |
| REQ-102-004 | 資格情報の値を解析証拠やログへ出力しないこと。既存の安全な資格情報管理手段を使用し、秘密値不在の検証を実施すること。必要な人間の認証操作を偽装・代行せず、非対話化によって認証・アクセス制御を回避しないこと |

## 適用範囲

- **対象**: 本リポジトリの GitHub 運用に接続する実行環境における Git 操作（push を含む）の認証、認証失敗・対話要求・タイムアウトの検出と報告、認証待機に対する再試行条件、資格情報の取り扱い
- **対象外**: 資格情報の自動収集・新規保存、秘密値の取得・出力、ADF 共通 workflow 契約への認証方式の固定、GitHub 以外の接続方式への強制適用、gh auth git-credential 以外の正規認証方式の禁止、agentdev_gh（Custom Tool）の起動環境障害（REQ-093）、opencode credential 供給ブリッジ（REQ-091）
- 既存の操作経路全体への適合は、文言の存在だけで実証済みとしない。git 操作を持つ操作経路が失敗識別（認証失敗・対話要求・タイムアウトの区別）を利用可能な状態にあること（共有template を含む）を適合の確認対象とする。実装・検証の変更を要求しない範囲で、文書・template の整備を要求する。
