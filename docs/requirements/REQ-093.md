## 目的

Custom Tool agentdev_gh に起動環境障害（AGENTDEV_GH_REPO 未設定、harness 内 spawnSync 失敗による起動不能）が発生した場合、影響は特定操作ではなく全操作に及ぶ。事象・診断・回復・作業再開（resume）を運用文書と失敗情報の両面から恒久化し、同じ障害への対処を都度再調査させない。

REQ-092 が issue_list 操作の呼出側運用規律（広範 filter への search 併用・labels の追跡Issue論理軸物理マッピング入力専用）を所有するのに対し、本 REQ は操作種別に依存しない起動環境障害の予防・診断・回復を所有する（対象操作範囲で区別。Tool 側操作契約〔安全上の上限・完全一覧契約・失敗分類〕は REQ-011-033 が所有）。

## 要件

| ID | 要件 |
|---|---|
| REQ-093-001 | agentdev_gh の既知事象（known-issues）記述は全操作を対象とし、起動環境障害（AGENTDEV_GH_REPO 未設定、harness 内 spawnSync 失敗による起動不能）の事象・診断手順・回復手段（harness 再起動）・workflow が blocked に遷移した場合の作業再開手順を運用文書に保持すること |
| REQ-093-002 | agentdev_gh を利用する自ホスト環境に対し、投入前の疎通確認手順と起動環境要件を既存ガイドと重複しない残差スコープとして整備し、周知可能な形で保持すること |
| REQ-093-003 | agentdev_gh は環境起因の起動・実行失敗においても fail-closed 契約を維持し、既存の失敗分類の値域を変更せず、環境起因である可能性の識別に役立つ最小限の detail（環境変数設定状態の要点、gh 終了コードと stderr の空・非空、spawnSync エラー種別等）を失敗情報に含めること。Tool の操作契約（入出力・失敗分類の構造）自体は変更しないこと。repo 解決失敗（config-uninterpretable）時の診断情報は REQ-052-013 が既に所有するため、本行は全操作（読取操作を含む）かつ gh 実行失敗（operation-failed）経路の環境起因可能性識別を追加する範囲とすること |
| REQ-093-004 | known-issues 記述は、劣化サイクル（再発までの呼出数・再発局面）の定量観測と縮退運用パターン（委譲前疎通確認、gh 呼出を伴う処理の最小副作用単位分割と durable state 先行、write-proxy payload の標準配置、gh exit 66 恒常失敗時の bash gh 例外手順と証跡様式）を保持すること |

## 適用範囲

- **対象**:
  - agentdev_gh 操作の呼出側運用規律（全操作横断の起動環境障害対応）
  - agentdev_gh plugin の環境起因失敗時の失敗情報（detail の充実）
  - 自ホスト利用者向けの投入前疎通確認・周知（残差スコープ）
- **対象外**:
  - agentdev_gh の fail-closed 契約・操作契約自体の変更（入出力・失敗分類の構造は現行維持）
  - harness 再起動手段の実装（harness 責務）
  - REQ-092 が所有する issue_list 呼出側運用規律（広範 filter への search 併用・labels の追跡Issue論理軸物理マッピング入力専用）
