# REQ-091: Supervisor 環境向け credential 供給ブリッジの正本管理

## 目的

Supervisor（Hermes 等、spawn する子プロセスから provider 資格情報を削除する実行環境）から dispatch された
opencode 実行において、Windows User スコープ環境変数（HKCU\Environment）に正本化された credential
（AI_GATEWAY_API_KEY 等）が子プロセスへ供給されず、Jev 先行評価の観測が not_configured に劣化する問題へ対応する。
credential 供給の原則は「Supervisor から env で配る」ではなく「実行側が自身の起動コンテキストで取得する」
（2026-09-23 ユーザー合意）であり、その橋となる実行環境ブリッジ道具（ocenv と opencode bridge shim）を
agent-dev-flow リポジトリで正本管理し、新規環境で導入マニュアルにより再現できるようにする。
ADF 側契約（REQ-090、Jev 観測契約の正規 Decision〔作成時点: DEC-044、DEC-040 は DEC-044 により superseded〕、Jev adapter の環境変数解決）と Supervisor 側の scrub 設計は変更しない。

## 要件

| ID | 要件 |
|---|---|
| REQ-091-001 | ADF は Supervisor 環境で opencode を起動する利用者向けの実行環境ブリッジ道具として、Windows User スコープ環境変数を現在の環境へ merge してコマンドを実行するラッパ（ocenv）と、opencode コマンド解決を横取りして ocenv 経由で opencode 本体を起動する bridge shim を、scripts/self/supervisor-bridge/ 配下で正本管理すること。REQ-050 の公開入口境界に従い、scripts/ 直下の公開入口構成を変更しないこと。 |
| REQ-091-002 | ocenv は HKCU\Environment の User スコープ変数を取得元として、現在の環境で未設定の変数のみを供給し、既設定の変数を変更せず、指定コマンドの引数と終了コードを透過して実行すること。bridge shim は導入環境の opencode 本体パスを調整点として明示すること。 |
| REQ-091-003 | 導入マニュアルを docs/guides/ 配下のガイドとして備えること。前提、インストール手順、opencode 本体パスの調整方法、検証手順（Supervisor の spawn コンテキストでの opencode コマンド解決先確認、scrub 模擬環境での変数 SET 確認、実Workflowでの agentdev_jev evaluate の構造化失敗応答に含まれる not_configured 区分の出現/非出現確認を含む）、失敗署名と対処（構造化失敗応答の not_configured 区分と API failure 区分の読み分け、shim のサイレント bypass、opencode 本体パス不一致、opencode 本体更新・PATH 変更後の再確認トリガを含む）を含むこと。ガイド索引へ反映すること。 |
| REQ-091-004 | ブリッジの機構、運用手順、失敗署名、検証手順を docs/knowledge/ 配下の知識文書として備えること。知識文書契約（frontmatter、必須5項目、領域 README の列挙整合）に従うこと。機構には ocenv の供給範囲と環境変数値の展開の扱いを含むこと。マニュアルと知識文書の重複は相互参照を許容すること。 |
| REQ-091-005 | ブリッジ成果物、マニュアル、知識文書は秘密値（credential 本体）を含まないこと。変数名、配置場所、手順のみを記述すること。 |
| REQ-091-006 | ブリッジ成果物（repo 配置物を検証対象とする）の導入検証結果として、opencode コマンドの解決先、scrub 模擬環境での変数 SET/UNSET 実測、実Workflowでの agentdev_jev evaluate の構造化失敗応答に not_configured 区分が出現しないこと（API key 供給正常時）を当該 Case の完了報告に含めること。 |

## 適用範囲

### 対象
- scripts/self/supervisor-bridge/（ocenv、opencode bridge shim）の新規配置と正本管理（改行コード LF 保持を含む）
- 導入マニュアル（docs/guides/ 新規ガイド、docs/guides/README.md と docs/README.md の索引更新）
- 知識文書（docs/knowledge/ 新規知識文書、docs/knowledge/README.md の列挙更新）
- REQ-050-009 の内部配置列挙への追記

### 対象外
- agentdev-jev adapter の credential 解決経路拡張（opencode.json 読取等。env 契約は REQ-090 で確定済み）
- REQ-090、DEC-040、各 Workflow Skill の Jev 関連契約行の変更
- Hermes 側コード・scrub 設計の変更（セキュリティ境界として正しいため）
- opencode.json の provider.vercel.options.apiKey の整理
- env_passthrough による再許可（設計的に拒否されるため）
- release archive 収録・配布 manifest 反映・consumer リポジトリへの配布・適用（必要になった時点で別件）
