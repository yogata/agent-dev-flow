## 目的

Supervisor（Hermes 等、spawn する子プロセスからプロバイダー資格情報を削除する実行環境）から dispatch された
opencode 実行において、Windows User スコープ環境変数（HKCU\Environment）に原本化された credential
（CLOUDFLARE_ACCOUNT_ID、CLOUDFLARE_API_TOKEN 等）が子プロセスへ供給されず、Jev 先行評価の観測が not_configured に劣化する問題へ対応する。
credential 供給の原則は「Supervisor から env で配る」ではなく「実行側が自身の起動コンテキストで取得する」
（2026-09-23 ユーザー合意）であり、その橋となる実行環境ブリッジ道具（ocenv と opencode bridge shim）を
agent-dev-flow リポジトリで原本管理し、新規環境で導入マニュアルにより再現できるようにする。
ADF 側契約（REQ-090、Jev 観測契約の正規 Decision〔作成時点: DEC-044、DEC-040 は DEC-044 により superseded〕、Jev adapter の環境変数解決）と Supervisor 側の scrub 設計は変更しない。

## 適用範囲

### 対象
- scripts/self/supervisor-bridge/（ocenv、opencode bridge shim）の原本管理（改行コード LF 保持を含む）
- 導入マニュアル（docs/guides/ のガイド、docs/guides/README.md と docs/README.md の索引）
- 知識文書（docs/knowledge/ の知識文書、docs/knowledge/README.md の列挙）
- REQ-050-009 の内部配置列挙

### 対象外
- agentdev-jev adapter の credential 解決経路拡張（opencode.json 読取等。env 契約は REQ-090 で確定済み）
- REQ-090、DEC-040〔superseded by DEC-044（決定4 部分置換。決定1〜3 は維持）〕、各 Workflow Skill の Jev 関連契約行の変更
- Hermes 側コード・scrub 設計の変更（セキュリティ境界として正しいため）
- opencode.json の Jev 以外の用途に由来する Vercel provider 設定の整理
- env_passthrough による再許可（設計的に拒否されるため）
- release archive 収録・配布 manifest 反映・consumer リポジトリへの配布・適用（必要になった時点で別件）
