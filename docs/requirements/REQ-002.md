## 目的

配布成果物（command、skill、template、script）は AgentDevFlow が適用先プロジェクトへ配布する成果物であり、自己完結性、harness 非依存性、責務分界の一意性を維持する。
配布成果物は消費プロジェクトの環境、内部文書、harness 選定に依存せず、新規 clone 環境でそのまま実行できる状態を保つ。
本 REQ は配布成果物の種別責務、原本と配置先、名前空間、ドメイン状態、skill 構造、自己完結性、harness 非依存、内部 ID と内部パスの排除、Project Extensions との境界を統括する。
委譲時の判断、承認、副作用発動の境界は REQ-003 が所有し、本 REQ は配布成果物側の正規所有者として接続点を参照する。
本 REQ が所有する安定外部契約の詳細実装（ロールテーブル、依存方向、frontmatter 詳細、template 構造、委譲契約詳細、result state machine）は SPEC を正規所有者とし、本 REQ は境界宣言へ縮約する。

## 要件

| ID | 要件 |
|---|---|
| REQ-002-001 | command はユーザー向け入口、入出力契約、ガードレール、高レベル手順を定義すること |
| REQ-002-002 | command は共通判断基準、大きな状態機械、長い失敗時手順を直接所有せず skill または script へ委譲すること |
| REQ-002-003 | skill は再利用可能な判断基準、共通知識、宣言的ルールを一次情報として所有すること |
| REQ-002-004 | skill は command 固有の Step 番号、局所ファイルパス、局所エラーメッセージを一次情報として保持しないこと |
| REQ-002-005 | template は Issue、PR、コメント、完了報告の本文構造、必須セクション、任意セクションを定義すること |
| REQ-002-006 | script はガードレール、検査、補助処理の決定的でテスト可能な実行ロジックを提供すること |
| REQ-002-007 | 配布成果物の原本は src/opencode/ 配下に配置し、.opencode/ は実行時の配置先とすること |
| REQ-002-008 | command 原本は src/opencode/commands/agentdev/ へ、skill 原本は src/opencode/skills/ へ配置すること |
| REQ-002-009 | AgentDevFlow の正規名前空間は agentdev とし、公開 command prefix は /agentdev/* とすること |
| REQ-002-010 | agentdev 名前空間および agentdev-* skill prefix は AgentDevFlow 本体用の予約名とし、プロジェクト固有カスタマイズで使用しないこと |
| REQ-002-011 | 本体リポジトリ専用の command 名前空間 /repo/* と skill prefix repo-* を定義し、導入先プロジェクトへの配布対象から除外すること |
| REQ-002-012 | ドメイン状態ディレクトリは .agentdev/ とし、実行結果と状態のみを格納し、git 管理対象とすること |
| REQ-002-013 | skill 名は小文字、数字、ハイフンのみの kebab-case とすること |
| REQ-002-014 | skill の frontmatter は name と description を基本構造とし、description に使用条件を明示すること |
| REQ-002-015 | skill は段階的開示を適用し、詳細は references/ ディレクトリへ分離すること |
| REQ-002-016 | ガードレールスクリプトは該当 skill の scripts/ 配下に配置し、所有 skill の公開操作契約経由で呼び出すこと |
| REQ-002-017 | command または skill が他 skill を参照する場合、skill 名レベルの参照とし、他 skill の内部構造（protocol 名、Step 名、Section 名、見出し名、references 内部パス）へ直接依存しないこと |
| REQ-002-018 | skill は同一関心、同一責務境界、同一判断モデル、矛盾しない USE FOR と DO NOT USE FOR を共有する単位とすること |
| REQ-002-019 | 配布成果物が参照する skill は src/opencode/skills/ 配下に配置し、配布物化すること |
| REQ-002-020 | 配布物が依存しない repo-local 専用 skill は .opencode/skills/ のまま管理し、src 昇格の対象外とすること |
| REQ-002-021 | 配布成果物は、消費プロジェクトの新規 clone 環境で依存先が解決できない参照を含まないこと |
| REQ-002-022 | 配布 command、skill、docs は harness 固有詳細（エージェント名、モデル名、必須 skill 名、timeout、retry、context 管理方式、起動 API、実行制御パラメータ）を含まないこと |
| REQ-002-023 | 配布 command、skill、docs は業務ワークフロー契約（工程目的、入力、前提、進行停止条件、永続成果物、許可禁止副作用、品質ゲート、結果契約）のみを記述すること |
| REQ-002-024 | runtime workspace ディレクトリの管理は harness 側の責務とし、配布 docs は規定しないこと |
| REQ-002-025 | 配布成果物本文はプロジェクト固有識別子（REQ-ID、DEC-ID、IR-ID 形式）を含まないこと |
| REQ-002-026 | 配布成果物本文は消費プロジェクトの文書ディレクトリ内部パス（docs/specs/**、docs/guides/**、docs/decisions/** 等）を含まないこと |
| REQ-002-027 | 配布成果物は、導入先プロジェクトで解決可能な .opencode/ 相対パスまたはシンボリックパスのみを使用すること |
| REQ-002-028 | 内部 ID 除去後、配布成果物は Markdown 構文破損、主要構造の意図せぬ重複、壊れた参照残骸を残さないこと |
| REQ-002-029 | 内部 ID 除去後、配布成果物は command、skill、SPEC 間で責務説明が矛盾しないこと |
| REQ-002-030 | Project Extensions は .agentdev/extensions/ 配下に配置し、標準 command/skill を上書きせずプロジェクト固有情報を追加すること |
| REQ-002-031 | command/skill は自身に対応する extension のみを読み、extension が不在または破損の場合も標準動作を維持すること |
| REQ-002-032 | 配布 command/skill 本文はプロジェクト固有の Decision、REQ、SPEC 具体 ID、具体パス、固定 URL に依存せず、トレーサビリティは extension で補完すること |
| REQ-002-033 | subagent 委譲プロトコルの配布成果物側正規所有者は本 REQ とし、委譲時の判断、承認、副作用発動の境界は REQ-003 が所有すること |
| REQ-002-034 | 本 REQ が所有する安定外部契約の詳細実装（ロールテーブル、依存方向、frontmatter 詳細、template 構造、委譲契約詳細、result state machine、launch mechanism）は SPEC を正規所有者とすること |
| REQ-002-035 | 配布 command 定義 case-auto.md の distribution-boundary 違反18件（pre-existing ベースライン）を段階的に解消する。具体ID（ADR-NNNN, REQ-NNNN）、具体パス、固定 URL の参照を project extension（.agentdev/extensions/commands/case-auto.yaml）経由へ分離する。 |

## 適用範囲

- **対象**: 配布成果物（command、skill、template、script）の種別責務、原本と配置先の規約、正規名前空間と repo-local 名前空間の宣言、ドメイン状態ディレクトリ、skill 命名と frontmatter と段階的開示の基本構造、ガードレールスクリプトの配置、配布物依存スキルの src 昇格と自己完結性、harness 非依存境界、内部 ID と内部パスの排除、ID 除去後の文意保持と構文健全性と責務整合、Project Extensions との配置と読込境界、subagent 委譲プロトコルの配布成果物側正規所有
- **対象外**: 配布基盤の同期、リポジトリ種別、導入先インストール（REQ-009）、委譲時の判断、承認、副作用発動の境界（REQ-003）、REQ/Decision/SPEC の文書体系基盤と正規所有モデルと責務体系マトリックス（REQ-001）、要件定義プロセス（REQ-004）、ワークフロー protocol と工程接続（REQ-005）、個別 command、skill、template、script の詳細手順と実装詳細、inspect-* 検出と診断（REQ-010）、個別 IR 番号、正規表現、exemption 条件、severity、repo-local 検査実装、導入先固有の extension 内容
- **対象（REQ-002-035 追加）**: src/opencode/commands/agentdev/case-auto.md（具体ID参照の分離）、.agentdev/extensions/commands/case-auto.yaml（project extension への集約先）
- **対象外（REQ-002-035 追加）**: distribution-boundary 要件そのものの変更（要件は REQ-002 で確立済み）
