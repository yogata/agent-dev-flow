## 目的

case-close の実行契約を所有する。
case-close は ADF v4 公開運用モデル（DEC-033）において内部 lifecycle 段階である。
達成判定、整合確認、PR マージ、Issue クローズ、ドメイン状態永続化、クリーンアップ、Epic Wave クローズを扱う。
QG-4 検査規則は agentdev-quality-gates が、Epic Issue 本文の単一書き手規則は Epic と Wave 実行モデル REQ が所有する。

| REQ-032-025 | case-close は評価対象の各 draft Design について、実装・検証との整合確認に基づく accepted 昇格または見送り理由と再評価契機の記録のいずれかの評価結果を確定すること。いずれの評価結果もない対象が残る場合、case-close を完了扱いにしないこと。見送り記録は当該 Case の Issue への対応記録コメントに保存し、現在 Design 本文へ作業履歴として新規保存しないこと（REQ-001-003、REQ-001-015）。再評価契機を持つ未解決の見送り事項は追跡Issue として育成できること。新規の一時成果物種別や新規ドメイン状態を作らないこと |
| REQ-032-026 | case-close は Design 状態評価の再実行時に、既に accepted へ遷移済みの Design に対して重複する状態遷移や記録を生成せず、同一 Case の再実行では既存の見送り記録を評価結果として認定して重複する見送り記録を生成しないこと |

| REQ-032-028 | case-close は公開 command ではなく内部 lifecycle 段階として case-auto の orchestration から駆動されること。単独の手動起動を公開 UX の標準としないこと |
| REQ-032-029 | case-close はリモートブランチ削除ステップを持たず、PR マージ後のリモートブランチ削除は GitHub の deleteBranchOnMerge 設定による自動削除（ADF 適用リポジトリでは必須、REQ-009-052）に委譲すること。ブランチ・worktree クリーンアップの責務はローカルに限定されること |
| REQ-032-030 | case-close の QG-4 checker 実測は、merge 直前の origin/main 取り込み済み branch HEAD で実施し、検出した新規 NG の出所が自 Case 変更であることを evidence として記録し、provenance-tracked baseline の登録漏れを検査すること |
| REQ-032-031 | case-close の完了条件評価は、実装 diff または case-run の自己申告だけを最終基準とせず、根拠となる正規契約から評価範囲、期待結果、反例条件、許容される除外を導出または照合すること。あわせて、完了条件から根拠正規契約、検証義務、評価範囲、検証手段、取得した証拠と対象成果物の状態、除外根拠、判定までの主要関係を既存証拠チャネル（Issue、PR、QG 結果、コメント等）から追跡可能にすること |
| REQ-032-032 | 完了条件単位の評価区分として pass（条件成立を十分な証拠で確認）、fail（条件不成立を確認）、blocked（必要な外部依存、証拠、再合意、追加設計判断等が不足）、not applicable（正規契約上、条件自体が評価対象に適用されない）を区別すること。not applicable は当該条件が評価対象に適用されないことを正規契約から説明できる場合だけ許可し、未投影、未実装、未検証、証拠不足、検証不能、予定変更対象外、実行担当の責務外判断を根拠にすることを認めず、適用性判断の根拠を追跡可能に保持すること |
| REQ-032-033 | 各完了条件に対応付けられた証拠がその条件の意味命題を実際に立証していることを確認すること。条件IDまたは名称の一致、テスト名の類似、関連ファイルの検査といった形式的一致だけを達成証拠としないこと |
| REQ-032-034 | 「残存0件」「全経路」「すべて整合」「漏れなし」等の全称・不存在条件では、正規契約から導出した評価範囲を対象に反例探索を行うこと。変更ファイルのみまたは実装担当が選択した対象のみの確認は、全評価範囲を被覆しない限り達成証拠としないこと |
| REQ-032-035 | Issue closed、PR merged、Child completed、Wave 完了、QG pass、完了条件チェック済み等の工程状態を、それらの成立前提である機能、品質、契約条件の証明へ循環利用しないこと。ただし「PR が merged であること」等、工程状態自体が明示的な完了条件である場合は当該条件に限り直接証拠として利用できること |
| REQ-032-036 | 現在の完了条件を否定する finding を intake、learning、後続 Issue、Findings、別途確認、予定変更対象外等へ分類しただけでは当該条件を達成扱いにしないこと。反例を元条件から切り離すには、正規な要件変更、対象範囲変更またはあらかじめ定められた項目固有処置を要すること |
| REQ-032-037 | 合意済み検証方法を別手段へ変更する場合、元の検証義務に対して同等以上の観測能力を持ち未証明範囲が増えないことを確認すること。同等性を確認できない代替検査（通し実行から単体テスト、実 runtime から静的構造確認、実ホストからスタブ、リポジトリ全体から変更ファイルのみへの変更を含む）を達成証拠としないこと |
| REQ-032-038 | 終了対象が負う必須完了条件に fail、blocked、未判定、未投影、証拠不足、検証不能、意味不一致または未解決反例が1件でも存在する場合、対象 Issue、Epic または Root Case を completed/closed へ遷移させず、必須未達を Gate 全体の warn 等で通過させないこと。子 Issue の終了は当該子が負う必須条件で判定し、親に残る横断義務の未完了だけを理由に条件を満たした子 Issue の終了を禁止せず、親の横断義務は Epic または Root Case の最終終了時に評価すること |

## 適用範囲

- 対象: case-close（達成判定、整合確認、Decision 確認、PR マージと Issue クローズと永続化とクリーンアップの分離報告、intake と learning 回収、ローカル変更安全停止、branch と worktree 削除安全、rebase による機械的コンフリクト解消とエスカレーション、mergeable 待機、main 同期安全、test strategy 完了条件、Epic Wave クローズと完了条件評価、docs 全体検索、Epic 自動クローズ判定の事前状態取得）
- verify-only closure の QG-4 達成判定における SSoT コメント（Issue コメント）の判定根拠参照と SSoT コメント不在時の完了抑止
- 対象 REQ に関係する draft Design の棚卸しと全件評価（申告候補との統合、見送り記録の既存履歴チャネル保存（保存先は対応記録コメント、Design 本体を除く）、再実行時の冪等）
- 対象外: QG-4 検査規則の定義（agentdev-quality-gates）、Epic Issue 本文単一書き手規則（Epic と Wave 実行モデル REQ）、委譲時の判断と承認（REQ-003）、mergeable 待機の詳細パラメータと capture の Split Rule（Design）、verify-only closure の判定条件の詳細と SSoT コメント参照手順の詳細（Design）
