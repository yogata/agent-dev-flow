## 目的

case-close の実行契約を所有する。
達成判定、整合確認、PR マージ、Issue クローズ、ドメイン状態永続化、クリーンアップ、Epic Wave クローズを扱う。
QG-4 検査規則は agentdev-quality-gates が、Epic Issue 本文の単一書き手規則は Epic と Wave 実行モデル REQ が所有する。

## 要件

| ID | 要件 |
|---|---|
| REQ-032-001 | case-close は未チェック項目の達成判定を実行し達成済み項目を更新すること |
| REQ-032-002 | case-close は要件、成果物、SPEC の整合確認と Decision 必要判断に対する Decision 作成済み確認を行うこと |
| REQ-032-003 | case-close は PR マージ、Issue クローズ、ドメイン状態永続化、branch と worktree クリーンアップの結果を分離して報告すること |
| REQ-032-004 | case-close は PR 本文の capture セクションから intake と learning を分離回収し各ドメイン状態に保存すること |
| REQ-032-005 | case-close における intake と learning 候補の入力源は PR 本文のみとし一時会話コンテキストを排除すること |
| REQ-032-006 | case-close における学びの検知はエージェント自律としユーザーへの有無問い合わせを行わないこと |
| REQ-032-007 | case-close は PR マージ前にローカル未コミット変更と対象 PR 変更ファイルの重複を検出し重複時は停止またはユーザー対応を促すこと |
| REQ-032-008 | case-close は pull 前にローカル変更を検出した場合変更を保持したまま停止し自動リセットを行わないこと |
| REQ-032-009 | case-close は branch または worktree 削除失敗時は警告して停止し危険な自動削除を行わないこと |
| REQ-032-010 | case-close は squash merge 失敗時に rebase による機械的コンフリクト解消を試みること |
| REQ-032-011 | case-close は rebase でコンフリクトが発生した場合実装変更を行わず上級オーケストレータへエスカレーションすること |
| REQ-032-012 | case-close は PR マージ前に mergeable 状態を確認し不明の場合は確定まで待機し上限超過時はマージ中止して停止すること（待機の詳細は SPEC） |
| REQ-032-013 | case-close は統合先ブランチ（REQ-042 の定義による、既定 main）同期時に worktree 状態、ref lock 競合、統合先以外のブランチ占有のリスクを事前検出し安全な代替同期手順を選択すること |
| REQ-032-014 | case-close は全 test strategy 項目が合格済みまたは Findings 記録済みであることを完了条件とし未処理項目が残る場合完了扱いしないこと |
| REQ-032-015 | case-close は Epic Issue 指定時 Epic Issue 本文から現在 Wave の PR 作成済み子 Issue を特定し PR マージと子 Issue クローズを行うこと |
| REQ-032-016 | case-close は最終 Wave 処理時 Epic Issue 自体をクローズし Epic レベルの最終処理を行うこと |
| REQ-032-017 | case-close は最終 Wave 以外の処理時残 Wave 状況を通知すること |
| REQ-032-018 | case-close は中間 Wave 終了時に当該 Wave の PR 対象範囲の完了条件のみ評価更新し最終 Wave で Epic 全体の完了条件を評価すること |
| REQ-032-019 | case-close は完了条件評価更新後に Issue 本文を再読込し未達チェックボックスが残る場合構造化エラーで停止すること |
| REQ-032-020 | case-close は乖離検出で削除、変更対象キーワードの docs 全体検索を必須ステップとすること |
| REQ-032-021 | case-close は Epic 自動クローズ判定の前に全子 Issue の open と closed 状態を事前取得すること |

## 適用範囲

- 対象: case-close（達成判定、整合確認、Decision 確認、PR マージと Issue クローズと永続化とクリーンアップの分離報告、intake と learning 回収、ローカル変更安全停止、branch と worktree 削除安全、rebase による機械的コンフリクト解消とエスカレーション、mergeable 待機、main 同期安全、test strategy 完了条件、Epic Wave クローズと完了条件評価、docs 全体検索、Epic 自動クローズ判定の事前状態取得）
- 対象外: QG-4 検査規則の定義（agentdev-quality-gates）、Epic Issue 本文単一書き手規則（Epic と Wave 実行モデル REQ）、委譲時の判断と承認（REQ-003）、mergeable 待機の詳細パラメータと capture の Split Rule（SPEC）
