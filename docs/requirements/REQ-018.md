## 目的

git worktree を作業環境とする場合の構造系テストの実行環境と、worktree に固有の構造的制約を扱う。
worktree は独立した working tree を持つため、本体リポジトリ直下を前提とする検査が worktree 内では成立しない事象へ対処する。
agentdev-git-worktree skill が worktree 操作を所管する一方、本 REQ は worktree 環境下で構造系テストが成立するための fallback 契約と制約の明文化を所管する。

## 要件

| ID | 要件 |
|---|---|
| REQ-018-001 | commands_e2e、skills_structure、templates_structure 等の構造系テストは worktree junction 未設定時に src/opencode/ への fallback で実行されること |
| REQ-018-002 | worktree の独立 working tree に起因する構造的制約（gitignore 対象ファイル受け渡し不可、junction 依存 checker の skip 挙動、永続シェルセッションの workdir ハンドルに起因する worktree 削除後の空ディレクトリ残留と git 管理状態による削除完了判定、git 管理外実体の worktree 未投影に起因する SoT パス起点実行・src 側のみ編集・依存整備の運用）を agentdev-git-worktree skill references へ明文化すること |
| REQ-018-003 | third-party 取得機構経由で配置された投影物は projection manifest 突合の管理対象として検査許容され、検出ノイズとして計上されないこと |
| REQ-018-004 | worktree junction 未伝播に由来する既知検出差分は環境差として扱い、変更起因検出と混同しないこと |
| REQ-018-005 | junction 系 skill scripts および plugins 系 gate を用いる検査は、main root 実体から `--root <worktree root>` 指定（必要に応じ `--files` 併用）で実行する汎用手順として agentdev-git-worktree skill references の worktree 構造的制約に明文化されること。main 側 root での実行は読取系 check の実行のみに限定し、実行形態は `bun <path>` 形式とすること |

## 適用範囲

- **対象**: worktree junction 未設定環境での構造系テスト fallback、worktree 固有の構造的制約の明文化
- **対象外**: worktree のライフサイクル管理（agentdev-git-worktree skill 所管）、構造系テスト自体の検査項目実装（各 checker 所管）
