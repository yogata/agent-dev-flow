## 目的
<!-- 【必須】 -->

Custom Tool agentdev_gh の issue_list 操作を、安全ページ上限（operation-failed）に構造的に到達しない形で使用するための呼出側規律を運用文書へ明記する。

closed 等の広範 filter による全件列挙は、closed Case 群等の累積 population の増加により上限到達を避けられない。絞り込みクエリへの推送を呼出側義務として規律化する。

issue_list の labels 引数が追跡Issue論理軸（role、kind、trackingState）の物理マッピング入力専用であることを明確にし、Case 物理ラベルとの混同による 0 件帰着を防止する。

安全ページ上限到達時の contingency 補完手順を運用文書から参照可能にする。

## 要件
<!-- 【必須】 -->

| ID | 要件 |
|---|---|
| REQ-092-001 | issue_list 操作を closed 等の広範 filter で実行する場合、search 引数（冪等キー語、REQ 番号、topic_slug 等の絞り込みキー）を必ず併用すること。広範 filter を search なしで実行しないこと |
| REQ-092-002 | issue_list 操作の labels 引数は追跡Issue論理軸（role、kind、trackingState）の物理マッピング入力専用とし、Case Issue の物理ラベル名（enhancement、bug 等の通常ラベル）を指定しないこと。Case Issue は role: case と機械判定されるため、物理ラベル名による絞り込みは 0 件帰着または無効となること |
| REQ-092-003 | 安全ページ上限到達（operation-failed）時に、運用文書が gh issue list --search --json labels による手動読取の contingency 補完手順を参照可能な形で保持すること。Tool 正規経路を第一とし、contingency は operation-failed 時の補完手段として位置づけること |
| REQ-092-004 | issue_list の search トークンは検索対象を実効的に絞り込める選択性を持つ語（冪等キー語、REQ 番号、topic_slug 等）を用いること。同一バッチの Case 群本文に頻出する相互参照トークン（兄弟 Case の RU 番号等）は選択性が低いため、単独の絞り込み根拠として用いないこと |

## 適用範囲
<!-- 【必須】 -->

- **対象**:
  - Custom Tool agentdev_gh の issue_list 操作の呼出側運用規律
  - issue_list 運用規律の運用文書（配布 skill reference issue-operation-safety.md、agentdev-issue-tracking Design 物理写像表補記）への明記
- **対象外**:
  - agentdev_gh の実装・操作契約自体の変更（完全一覧契約、安全上の上限、失敗分類は現行契約を維持）
  - gh CLI contingency 手順自体の新規整備（Tool 操作契約の一覧完全性節が定める呼出側回避手順として既存の contingency を参照）
  - issue_list 以外の操作への規律拡張
