## 目的

bun test の実行起点（cwd）とパス指定形式の非統一により、環境依存 fail やテスト未実行（0 件実行）が繰り返し発生した（case 2766/2768/2777/2779）。bun test の全実行形態を「repo root 起 cwd + `./` 付き相対パス指定」に統一し、逸脱時に実行形態由来であることを検知できるようにする。QG-4 フル suite 正規形（agentdev-quality-gates 正規所有）の所有権は侵食せず、参照・補完に留める。

## 要件

| ID | 要件 |
|---|---|
| REQ-060-001 | bun test の全ての実行（フル suite の 3 cwd 分割正規形に加え、単独実行・ファイル単体指定を含む）は、起動 cwd をリポジトリルート（main root または worktree root）に統一し、対象パスを `./` 付き相対パスで指定すること。ファイル単体指定も `./` 付きとし、`.opencode/...` のような `./` なし表記は標準としないこと |
| REQ-060-002 | bun test 実行形態契約には、逸脱時の検知条件（REPO_ROOT を cwd からの相対解決で求めるテストの fail、bun test 出力の no test files matched による 0 件実行、worktree node_modules 未伝播由来の依存解決失敗）が併記されていること |
| REQ-060-003 | bun test 実行形態契約は、QG-4 フル suite 正規形（agentdev-quality-gates が正規所有）の所有権を侵食せず、参照・補完に留まること |
| REQ-060-004 | bun test 実行形態由来の環境依存 fail・0 件実行の知識が docs/knowledge/ に文書化され、既存の bun test 関連知識と相互参照されること |
| REQ-060-005 | agentdev-quality-gates 配布 references から、bun test 単独実行・ファイル単体指定の実行形態規約（checker 実行契約 Design の該当セクション）への参照が存在すること |

## 適用範囲

- **対象**: bun test の全実行形態（フル suite、単独実行、ファイル単体指定）、checker 実行契約 Design の bun test 実行形態契約、bun test 実行形態由来の知識文書（docs/knowledge/）、agentdev-quality-gates 配布 references からの参照
- **対象外**: QG-4 フル suite 正規形の所有権と記述内容（agentdev-quality-gates が正規所有）、bun test 以外の checker 実行形態、bun test ランナー・スクリプトの実装詳細
