## 目的

AgentDevFlow の配布成果物を適用先プロジェクトへ同期、導入する基盤と、GitHub Issue/PR を使えない環境向けのローカル版導入方式を所有する。
配布基盤は原本と配置先の乖離を検出、報告、解消する手段を提供し、一回限りの初回導入と継続的な同期を分離する。
ローカル版は link mode により配布成果物を接続し、GitHub Issue/PR の役割をローカルCaseファイルで置き換える。
実行時パッケージ境界は link mode における原本保護と配置先の一意性を担保する。
配布成果物の原本配置、配置先の宣言、ドメイン状態ディレクトリは REQ-002 が所有し、本 REQ はそれらを同期、導入する基盤を所有する。
外部システムとの I/O 境界は REQ-011 が所有し、本 REQ はローカル版における agentdev-gh-cli の差し替え接続点を交叉参照する。

## 適用範囲

- **対象**:
  - 同期基盤（原本と配置先の乖離検出、同期、移行手段、3モード分離）、シンボリックリンク健全性検出、リポジトリ種別定義と .opencode/ の意味の切替、プロジェクト固有命名規則、symlink または junction ベースの link mode による導入モデル、具体化された release archive projection（別個の配布・検証 projection）と link projection の区別、導入先インストール対象と推奨 .gitignore
  - ローカル版導入方式（link mode、src/opencode-local/ 原本領域、link target 確認、unlink/relink による更新運用、変換スクリプト不使用、generated_by 非主制御化、runtime-overrides/ 不設置）
  - ローカルCaseファイルの基本構造、YAML 前書き、status、labels、必須セクション、ローカル版 case-open/run/close の動作、マージ結果記録、GitHub 固有参照の違反基準
- **対象外**:
  - 配布成果物の原本配置、配置先の宣言、正規名前空間、repo-local 名前空間、ドメイン状態ディレクトリ、配布物依存スキルの src 昇格（REQ-002）
  - agentdev-gh-cli の I/O 境界、手続き委譲基盤、外部実行バックエンド連携（REQ-011）
  - link mode の接続手順の技術詳細、ローカルCaseファイルの詳細 schema、status 遷移表、labels 値域、見出し一覧、マージ結果 schema（Design）
  - ローカル版と GitHub 版の同一 .opencode/ 内での同居、複数利用者による同時実行排他制御、GitHub 版との双方向同期、link 接続された .opencode/ 配下成果物のリポジトリ管理、バックエンド抽象化、GitHub 互換ローカルサーバ、コピーベースインストール、npm/package 化
