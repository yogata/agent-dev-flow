## 課題内容

サブエージェント（子セッション）間で探索（read）の責務を分割すべきか否かを判断する。

改善前分析では、異なる子セッション間で同一 path が読み込まれる探索重複が確認されている。
この重複を責務分割で除去するか、重複を許容する現行構成を維持するかは未解決である。

## 背景

RU-0001（OpenCode セッション分析に基づく ADF 実行効率の第1次改善）の検討過程で、改善前の OpenCode セッション履歴の分析が実施された。
分析の結果、探索重複が実行効率への影響要因として識別された。
RU-0001 は REQ-048（ADF 実行効率第1次改善（実行観測基盤））として要件化され、実装済みである。

## 影響

探索責務分割は子セッションの構造変更を伴う。
判定結果は以後の case 実行全般（設計、実装、検証の各工程）の探索効率と、検証の独立性に影響する。

## 関連成果物

- docs/requirements/REQ-048.md: RU-0001 に由来する ADF 実行効率第1次改善の要件。本課題の再評価は RU-0001 の改善効果の観測を待つ
- docs/reports/req-048-reanalysis-baseline.md: 改善前分析のベースライン。判断材料の出所

## 選択肢

- 探索責務を分割する: 子セッションごとに読込範囲を割り当て、重複読込を抑止する
- 探索責務を分割しない: 現行の重複許容構成を維持する

## 判断材料・証拠

- 改善前分析で、read を伴う97論理実行単位のうち68単位で、異なる子セッション間の同一 path 参照を確認した

## 不足情報

- RU-0001 の改善効果の実運用での観測結果（改善適用後のセッション履歴に基づく残存重複の実態）

## 再評価条件

### 判断保留の理由

RU-0001 の改善効果を観測する前に構造を変更すると、原因と効果を分離できない。
改善前後で比較可能な観測が得られるまで、変更の要否を判断しない。

### 再評価条件

RU-0001 の改善を実運用へ反映した後、改善前と同じ観点で比較可能な OpenCode セッション履歴が十分に蓄積したこと。

再評価時には次の再分析事項を確認する。

- 子セッション間の同一 path 再読込
- source / projection 由来の重複を除いた残存重複
- 工程間の文脈引き継ぎ不足による重複
- 独立検証として必要な重複
- 同種検証による新規 finding の有無
- 残存する不要な探索重複
- 残存重複の token 消費への影響

再評価結果は次のいずれかに分岐する。

- 不要の場合: 探索責務分割を実施せず、解決してクローズする
- 判断不能の場合: 理由を追記して保留を継続する
- 必要の場合: 解決し、当該変更を新規 RU として要件化する
