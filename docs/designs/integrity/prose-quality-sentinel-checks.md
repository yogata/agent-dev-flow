# 既知不備センチネル検査

配布 command・skill の文章品質是正における既知不備の残存を確認するセンチネル検査の項目カタログと検出方式を正規所有する。
REQ-053-022 が要求する「既知不備として固定した項目の最終 HEAD での残存は決定的に確認できる」ことを本 Design が実現する。
センチネルは全件再査読が正しく行われているかを確認する最低限の検査対象であり、修正範囲をこの項目に限定しない。

## 対象ファイル集合

検査対象は REQ-053 の文章品質契約の対象配布物と同一集合である。

- 配布 command 本文: `src/opencode/commands/agentdev/*.md`（`README.md` はコマンド定義件数に含めない）
- 配布 skill 本文: `src/opencode/skills/agentdev-*/SKILL.md`

実行開始時点と最終検証前に実ファイルから対象を列挙し、追加・削除・改名されたファイルを最終検証対象へ含める。

## センチネル項目カタログ

14 項目を定義する。
項目ごとに検出方式を 2 段に分類する。

| 項目 ID | センチネル | 検出方式 |
|---|---|---|
| S-01 | 「工程上の選好を肯定形の不変条件として示す:」 | 列挙後確認 |
| S-02 | 「硬い境界（破壊的操作・state 破壊等の否定規則）に限定する:」 | 列挙後確認 |
| S-03 | 「Decision保存の直前に妥当性を再検証する:」 | 列挙後確認 |
| S-04 | 「status 维持」 | 確定一致 |
| S-05 | 「查読」 | 確定一致 |
| S-06 | 「docs/decisions<README>.md」 | 確定一致 |
| S-07 | 既知の壊れたテンプレート参照 | 確定一致 |
| S-08 | 「-066」（不在 ID 番号への参照残骸） | 確定一致 |
| S-09 | 「-151 相当」 | 確定一致 |
| S-10 | 「根拠のない〜を正とする」 | 列挙後確認 |
| S-11 | 「根拠のない〜が正」 | 列挙後確認 |
| S-12 | 「順序の正」 | 列挙後確認 |
| S-13 | 「操作知識の正」 | 列挙後確認 |
| S-14 | 「非破壊性の正」 | 列挙後確認 |

## 検出方式の 2 段分類

### 確定一致（機械判定）

文字列の出現そのものが違反である項目である。
完全一致または正規一致で決定的に検出できる。

- S-04、S-05: 簡体字中国語文字の混入である。文字列一致で検出する
- S-06: 誤記リンク表記である。正規表現で検出する
- S-07: 既知の壊れたテンプレート参照の具体パターンである。パターン列挙を本 Design が所有し、列挙したパターンへの一致で検出する
- S-08: 現行体系に不在の ID 番号への参照残骸である。ID 参照内の `-066` を正規表現で検出する。行番号が 66 を超える REQ 行 ID の増加時は本項目の対象語を更新する
- S-09: 無関係な外部番号を引き合いに出した残骸表記である。文字列一致で検出する

確定一致の検出は機械検査として実行でき、REQ-053-012 の決定的検査の検出シグナルへ組み込み可能である。

### 列挙後確認（列挙後に規範参照を確認）

表現の出現を列挙したうえで、出現箇所が規範原本への参照を伴うかを確認する項目である。

- S-01、S-02、S-03: 工程上の選好を不変条件として示した見出し・箇条書き表記である
- S-10 から S-14: 規範宣言の「〜を正とする」「〜が正」形式の無根拠使用である

REQ-053-005 は「規範原本への参照を伴い、定義元・参照元・所有関係のいずれの関係か一義的に判断できる場合」の規範宣言を許容する。
そのため出現そのものは違反と確定できず、出現箇所の列挙後に規範参照の有無を確認する。
この確認は最終全件検証の手順として実行し、機械検査だけでの確定をしない。

## 合格条件

提出対象となる最終 HEAD の実ファイル全文に対して検査を実行し、14 項目すべての残存が 0 件であることを合格条件とする。

- 確定一致項目: 機械検査で残存 0 件を確認する
- 列挙後確認項目: 出現 0 件、または出現箇所すべてで規範参照の確認が完了し違反なしと判断された場合に 0 件とみなす

意味の確定ができない箇所は REQ-053-013 に従い blocked として記録する。
blocked が残る間は REQ-053-020 により完了としない。

## REQ-053-012 の決定的検査契約との関係

REQ-053-012 は機械判定可能な文章品質違反の決定的検査の存在を契約し、個別 checker の実装方式を Design へ分離している。
本 Design の確定一致型センチネル（S-04 から S-09）は機械判定可能な性質を持ち、決定的検査の検出シグナルとして実装できる。
列挙後確認型センチネル（S-01 から S-03、S-10 から S-14）は機械判定のみでの確定ができないため、REQ-053-012 の「決定的検査」の対象からは分離し、最終全件検証の手順（列挙後の規範参照確認）として実行する。
両段を合わせて REQ-053-022 の「残存は決定的に確認できる」を満たす。

## 決定的破損検査クラス Design との関係

決定的破損検査クラス（`content-corruption-checker`）は Markdown 構造破損、制御文字混入、不正な Unicode 文字、意図しない異言語文字、既知形式の参照残骸の 9 検出カテゴリを機械検査として正規所有する。

- S-04、S-05（簡体字混入）は `foreign-script` / `invalid-unicode` カテゴリと検出機構を共有できる
- S-06、S-07、S-08（誤記・壊れた参照・不在 ID 参照）は `broken-link` / `stale-reference` カテゴリと検出機構を共有できる

共有可能な場合でも、センチネルは「過去に発見された既知不備の残存確認」という目的特化の検査であり、決定的破損検査クラスの検出カテゴリの一般化・再編を行わない。
列挙後確認型は機械判定不能の査読・手順観点であり、決定的破損検査クラスの対象外である。

## 対象外

- センチネル以外の文章品質違反の全件検査手順（REQ-053 の品質観点を最終全件検証で適用する手順そのもの）
- checker 実装への新規組み込みと回帰テストの新設（REQ-010-068 の回帰テスト義務は checker 実装時に発生する）
- 配布物以外（repo-local command、docs/ 配下の本文記述）への適用
