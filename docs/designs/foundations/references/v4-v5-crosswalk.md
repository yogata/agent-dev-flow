# v4 -> v5 Concept / Artifact Crosswalk

位置づけ: 本 Design は v4 現行要件行の v5 での処遇を記録する棚卸し構造（crosswalk）である。
REQ-108「ADF v5 有限実行とワークフロー責務再編」のうち、移行期権威行（REQ-108-012）の
設計対応として、v5 の実行モデルの実現確定までの間に v5 モデルと両立しない現行要件行を
棚卸し対象として優先順位を付けて管理する。分類スキーマ、権威移行の管理構造、優先行の
処遇記録を本 Design が所有する。他 Design による本 crosswalk の参照は、(a) 処遇未完了
エントリの処遇記録としての参照と、(b) 現行契約の正規所有を本 crosswalk に求める参照に
分類する。(b) の参照は現在の正規所有者へ付け替え、(a) は処遇が完了するまで本 crosswalk を
参照先として維持する。

## 分類スキーマ（3 列）

処遇は次の 3 列で記録する。

- 意味処遇: keep（v5 でも保持する）/ redefine（v5 で意味を再定義する）/ supersede
  （後継が確定した置換）/ retire（後継なしの廃止）/ defer（v5 の実行モデルの実現確定まで
  処遇判断を留保する棚卸し対象）
- 帰属: v5 有限実行の責務分割語彙（要件確定 / 設計確定 / 実装・構築 / 検証 / Issue 協調 /
  後処理）で表記する。現行の帰属語彙（semantic Skill、deterministic code/tool 等）を
  記録済みのエントリでは、実行時点の v4 語彙の値を保持する
- 処遇時点: 現時点では棚卸し対象の記録（planned）のみ。v5 の実行モデルの実現確定時に
  confirmed、処遇実行完了時に executed へ遷移する（living tracking）

## 処遇実行原則

- 本 Design は棚卸し構造である。優先順位を付けた棚卸し対象の記録までを扱い、対象行の
  実際の再定義・廃止の実施は本 Design の対象外とする。処遇の実行は後続の正規改訂経路
  （REQ-108-005）で行う
- 宣言型移行パターン（v3 -> v4 crosswalk 先例の踏襲）: 処遇は宣言的に記録し、対象行本文を
  本 Design から書き換えない。処遇未完了エントリは削除せず処遇記録として保持する
- 移行期権威行（REQ-108-012）: v5 の実行モデルの実現確定までの間、現行の実行契約
  （REQ-005、REQ-006、REQ-030、REQ-031、REQ-032、REQ-034、REQ-035、REQ-061、REQ-062 等）
  が実行経路の正として維持される。棚卸し対象の現行行は移行期権威行の保護下にあり、
  現行どおり正である

## 権威移行の管理構造

- 権威の現在地: v5 の実行モデルの実現確定までは現行実行契約が実行経路の正である
  （REQ-108-012）。v5 の実現確定後は、採用規約機構（v5-adopted-conventions Design）が
  採用済み工程・成果物の基準源となり、本 crosswalk が記録した処遇へ従って現行行が
  再定義・廃止される
- 管理された矛盾の合意方法: v5 新規 REQ（REQ-104〜109）と現行要件行の間で宣言が競合する
  場合、移行期権威行（REQ-108-012）または本 crosswalk の棚卸し対象記録のいずれかに含まれる
  場合を「管理された矛盾」とする。どちらにも含まれない矛盾（未管理矛盾）を観測した場合は
  本 Design の棚卸し対象集合へ直ちに記録する
- 処遇記録の更新契機: 新たな競合候補を観測した場合、本 Design の棚卸し対象表へ追記する。
  処遇の confirmed / executed 遷移は、v5 実行モデルの実現確定と処遇実行を担当する後続
  工程が行う

## 後継経路（工程駆動実行）の処遇確定記録様式

REQ-111、DEC-058 に基づく工程駆動実行の確定は、REQ-005-001/010/011 の再定義行に対し次の様式で記録する。

- 確定契機: 後継経路の実現（テーマ初回形成、テーマ更新、正規成果物への反映、独立レビューの4操作と利用者判断による工程遷移の実装）、検証（実装着手時の有効な正規契約の外部的結果を基準とした合格、REQ-111-010）、正式採用（採用規約機構への採用登録）の3点が揃った時点を confirmed 遷移の契機とする
- 前提: 設計PR の作成・マージだけでは、後継経路の実現確定、処遇の confirmed 遷移、旧経路の失効を意味しない（DEC-058、REQ-108-012）
- 記録方法: 対象行（REQ-005-001、REQ-005-010、REQ-005-011）の意味処遇列は redefine のまま維持し、備考列へ confirmed 遷移の時点と根拠（検証証跡への参照）を追記する。対象行本文の書き換えは処遇実行（executed）時に行う
- 移行期条項: confirmed 遷移後も、v4 経路の変更駆動能力群の外部的結果と検証義務（REQ-111-010）は処遇実行が完了するまで現行経路の記述どおり維持する。confirmed 遷移を旧経路の失効扱いにしない

## 集約サマリ

- 優先行6項目（REQ-030-001、REQ-005-001、REQ-005-010、REQ-005-011、REQ-035-006、REQ-061周辺行）を棚卸し対象として記録した。keep 1 / keep・defer 1 / defer 1 / redefine 3
- REQ-005-001/010/011 は REQ-111 と DEC-058 に基づく変更駆動・工程駆動の併存モデルへ再定義する。後継経路の実現・検証・正式採用が成立するまでは現行経路の権威を維持し、設計PR の作成・マージだけで処遇確定や旧経路の失効を扱わない（REQ-108-012）
- v5 新規 REQ と現行要件行の宣言なし直接矛盾の検証では、競合候補は上記優先行に集約され、全て本 crosswalk の棚卸し対象記録または移行期権威行（REQ-108-012）により管理される。未管理矛盾 0 件（検証結果は当該 Case の PR 本文検証差分を参照）
- 本 Design は棚卸し構造であり、優先行の実際の再定義・廃止実施と v5 実現確定後の現行公開経路の置換・廃止は対象外である
