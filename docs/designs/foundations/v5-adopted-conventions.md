# ADF v5 採用規約機構（採用済み工程・成果物規約の宣言・保存・解決）

位置づけ: 本 Design は、プロジェクトが採用した詳細工程・工程間関係・必須成果物（以下「採用規約」）を宣言・保存し、対象作業の基準として参照して解決する機構を定義する。REQ-104「ADF v5 基盤要件（共通責務とプロジェクト別工程構成）」のうち、採用済み工程・成果物の解決と保持、および未採用参照例を欠落と誤判定しない判定の設計対応を所有する。採用規約の機械的解決器の実装面は本 Design の対象外であり、後続の実装 Design へ委譲する。

## 目的と適用範囲

ADF v5 は、要件定義・設計・実装・構築と各段階の検証を共通責務として全プロジェクトへ必須基準として適用する。基本設計・詳細設計・環境定義等の詳細工程は任意の参照モデルであり、プロジェクト方針による採用に委ねられる（ADF v5 工程・成果物モデル Decision、REQ-104）。

この構造の下では、参照モデルに示された工程・成果物をそのまま判定基準として取り違える誤判定が生じ得る。本 Design は次の 3 機能を持つ機構を定義してこの誤判定を防ぐ。

1. 宣言: プロジェクトが詳細工程・工程間関係・必須成果物を採用した事実と内容を明示する
2. 保存: 採用の事実と内容を、対象作業の実行時点から再構成できる形で保持する
3. 解決: 対象作業が基準となる採用済み工程・必須成果物を、採用規約から確認する

適用対象は、工程構成に基づいて成果物の有無・成立を判定するすべての作業（Case 実行、品質ゲート、docs 診断等）である。

対象外は次のとおりである。

- 採用規約機構の実装面（機械的解決器の実装）
- 採用規約の具体的な保存形式・解析方式・設定ファイル名の固定（REQ-104 の適用範囲が対象外とする領域を継承する）
- WBS・工数・要員・予算・進捗率の管理機能
- 隣接工程間対応・追跡単位・差分影響評価（ADF v5 追跡・品質検証モデル Decision と後続 Design が所有する）

## 採用規約の構成要素

採用規約は、プロジェクトが採用した次の 3 要素の宣言的集合である。

| 構成要素 | 内容 | 例 |
|---|---|---|
| 採用済み工程 | プロジェクトが必須として採用した詳細工程の種別と範囲 | 詳細設計、環境定義 |
| 工程間関係 | 採用済み工程間の順序・依存・上位下位関係 | 詳細設計は基本設計の確定後に実施する等 |
| 必須成果物 | 採用済み工程ごとに必須とする成果物と、その成立条件 | 工程の完了判定に用いる成果物 |

採用規約は宣言的である。参照モデルの工程を既定で必須化せず、採用されていない工程・成果物は判定基準に含まれない。

前提として、工程構成の説明（プロセスモデル）と対象システムの設計内容（システムモデル）を別の関心として区別する（REQ-104 の工程構成の区別要件）。採用規約はプロセスモデル側の宣言であり、システムモデルの設計内容を所有しない。

また、工程の分割・統合・省略が行われる場合も、元の要求・制約・受け入れ条件・検証義務は失われない（REQ-104 の工程再構成要件）。採用規約の採用済み工程を再構成する場合、この要件を保存側の更新契約として満たす。

## 宣言と保存

採用規約の宣言・保存は、Project Model 層の正規成果物として行う（v4 Operating Model「三層責務モデル」節の層帰属に従う）。プロジェクトの採用する工程・成果物規約は Project Contract の再構成要素の一部として扱う（ADF v5 工程・成果物モデル Decision の関連宣言）。

- 採用規約は、プロジェクトが参照・再構成できる正規成果物として保存する。会話・記憶・一時コンテキストを保存先としない
- 採用宣言には、採用の適用開始点と、採用規約の 3 構成要素（採用済み工程、工程間関係、必須成果物）を含める
- 保存形式・配置先の具体名は本 Design では固定しない。ただし、採用規約が決定的に読み取れて、対象作業から正規の参照点へ到達できる構造であること
- 採用規約の変更は、プロジェクト方針の変更として正規の変更手続き経由で行う。未反映の変更方針を判定に使用しない

## 解決手順

解決とは、対象作業が基準となる採用済み工程・必須成果物を確認する手続きである。手順は次のとおりである。

1. **採用宣言の確認**: プロジェクトの採用宣言が存在するかを確認する
   - 採用宣言が存在する場合: その宣言を正規の採用規約として解決する
   - 採用宣言が存在しない場合: 移行期デフォルト（次節）へ接続する
2. **基準の特定**: 採用規約から、対象作業に適用される採用済み工程・工程間関係・必須成果物を特定する。参照モデル（未採用の例示）は基準の特定の入力にしない
3. **判定**: 特定した必須成果物を判定基準として、対象作業の成果物の有無と成立根拠を判定する

解決が実行不能な場合（採用規約の読取不能、基準の特定不能）は、判定を下さず判断留保として扱う。実行不能な解決を、全要件の不存在や全工程の省略として解釈しない。

### 移行期デフォルトとの接続

REQ-105「ADF v5 成果物の意味と工程別正式確定」の移行期デフォルト要件に従い、プロジェクトが v5 の工程・成果物規約の採用宣言を行うまでの間は、当該プロジェクトの現に実効している工程・成果物の運用を採用済み規約として扱う。

- 接続方式: 移行期デフォルトは、解決手順の第 1 段階で採用宣言不在時に接続される第 2 の基準源である。解決手順そのものは単一経路であり、デフォルト専用の別手順を作らない
- 現に実効している運用の確認: 現行の正規成果物（REQ・Decision・Design・配布物の workflow 定義等）が実効している工程構成・成果物運用を、移行期デフォルトとして解決する。実効していない参照例の工程を、現行運用に読み込んで解決しない
- 接続の終了: 採用宣言が行われた後は、採用宣言を正規基準として解決し、移行期デフォルトを判定に使用しない。移行時に既存の有効な正規情報の意味と関係を保つ方式は ADF v5 移行と互換性の境界 Decision（REQ-109「ADF v5 移行と互換性の境界」）に従う

### 未採用参照例を欠落と誤判定しない判定規則

参照例と採用済みを区別する。ADF が示す詳細工程の参照例（基本設計・詳細設計・環境定義等）は、プロジェクトが採用した場合に限り判定基準になる。

判定規則は次の 2 条である。

1. **誤判定禁止**: 採用されていない参照例の工程・成果物が存在しないことを、欠落と判定しない。参照例は基準に含まれず、基準に含まれない成果物の不在は正である
2. **省略合格禁止**: 採用済みで必須の成果物が存在しない場合、ファイル不在だけを根拠に工程省略として合格させない。工程省略は、採用規約上の採用外・省略の明示、または対象作業の実行契約における根拠ある除外宣言によってのみ成立する。ファイル不在は欠落として検出した上で根拠確認（作成・採用外・省略のいずれかに分類する確認）を経て解消し、根拠確認を経ない不在は欠落のままとする

判定の入力は採用規約（または移行期デフォルト）であり、参照モデルの工程一覧を入力にしない。この入力限定により、採用していない参照例の不在が欠落として計上される誤判定を構造的に防ぐ。

## 責務境界

| 関心 | 正規所有 |
|---|---|
| 本 Design が所有する | 採用規約の宣言・保存・解決の構造、移行期デフォルトとの接続、未採用参照例の判定規則 |
| 採用規約機構の実装面（機械的解決器） | 後続の実装 Design |
| 詳細工程の参照モデル化と成果物の意味境界 | REQ-104、REQ-105、ADF v5 工程・成果物モデル Decision |
| 採用規約と Project Contract の関係 | v4 Operating Model「Project Contract の論理ビュー」節 |
| 隣接工程間対応・追跡・品質検証の責務分離 | ADF v5 追跡・品質検証モデル Decision と後続 Design |
| 工程独立実行・有限実行・Issue の必要時利用 | ADF v5 有限実行と責務再編 Decision と後続 Design |
| 移行の標準境界 | ADF v5 移行と互換性の境界 Decision と後続 Design |
