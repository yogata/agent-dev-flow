# ADF v5.1 工程遷移・独立レビューと双経路併存モデル

## 目的と適用範囲

本 Design は REQ-111 が定める工程遷移、独立レビュー、有限作業、変更駆動との併存に関する内部設計の要綱を示す。公開操作の最終名（phase-tasks-create、phase-tasks-update、phase-artifacts-update、phase-review、phase-transition）と保存方式（.agentdev/phase/ 配下の保存状態）は実装・公開済みである。Capability Skill 等の具体的なスキル構成の分担と個別 command Design の整備は確定していない部分であり、外部動作と検証義務を保つ範囲で後続設計に委ねる。

## 工程遷移

工程の完了・遷移は利用者が判断する。遷移操作は確定した工程関係と既知義務を次工程へ渡し、前工程を完了済みの過去工程として一回だけ記録する。利用者が取消した場合は現在工程を維持する。工程の解決不能、永続化失敗、中断後の再実行では成立済みの状態を正規記録から復元し、未成立の技術処理を成功として扱わない。

採用済み工程関係に後続工程がない場合は終端として扱う。後続が1件なら一意に選び、複数件なら利用者の選択を求める。複数の前置工程がある場合は既知義務と未確認範囲を保持して引き継ぐ。遷移後の初回テーマ形成は遷移成立と独立させる。

## 独立レビュー

独立レビューは既定要求、対象成果物、検証証拠と照合し、確定違反、証拠不足、推測、未採用改善候補を区別して所見を示す。テーマの解消や構造上の成立だけで要求充足・工程完了を認定しない。レビューを工程完了の必須ゲートとせず、レビューの深さも必須基準にしない。

## 有限作業と実装接続

利用者が要件確定または設計確定だけを求めた場合は、その有限作業と正規成果物・技術的根拠を確定して終了する。Issue、PR、後続実装を一律に要求しない。利用者が確定済み詳細設計、有限な実装対象、既存検証条件を示した場合は、最新の実リポジトリ、対象、依存、証拠を確認して実装・検証へ接続する。未検証結果は未検証として報告する。

## 過去工程の改訂と影響伝播

完了済み過去工程の正規改訂は、下流が実際に依拠した版と現行版の差を起点に必要な下流更新・再検証へ接続し、現在工程を巻き戻さない。中間工程の更新必要・不要・作成・未確認とその理由を保持する。処理失敗時は全反映完了を宣言せず、再開に必要な情報を示す。対応関係や正味差分がゼロでも無影響の証明とはせず、実在成果物・途中版への実依拠と再利用する旧証拠の現行適用可能性を確認し、比較不能な対象は未確認とする。差分・影響評価の一般義務は REQ-106 に従う。

## 外部検討結果の受入経路との分離

phase-review の所見と外部AIからの戻り入力は別の概念として扱う。外部AIから受領した入力を intake inbox へ自動投入しない。採用する場合は根拠を示す受理経路を通し、Learning / Intake の既存責務と混同しない。

## 双経路併存と移行

変更駆動（req-define → case-auto）と工程駆動（4操作と利用者判断による工程遷移）は独立した正規利用経路として併存する。変更駆動は工程駆動の操作・遷移を前置必須とせず、従来の外部的な作業結果と検証義務を維持する。旧コマンド名や旧内部構造の一致は合否条件としない。後継経路の実現・検証・正式採用が成立するまでは REQ-108-012 に従って現行経路を正として扱う。設計PR の作成・マージだけでは、後継経路の実現・検証・正式採用を満たさない。

## 実行主体と責務境界

| 操作 | 実行主体分類 | 責務境界 |
|---|---|---|
| 独立レビュー | Workflow Skill と GitHub／Local の公開入口 | Skill が所見区分と意味評価を担い、入口は両版の正規利用経路へ接続する。レビューは工程完了ゲートにしない |
| 工程遷移 | 公開操作（command／adapter）と harness の状態保存 | 利用者が遷移を決定し、操作は正規状態の一回記録、再開、失敗報告を担う |
| 確定済み設計からの実装接続 | case 系 workflow、実行担当 subagent、harness | 既存 case 実行契約を再利用し、最新リポジトリの実変更と検証証拠を確認する |

公開名（phase 系 5 公開操作）と保存実装（.agentdev/phase/ 配下の保存状態）は確定済みである。既存 case 系実行契約および REQ-009/106/107/109 の契約を重複定義しない。

## 検証時参照

REQ-111 の受け入れ条件（REQ-111-001〜013）、v4-v5-crosswalk の処遇記録、および DEC-057/058 の承認記録を検証時参照として用いる。実現面の責務は次の RA を保ち、検証は REQ-111 の各受け入れ条件の合格条件と反例を確認する。次表の TS-001〜TS-014 は削除済み一時成果物 RU-0002 出所の検証項目番号であり、出所の履歴注記として保持する。
