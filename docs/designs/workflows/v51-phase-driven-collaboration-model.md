# ADF v5.1 工程駆動コラボレーションモデル

## 目的

本 Design は REQ-110 の外部契約を満たす工程駆動コラボレーションの保存構造、操作手順、実行主体と責務境界を定める。工程駆動は変更駆動を置き換えず、両経路は同じ正規成果物と有効な合意を利用する。

## 設計原則

- 採用済み規約と既存の有効な実効規約を優先し、参考案を自動で必須化しない。規約の状態は採用宣言あり、宣言なしで実効運用あり、どちらもなし、宣言があるが読取不能の4状態に分ける。既存規約がある場合はそれを適用し、基準がない場合に限り標準案を未採用候補として示す。読取不能時は判断を留保する。
- 工程全体の完了をADFが認定しない。工程遷移は利用者判断による独立操作とする。
- テーマは参照用の検討単位であり、テーマとIssue・成果物を一対一に対応付けない。テーマ一覧はテーマ正本から導出する。
- テーマ、成果物、必要最小限の識別情報、Git履歴から対応と変更結果を再構成する。独立したテーマ履歴DB、深度採点器、作業分解管理制度を要求しない。
- 閲覧用の工程全体像を導出し、第二の更新可能な正本として保存しない。

## 工程駆動の公開操作

- `phase-tasks-create` は工程初回に参考テーマを形成する。先行する `phase-tasks-update` で作成したテーマ識別、手修正、未決事項を保持し、必要な参考候補だけを加える。既知の必須事項と新しい参考候補を分け、成果物構成や粗い検討作業の参考案も提示できる。旧 `phase-plan` による追加候補提示は次工程の初回テーマ形成へ統合する。
- `phase-tasks-update` は初回形成の前後を問わず独立実行でき、テーマの追加、具体化、分割、統合、廃止と旧新対応を扱う。
- `phase-artifacts-update` は採用済みの戻り内容を正規成果物へ増分反映し、独立反映可能な項目と衝突・未確認・保存失敗を区別する。
- `phase-review` は現在の正規成果物群から工程全体像を導出して提示する。工程の完了を認定しない。

## 保存構造と識別

テーマ正本と取組・対象版・現在工程の識別状態は `.agentdev/` 配下の domain state とする。配置は REQ-001/002 の文書体系・配布境界および REQ-009 の導入モデルに従う。保存状態は書込対象の解決、再開、受領済み検討知見の継続に必要な最小情報に限り、進行度・完了率・残作業を記録する恒久台帳を設けない。

各操作は既存の正規情報から対象の取組、対象版、現在工程を解決する。同一取組の再開では確定済み状態を復元する。別取組へ別版の工程や未決テーマを無条件に継承しない。対象を一意に解決できない場合は正規成果物への変更を保留し、候補と不足を報告する。テーマの追加、具体化、分割、統合、廃止はテーマ初回形成の前後を問わず実行できる。意味のある変更では変更理由と旧新対応を必要な範囲で保持し、実質変更のない再実行では変更報告を増やさない。

## 初回テーマ形成と更新

初回工程に有効な上流成果物がなくても異常としない。利用者が示した目的、対象範囲、既知制約と参考テーマの対応、または根拠付きの非該当・未確認を提示する。既知制約間の衝突は未決と表示し、提案を必須要求へ自動昇格しない。テーマ更新は初回形成より前でも後でも独立して実行できる。更新が先行した場合、初回形成は既存のテーマ識別、手修正、未決事項を保持して必要な参考候補だけを加える。

テーマの統合・廃止では継続対象の未決事項を後継テーマへ引き継ぎ、対象外・不要とした事項は判断根拠を追跡可能にする。未決事項を自動解消済みと扱わない。外部検討中のテーマが改名・分割・統合された後に旧識別子で結果が戻った場合は、旧新関係と現行正規成果物を照合し、安全に対応できる部分だけを再接続する。不一致または解決不能な部分は保留する。

## 外部検討の仲介

### 持出し

持出し文書には有効な目的、問い、必要な前提、参照元を示す。ADFは外部AIへ自動送信しない。既知の機密指定情報や認証値を無断で含めず、利用者が送出内容を確認・選択できる機会を設ける。未知の秘密情報を完全に自動発見する分類器は設けない。

### 戻り受理

外部AIの戻り入力は貼付と利用者が指定するファイルの両方を受け付ける。両経路は意味上同じ確定結果となるよう正規化する。外部AIの自己申告を採用根拠とせず、利用者の明示判断または有効な正規決定だけを採用根拠とする。採否が不明な部分だけを確認対象にする。

戻り入力に衝突事項と独立反映できる採用事項が混在する場合、安全な独立事項を反映可能にし、衝突、未確認、保存失敗を区別して報告する。書込失敗後の再投入では、実際に確定した状態を読み直し、未反映分だけを処理する。旧テーマ識別で届いた結果は現行の識別関係と成果物を照合し、対応できない部分を保留する。

戻り入力の受理・解釈は入力サイズ n に対して線形走査 O(n) とし、採用・不採用の記録量は明示採用件数に比例させる。不正または曖昧な入力は不採用として残し、確定しない。外部AIの出力は内容の正確性を事前保証できない外部入力であり、誤りや偽装された承認申告を含み得る。

## 正規成果物への形成と全体像

採用済みの内容は既存の有効な正規成果物へ意味のある増分として反映する。変更駆動で確定した正規成果物と合意を工程駆動でも参照・再利用する。先行合意と矛盾しない範囲を保持し、矛盾部分は根拠とともに保留する。書込みに失敗した場合は実状態を基準に再開し、重複や消失を防ぐ。

工程全体像は、その時点で有効な工程全体の正規成果物群から採用済み事項、必要な上流前提、未決事項を区別して導出する。閲覧用出力を第二の正本として管理しない。次工程の初回テーマ形成では既知の必須事項を欠落させず、新しい参考候補と区別し、成果物構成や粗い検討作業の参考案も提示できる。候補を要求や工程完了判断へ自動昇格しない。別セッションではADFが受領済みの知見を正規情報から再取得し、未受領の外部検討内容を復元したと主張しない。

## 帰納的候補の調整と限界

参考候補は有効な複数の正規成果物の実内容と工程間の対応に照らして帰納的に調整する。意味が変わらない見出しや改行の差から新しい必須条件を導出しない。資料がない、比較できない、または特殊な一例しかない場合は比較不能や適用限界を示す。未採用の自己生成案を採用済み慣行として扱わず、新しい義務や完了基準を作らない。

## 実行主体と責務境界

テーマ形成・更新、成果物反映の公開操作とWorkflow Skill群は個別の責務に分ける。テーマ正本の管理と外部検討の持出し・戻り受理はCapability Skillが所有する。各公開コマンド、Workflow Skill、Capability Skill、adapter、subagent、harness の具体的な分担は各成果物の設計時に定める。

保存・確定経路の所有境界は変更駆動では case-ready / case-revise が所有する。工程駆動ルートの経路別所有境界とDesignのdraftからacceptedへの昇格は、v4-standard-lifecycle の工程駆動対応行（REQ-111、v51-phase-transition-and-coexistence-model 参照）および v4-v5-crosswalk の処遇記録と整合させる。本 Design はその境界を再定義しない。出所: 一時成果物 RU-0002 は case-ready 成功後に削除済みであり、出所記録は v4-v5-crosswalk と DEC-057/058 承認記録に残る。

## 検証との対応

REQ-110 の受け入れ条件と検証義務を下流の設計・実装・検証で維持する。特に、別取組・別版の誤書込み防止、上流不存在と衝突の扱い、同一入力の再実行、未決の引継ぎ、旧テーマ結果の安全な再接続、持出し確認、貼付・ファイルの等価性、部分反映と再投入、全体像の再構成、根拠に基づく候補調整、移行期の採用規約解決、戻り入力の O(n)・証跡量・fail-closed 条件を各検証へ対応させる。
