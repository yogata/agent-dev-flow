# ADR-008: case-auto の限定的親判断解決（bounded parent decision resolution）

## 背景

adversarial-review は default-on + skip policy により case-auto 配下の各 caller command で原則実行される（REQ-014-013、REQ-015-002）。各 caller command は自身が所有する候補について adversarial-review を実施し、finding の意味解釈、採否、候補への反映を維持する（REQ-014-006、REQ-015 caller integration）。一方で case-auto は下位 command から user-decision-required + decision_context を受領して自走を停止し、review 直接起動、finding 解釈、採否、再評価を行わない（REQ-015-012）。

この二つの前提を両立させるため、下位 command が自身の責務と利用可能な合意済み情報で解決できない判断事項を構造化 decision_context として case-auto へ返した場合、case-auto がそれをどの範囲まで自律解決でき、どこでユーザーへ返すべきかの境界を明確にする必要がある。境界が明示されない場合、case-auto は raw finding の解釈へ踏み込むか、逆に一意に回答可能な事項でもユーザー停止を選ぶ過剰停止に陥る。

## 決定

1. case-auto は下位 command から受領した構造化 decision_context について、現行正規成果物（REQ、ADR、SPEC、Issue その他合意済み情報）から一意に回答可能な場合はユーザー停止せず回答して下位 command を resume させる（REQ-006-112）。
2. 外部仕様、互換性、データ保持、セキュリティ、対象範囲、受け入れ条件を変更しない可逆的内部詳細は、既存契約で許容された範囲に限り case-auto が作業仮定と根拠を明示した上で自走を継続できる（REQ-006-113）。
3. 上位 REQ/ADR/SPEC/Issue 等の矛盾、欠落、曖昧性が finding の対象である場合、case-auto は当該矛盾を根拠に一方を勝手に採用しない（REQ-006-114）。
4. 新しいユーザー価値判断、対象範囲変更、外部契約変更等が必要な場合のみ、case-auto は既存停止経路（REQ-006-086 停止理由分類）でユーザーへ返す。
5. case-auto は回答、根拠、または作業仮定を下位 command へ返し、既存 resume point から処理を継続する。adversarial-review の再実行要否は adversarial-review 側の再 review 契約（REQ-014-007/008）に従い、case-auto は独自の再 review 条件を持たない。
6. case-auto は中央集約 review engine とはならず、raw finding を解釈、採否、候補反映しない（REQ-015-012 維持）。

## 結果、影響

### 正の影響

- default-on + skip policy と case-auto の自走性が両立する。各 caller command の finding 採否・反映責務を維持したまま、ユーザー停止を本質的な場面へ集約できる。
- 一意回答可能な判断事項でユーザーが繰り返し確認を求められる過剰停止を防げる。
- 既存 resume point 機構（REQ-006-085）を再利用し、新規永続結果型を導入しない。

### 負の影響

- case-auto と下位 command 間の責務境界と HITL 境界が変化する。REQ-006-086 の停止理由分類へ「上位合意矛盾」「新規ユーザー判断事項」を統合して運用する必要がある。
- 「一意に回答可能」「既存契約で許容された範囲」の判定を誤ると、raw finding 解釈や勝手な合意採用へ滑り込むリスクがある。実装は判定基準を厳格に保つ必要がある。

### 整合性

- REQ-003-008/009/010（外部助言とブロッカー扱い）および REQ-014-009（unresolved 時の不可逆処理回避）と整合する。
- ADR-003（req_draft ソフトコントラクト原則）を置換しない。draft は恒久 SSoT ではなく、判断は現行正規成果物を根拠とする。
- REQ-006-024（case-run 既存契約 scope 内自律処理）および REQ-006-025（scope 変更は blocked）とは、「case-run 内部実装判断」と「case-auto が受領した親判断文脈」を分離すれば重複しない。
