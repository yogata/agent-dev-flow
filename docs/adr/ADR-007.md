# ADR-007: Artifact Graph 標準化と配布スキル昇格

## 背景

現行 SPEC docs/specs/local/artifact-graph.md の「対象外」節は、consumer リポジトリへの導入、ADF 標準機能への昇格、src/opencode/commands/**, src/opencode/skills/** への Artifact Graph 固有処理追加を明示的に除外している。現行実装 .opencode/skills/repo-agentdev-artifact-graph/ は self-hosting 固有で、config.ts が INDEXED_PATHS を hard-code し、model.ts が NODE_TYPES を closed-enum で保持する。

REQ-013 により廃止された旧文書探索経路インデックスに代わる標準探索モデルとして、consumer でも利用可能な Artifact Graph が必要である。標準化には現行 SPEC「対象外」節の撤回と、open extensibility を持つ新スキーマ設計が必要である。ADR-002「ソース・プロジェクション分離」は配布物原本を src/opencode/ へ配置する原則を定めており、本決定はこの原則に従う。

## 決定

1. agentdev-artifact-graph を標準配布スキルとして src/opencode/skills/agentdev-artifact-graph/ へ新設する。現行 SPEC docs/specs/local/artifact-graph.md の「対象外」節（consumer導入・標準機能昇格の除外）を撤回する。
2. 標準スキルの node_types と relation_types は closed-enum ではなく augmentation から追加可能な open extension point として実装する。
3. 標準コアと augmentation の責務分界を次のとおり定める:
   - 標準コア node_types: requirement, adr, specification の3種
   - 標準コア relation_types: references, supersedes, defined_in, contains, extends の5種
   - 標準コア indexed_paths デフォルト: docs/requirements, docs/adr, docs/specs の3種
   - augmentation が追加可能: command, skill, integrity_rule, extension, source_file 等、delegates_to, governs 等
4. project augmentation により consumer は project 固有正規成果物を追加可能とする。project augmentation が存在しなくても標準動作する。
5. project-owned source（src/tests/scripts/config 等）は indexed_paths へ含めず、discovery_roots（明示参照起点リスト）と query 時 rg/filesystem 補完で必要時探索する。固定 directory 知識を標準スキルへ埋め込まない。
6. consumer 環境では AgentDevFlow 配布物（.opencode/commands/agentdev/, .opencode/skills/agentdev-*/, .agentdev-plugin/**）を indexed_paths へ含めず、生成 Graph へこれらパターンのノードを含めない。
7. self-hosting augmentation は command, skill, integrity_rule, extension, source_file の node_type と delegates_to, governs の relation_type を追加し、indexed_paths デフォルトへ src/opencode, .opencode, .agentdev/extensions, scripts, tests を追加する。
8. Artifact Graph は SSoT ではなく、Graph 候補は正規成果物での確認を常時実施する。差異は原因分類（canonical defect / graph defect）し、Graph 側を直接手編集せず原因側を修正して再生成する。
9. fail-open 原則を維持する。Graph 不在・stale・生成失敗でも標準 workflow を恒常停止しない。
10. 同一入力からの Graph 生成の決定論性を維持する。manifest.json の input_digest, indexed_paths, excluded_paths, schema_version, generator_version が同一の場合、生成5ファイルはバイト単位で同一となる。
11. 標準スキルは Graph と独立確認結果の差異を検出・分類・是正・回帰検証する verification feedback 機構を持つ。

## 結果、影響

### 正の影響

- consumer でも Artifact Graph が利用可能となり、標準探索モデルが Graph へ統一される。
- ADF 本体は self-hosting augmentation で現行 repo-local と同等の探索能力を維持する。
- open extensibility により将来の新 node_type 追加が augmentation で対応可能となる。

### 負の影響

- 標準スキル設計難易度が上がる（open extensibility のスキーマ設計が必要）。
- augmentation 仕様の整備（project augmentation と self-hosting augmentation の2種）が必要。
- 現行 repo-local 実装から標準スキルへの移行作業が発生する。

## 関連する決定

- ADR-002（OpenCode ソース・プロジェクション分離）: 本 ADR は ADR-002 の原則（配布物原本は src/opencode/）に従う。標準スキル新設は ADR-002 適用範囲内。
- REQ-002（配布成果物の責務境界）: agentdev-artifact-graph は REQ-002 適用対象の配布 skill となる。REQ-002 自体の要件行変更は不要。
- REQ-009（配布基盤と導入モデル）: install-consumer-opencode.ps1 の agentdev-* glob により自動 junction 対象となる。REQ-009 自体の要件行変更は不要。
- 現行 SPEC docs/specs/local/artifact-graph.md: 本 ADR 採用により superseded とし、新 SPEC docs/specs/skills/agentdev-artifact-graph.md（skills ドメイン）へ移行する。
