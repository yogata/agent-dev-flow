# ADR-004: 差し替え可能な I/O 境界

## 背景

AgentDevFlow の中心責務（憲章決定1）のうち、承認境界、許可・禁止副作用、永続状態、完了証拠は、いずれも GitHub Issue/PR への読み書きを介して物理的に作用する。
これらの責務を一貫して担保するには、GitHub I/O が単一の境界を経由し、配布物が I/O 手段を個別に持たないことが必要である。
配布 command/skill の各ファイルが gh コマンドを直接記述すると、環境依存の取扱い（Windows エンコーディング、--body-file、VERIFY 手続き）が分散されるリスクがある。
憲章決定1へ照らして I/O 境界を定義する。
ローカル版は GitHub Issue/PR の代わりに Case ファイルを読み書き対象とするため、境界の差し替え可能性が成り立つ前提となる。
境界が存在しなければ、承認・副作用・永続状態の各責務を配布物の各所で再実装することになり、憲章決定1と物理層が一致しない。

## 決定

`agentdev-gh-cli` を GitHub I/O の唯一の差し替え可能な境界として確立する。
配布物（command、skill、template、script）は gh コマンドを直接記述せず、`agentdev-gh-cli` の手続きへ委譲する。
`agentdev-gh-cli` は I/O 手続きと検証（VERIFY）を担当し、本文生成、完了判定、Epic 依存判定、capture 分類は担当しない。
境界は薄いルーティング入口とし、操作契約と標準実装は references へ分離する。
ローカル版は `src/opencode-local/agentdev-gh-cli/` で境界を実装し、同一手続き名で Issue/PR 相当の読み書きを Case ファイルへ読み替える。
上位 command/skill は常に `agentdev-gh-cli` のみを参照し、別名スキルを参照しない。
抽象 backend は新設せず、GitHub 前提の標準実装と差し替え可能性で担保する。
責務境界の宣言は REQ-011 が所有し、本 ADR は境界のアーキテクチャ決定を定義する。

## 結果、影響

### 正の影響

- 承認、副作用、永続状態、完了証拠の各責務が単一の I/O 境界で集約され、憲章決定1と物理的に一致する。
- 配布物から環境依存（Windows、PowerShell、エンコーディング、一時ファイル、--body-file）が排除される。
- ローカル版は `agentdev-gh-cli` の差し替えだけで対応でき、command/skill 全体の分岐が不要になる。
- 新規 command 追加時も I/O 境界を経由することが前提として固定され、将来の設計を制約する。

### 負の影響

- `agentdev-gh-cli` の責務が大きく、SPEC の体系的管理が必要である。
- 配布物が gh 直接記述へ後退しないよう、継続的規律が必要である（委譲形の維持は機械検出により支えられ、検出体系は REQ-010 が所有する）。
