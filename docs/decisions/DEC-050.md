# DEC-050: マージ済みリモートブランチの削除と操作安全性

## 根拠

マージ後の削除を GitHub に任せれば、クライアントが途中で停止してもクライアント側の後処理を待たずに済む。自動削除の設定と、Issue・PR 操作に必要な権限は独立している。

## 決定

1. GitHub Issue・PR を使うリポジトリの導入条件は `deleteBranchOnMerge=true` とする。マージ済みリモートブランチは GitHub が削除し、case-close のブランチと worktree の後処理はローカルに限る。ADF はリモート削除、監視、回収、再試行を行わず、個々の削除結果を保証しない。マージ時に `--delete-branch` は使わない。
2. case-open の事前確認では `gh repo view --json deleteBranchOnMerge` で設定を読み取る。`agentdev_gh` の操作追加や導入スクリプトのネットワーク接続は不要とする。GitHub Issue・PR を使わないローカル版には導入条件も事前照会も適用しない。
3. 設定無効と設定照会不能は区別して警告し、その理由だけでは停止しない。認証・権限・必要な読み書きが成立することは別に確認し、確認できなければ操作を停止する。
