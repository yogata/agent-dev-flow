# DEC-050: deleteBranchOnMerge 設定不備の警告化と操作安全性停止の維持

## 決定背景

DEC-045 は case-open の preflight で deleteBranchOnMerge が true でない場合または検証不能な場合を
blocked 停止としていた。設定不備はCase開始の安全性と無関係であり、開始前の停止条件として過剰である。
一方、実操作（Issue作成・PR操作）の認証・権限・書込みが成立しない場合の停止は安全性の本質である。

## 決定

1. deleteBranchOnMerge が true でない場合と設定を確認できない場合は、両者を区別した警告
   （設定無効 / 設定照会不能）として報告し、その理由だけでは case-open を blocked にしない。
2. 設定照会不能は実操作の認証・権限・書込み成立の証明ではない。独立した実操作の安全性確認で
   認証・権限・必要な読取・書込み等の成立を確認できない場合は、既存の安全契約に従って停止する。
3. リモートブランチ削除の GitHub 自動削除への委譲（DEC-045 決定1）、deleteBranchOnMerge=true の
   必須導入条件（DEC-045 決定2、REQ-009-052）、ローカル版の対象外（DEC-045 決定4）は維持する。
   代替のリモート削除・削除監視・回収・再試行機構を追加しない。設定が有効でも個々の削除結果を
   保証しない。
4. 本 Decision は DEC-045 の決定3後半（設定が true でない場合または検証不能な場合は blocked で
   停止する部分）を部分置換する。それ以外の DEC-045 の決定は維持する。
