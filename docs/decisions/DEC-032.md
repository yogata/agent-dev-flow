# DEC-032: ADF 責務の三層モデルと Project Contract の論理ビュー・情報寿命モデル

## 背景

v3 では配布成果物（Runtime 機構）、標準プロセス定義（Design/Skill）、適用 Project 固有情報が文書単位で混在しており、「どの変更が ADF 全体・当該 Project・一時的な実行状態のいずれに影響するか」を判断しにくかった。DEC-015 は決定論的実行中核と実行基盤実行機構の責務分界を定めたが、durable state・権威・Project 差分まで含む全体責務モデルとしては不十分であった。

## 決定

ADF の責務を (1) ADF Runtime（durable state、resume/recovery、authority/side-effect control、idempotency/concurrency、deterministic execution、adapter execution）、(2) ADF Standard Operating Model（requirements-driven lifecycle、文書意味、work_type/scale/Epic/Wave、Case lifecycle、Quality/Verification/Evidence/Gate、Intake/Learning/Backlog loop、協業境界、bootstrap/migration/self-hosting の標準境界）、(3) Project Model（当該 Project の REQ、accepted Decision、current Design、policy、Knowledge、Backlog、extension、operating state）の三層に分離する。

Project Contract を単一巨大文書ではなく、AI が新規 session から現在契約を再構成できる論理的情報集合とし、各要素に canonical owner・更新契機・寿命を定義する。再構成要素は少なくとも purpose/goals/non-goals、REQ、accepted Decision、accepted/current Design、architecture invariants、project policy、quality/evidence policy、reusable Knowledge、current development direction、active work とする。

情報寿命を 8 種（ADF lifetime、Project lifetime、Architecture lifetime、Requirement lifetime、Change/Case lifetime、Runtime lifetime、reusable Knowledge、未評価 Observation）で区別し、各寿命について適切な artifact 種別、canonical owner、昇格条件を定義する。Learning/Observation が無条件に REQ へ昇格しない昇格条件を定義する。

本 Decision は DEC-015 の実行境界を Project Model 差分と durable state 権限まで拡張する差分を決定する（DEC-015 本体は v3 として有効のまま保持する）。

## 結果、影響

現行 Command/Skill/docs は三層のいずれの手段かを crosswalk で再分類される。Project ごとの状態は Project Model 層に集約され、ADF 配布物と Project 固有情報の境界が明示される。
