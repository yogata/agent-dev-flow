# DEC-035: v4 Quality / Verification / Evidence / Gate モデルへの分解

## 背景

v3 の QG-1〜QG-4 は品質方針、検証義務、検証主体、証跡、状態遷移条件が一体として定義されており、tool-specific detail（Bun 起動形態、path check、lint command）が Gate の意味契約に混入していた。要求形成時点で必要 Evidence を確定し、実行後に同一の Evidence で完了判定する閉ループが弱かった。

## 決定

品質モデルを Quality Policy（何を品質として要求するか）、Verification Obligation（Requirement/risk/acceptance から何を検証すべきか）、Verifier（deterministic または semantic な検証主体）、Evidence（検証結果の根拠）、Gate（次状態へ遷移するために必要な条件/Evidence が揃っているかを判定する predicate）の 5 概念に分解する。Gate を checker、test、Skill の別名として定義せず、tool-specific detail を Verifier/adapter 側に置く。現行 QG-1〜QG-4 を前提とせず、v4 standard lifecycle と requirements-driven verification から Gate を再導出する。change -> risk -> verification obligation -> test strategy の経路を品質モデルへ接続する。QG-1〜QG-4 の個別対応（保持・統合・置換）は crosswalk で記録する。

## 結果、影響

品質関連 Design/Skill/checker は 5 概念のいずれの実現手段かを明示して再編される。検証契約と Evidence の所有が明確化される。
