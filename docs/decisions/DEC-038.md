# DEC-038: ADF v4 durable state 配置と再構成の契約（状態権威・証跡分離・非原子調整原則）

## 背景

v3 では状態が GitHub Issue/PR/comment、docs/ 正規成果物、.agentdev/ の Git 管理ドメイン状態、ローカル実行環境に分散しており、input-resolution-and-durable-state Design が STEP 再開の優先順位を定めた。DEC-032 は ADF Runtime 層の責務に durable state を含めたが、配置・権威・再構成の一般契約は不在のままであった。並列実行・中断再開・部分失敗の実績（v4 Foundation Case の実行）において、cursor 状態・証跡・状態の混在と、複数記録先にまたがる論理状態の権威の曖昧さが運用慣行として残っている。

## 決定

(1) durable state の分類を 5 種とする。(a) GitHub 正規状態（Issue/PR/comment の状態）、(b) repo 内正規状態（docs/ 正規成果物、.agentdev/ の Git 管理ドメイン状態）、(c) ローカル実行環境状態（worktree・checkout・git index・導入状態等。Runtime lifetime であり正規状態として保存しない）、(d) 証跡（evidence/記録。検証結果・対応記録等の不変記録であり状態ではない）、(e) 導入可能情報ではなく導出可能情報（決定的手順で許容可能なコストで再現できるもの。正規状態として保存しない）。

(2) 各論理状態の権威 (authority) を 1 つとする。権威以外の記録はすべて権威から導出可能な投影とする。同一論理状態に権威を並立させない（1 状態 1 記録先ではなく、1 権威 + 導出投影の構成）。

(3) cursor 的状態（現在 stage、workflow route 等）を正規状態として保存しない。中断再開は永続状態から最も早い未収束点として再構成する。中断再開に必要な期間に限定したローカル一時保持はこれを妨げない。

(4) 導出可能情報の判定基準を「決定的手順で許容可能なコストで再現できること」とする。再現コストが高い、環境依存、非決定的なものは証跡として保存する。状態と証跡を分離し、同一情報の二重権威を持たない。

(5) ADF は複数 store（GitHub、repo、ローカル実行環境）にわたる原子トランザクションを前提としない。部分失敗時はクラス別権威順で調整し、安全に自動解消できない場合は停止する。意味的な自動マージを行わない。

(6) 5 分類と 8 情報寿命（DEC-032）の対応表、配置表、権威移行点（draft -> Definition PR -> merge 後 branch、case-ready 完了後は Issue と Epic が権威）の詳細は Design（ADF v4 durable state と再構成・恢復）が所有する。

v3 保持: DEC-011（STEP resume point と会話記憶非依存）および input-resolution-and-durable-state Design の再開優先順位は v3 として有効のまま保持し、本 Decision はこれらを一般化する契約として接続する。置換の実行は後続 Sequence 段階が所有する。

## 結果、影響

現行 Command/Skill/checker の状態保存・再構成の判断は、本契約の 5 分類と 1 権威原則に従って後続段階で再編される。Project ごとの状態は Project Model 層に集約され、ADF 配布物と Project 固有情報の境界が明示される。
