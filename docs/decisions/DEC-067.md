# 仮説に基づく既存統制変更原則

## 根拠

事前に実測しにくい統制でも、仮説と変更後の適合検証があれば改善できる。機構の追加量は成果とせず、安全上の不変条件を守りながら便益と費用を評価する。

## 決定

1. 既存統制の変更・統合・降格・削除に事前実測は必須としない。正本から一意に導出できる情報の重複と、品質や自律性に便益があり得る機構の重複は区別する。固有の成果・所見、自律性、復旧・安全への寄与を、時間、トークン、ツール呼出し、重複した読み書き、調整・保守の費用と対で評価する。
2. 目的と仮説、対象範囲、維持条件、問題発生時の処置を明示し、確認した事実と期待する効果を区別する。測定結果がないだけで変更を禁止も削除もせず、測定待ちで無期限に保留しない。仮説に基づいて導入するか、理由を明記して削除する。学習の保留（REQ-038）と作業の停止（REQ-120）の機構は維持する。
3. 変更後は、影響を受ける要件・受入条件と DEC-001 の安全上の不変条件への適合を検証する。不変条件を満たすなら重複機構の縮小を評価できる。未測定の時間・品質・自律性への効果は実証済みと扱わない。実測を伴う実験では、基準測定、仮説、変更、保護条件、観測、判断を区別し、一つの実験に複数の独立した主要構造変更を混ぜない。
4. 仮説・根拠・検証結果・撤回条件は既存の Case、Issue、PR または Git 履歴で確認できるようにする。復元には Git 履歴を使い、恒久台帳、状態、検査器、停止点、必須様式を新設しない。評価軸は REQ-048、測定手続きは Design が所有する。
5. 維持するのは現行の表記・参照・契約とする。変更時は利用箇所を直接修正し、移行補助の資産を恒久化しない。移行中は DEC-056 と REQ-109 の意味保存と検証を優先する。存続する検査の違反は免除台帳に登録せず、対象を直接修正する。

## 再評価条件

運用費用が縮小の便益を上回る、新しい恒久機構が必要になる、安全確認を欠く変更や未測定効果を実証扱いする報告が繰り返される、または維持条件の間に矛盾が生じる場合は再評価する。
