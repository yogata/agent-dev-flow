# DEC-046: Jev 実行基盤の Cloudflare AI Gateway への完全置換

## 決定

1. Jev 実行基盤は Cloudflare AI Gateway を唯一の現行 provider とする。接続契約は API `/ai/run`、model `typesafe/jev`、credential `CLOUDFLARE_ACCOUNT_ID` と `CLOUDFLARE_API_TOKEN`、default AI Gateway の利用（Gateway ID を ADF の設定契約として持たない）とする。
2. Vercel との後方互換、provider selector、credential alias、model alias、fallback、移行互換層を設けない。Vercel adapter、Vercel SDK 依存、Vercel 固有設定、現行文書の Vercel 記述を撤去する。
3. provider 境界は複数 provider 対応のためではなく、外部 API 固有処理を Semantic Evaluation の意味契約から隔離する最小境界として維持する。将来の provider 交換可能性を理由とした抽象化を追加しない。
4. 過去の Vercel 経由 observation は当時の一次事実として保持し、Cloudflare 表現への migration・書換えを行わない。Semantic Evaluation の意味契約（観測契約、基本判断経路）は本変更の対象外とする。

## 背景

agentdev_jev Custom Tool は外部実行基盤として Vercel AI Gateway（model typesafe-ai/jev、credential AI_GATEWAY_API_KEY）を使用してきた。Vercel 側の利用制限（free tier における model access 制限。2026-09-27 に GatewayInternalServerError として実証）への対応と、現行契約上使用しない Vercel 経路の残存による実装と文書の責務不整合の解消のため、実行基盤を Cloudflare AI Gateway へ完全置換する。複数 provider 対応や移行用互換層は不要なソフトコントラクトと統制複雑性を増やすため新設しない。

## 判断根拠

agentdev-decision-guidelines「主要な外部サービスの選定」該当（外部評価サービス実行基盤の変更、後方互換撤去という難逆転判断を含む）。

## 影響

- 正: 使用制限を受けない現行実行経路が得られる。現行契約上使用しない Vercel 経路が撤去され、実装と文書の責務不整合が解消される。単一経路の維持により provider 選択に由来する分岐・互換契約・テストが増えない。
- 負: 従来 credential（AI_GATEWAY_API_KEY）からの切替が必要となる。既存 observation は Vercel provider identity のまま保持されるため、切替前後で provider 由来の実行時特性が変わる。
- 関係: DEC-040 決定2（provider 方針: Vercel）を置換する（決定1・3は DEC-040 が現行維持。決定4は DEC-044 が既に置換済み）。DEC-040 側の supersede_note に決定2 の置換（本 Decision）を追記する。DEC-044 とは relates-to（観測契約・基本判断経路は本変更で不変）。
