# DEC-030: トレーサビリティ標準機能への一般化と producer / consumer 境界の確立

## 背景

DEC-017 は最小トレーサビリティモデル（TIM）を採用し、汎用 Artifact Graph を廃止した。運用の結果、次の課題が観測された。
第一に、agentdev-traceability の能力は ADF 本体専用の位置づけであり、AgentDevFlow を導入するプロジェクトが自プロジェクトの要件トレーサビリティのために利用する標準機能として一般化されていなかった。
第二に、対応宣言は inline（ADF-COVERS）のみであり、配布対象の製品ソースに埋め込まれた producer 側メタデータが配布閉包に混入していた。配布境界検査はこの混入を例外として許容していた。
第三に、検証対応要否を Design が所有するカタログで管理するモデルは、中間状態（未分類）とその工程ゲートを必要とし、policy としての宣言に比べて運用負荷が高かった。
RU-0001（トレーサビリティ標準機能と producer / distribution 境界の再設計）において、これらの再設計方針が合意された。

## 決定

1. DEC-017 決定1を部分改正する。TIM の標準成果物役割を decision、design、implementation、verification の4種とし、design と implementation を必須対応、decision を任意対応、verification をトレーサビリティポリシーが定める検証対応要否に従う役割とする。Design 対応を必須化し、Decision を対応対象に含める。DEC-017 決定2（直接走査・派生索引なし）、決定3（agentdev-traceability 標準スキル）、決定5（用語政策）は維持する。
2. トレーサビリティを ADF 利用プロジェクトへ提供する標準機能として一般化する。AgentDevFlow 自身のトレーサビリティデータも同一の TIM、sidecar、ポリシー、coverage / impact / check により管理・検査する（自己適用）。agentdev-traceability 配布スキルは知識と手順のみを配布し、個別プロジェクトの対応関係データを保持しない。
3. 対応関係の保存を分離する。配布対象成果物（製品ソース）の対応関係はリポジトリルート直下の traceability/ 配下に component / package 単位の sidecar として保持する。sidecar の最小データは対応対象成果物のリポジトリ相対パス、役割、要件行 ID とし、専用の成果物 ID、関係 ID、リビジョン、ダイジェストを必須としない。inline 宣言（ADF-COVERS）は producer 側成果物のみで利用可能な直列化形式に位置づける。sidecar と inline は coverage / impact / check において同一の論理対応関係として正規化する。
4. 検証対応要否をトレーサビリティポリシー（traceability/policy.yaml）として宣言する。未指定の要件行は検証対応必須とし、検証対応を任意とする要件行はポリシーへの明示登録によってのみ宣言する。検証対応要否カタログと未分類状態、およびその工程ゲートを廃止する。sidecar とポリシーの YAML は、DEC-019 が保証する YAML 機能サブセット（anchor、alias、カスタムタグ、複数ドキュメントを除く）に従い、標準 API により解析する。
5. 配布閉包の純度を確立する。consumer distribution closure 内の全テキスト成果物について producer 側トレーサビリティメタデータを0件とし、配布時の strip 処理を前提とせず、例外を設けない。配布境界検査における distribution-bound ADF-COVERS の例外許容を撤廃する。
6. 完全性検査を強化する。check は sidecar・ポリシーの構文不正、未知の役割、未知の要件参照、無効パス、Design・実装・検証対応の欠落（検証対応は必須行のみ計上）、ポリシー参照不正、重複宣言の不整合を検出し、Decision 欠落を不合格としない。最終完全性ゲートにおいて check が判定を実行不能な場合、合格として扱わない（fail-closed）。coverage / impact は助言的能力とし、fail-open で運用する（REQ-021）。

## 結果、影響

- REQ-012 は TIM 4役割、sidecar、ポリシー、check 検出項目、標準機能一般化と自己適用を反映して更新される。REQ-021 は工程ゲートを Design 対応・ポリシー整合基盤へ更新する。REQ-029 は配布閉包純度の不変条件を追加する。REQ-002 は開発管理成果物・製品ソース・配布成果物の区分を追加する。REQ-061 は case-ready 実行契約の未分類ゲート行をトレーサビリティ完全性ゲートへ更新する。REQ-057 は docs 集約前提の対応宣言配置行を sidecar 正規配置先・producer 側パスへ更新する
- 検証対応要否カタログ（docs/designs/foundations/references/verification-scope-catalog.md）は廃止し、ADF 自身の検証対応要否は traceability/policy.yaml へ移行する
- 製品ソース（src/opencode 配下）の inline 対応宣言は sidecar へ移行する。producer 側文書（docs 配下等）の inline 宣言は継続利用する
- check の検出項目拡張に伴い、case-ready、case-run、case-close、QG-4 の各検査契約が更新される
- 本 Decision は DEC-017 決定1を部分改正する。DEC-017 の決定2、決定3、決定5は維持され、決定4（段階的移行）は履行済みの履歴として維持する
