# DEC-039: ADF v4 authority・副作用統制と冪等・並行性モデル

## 背景

v3 の authority・並行性規則は、case-auto 実行契約、per-Epic 単一書き手、自走対象外リスト、採番・AUTOGEN グローバル直列化等に個別分散しており、tag/branch のオブジェクト別規則は Case 個別の限定逸脱記録に散在していた。並列実行の実績（v4 Foundation Case の実行）において、作成系操作の検出→作成の競合（TOCTOU）と worktree/git index の競合が運用対応として残っている。

## 決定

既存 Decision との差分として次を決定する。

(1) 副作用を 4 分類（repo 内ファイル / GitHub Issue・PR・comment / remote branch・tag / repo 外）し、各分類の実行権限を分類単位ではなく「対象 × 操作 × 寿命」の格子で決める。tag は lifecycle role 別（baseline anchor / release / rc）に権威を定め、remote branch 削除は自 Case が作成した branch に限定し、既存 release tag は移動しない。repo 外操作（DB migration 実行、deploy/apply、クラウドリソース操作、外部SaaS 設定変更、課金、権限、認証情報、repo 外実データ操作、通知送信）は自走対象外とする。

(2) 競合する共有書き込みの直列化単位を 5 種とする。merge/push: リポジトリ単位。Epic Issue 本文: per-Epic 単一書き手。採番割当: グローバル（AUTOGEN とは別単位）。AUTOGEN 索引再生成: グローバル。worktree/git index: worktree 単位の隔離または直列化。局所直列化原則（当該競合と無関係な対象の並列を妨げない）を維持する。直列化の実行機構の所有は Tool 契約・実装段階が担い、本 Decision は単位の定義と原則を所有する。

(3) 成果物作成操作は並行安全な冪等経路を要件とする。安定キー付き作列または作成経路の直列化のいずれかにより、検出→作成の競合（TOCTOU）による二重作成を防止する。verify-only closure の SSoT コメントヘッダ規約（DEL-{N}-{n} 形式）は現行の事実上の冪等キーとして位置づける。

(4) 直列化違反・競合書き込みの検出時は、権威優先での解消または停止とし、意味的な自動マージを行わない。

(5) 状態遷移 predicate 評価・冪等キー照合・依存解決・Wave scheduling の決定的所有は DEC-036 の deterministic 項目分類に従い、本 Decision は再列挙しない。semantic 判断（要件解釈、block 判定等）は Skill が所有する。

(6) 書き込み経路の統制点（Custom Tool、書込み guard）は fail-closed とし、助言的統合（検査・診断系）のみ fail-open を許す。

(7) adapter execution の境界は DEC-036（Harness/Backend adapter 境界）が所有し、本 Decision は副作用分類経由で接続する。

v3 保持: DEC-015（ADF決定論的実行中核と実行基盤実行機構の責務分界）および DEC-004（差し替え可能な I/O 境界）の本体は v3 として有効のまま保持する。置換の実行は後続 Sequence 段階が所有する。

## 結果、影響

現行 case-auto/case-run の実行契約・単一書き手規則・冪等再実行は、本モデルの 5 直列化単位と冪等経路要件へ後続段階で整理される。tag/branch 運用の権威は lifecycle role 別サブ表により Case 個別の限定逸脱記録への散在から正規モデルへ集約される。
