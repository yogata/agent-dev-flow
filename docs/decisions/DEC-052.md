# DEC-052: Jev 評価器障害時の判定未確定と依存後続抑止への移行（DEC-044 決定3 の部分置換）

## 背景

REQ-103「ADF v4 正規モデル再確定と現行規範の全面収束」の Wave 1 で、判断アーキテクチャの正規モデルが確定した。
閉じた意味評価の障害時契約（REQ-103-008〜011、v4-responsibility-boundaries Design「閉じた意味評価の障害時契約」節。
runtime 面の適用は v4-runtime-execution-model Design「判定未確定時の依存後続抑止」節、durable state 面の再開契約は
v4-durable-state-and-recovery Design「評価器復旧後の評価再開契約」節）では、必須の閉じた意味評価が評価器の未設定、
利用不能、timeout、rate limit、network error、provider error、応答検証失敗等で成立しない場合、LLM 推論へ
fallback して判定を継続せず、当該判定を未確定として扱い、依存する後続の副作用および状態遷移を開始しない。
LLM 推論を前段失敗時の一般 fallback に使用すること自体が REQ-103-007 で禁止されている。

DEC-044 決定3 は「evaluator 失敗・未設定・事前検証失敗時も reasoning model 経由で Workflow を継続する」と規定しており、
この部分は評価器障害時の LLM 推論経由での判定継続（一般 fallback）を許容する記述として、確定した正規モデルの
障害時契約と矛盾する。Root Case #3530 の実現方針（CR-001、case-ready 記録済み）で、DEC-044 決定3 を
REQ-103 の正規モデル確定後に後継 Decision による部分置換で置換することが合意済みである。
本 Decision はその合意済み方針の実行時反映であり、新しい意味的決定を含まない。

## 決定

1. **部分置換の対象と内容**: DEC-044 決定3 のうち「evaluator 失敗・未設定・事前検証失敗時も reasoning model 経由で
   Workflow を継続する」部分を本 Decision で部分置換する。置換後の障害時契約は REQ-103-008〜011 に従う:
   - LLM 推論へ fallback して判定を継続しない（REQ-103-008。LLM 推論を前段失敗時の一般 fallback としない REQ-103-007 と同一境界）
   - 必要な判定を未確定として扱い、当該判定に依存する後続の副作用および状態遷移を開始しない（REQ-103-009）。
     判定不能を不合格または非該当へ変換せず、依存しない独立処理を一律に停止しない
   - 評価器障害だけを理由に人間判断へ移行しない（REQ-103-010。人間判断への移行は、当該判断自体が人間に留保された
     判断である場合に限る）
   - 評価器復旧後、未確定状態から正規の再実行・再開経路によって評価を再実行する（REQ-103-011）。再開前に入力・規則・
     成果物・証拠への変更影響を確認し、影響する古い判定を再利用せず、成功済み副作用を重複実行せず、影響しない証拠は
     再利用する。修復・再試行・設定等の運用介入を判定方式の代替または新規規範の確定と混同しない
2. **残存部分の維持**: DEC-044 決定3 のうち evaluator 成功時の「結果・確率分布・取得できた confidence を reasoning model へ
   判断材料として渡し、reasoning model が最終判断する」部分、および「新規 fallback framework・routing 機構を作らない」
   部分は本 Decision が維持する。evaluator 成功時の判断材料渡しは評価器障害時の判定継続経路ではなく、
   REQ-103-003（決定的に処理できる判断の再判定禁止）と矛盾しない（Jev は正規判定主体ではなく材料収集であり、
   入力の十分性・別命題の評価とは区別される）。DEC-044 決定1・2・4〜8（観測単位、一次事実への限定、派生状態の除去、
   0.9 の位置づけ、fail-open と中断耐性、v1 観測履歴、履歴扱い）は本 Decision が置換せず DEC-044 が現行として維持する
3. **実現物への反映**: 6系統 Workflow（learning-promote、req-define、case-ready、intake-promote、inspect-promote、
   backlog-review）の Jev 逐次経路記述、Custom Tool `agentdev_jev` の呼出側契約（Custom Tool 操作契約 Design
   「Jev 先行評価」節）、Tool 側 README と記述、および REQ-090-002〜004 の障害時経路記述を、本 Decision と
   REQ-103-008〜011 に整合させる。歴史的判断本文の事実（DEC-044 本文中の決定3 の記述）は保持し、
   部分置換の構造は DEC-044 frontmatter の `supersede_note` で機械判別可能にする
4. **failure observation と観測契約の不変**: 評価器障害時の failure observation（実際の evaluator 呼出し開始後の失敗のみ
   対象、失敗分類と最小 diagnostic）と観測保存の fail-open 契約（DEC-044 決定6）は本 Decision で変更しない。
   観測保存の fail-open は保存処理の契約であり、評価成立の停止契約とは適用対象が異なる

## 代替案

- (a) DEC-044 決定3 の全体置換 — 決定1・2・4〜8（観測契約と基本判断経路の中核）は REQ-103 正規モデルと矛盾せず
  現行として維持すべきため不採用。部分置換の記録様式（decision-lifecycle Design「部分置換の記録様式」節、
  status 維持・`supersede_note` 記録）に従う
- (b) 評価器障害時も reasoning model 経由での継続を許容したまま、対象を「必須評価に限定する」形での限定追記 —
  REQ-103-007 が前段失敗時の一般 fallback を一般に禁止しており、障害という事象を契機にした判定継続経路を
  限定的に残す構成は正規モデルの禁止範囲に含まれるため不採用
- (c) Jev credential 未設定環境向けに LLM 経路での恒常継続を例外として規定 — 未設定は運用上の前提不足であり、
  「失敗・停止理由の原因別処理対応表」（v4-responsibility-boundaries Design）の処置である手動による運用上の介入
  （credential 設定）と正規再開経路で扱うのが正で、判定方式の代替を恒常規定する根拠がないため不採用

## 結果、影響

- 正: 6系統 Workflow の意味評価経路が確定した正規モデル（REQ-103-003〜011）と一意に整合し、評価器障害時の
  判定継続による規範違反の混入（fallback 判定の正規工程への流入）が構造的に除去される。
- 負: Jev credential 未設定・評価器障害環境では、閉じた意味評価に依存する工程が判定未確定として停止する。
  再開には credential 設定等の運用介入が必要であり、DEC-044 決定3 が許容していた「障害時も Workflow を完了させる」
  経路は失われる。
- 観測: 評価器障害の failure observation は現行どおり蓄積され、障害時停止の実害評価（REQ-090 の観測契約に基づく
  集計）の材料となる。

## 再評価・撤回条件

- REQ-103 の障害時契約（REQ-103-008〜011）が正規の訂正経路で再確定された場合は本 Decision を再評価する
- 評価器障害・credential 未設定に起因する工程停止が実運用で継続的に観測され、運用上の介入の負担が
  受け入れ不能と実証された場合は、新たな判断材料として別 Decision で再評価する（本 Decision 内で
  fallback 経路を復活させない）
