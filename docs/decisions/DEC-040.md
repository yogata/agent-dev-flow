# DEC-040: typesafe/Jev 先行評価の採用（Stage 1: 観測可能化）

## 背景

ADF の6系統 Workflow（learning-promote、req-define、Epic/Wave 構成判断、intake-promote、inspect-promote、backlog-review）の閉じた意味判断は LLM 単独で行われている。実験として typesafe/Jev による先行評価を逐次経路で組み込み、実運用で confidence と unchanged/corrected の関係を観測し、将来の置換判断（Issue C）の根拠を蓄積する。旧 REQ-089（J2 shadow 実験、完全 revert 済み）由来の合意・設定は破棄されており、本案とは無関係である。

## 決定

1. Jev 先行評価の採用: 対象は6系統の閉じた意味判断に限定する。逐次経路（Jev 先行評価 → Jev 結果と confidence を情報として含む LLM 推論 → LLM 最終判断）とし、Jev は最終判断者としない。
2. provider 方針: 初期 provider は Vercel AI Gateway（model ID typesafe-ai/jev、credential AI_GATEWAY_API_KEY）とする。Custom Tool の公開契約は provider・SDK 非依存とし、AI SDK 7 experimental_evaluate の利用は Vercel adapter 実装内部に限る。複数 adapter を先行実装しない。REQ-089 由来の TypeSafe 直 API・TYPESAFE_API_KEY 設定は復活させない。
3. 失敗契約: Jev API 呼出し後の失敗は自動 retry せず即座に従来 LLM 経路へ fallback する。API key 未設定時は Jev を呼ばず not_configured として区別し、Jev API 失敗率に含めない。
4. 観測基盤: .agentdev/jev-observations/ を正式な永続 domain state とし、1 Workflow 実行 = 1 JSON で保存する。confidence と llm_treatment を独立した一次観測値とし、観測時に confidence 閾値を固定しない。
5. 基準点と撤退: Jev 実装開始直前の main に v4.0.2 tag を作成する。致命的問題（Jev 障害で6系統継続不能、Jev 結果が LLM 最終判断を経ず正規状態を確定、無効化後に既存動作へ安全復帰不能、データ破損・domain state 不正変更、想定外の大規模 Harness 改修が必要）発生時は v4.0.2 基準挙動へ復帰する（Jev 導入差分の無効化または revert。Jev 無関係の後続変更は失わない）。
6. 段階的進行: Stage 1（本 Decision の対象）は観測可能化のみとし、有効性評価（Issue B）と置換（Issue C）は別 Issue とする。Stage 1 の完了条件に Issue B/C の成果を含めない。将来の置換採用は別 Decision を要する。

## 結果、影響

- 正: 実運用データに基づく将来の置換判断が可能になる。provider/SDK 非依存契約により provider 差し替え可能性を確保する。観測が正規状態と分離され実験が運用を歪めない。
- 負: 6系統の実行時間が Jev 呼出し分増加する。API コストが生じる（Vercel プロモ終了後）。観測 JSON が git 管理対象として蓄積する。
- 判断根拠の記録: agentdev-decision-guidelines の「主要な外部サービスの選定」に該当（サードパーティ評価サービス typesafe/Jev と Vercel AI Gateway 経路の採用、6系統の判断経路という構造変更、Issue B/C の将来路線の基盤）。Decision 禁止ゲート（仕様変更のみ・workflow 定義・運用ルール等）のいずれにも該当しない技術的意思決定を含む。STEP-4 の助言委譲（agentdev-architecture-advisory）は委譲先中断により出力未確定となったため、ユーザーの明示指示（再委譲せず explore 照合結果 + durable state で続行）に基づき親エージェントが判断した。
