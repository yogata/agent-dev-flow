# DEC-016: 導入系スクリプトの副作用ゼロ原則

## 背景

導入モデルの従来前提は install スクリプト自身が provisioning（clone、fetch、reset）を実行するものであった。
この前提はスクリプトの実行に network access を必要とさせ、実行がチェックアウト状態を変える副作用を持たせる。
本 Decision は provisioning 責務を利用者へ移転し、導入系スクリプトの副作用ゼロ原則を長寿命の設計原則として確定する。

## 決定

1. 導入系スクリプト（scripts/install.ps1、scripts/self-sync.ps1）は provisioning（チェックアウトの取得・更新）を行わず、network access を行わない。
2. provisioning は利用者の責務（git clone または GitHub ソースアーカイブ ZIP の展開）とし、チェックアウトの出所と版は利用者が制御する。

判断根拠は offline-first（導入時に network 前提を置かない）、スクリプト副作用の排除（実行がチェックアウト状態を変えない）、provisioning と install の責務分離によるスクリプトの単純化、利用者による版固定の許容である。

## 代替案

アーキテクチャ助言は REQ-009 の UPDATE のみで十分として Decision 新設不要（確信度 70%）を推奨した。
ユーザー判断により、副作用ゼロ原則を長寿命の設計原則として Decision に記録し、将来の clone 復活提案を Decision でも止めるため本 Decision を新設する。

## 結果、影響

- REQ-009（配布基盤と導入モデル）の要件行更新。
- runtime-package-boundary Design、install-script-usability Design の更新。
- README、consumer-project-setup guide の導線更新。
