# DEC-045: リモートブランチ削除の GitHub 自動削除への委譲と deleteBranchOnMerge 設定前提の必須化

## 決定

1. case-close のリモートブランチ削除ステップを撤廃する。PR マージ後のリモートブランチ削除は
   GitHub の repo 設定 deleteBranchOnMerge=true によるプラットフォーム側の自動削除に委譲する。
   case-close のブランチ・worktree クリーンアップ責務はローカルに限定する。
2. GitHub Issue/PR を使用するリポジトリ種別（現行では self-hosting、consumer-with-agentdev）では
   deleteBranchOnMerge=true を必須の導入条件とする。設定手順と確認コマンドは適用プロジェクト
   導入ガイド（consumer-project-setup）に記載する。
3. 設定検証は case-open の preflight が担う（読取専用の repo meta 照会。gh repo view --json
   deleteBranchOnMerge を正規手段とし、Custom Tool agentdev_gh の操作カタログは拡張しない）。
   設定が true でない場合または検証不能な場合は blocked で停止する（fail-closed、停止理由は
   設定無効と検証不能を区別）。導入系スクリプトはネットワークアクセスを行わない既存契約
   （REQ-009-046、DEC-016）を維持する。
4. GitHub Issue/PR を使用しないローカル版（consumer-local、consumer-generated）は設定必須化と
   preflight 検証の対象外とする（REQ-009-039/031/034 との整合）。

## 背景

agent-dev-flow・reENC の2リポジトリで、マージ済み Case ブランチが大量残存していた
（2026-09-27 実測: agent-dev-flow 18本 + worktree 2件、reENC 3本。全 PR MERGED・全 Issue CLOSED、
git cherry で main 到達確認済み）。原因はクライアント側テールステップの系統的リークである
（crash・resume 反復・turn-boundary child-kill・gh-spawn degradation 等の実環境乱数で、
フロー末尾のクリーンアップが失われる。削除は成功時のみ動くベストエフォートであり、失敗や消失に
対する再試行・回収の保証がない）。サーバ側設定による自動削除はこのリーククラスを構造的に排除する。
契約上の削除ステップ自体は動作時に正常に機能しており、到達保証の欠如が本質である。

## 判断根拠

- 削除権威を ADF 実行（case-close）からプラットフォーム設定へ移譲する副作用統制の変更であり、
  DEC-039（authority・副作用統制と冪等・並行性モデル）のドメインに関係する（relates-to）。
- 全 ADF 適用リポジトリへ外部プラットフォーム前提を課す長期的影響を持つ（アーキテクチャ上重要）。
- 検証を導入系スクリプトに置けない根拠は DEC-016（導入系スクリプトの副作用ゼロ原則）が裏付ける
  （relates-to）。
- 既存 Decision（DEC-001〜044）にブランチ削除・GitHub repo 設定をカバーするものは存在しない
  （REQ-042「Case統合先とブランチモデル」は retired）。

## 影響

- REQ-032 / REQ-009 / REQ-030 への要件行追加、system.md・case-close.md・case-open.md Design の更新、
  agentdev-git-worktree / agentdev-workflow-case-close / agentdev-workflow-case-open 各 skill の更新、
  consumer-project-setup ガイドの追記。
- `--delete-branch` フラグ禁止条項（gh CLI フラグのローカル副作用への規制）は維持する。
- local 側リーク（worktree・local branch 残留の掃除機構）は本決定の対象外（別課題）。
