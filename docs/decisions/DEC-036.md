# DEC-036: 意味 Skill と決定的実装の責務分離および Harness/Backend adapter 境界

## 背景

DEC-015（決定論的実行中核と実行基盤の分界）、DEC-019（一般処理の標準API委譲）は決定的処理の一部委譲を定めたが、v3 Skill には引き続き deterministic に実行できる処理（採番、整合検査、依存解決等）が残存し、Skill 数の増加と判断責務の拡散を招いていた。Harness 依存も配布物に埋め込まれていた。

## 決定

既存 Decision との差分として次を決定する。

(1) deterministic 処理の委譲対象を拡張する: parsing、validation、ID 採番、状態遷移、dependency graph、Wave scheduling、path safety、traceability extraction、evidence aggregation、API I/O、file transformation は code/script/tool が所有し、Skill は semantic 判断（requirement analysis、architecture/design judgment、decomposition judgment、adversarial review、learning evaluation、semantic classification）のみを所有する。Skill 数削減自体を目的としない。

(2) OpenCode を first-class reference harness と位置づけ、ADF は requirement/lifecycle/authority/evidence 等の semantic contract を、Harness は agent 起動・context・background execution・tool invocation 等の実行機構をそれぞれ所有する。別 Harness/Backend が必要になった時点で adapter を追加し、未使用 adapter を先回りして実装しない。

(3) Project Extensions を標準プロセス置換ではなく、標準プロセスへの追加情報・制約・検証・capability を与える semantic extension point とし、現行 Skill 名への直接結合を安定 API としない。Project Extensions は、project context、rules、quality/evidence policy、project-specific verifier/check、tool/config integration、semantic guidance を標準プロセスへ追加する仕組みとする。

## 結果、影響

現行 Skill の再分類基準が確定し、後続の Skill 再編（RU §24 Skill restructuring）の判断基準となる。Harness 依存の切り替え可能性が担保される。

- relates-to: DEC-004（差し替え可能な I/O 境界）。Harness/Backend adapter 境界は I/O 境界差し替えの一般化
