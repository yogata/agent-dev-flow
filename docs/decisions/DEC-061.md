# DEC-061: 改善サイクルのパッチリリースと公開承認

## 根拠

改善サイクルの完遂と配布物の公開は別の判断である。版番号はリリース対象の履歴から決め、公開には草稿作成から独立した承認と、承認後に実行できる経路を持たせる。

## 決定

### 版番号と完遂条件

1. backlog-auto の一気通貫実行では、対象コミットの祖先から到達可能な正式 SemVer タグの最大版を選び、パッチ番号を 1 つ進める。比較は SemVer 順序とし、プレリリースと非 SemVer タグは基準に含めない。メジャー・マイナーへの自動振り分けは行わない。
2. 正式タグが存在するが一つも到達できない場合は停止し、版番号の後退を避ける方針を利用者に確認する。正式タグも採用済みの初期版規則もなければ、開始前に停止し、初期版を利用者に確認する。リリース時に正式タグを再確認し、基準が進んでいれば採番し直す。既存タグとの衝突・移動、二重採番は認めない（DEC-039）。
3. ADF 本体では DEC-001 のリリース条件を適用する。draft・RU・Issue の決着確認は当該一式に由来するものに限る。適用プロジェクトでは採用済みの条件を適用し、不明なら利用者に確認する。条件や権限が成立しないときは理由を記録して「完遂済み・リリース保留」とし、再開時はリリース段階から進める。

### 公開経路と承認

4. 共通の最小形は Git タグとし、追加の公開成果物はプロジェクトの採用方式に従う。リモートへの push には非対話認証を用いる。ADF 本体では、workflow が `agentdev_gh` で GitHub Release 草稿を作成して読み戻す。`release_create` に公開モードは設けない。
5. 公開は利用者が草稿作成とは別に明示承認した場合に限る。workflow は承認記録の実在と承認済み状態を確かめ、タグ名、承認質問 ID、回答の記録参照を `release_publish` に渡す。Tool は必須・非空・形式を検査して不備を副作用前に拒否し、対象の draft フラグだけを解除して、読み戻しで `draft=false` と `published_at` を確認する。カタログとその操作契約・契約テストに草稿作成、読み戻し、承認付き公開を定義する。
6. `set-state` には workflow による公開、代行、利用者による手動公開を区別して記録する。未承認の公開済み状態は不整合として報告し、完了扱いにしない。
