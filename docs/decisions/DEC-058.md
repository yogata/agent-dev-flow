# 工程遷移と双経路併存モデルの採用

## Context

工程駆動の公開操作と利用者判断による遷移が、現行 REQ-005 の要求入口2つ・case-auto 合流・別経路不新設の規則と衝突する。v4-v5 crosswalk は REQ-005-001/010/011 を優先棚卸し行（処遇 defer）として記録している。

## 決定

変更駆動（req-define → case-auto）と工程駆動（4操作＋利用者判断の遷移）の双経路併存を採用する。REQ-005-001 は旧3マクロフェーズ記述を変更駆動経路の有効能力の記述へ限定し、工程駆動の独立操作に Root Case・内部 lifecycle を一律必須としない。REQ-005-010 は公開分類へ「工程駆動実行」を追加する。REQ-005-011 は工程駆動実行の公開経路を標準経路の置換ではなく別経路の併存とする。工程遷移は利用者の判断による単独操作とし、独立レビューは工程完了の必須ゲートとしない。

## 結果、影響

REQ-005-001/010/011 の改訂と v4-v5-crosswalk の処遇記録更新は同一変更セットで行う。後継経路の実現・検証・正式採用が成立するまでは現行経路の権威を維持する。設計PR の作成・マージだけで実現確定、処遇の実行完了、または旧経路の失効を宣言しない。移行順序は REQ-108-012 に従い、旧形式の廃止だけで外部的な変更駆動能力を失わせない。

出所: RU-0002 Source Summary と「現行REQ-005との競合解消に求める結果」（2026-10-12 利用者承認）。アーキテクチャ助言の採用（親エージェント分類）。NFR 条件の連動解消は Supervisor 経由の利用者確認（2026-10-12）。
