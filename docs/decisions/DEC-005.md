# DEC-005: Project Extensions Architecture

## 背景

AgentDevFlow（ADF）は配布 command/skill を複数プロジェクトへ提供する。
各プロジェクトは、標準 command/skill に対してプロジェクト固有の文脈、規約、検査、受け入れゲート、禁止事項を追加したい。
この追加を配布 command/skill 本文へ直接書き込むと、配布物が特定プロジェクトへ依存し、他プロジェクトでの再利用性を失う。

憲章（DEC-001）決定4は、ADF core への新規統制追加を抑制する原則を定める。
新しい REQ、SPEC、Decision、command、skill、state、schema、gate、必須 field、checker を既定で追加しない。
この原則を維持するには、プロジェクト固有統制を ADF core へ持ち込まず、project layer で与える制御された経路が必要である。
経路がなければ、プロジェクトは独自統制を ADF core へ追加するか、配布物を fork するしかなく、決定4 か配布物の自己完結性のいずれかが崩れる。

本 Decision は上記憲章原則の下で本機構を採用し、憲章決定4 の実現機構として位置づける。

本判断は Decision 評価基準（アーキテクチャ上の重要性、長期的影響、逆転の困難さ）を満たす。
配布物とプロジェクト固有拡張の分離はシステム全体の構造に影響し、将来の command/skill は本機構へ従う必要があり、事後の差し戻しは全 command/skill の読み込み契約変更を伴う。

## 決定

`.agentdev/extensions/` 配下の project-extensions 機構を、配布 command/skill へのプロジェクト固有拡張の唯一の経路として採用する。

extension は配布 command/skill 本文へ追加・拡張される文脈、規約、検査、受け入れゲート、禁止事項を提供する。
対応する5セクションを次のとおり定義する。

- context: command/skill に追加で与える文脈
- rules: command/skill に追加で守らせる規約
- checks: command/skill に追加で実行させる検査
- acceptance_gates: command/skill が完了前に追加で通過するゲート
- must_not: command/skill に追加で課す禁止事項

配布 command/skill 本文はプロジェクト非依存とし、プロジェクト固有の具体参照を持たない。
具体参照とは、具体的 Decision/REQ/SPEC ID、プロジェクト固有パス、固定 URL を指す。
プロジェクト固有参照は extension 経由でのみ与える。

配布 command/skill は実行時に対応 extension を1件読み込む。
extension の配置は command と skill で分離し、`.agentdev/extensions/commands/<command>.yaml`、`.agentdev/extensions/skills/<skill>.yaml` とする。
command/skill は自分に対応する extension のみを読み、他 command/skill の extension は読まない。

extension は配布 command/skill の標準動作を上書きせず、追加・拡張のみを行う。
extension が存在しない場合は空 extension として扱い、標準動作で続行する。
extension が破損している場合（YAML 構文エラー、必須フィールド欠落等）はエラーを表示し、当該 extension を無視し、標準動作で続行する。
破損 extension により処理全体を停止しない。

旧 doc-inputs 機構はサポートされない。
本 Decision は project-extensions 機構のみを採用し、旧機構との併存を行わない。

## 結果、影響

ADF core への新規統制追加需要が project-extensions 経由で吸収される。
これにより憲章決定4（新規統制追加の抑制）が運用可能になる。
プロジェクトが ADF core へ統制追加を求める動機を、project layer での拡張設定で充足できる。

配布 command/skill 本文からプロジェクト固有参照が除去される。
consumer プロジェクトは配布物をそのまま利用し、独自の規約、検査、受け入れゲート、禁止事項を `.agentdev/extensions/**` で追加できる。

保守診断 command（inspect-extensions）は extension 一覧化、構造確認、path 実在確認、project-local skill 存在確認、旧 doc-inputs 機構残存検出を担う。
extension 破損時の標準動作継続により、extension 設定の不備が配布 command/skill の実行を全体停止させない。

- v2:ADR-0135（Project Extensions Architecture）: relates-to。
  旧 doc-inputs 機構から project-extensions 機構への全面置換、5セクション構成、追加・拡張（上書きでない）、配布物本文からのプロジェクト固有参照除去を v2 で確立済みである。
  本 Decision は憲章原則の下で同機構を採用し、憲章決定4 の実現機構として位置づける。
- DEC-001 決定4（新規統制追加の原則、憲章）: relates-to。
  project-extensions 機構は決定4 を運用可能にする実現機構である。
  ADF core への新規統制追加を抑制しつつ、プロジェクト固有統制を project layer で与える経路を提供する。
