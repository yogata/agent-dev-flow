# DEC-044: Semantic Evaluation 観測契約の一次事実中心再設計と基本判断経路への復帰

## 背景

Stage 1 観測（DEC-040 採用、REQ-090 実装）の運用により、観測契約に次の混在が生じていた。
(1) provider 由来の confidence と probability distribution から導出した代替 confidence が同一視されて蓄積されていたこと、
(2) 観測が 1 Workflow 実行 = 1 JSON に集約され、複数の semantic evaluation の一次事実と Workflow 実行の派生状態
（partial/complete、outcome、llmTreatment 等）が同一 JSON に混在していたこと、
(3) DEC-043 採用時の case-ready 実績（T=0.9 フロンティア）の大部分が代替導出値に基づくものであったことが実証されたこと。
DEC-043 は accepted（PR #3157 merged、74ac980c）であるが実運用では未発火（閾値ルーティング未実行）であり、
移行観測の混入はない。

2026-09-26 のセッション合意（RU-0142）により、routing 精密化ではなく観測契約の簡素化と
reasoning model 最終判断への復帰を決定した。後継 Decision の DEC-040 決定4 の部分置換および
REQ-091 検証手段の代替については同一セッションでユーザー承認を得た。

## 決定

1. **観測単位**: 1 semantic evaluation = 1 observation とし、1 Workflow 実行 = 1 JSON の集約を廃止する。
   各 observation から実行元 Workflow と評価種別を識別できること。field 名・物理表現は Design の自由度とする。
2. **一次事実への限定**: 恒久観測は evaluator 返却結果（canonical result と入出力1対1相関を含む）、
   候補別確率分布、provider が実際に返した confidence（evaluation 単位のみ。judgment 単位への複製・
   分布からの代替生成の禁止）、入力再構成情報（source revision・request digest・再構成不能入力の最小 snapshot）、
   reasoning model の最終判断結果（evaluator 成功観測に限定）、差異理由分類（結果相異時のみ）、
   呼出し時間、input token 数（provider 返却時のみ）、失敗分類と最小 diagnostic に限定する。
   source revision から導出可能な provider・requested model 等を観測ごとに必須保存しない。
3. **基本判断経路への復帰**: evaluator 成功時は結果・確率分布・取得できた confidence を reasoning model へ
   判断材料として渡し、reasoning model が最終判断する。evaluator 失敗・未設定・事前検証失敗時も
   reasoning model 経由で Workflow を継続する。新規 fallback framework・routing 機構を作らない。
   DEC-043 の閾値ルーティング（T=0.9 で Jev 単独採用、LLM 省略）を撤回する。
4. **派生状態の除去**: recordState、outcome、llmTreatment、unchanged/corrected、finalizedBy、
   direct-finalization marker、fallback reason、not_configured/invalid_input observation を正規契約から除去する。
5. **0.9 の位置づけ**: T=0.9 は case-ready 過去実績上の経験的目安に格下げする。
   将来の early-exit は十分な実績が得られた個別ユースケースごとに別途検討する（本 Decision では採用しない）。
6. **fail-open と中断耐性**: 観測保存のみの失敗は Workflow の正規処理結果を維持し（fail-open）、
   rollback・再実行・擬似再生成を行わず識別可能な warning を報告する。evaluator 成功後・reasoning model へ
   進む前に一次観測の永続化を試みる。
7. **v1 観測履歴**: 既存の v1 観測は履歴として保持し、migration・変換・読み取り互換を要求しない。
   v1 観測を新契約の現行 observation として解釈しない。
8. **DEC-043 の履歴扱い**: DEC-043 の意味を直接改変せず、本 Decision により superseded として識別する。
   DEC-040 の決定4（観測基盤）は本 Decision により部分置換する。DEC-040 の決定1〜3（6系統への適用、
   逐次経路の基本構造、Jev は最終判断者としない）は本 Decision が維持する。

## 代替案

- (a) routing 方式の精密化（margin 併用、閾値再評価）— 実績の大部分が代替導出 confidence であった実証により、
  観測の信頼基盤が先に必要であり不採用
- (b) 観測契約は現状維持で Stage 2 を継続 — 派生状態と一次事実の混在が分析を困難にしており、
  一次事実の蓄積が将来の再評価の前提であるため不採用
- (c) reasoning model early-exit の段階拡大 — 十分な一次事実の蓄積前に拡張する根拠がなく不採用

## 結果、影響

- 正: 観測が evaluator 単位の一次事実に純化され、将来の有効性評価（Issue B）の分析が簡素化される。
  reasoning model が全経路で最終判断するため判断品質の回復経路が一貫する。
- 負: evaluator 成功時も reasoning model の推論を実行するため、閾値 routing による処理時間・token 削減を放棄する。
- 観測: 新契約の一次事実蓄積により、将来の early-exit 再検討の材料が得られる。

## 再評価・撤回条件

- 新契約での観測蓄積により evaluator と reasoning model の一致率等の材料が揃った場合、
  個別ユースケースごとに early-exit の採用を別 Decision としてユーザー承認に付す
- 一次事実の不足・欠損が観測運用で発覚した場合は観測契約の補修を別途検討する
