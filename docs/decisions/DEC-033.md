# DEC-033: ADF v4 公開運用モデル（UX 2入口収斂・内部 lifecycle・継続コラボレーションループ・学習昇格ガード）

## 背景

v3 の公開 command は case-open/case-ready/case-run/case-close/case-revise を利用者が正しい順に手動実行する UX を前提としていた（DEC-029 は状態遷移中心へ再構成したが個別手動操作は公開のまま）。実利用では req-define -> case-auto へ収束している。一方、Intake/Learning は補助機能の位置づけであり、実行経験の還流が標準プロセスの本流になっていなかった。

## 決定

公開インターフェースを「req-define -> case-auto」と「backlog-auto -> req-define -> case-auto」の 2 中心フローに収斂する。req-define を自然言語要求、bug report、エラー/ログ/障害事象、外部課題、RU、設計・調査メモ、診断由来 finding を受け付ける requirements-driven entry point とし、case-open/case-ready/case-run/case-close/case-revise の意味責務は v4 concept model の内部 lifecycle へ回収する（内部状態遷移の手動順次実行を公開 UX の標準としない）。

work_type を workflow route 直接決定の責務から分離し、scale を work_type 非限定とし、Epic を協調管理、Wave を実行スケジューリング単位として直交させ、大規模 bugfix 等も対象になり得るものとする（Decision 必要性のみによる work_type 変換は禁止）。用語名は、意味モデルの一貫性を改善する明確な理由がある場合のみ見直してよい（その場合も概念責務を失わない）。

Observe -> Intake/Learning -> Backlog -> req-define -> REQ/Decision/Design -> case-auto -> Execute -> Verify -> Integrate -> Observe/Learn の継続コラボレーションループを標準プロセスの本流とする。Intake は未処理の開発需要の受容、Learning は実行経験から得た再利用可能な知識の評価を担い、Learning の評価結果を Knowledge/Decision/Project Policy/Design update/REQ update/Intake-Backlog/一時的記録の終了へ寿命と内容に応じて振り分ける昇格ガードを設ける（Learning/Observation の無条件 REQ 昇格を禁止する）。状態遷移の詳細は v4-standard-lifecycle Design が所有する。

## 結果、影響

公開 command 群の位置づけが変更される。v3 の case-* command 定義の処遇（内部化・統合）は crosswalk で記録し、置換は後続段階で実行する。
