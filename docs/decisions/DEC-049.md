# DEC-049: ADF 共通正本とホスト接続領域の分離によるマルチホスト配布モデル

## 背景

OpenCode を前提とする ADF を Senpi（OmO Native v5）でも利用できるようにする要求（RU-0159、合意済み）に対し、業務契約の全面変更は不要と確認された一方、Tool登録・guard入力・Skill探索・Command入口・workspace・task実行の接続に差分がある。既存の配置構造は src/opencode/ を正本とする単一 reference harness 前提（REQ-002-007/008/047、REQ-009-015/019/020）であり、複数ホストの併存を正本構造として支えられない。

## 決定

既存 Decision との差分として次を決定する。

(1) 業務・安全・品質契約の正本を host 非依存の共通正本領域 src/common/ へ集約し、src/opencode/ と src/senpi/ をホスト別接続領域（公開入口、Tool登録、plugin/hookまたはextension、引数・結果・実行contextの変換）とする。ホスト別コピーの業務手順を独立編集する構造を持たない。

(2) OpenCode を first-class reference harness として維持する。Senpi 接続の追加は DEC-036 決定(2) の「別 Harness/Backend が必要になった時点で adapter を追加」の適用である。OmOのバージョンだけでホストを推測しない。

(3) installer は単一公開入口と check/dry-run/apply を維持し、配置対象（OpenCodeのみ、Senpiのみ、両方）を選択可能にする。新規導入は両方を推奨し、既存導入の更新は現在の配置対象を維持する。scripts 公開入口の2本固定（DEC-021）と導入系スクリプトの副作用ゼロ原則（DEC-016）は維持する。

(4) バックエンド選択（GitHub、ローカルIssue）とホスト選択を独立した軸とする。操作契約の接続境界は Custom Tool 操作契約（GhRunner 型）に限定し、バックエンド抽象層と GitHub 互換ローカルサーバを導入しない（REQ-009-035 維持、差し替え可能な I/O 境界は DEC-004 維持）。

(5) クロスホスト排他機構、実行中台帳、起動拒否機構を新設しない。同一Caseを両ホストで同時処理しないこと、切替前の旧実行停止と永続状態確認はユーザーの運用責任とする。生きたsessionやtaskの別ホストへの移送は行わない。

## 結果、影響

- 既存REQ行（REQ-002-007/008/009/019/045/047、REQ-009-015/016/019/020/040/042）の意味変更更新を伴う。参照、配布検査、テスト、ガイドの更新と既存consumerの更新互換確認が必要になる。
- 共通正本への投影は同一ADF版に整合させ、ホスト別の管理範囲を分離する。片方のホスト投影の更新・除去は他方を壊さない。
- 対応済み宣言は検証した組合せ（ADF／adapter／ホスト／OmO版）に限定する。任意の将来版への無条件の互換保証はしない。
