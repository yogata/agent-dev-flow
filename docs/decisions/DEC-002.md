# DEC-002: OpenCode ソース・プロジェクション分離

## 背景

DEC-001（憲章）は、ADF core が所有する責務と harness、モデル、適用プロジェクトへ委譲する領域を明確に分けた（決定1、決定2）。
この責務分界を物理層で担保するには、配布物の原本と実行時プロジェクションを分離し、原本に harness 固有の記述が混入しない状態を保つ必要がある。
憲章決定5は docs ディレクトリ配置として現行配置を維持する一方、憲章の結果、影響は配布物から harness 固有記述を除去する個別判断を決定2へ照らして行うとした。
配布物の原本と実行時プロジェクションを分離するアーキテクチャは、憲章原則から演繹される物理層の前提である。
再確認により、憲章決定4（新規統制追加抑制）と SPEC から実装詳細を剥離する方針が、原本とプロジェクションの混淆なしに進むことを担保する。

## 決定

1. 配布物（command、skill、template、script）の原本を `src/opencode/` に配置する。
2. 本体リポジトリの `.opencode/` は実行時プロジェクションとし、実行時入口を提供する。
3. プロジェクションは原本から再生可能であり、原本が編集の唯一の入口となる。
4. 初回移行は移行スクリプト（一回限り）で実行し、日常同期は同期スクリプト（継続的）で実行する。
5. 両スクリプトの責務を混ぜない。移行は前提の払拭、同期は継続的整合性の維持に専念する。
6. `src/opencode/` の原本は憲章決定2に従い、エージェント名、モデル名、必須 skill 名、timeout、retry 等の harness 固有記述を含まない。
7. 詳細仕様（リンクモード、コピーフォールバック、同期手順、Windows 環境リスク）は REQ-009（配布基盤・導入モデル）と配布基盤 SPEC へ委譲する。

## 結果、影響

### 正の影響

- 憲章決定2（配布物の harness 非依存）が原本とプロジェクションの分離によって物理層で担保される。
- 整合性検査が原本とプロジェクションを区別できるため、憲章決定3（hard governance の限定）を重複統制なく適用できる。
- 利用プロジェクトは `.opencode/` をローカルカスタマイズの入口として利用できる。
- REQ/SPEC 再構築が原本ベースで進むため、履歴境界を保てる。

### 負の影響

- 開発ワークフローに同期手順が加わる。
- シンボリックリンクを利用できない環境ではコピーベースのプロジェクションへのフォールバックが必要になる。
- 既存のパス参照を含む文書に更新が必要になる。
