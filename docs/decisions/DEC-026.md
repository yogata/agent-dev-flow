# DEC-026: 実現面変更方針の構造化ハンドオフ（realization_actions）

## 決定

req-define が確定した実現面の変更方針を、artifact_actions とは分離した独立構造 realization_actions として draft-data に第一級導入し、case-open が Issue / Epic の execution contract へ投影する。

## 背景

learning-promote が具体的反映先を分類し、backlog-review がその分類を昇華先へルーティングする現行構造により、backlog 処理が Skill・Command 更新を早期選択し、req-define の変更影響分析を先取りしていた。artifact_actions を実現物 enum（skill / command / plugin 等）へ拡張する案は、REQ / Decision / Design 保存操作の責務を混在させるため採用しない。

## 代替案と選択根拠

1. artifact_actions を実現物 enum へ拡張 — 却下。REQ / Decision / Design 保存操作という既存責務が混在し、適用プロジェクト間の中立性を失う
2. execution_unit（case-open 内部構造）へ実現面決定を前倒し — 却下。req-define の変更影響分析が確定する前に構造が固定され、REQ-004-037/038 の確定責務と矛盾する
3. 別構造 realization_actions を draft-data に導入（採用）— artifact_actions の責務を維持したまま、ドメイン中立な実現面変更方針を req-define が確定し、case-open が execution contract へ投影できる

## 判断根拠

- ドメイン中立性: ADF 固有成果物種別を固定 enum にしないことで、ADF 自身・Web アプリ・インフラ等で同じ変更計画モデルを共用できる
- SSoT 遷移の維持: case-open 成功後は Issue が正であり、case-run は req_draft を参照しない既存契約（REQ-008-036/037、REQ-017-016）を変えない
- DEC-003（soft-contract 方針）との整合: realization_actions は soft contract として LLM 推論経由で消費され、スキーマバリデータを導入しない
- 既存フロー非破壊: RU → req-define → case-auto、req-save / design-save の任意実行・スキップは維持される

## 影響

REQ-008（標準フィールド追加）、REQ-004（確定責務の明示）、REQ-017（投影契約）、REQ-038（learning 固有評価への縮約）、REQ-039（backlog-review 責務限定）、artifact-contracts Design、document-model Design、req-draft テンプレート、case-open / case-run Design、learning-pipeline / backlog-review 系 Design・Skill・Command・template。
