# DEC-012: Extension を file-kind から workflow/capability responsibility へ再編

## 背景

現行の extension model（REQ-002-030/031）は file-kind（command-extension / skill-extension）中心であり、
workflow と capability の責務差を反映していない。後方互換性のためだけの二重extension model が残存している。

## 決定

Extension を file-kind 中心から workflow / capability responsibility 中心へ再編する。

- **Workflow Extension**: 公開Workflow Skill への追加・拡張。internal workflow / STEP 全体を拘束する。
- **internal Workflow Extension**: Workflow Skill の内部動作への追加・拡張。Workflow Skill のみが読む。
- **Capability Skill Extension**: Capability Skill への追加・拡張。

public Workflow Extension が Capability Skill extension へ暗黙コピーしない。
後方互換性のためだけの二重extension model を正規状態として残存させない。

配置・適用順序の詳細は Design（`docs/designs/foundations/project-extensions.md` UPDATE）が正規所有者として定義する。

## 結果、影響

- DEC-006（inspect 3-command正規化）を reaffirms / relates-to とする。inspect 3層所有を維持する。
- DEC-005 は歴史参照のみ（superseded 維持）。
- REQ-002-030 / 031 の意味変更を伴う。
- 旧kind（command-extension / skill-extension）は完全廃止。runtime後方互換なし。
- consumer プロジェクトも新kindへの移行対象（配布物変更としてconsumer影響を取る）。
- 旧kind残存時は deterministic check で検出し migration-required として停止。silent ignore しない。
- 新kindへのmapping をmigration documentation（`docs/designs/foundations/project-extensions.md` UPDATE）として提供する。

## Inventory による裏付け（AG-001）

Workflow Architecture Inventory（`docs/designs/foundations/system.md`）が file-kind 中心 model の限界と workflow/capability 責務差の必要性を裏付ける。

- **file-kind 共通性の限界**: 全16 Command が `agentdev-project-extensions` に依存し、`context` / `rules` / `checks` / `acceptance_gates` / `must_not` の5セクションを読み込む（fail-open）。現行 model では Command 単位の file-kind（command-extension）中心であり、Workflow 拘束と Capability 拘束の責務差を表現できない。
- **Workflow 拘束の実例**: `case-run` は worktree 隔離・QG-3 前置 staleness check・targeted docs guard・adapter 委譲契約・adversarial-review 経路G 挿入等、workflow 全体を拘束する拡張点を持つ。`case-auto` は orchestration stage・Wave 反復・bounded parent decision resolution 等、内部 workflow 動作を拘束する拡張点を持つ。これらは public Workflow Extension / internal Workflow Extension の区別 없ければ単一 file-kind で表現力不足となる。
- **Capability 拘束の実例**: `req-save`・`design-save`・`case-open`・`case-close` が呼び出す決定的スクリプト（check-entry-existence・check-change-impact・search-target-area・check_changed_docs.ts・check_extensions.ts）は Capability Skill 側の能力拡張であり、workflow STEP 全体を拘束しない。public Workflow Extension が Capability Skill extension へ暗黙コピーしない分離が必要な concrete case である。
- **二重 extension model 残存のリスク**: Inventory で確認された共通 Capability Skill（`agentdev-git-worktree`・`agentdev-gh-cli`・`agentdev-artifact-validation`・`agentdev-project-extensions`）への拡張が、後方互換性のためだけに command-extension / skill-extension の二重定義を強いられる場合、maintainability と一貫性が損なわれる。新kind（Workflow Extension / internal Workflow Extension / Capability Skill Extension）への再編が migration-required で解決する対象である。
