# AgentDevFlow 憲章

AgentDevFlow の目的、責務境界、基本原則、管理方式を要約する。
基準は [ADR-001](../adr/ADR-001.md) であり、本ガイドは基準への導線を提供する。
基準と矛盾する記述がある場合は ADR-001 を優先する。

## 目的

AgentDevFlow は AI エージェントによる開発ワークフローを支えるプラグインである。
過剰な統制を削減し、責務を限定して明確化する。
harness、AI モデル、適用プロジェクトとの責任分界を明確にする。
新規統制を安易に追加しない仕組みを確立する。

## 責務と境界

### ADF が所有する領域

AgentDevFlow は次を所有する（ADR-001 決定1）。

要求の形成と合意。
事実調査とユーザー意思決定の分離。
REQ/ADR/SPEC 等の成果物責任分界。
実行可能な作業単位の形成。
Issue/PR/Case 間の工程接続。
SSoT の移行。
承認境界。
許可・禁止副作用。
永続状態。
依存、停止、再開、競合防止。
受け入れ条件と完了証拠。
実装中の発見の還流。

### ADF が所有しない領域

次の具体的実現方法は harness、AI モデル、適用プロジェクトが決定する（ADR-001 決定2）。

モデル選定、エージェント選定、サブエージェント階層。
skill の具体的な呼出し。
timeout、retry、context 管理。
TDD、コードレビュー、デバッグの具体的実現。
実装計画の内部形式、コード構造、テスト構造。

AgentDevFlow は必要能力と標準方針を定義できる。
特定のエージェント名、skill 名、起動 API、実行順序は固定しない。

## 基本原則

### hard governance の限定

工程を停止する機械的強制は、次の8点に限定する（ADR-001 決定3）。

状態破壊。
権限逸脱。
ユーザー合意の偽装。
作業または永続情報の喪失。
二重実行、競合更新。
誤った成果物の正規化。
下流工程の実行不能。
後から検出・回復できない重大な失敗。

文章品質、推奨実装方法、分類の細部、改善候補は guidance または finding であり、停止条件にしない。

### 新規統制追加の原則

新しい REQ/ADR/SPEC/command/skill/state/schema/gate/必須 field/checker を追加しないことを既定とする（ADR-001 決定4）。
追加を提案する場合は、次の7条件を全て立証する。

再現可能または複数回観測された問題がある。
被害が hard control に値する。
削除、統合、interface 縮小、guidance 改善では防げない。
機械的または運用上、強制できる。
正規所有者が一つに定まる。
既存の何を削除または簡略化できるか説明できる。
将来の削除条件または再評価条件がある。

「念のため」「将来必要かもしれない」「網羅性を上げたい」のみでは追加しない。

## 利用者の読み方

個別の REQ/ADR/SPEC/command/skill/template/script は、本 charter の原則へ照らして位置づく。
「この統制は本当に必要か」を判断する際は、まず hard governance の8点に該当するか、次に新規統制追加の7条件を立証できるかを検討する。
該当しない場合は guidance・finding・reference へ降格する候補とする。
