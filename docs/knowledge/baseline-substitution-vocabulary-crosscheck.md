# baseline-known 違反の一般化置換は検出器パターンと突合してから行う

## 知識内容

baseline-known 違反を、内部 ID を含む語から一般化表現へ置換して解消する作業では、置換後の語彙選択が検出器のパターン定義（`repo-*` 等のプレフィックス系）に該当すると、置換自体が新規違反を生む。取り扱いは次のとおりである（fix-and-reverify 運用）。

1. 置換候補語彙を検出器パターン定義と事前突合する。事前突合を省略する場合は、置換後に当該検査を必ず再実行して新規違反 0 を確認する。
2. 再実行で新規違反が出た場合は別の一般化語彙へ再置換し、再度検査して新規違反 0 を確認する（1 回の fix-and-reverify で解消する）。
3. 検出器パターン定義の一覧は検査器実装側が所有する。本知識は突合・再検査の手順に留まり、パターン定義の変更を含まない。

## 適用条件

- baseline-known 違反の一般化置換解消作業（内部 ID を含む語を一般化表現へ置換する場面）。
- baseline 運用を持つ検査器（IR-055、IR-059 等）の違反解消作業。

## 適用対象

- 配布依存境界（IR-055）triage 運用の解消作業、baseline 保持型検査器の違反解消作業全般。
- 検出器パターン定義自体の変更、baseline の再生成運用は対象外。

## 根拠

- case 2766: 置換語「repo-local」が `repo-*` 検出パターンに該当し、新規 strict 違反が発生（worktree-operations.md）。「本体リポジトリ専用の整合性検査 skill」へ再置換し、再検査で新規違反 0 を確認した観測（inbox 2026-09-11）。
