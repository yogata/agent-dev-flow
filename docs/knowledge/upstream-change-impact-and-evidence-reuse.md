# 上流変更の影響分析と成果物・検証証拠の再利用

## 知識内容

### 差分と影響は別の問いである

工程駆動では、要件や設計を途中で改訂したときに、後続の成果物と検証をどこまでやり直すかが問題になる。「Git上で何が変わったか」と「どの下流成果物が影響を受けるか」は同じではない。

下流成果物の更新要否を考えるには、現在の上流状態だけでなく、当該下流成果物が**実際に依拠して形成された上流状態**を把握する必要がある。作業開始時のコミットやタグが、必ずしも依拠状態を表すとは限らない。

例えば、上流がA→B→Aと変化した場合、現在と最初のAの差分はゼロでも、途中のBを使って形成された下流成果物が残っていれば影響があり得る。逆に、Git上の文字列差分が存在しても、対象成果物の意味と検証条件に影響しなければ更新は不要なことがある。

### 更新範囲と検証範囲の判断

影響の候補を見つける段階では、見落としを防ぐために候補をやや広く拾うことは合理的である。ただし、候補に挙がったというだけで成果物の再生成を決めず、更新が必要か、不要か、作成対象か、未確認かを根拠とともに区別する。

既存の成果物や検証証拠は、現在有効な条件に照らして利用できる場合には再利用してよい。一方、古い証拠があるだけで現在の要求を満たしたと推定してはならない。必要なのは、その証拠が何をどの範囲で立証しているかの確認であり、「証拠の鮮度」を一律の管理項目として増やすことではない。

### 過去に対象外とした方向と理由

- **上流変更のたびに下流成果物をすべて再生成すること**：影響がない部分まで更新し、実質的な変更の確認や既存証拠の再利用を難しくする。
- **工程開始時のタグ・コミットだけを旧版と決めること**：下流が実際に参照した途中版や工程中の変更を見落とし得る。
- **対応宣言がないことや、正味差分がゼロであることを「影響なし」の証明にすること**：対応登録外の実在成果物や途中版への依拠が残り得る。
- **すべての成果物の恒久的な版台帳・汎用依存グラフ・証拠鮮度台帳を一律に設けること**：対象の追跡や比較を超えて管理の仕組みが肥大化し得る。既存の正規成果物とGit履歴から確認できるものを優先する。

一方、規模・規制・分散開発などの事情により、明示的な版対応や追加の記録が必要になる場合もあり得る。そのときは、どの検証義務を守るためにどの情報が必要かを示し、従来の対象外判断を再評価する。

### 判断方法に関する補足

差分抽出、参照先の有無、明示的な対応関係など、決定的に確認できる事実は機械処理を優先する。内容の意味上の影響は必要な範囲で評価する。機械的確認と意味上の判断を混同せず、比較基準や根拠を特定できない対象を安易に「影響なし」としない。

## 適用条件

- 先行する要件・設計の改訂を、実装・構築・検証等へ反映する必要がある場合
- 段階開発の途中で成果物を改訂し、既存の下流成果物と証拠の再利用を検討する場合
- 差分抽出・変更影響分析の機能を拡張し、見落とし対策と処理負担を比較する場合

## 適用対象

ADF v5.0.0・v5.1.0の工程間追跡、差分・変更影響、増分更新、および過去工程の正規改訂。正規要件を緩めたり新たな完了判定を定義したりするものではない。

## 根拠

- 2026-10-07〜08のChatGPTでの工程差分・影響分析の議論。上流の旧新比較、必要部分のみ更新、依拠状態の特定、専用の証拠鮮度管理を設けないこと等の判断。
- REQ-106（依拠版比較、候補抽出、分類、後続伝播、証拠再利用）、REQ-107（工程間追跡と検証義務）、REQ-111（過去工程改訂と影響伝播）。
