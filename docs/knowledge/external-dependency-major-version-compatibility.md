# 外部依存メジャーバージョン互換性の事前確認

## 知識内容

外部依存のメジャーバージョンアップは互換性非整合を引き起こす事例がある。

1. 依存追加・更新前にメジャーバージョン互換性を事前確認する。検査器要件と対象コード要件を突き合わせる
2. 依存追加・更新前に影響範囲をスキャンし、互換性非整合箇所を特定する。API 非互換のシグナル（非推奨メソッド、削除メソッド、シグネチャ変更）を検出対象とする
3. 検査器（no-excuse 等）と対象コードの TypeScript バージョン整合を必須とする。検査器が要求するバージョンと対象コードが使用するバージョンが不一致の場合、依存追加・更新を停止する

## 適用条件

- 外部依存（npm パッケージ、検査器等）の追加・更新においてメジャーバージョンの変更または要件差異が生じ得る場合
- 検査器と検査対象コードで処理系バージョン（TypeScript 等）の整合が必要な場合

## 適用対象

- AgentDevFlow リポジトリの package.json / bun.lock で管理される依存
- repo-local 検査器群（`.opencode/skills/repo-agentdev-integrity/scripts/`）が要求する処理系バージョン

## 根拠

- PR #1945、PR #1955（導入契機）
  - 具体例1: no-excuse 検査器が TypeScript 7 を要求するが対象コードは TypeScript 5.9 で起動不能となった事例
  - 具体例2: zod v3 → v4 の `.refine` API 非互換の事例
