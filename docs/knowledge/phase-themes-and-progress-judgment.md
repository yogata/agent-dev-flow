# 工程内の検討テーマと工程進行判断の境界

## 知識内容

### 検討事項、実施作業、成立判断の違い

工程駆動における「検討テーマ」は、何について考え、何が未決で、どの成果物に反映すべきかを整理するための単位である。担当者・期限・作業量を割り当てて進捗を計測する作業分解表（WBS）とは目的が異なる。また、検討テーマの一覧をすべて消化したことは、その工程の成果物が妥当であることや、工程を終えてよいことの証明にはならない。

ADF v5.1.0で重視されたのは、一度にすべての論点を網羅・確定することよりも、複数の有限な検討を通じて論点を追加・具体化・統合し、採用された内容を正規成果物へ段階的に反映できることである。AIが提示した参考テーマは、その時点での探索の材料であり、正式な要求や必須作業ではない。

工程内の独立レビューは、既存の要求、成果物、証拠の不一致や不足を発見する支援である。確定した違反、証拠不足、推測、未採用の改善候補を区別できることには意味がある。一方、レビュー実施や参考テーマの解消を、利用者による工程完了・遷移判断の代用にすると、評価結果から根拠なく新しい義務や停止条件が生じ得る。

### 過去に対象外とした方向と理由

- **検討テーマを恒久的なWBS・進捗台帳にすること**：論点の整理を作業進捗の報告制度に置き換えると、工程駆動が重くなる。現行ADFでは作業管理の網羅性を中核目的としていない。
- **テーマとIssue・成果物の一対一対応を必須とすること**：一つの論点が複数成果物に及ぶ場合も、複数の論点が同じ成果物に反映される場合もあり、対応関係の形式だけでは妥当性を示せない。
- **AIによる検討深度や工程全体の完了度の一律採点**：対象に応じた十分性の判断を、一般的な点数に置き換える合理性が確認されていない。利用者の目的や採用した成果物・検証条件も異なる。
- **独立レビューをすべての工程の必須ゲートにすること**：任意の時点で問題を発見する支援と、工程を進める権限は異なる。新たな一律ゲートが実質的な検証を代替するわけではない。

これらを永久に禁止する趣旨ではない。特定の利用者・組織に進捗管理の明示的な要求や、根拠ある定量的な判定基準があるなら、当初の前提との違いを確認して改めて採否を判断できる。ただし、既存の合意や受け入れ条件を無断で変更してよいわけではない。

### 新しい提案を評価する観点

新たな管理項目や評価機能を提案する場合は、「何の意思決定を助ける情報か」「現行成果物や検証で足りないことは何か」「参考情報なのか、正式な完了条件なのか」を分けて考える。

たとえば進捗率の表示を求められた場合、まず何に対する進捗か（作業消化、論点整理、要求充足）を区別する。論点数の消化率から要求充足率を導くことはできない。工程レビューで重大な不一致が確認されれば、その事実を報告する必要があるが、推測上の懸念だけを利用者の判断に優先させるべき理由にはならない。

## 適用条件

- 工程内のテーマ管理、成果物への段階反映、レビュー、工程遷移の責務境界を見直す場合
- 検討の「深さ」「網羅性」「進捗」「完了」を表示・判定する機能の追加を検討する場合
- WBS、担当者・期限、Issue管理との接続を検討する場合

## 適用対象

ADF v5.1.0の工程駆動コラボレーション、工程遷移・独立レビュー、および関連する将来の設計判断。導入先プロジェクトにADF開発上の議論経緯を一律に適用するものではない。

## 根拠

- 2026-10-10〜12のChatGPTでのv5.1.0工程駆動の議論。検討事項を段階的に育てること、工程の深度・進行判断を利用者に残すこと、作業管理・自動採点を中核にしないことに関する利用者の判断。
- REQ-110（テーマの形成・更新、外部検討、成果物の段階形成と対象外）、REQ-111（独立レビュー、利用者による遷移判断）、DEC-057・DEC-058（採用背景）。
- docs/designs/workflows/v51-phase-driven-collaboration-model.md、v51-phase-transition-and-coexistence-model.md（現在の責務境界）。正規要求・設計の再定義ではなく、その背景の判断材料を補足する。
