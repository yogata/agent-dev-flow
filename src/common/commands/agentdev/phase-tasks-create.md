# テーマ形成（phase-tasks-create）

工程初回に参考テーマを形成する人間向け公開入口である。
ユーザーは工程の目的・対象範囲・既知制約を自然言語で伝え、テーマ正本（`.agentdev/phase/themes.md`）への初回形成を受け取る。
既知の必須事項と新しい参考候補を区別して提示し、候補の採否判断はユーザーが担う。

初回工程に有効な上流成果物が存在しなくても異常としない。
利用者が明示した目的・対象範囲・既知制約と参考テーマとの対応、または根拠付きの非該当・未確認を提示し、制約間の未決の衝突は未決として表示する。

## 入力

- ユーザーの自然言語による形成指示（例: 「この工程の検討テーマを形成して」「次工程の初回テーマ形成をして」）
- 現在の会話コンテキスト（工程目的、対象範囲、既知制約、対象が次工程か初回工程かの情報）

## 出力

- テーマ初回形成の結果（形成・追加分のテーマ識別と一覧、参考候補と既知の必須事項の区別）
- 上流不存在時は目的・制約とテーマの対応の明示。次工程の形成では前工程までの既知の必須事項の保持と、成果物構成や粗い検討作業の参考案の提示
- 対象解決不能の場合は候補と不足の報告

本操作はテーマ正本と未決記録への追加・更新を行う操作であり、保存先の一覧には保存したファイルを含める。対象解決不能で保存しない場合は保存しない旨を報告する。機械検証を実行していない場合はその旨を報告する。返却時点で裏で継続している処理はない。

完了報告は、次を必須要素として含める。操作の性質に応じて値が変わり、保存を行わない操作では保存しない旨を、機械検証を実行していない場合はその旨を、完了報告に含める:

- 保存した成果物・記録の保存先の一覧
- 実行した機械検証とその結果
- 操作の返却時点で裏で継続している処理の有無

採用内容の範囲が未決事項と重なる場合はその旨を、検討方向の差し替えを受領する場合は旧方向が持っていた前提の行き先（継承または破棄）を、完了報告に含める。採用・採用根拠の判断自体は既存の採用根拠の規律が担い、この報告は判断を代理確定しない。

機械検査の合格は意味品質の保証ではなく、必要条件であって十分条件ではない。

## workflow

本コマンドは workflow 実装本体を `agentdev-workflow-phase-tasks-create` スキルへ委譲する。
対象の特定、上流不存在の扱い、採用規約の解決の利用、帰納的候補調整、初回形成の実行は同スキルの制御平面が所有する。
テーマ一覧の導出・旧新対応の解決の機械的部分は Capability Skill `agentdev-phase-theme-collaboration` の決定的処理 script を利用する。
本コマンドは単独で起動でき、他の工程操作や遷移操作を前置しない。テーマ更新操作が先行していても、初回形成は既存のテーマ識別・手修正・未決事項を保存して必要な参考候補だけを加える。

## 不変条件

工程上の選好を反映した肯定形の不変条件:

- 対象の取組・対象版・現在工程は既存の正規状態から特定し、同一取組の再開では確定した対象版・現在工程を復元する
- 上流成果物がなくても異常とせず、目的・制約と参考テーマの対応を提示する。制約間の未決の衝突は未決として表示する
- 採用規約の解決（4状態）を利用し、既存の有効規約を優先し、基準がないときだけ標準案を未採用候補として提示する。読取不能時は判断を留保する
- 参考候補は正規成果物の実内容と工程間の対応に照らして帰納的に調整し、意味不変の差から新しい必須条件を導出しない。比較不能・適用限界を明示する
- 候補は参考であり、正式な要求や工程完了の判断へ自動昇格しない。採否判断はユーザーが担う

## ガードレール

否定規則は破壊的操作・state 破壊等の硬い境界に限定する:

- Decision、REQ、Design 等の正規成果物を直接更新しない（テーマ正本は `.agentdev/phase/` 配下の domain state である）
- 領域契約文書（`.agentdev/phase/README.md`）を既存の場合は上書きしない（不在時の初回保存での配布テンプレート実体化を含め、非破壊に維持する）
- decision 成果物は、工程をまたぐ意思決定・未解決課題の管理・方式選択を記録する成果物である。正本の優先度（source-of-truth priority）は `inspect-docs` コマンド定義「不変条件」を、decision の記録内容の規定は document-model Design「責務マトリックス」を参照する（定義本文は複製しない）
- 対象を一意に解決できない場合にテーマ正本へ書込まない（候補と不足を報告する）
- 別取組へ、別版の工程や未決テーマを無条件に引き継がない
- 未採用の自己生成案を採用済み慣行として扱わず、新しい義務や完了基準を作らない
- ユーザー合意が必要な設計判断を代理確定しない
