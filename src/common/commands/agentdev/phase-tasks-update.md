# テーマ更新（phase-tasks-update）

テーマの追加、具体化、分割、統合、廃止をテーマ正本（`.agentdev/phase/themes.md`）に対して独立して実行する人間向け公開入口である。
テーマ正本の初回形成の前後を問わず実行でき、変更理由と旧新対応を保持する。
テーマ一覧はテーマ正本から導出し、別の更新可能な恒久一覧を作らない。

統合・廃止に際して、継続対象の未決事項は後継テーマへ引き継ぎ、対象外・不要とされた事項はその判断根拠が追跡できるようにする。
未決事項を自動解消したと扱わない。

## 入力

- ユーザーの自然言語による更新指示（例: 「テーマAを分割して」「テーマBとテーマCを統合して」「テーマDを廃止したい」）
- 現在の会話コンテキスト（更新種別、対象テーマ識別、更新内容、判断根拠）

## 出力

- 更新の結果（更新適用のテーマ識別、変更理由、旧新対応、未決事項の引継ぎ結果）
- 外部検討中テーマの旧識別で結果が戻った場合の再接続の可否と保留の明示
- 対象解決不能の場合は候補と不足の報告

本操作はテーマ正本と未決記録の更新を行う操作であり、保存先の一覧には保存したファイルを含める。機械検証を実行していない場合はその旨を報告する。返却時点で裏で継続している処理はない。

完了報告は、次を必須要素として含める。操作の性質に応じて値が変わり、保存を行わない操作では保存しない旨を、機械検証を実行していない場合はその旨を、完了報告に含める:

- 保存した成果物・記録の保存先の一覧
- 実行した機械検証とその結果
- 操作の返却時点で裏で継続している処理の有無

採用内容の範囲が未決事項と重なる場合はその旨を、検討方向の差し替えを受領する場合は旧方向が持っていた前提の行き先（継承または破棄）を、完了報告に含める。採用・採用根拠の判断自体は既存の採用根拠の規律が担い、この報告は判断を代理確定しない。

機械検査の合格は意味品質の保証ではなく、必要条件であって十分条件ではない。

## workflow

本コマンドは workflow 実装本体を `agentdev-workflow-phase-tasks-update` スキルへ委譲する。
更新の適用、未決の引継ぎ、旧新対応の保持、冪等の維持は同スキルの制御平面が所有する。
テーマ一覧の導出・旧新対応の解決・未決連携の機械的部分は Capability Skill `agentdev-phase-theme-collaboration` の決定的処理 script を利用する。
本コマンドは単独で起動でき、テーマ形成や他の工程操作を前置しない。

## 不変条件

工程上の選好を反映した肯定形の不変条件:

- 更新操作はテーマ正本の初回形成の前後を問わず独立して実行できる
- 統合・廃止では、継続対象の未決事項を後継テーマへ引き継ぎ、対象外・不要とされた事項の判断根拠を追跡可能に保つ
- 変更理由と旧新対応をテーマ正本のセクション内に保持する
- 実質的な変更がない同一入力の再実行では、セクションを不当に再編せず、変更報告を増やさない
- 外部検討中テーマの改名・分割・統合後に旧識別で結果が戻った場合、後継関係と現行テーマを照合し、安全に対応できる部分だけを再接続する

## ガードレール

否定規則は破壊的操作・state 破壊等の硬い境界に限定する:

- Decision、REQ、Design 等の正規成果物を直接更新しない（テーマ正本は `.agentdev/phase/` 配下の domain state である）
- decision 成果物は、工程をまたぐ意思決定・未解決課題の管理・方式選択を記録する成果物である。正本の優先度（source-of-truth priority）は `inspect-docs` コマンド定義「不変条件」を、decision の記録内容の規定は document-model Design「責務マトリックス」を参照する（定義本文は複製しない）
- テーマ識別を再利用しない（廃止・統合された識別を新規テーマに付け替えない）
- 未決事項を自動解消済みとして扱わない
- 別取組へ、別版の工程や未決テーマを無条件に引き継がない
- 一致しない旧識別の結果を勝手に破棄・再割当てしない（不一致・解決不能な部分は保留する）
- ユーザー合意が必要な設計判断を代理確定しない
