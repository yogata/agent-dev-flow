# 独立レビューと工程全体像（phase-review）

現在の正規成果物群、既定要求、検証証拠を照合して独立レビューを実行する人間向け公開入口である。
ユーザーはレビュー対象を自然言語で伝え、確定違反・証拠不足・推測・未採用改善候補の4区分に分けた所見を受け取る。
レビューは工程完了の必須ゲートではなく、所見の採否と次の行動の判断はユーザーが担う。

あわせて、その時点で有効な工程全体の正規成果物群から、採用済み事項・必要な上流前提・未決事項を区別した一貫した閲覧像（工程全体像）を再構成して提示できる。
閲覧像はセッション内の提示にとどめ、第二の正本として保存しない。

テーマ一覧の解消状態だけを根拠に問題なしと判定せず、工程全体の完了も認定しない。
テーマ一覧外の違反を発見した場合は除外せず所見に含め、レビューの深さは必須基準としない（浅いが採用範囲内の資料も対象とする）。

## 入力

- ユーザーの自然言語による指示（例: 「現行の正規成果物群を独立レビューして」「この設計確定後の成果物を見て」「現在の工程全体像を再構成して」）
- 現在の会話コンテキスト（レビュー対象の範囲指定、既知の懸念、全体像の導出範囲）

## 出力

- 独立レビュー: 4区分（確定違反・証拠不足・推測・未採用改善候補）に分けた所見（セッション内テキスト出力）。所見の区分根拠（照合した要求・成果物・証拠の参照）を伴う。工程完了の認定は行わない
- 工程全体像: 採用済み事項・必要な上流前提・未決事項を区別した閲覧像（セッション内テキスト出力。保存しない）

本操作は保存を行わない操作であり（所見と閲覧像はセッション内の提示のみ）、保存しない旨と機械検証を実行しない旨を完了報告に含める。返却時点で裏で継続している処理はない。

完了報告は、次を必須要素として含める。操作の性質に応じて値が変わり、保存を行わない操作では保存しない旨を、機械検証を実行していない場合はその旨を、完了報告に含める:

- 保存した成果物・記録の保存先の一覧
- 実行した機械検証とその結果
- 操作の返却時点で裏で継続している処理の有無

採用内容の範囲が未決事項と重なる場合はその旨を、検討方向の差し替えを受領する場合は旧方向が持っていた前提の行き先（継承または破棄）を、完了報告に含める。採用・採用根拠の判断自体は既存の採用根拠の規律が担い、この報告は判断を代理確定しない。

機械検査の合格は意味品質の保証ではなく、必要条件であって十分条件ではない。

## workflow

本コマンドは workflow 実装本体を `agentdev-workflow-phase-review` スキルへ委譲する。
照合、所見区分の判定、閲覧像の導出、提示形式は同スキルの制御平面が所有する。
工程駆動の保存状態（テーマ一覧・未決・受領記録）の導出の機械的部分は Capability Skill `agentdev-phase-theme-collaboration` の決定的処理 script を利用する。
本コマンドは単独で起動でき、他の工程操作や遷移操作を前置しない。

## 不変条件

工程上の選好を反映した肯定形の不変条件:

- 独立レビューは単独で起動でき、既定要求・対象成果物・検証証拠と照合して所見を示す
- 所見は確定違反・証拠不足・推測・未採用改善候補の4区分で区別され、各所見は照合根拠を伴う
- 工程全体像は、その時点で有効な正規成果物群と工程駆動の保存状態から、採用済み事項・必要な上流前提・未決事項を区別した一貫した閲覧像として再構成する
- テーマ一覧の解消状態だけを根拠に要求充足・工程完了を認定せず、完了判断はユーザーへ返す
- レビューは工程完了の必須ゲートとせず、レビューの深さの必須基準を設けない
- 所見・閲覧像はセッション内の提示にとどめ、intake inbox や学びの蓄積先へ自動投入せず、閲覧像を第二の正本として保存しない。採用する場合はユーザーの明示判断と根拠を伴う受理経路を通す

## ガードレール

否定規則は破壊的操作・state 破壊等の硬い境界に限定する:

- Decision、REQ、Design 等の正規成果物を直接更新しない
- decision 成果物は、工程をまたぐ意思決定・未解決課題の管理・方式選択を記録する成果物である。正本の優先度（source-of-truth priority）は `inspect-docs` コマンド定義「不変条件」を、decision の記録内容の規定は document-model Design「責務マトリックス」を参照する（定義本文は複製しない）
- テーマ一覧の解消状態・構造上の成立だけから合格判定を出さない
- 所見に区分の根拠を欠いた指摘を含めない
- 閲覧像をファイルへ保存しない（第二の正本を作らない）
- intake inbox、learning、backlog の各状態領域へ所見を自動投入しない
- ユーザー合意が必要な設計判断を代理確定しない
