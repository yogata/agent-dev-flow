# phase-tasks-create workflow スキル

phase-tasks-create command の workflow 実装本体である。
工程初回に参考テーマを形成し、テーマ正本（`.agentdev/phase/themes.md`）への初回形成を実行する制御構造を所有する。
候補は参考であり、正式な要求や工程完了の判断へ自動昇格しない。

phase-tasks-create command は公開 interface（入出力契約・ガードレール）と本スキルへの dispatch のみを持ち、本スキルが workflow 実装本体を提供する。

## 入力

- phase-tasks-create command から渡される形成指示（自然言語。工程目的、対象範囲、既知制約、対象が次工程か初回工程かの情報を含む）
- 現在の会話コンテキスト

## 出力

- テーマ初回形成の結果（形成・追加分のテーマ識別と一覧、参考候補と既知の必須事項の区別、上流不存在時の対応の明示）
- 対象解決不能の場合は候補と不足の報告（テーマ正本への書込みは行わない）

## 副作用

- テーマ正本（`.agentdev/phase/themes.md`）と未決記録（`.agentdev/phase/pending.md`）への追加・更新
- identity（`.agentdev/phase/identity.yaml`）の値の確定（操作実行時に正規状態から解決して確定する）

## workflow model（STEP model 対象外）

本スキルは対話操作完結型の workflow であり、STEP model の対象外である。
resume point / export / import を持たない。各形成操作が1完結単位であり、テーマ正本自体が durable state であるため、中断後の同一要求再実行ではテーマ正本の実ファイルから状態を再構成する。
工程一覧のラベルは順序ラベルであり resume point ではない。

| 工程 | 名称 | 内容 |
|---|---|---|
| 1 | 対象の特定 | 指示と正規状態から操作対象の取組・対象版・現在工程を特定する（下記「対象の特定と再開」）。特定できない場合は形成を実行せず、候補と不足を報告する |
| 2 | 既存テーマ・未決の読み取り | テーマ正本と未決記録の実ファイルを読み、既存のテーマ識別・手修正・未決事項を把握する。一覧の導出は Capability Skill の決定的処理 script を利用できる |
| 3 | 上流成果物の確認 | 対象工程に有効な上流成果物が存在するか確認する。存在しなくても異常としない（下記「上流不存在の扱い」） |
| 4 | 採用規約の解決 | 採用規約の解決（4状態）を確認し、基準の有無を参考候補の調整に反映する（下記「採用規約の解決の利用」） |
| 5 | 参考候補の帰納的調整 | 有効な複数の正規成果物の実内容と工程間の対応に照らして参考候補を帰納的に調整する（下記「帰納的候補調整と限界」） |
| 6 | 初回形成の実行 | テーマ正本へ初回形成を書き込む。更新操作が先行していた場合は既存のテーマ識別・手修正・未決参照を保存し、必要な参考候補だけを追加する（下記「初回形成と更新先行の扱い」） |
| 7 | 報告 | 形成結果（追加したテーマ、参考候補と必須事項の区別、次工程形成の場合の必須事項の保持）を報告する。候補の採否判断をユーザーへ返す |

ファイル検索・内容検索・ディレクトリ列挙は実行基盤の内蔵ツール（ファイル検索、内容検索、読み取り）を使用し、bash 内蔵コマンド（grep、ls 等）を標準手順としない。ただしテーマ一覧の導出・旧新対応の解決は Capability Skill の決定的処理 script の呼出しであり、この限りではない。

## 対象の特定と再開

操作対象の取組・対象版・現在工程は既存の正規状態から特定する。

- `identity.yaml` の実ファイルから現在の対象を復元する。同一取組の再開では確定した対象版・現在工程を維持する
- 別取組へ、別版の工程や未決テーマを無条件に引き継がない
- 対象を一意に解決できない場合は、テーマ正本への書込みを実行せず、候補と不足を報告する

## 上流不存在の扱い

初回工程に有効な上流成果物が存在しない場合も異常としない。

- 利用者が明示した目的・対象範囲・既知制約と参考テーマとの対応を提示する。根拠付きの非該当・未確認を提示できる場合はそれを代替として示す
- 既知制約間の未決の衝突は未決として表示し（pending.md への記録を含む）、参考候補を必須要求へ自動昇格させない

## 採用規約の解決の利用

参考候補の基準は採用規約の解決（4状態）を利用して確認する。機械的解決は Capability Skill `agentdev-adopted-conventions` の決定的解決器を利用できる。

| 採用規約の状態 | 本スキルでの扱い |
|---|---|
| 採用宣言あり | 宣言を正規基準として解決し、採用済みの工程・必須成果物を優先する |
| 宣言なしで有効な既存運用あり | 既存の有効な実効規約を優先し、現行運用の正規成果物から基準を解決する |
| 両方なし | 基準がないことを明示し、標準案は未採用候補としてのみ提示する。候補を必須にしない |
| 宣言ありで読取不能 | 判断を留保し、解決不能として報告する。読取不能を基準不在として扱わない |

## 帰納的候補調整と限界

参考候補は有効な複数の正規成果物の実内容と工程間の対応に照らして帰納的に調整する。

- 意味が変わらない見出しや改行の差から、新しい必須条件を導出しない
- 資料がない、比較できない、または特殊な一例しかない場合は、比較不能・適用限界を明示する
- 未採用の自己生成案を採用済み慣行として扱わず、新しい義務や完了基準を作らない
- テーマに実現手段・数値条件・技術候補を記載しても、有効な採用根拠がない内容を正式な採用済み要求として扱わない。採用を示す主張は、対象内容が有効な利用者判断または正規決定によって裏付けられることを照合してから扱い（参照先の存在だけでは認定しない）、根拠が不足する場合は確認不足または候補として示す。採用主張のない通常の参考テーマを根拠参照の不在だけで一律に無効にしない。機械的部分は Capability Skill `agentdev-phase-theme-collaboration` の採用状態照合（`src/themes.ts --assess-adoption`）を利用できる

## 初回形成と更新先行の扱い

テーマ更新操作（phase-tasks-update）が初回形成より前に実行されていた場合でも、初回形成は既存状態を保存する。

- 既存のテーマセクション（テーマ識別、手修正、未決参照）を保存し、必要な参考候補だけを追加する
- 実質的な変更がない同一入力の再実行では、セクションを不当に再編せず、変更報告を増やさない
- 候補の追加はテーマ識別の新規作成または既存セクションの具体化の追記であり、既存識別の再利用・改変を行わない

## 次工程の初回形成

対象が工程遷移後の次工程である場合は、次の規律を追加する。

- 前工程までの既知の必須事項（前置工程の既知義務・未決事項）を欠落させずに保持する
- 既知の必須事項と新しい参考候補を区別して提示する
- 成果物構成や粗い検討作業の参考案も提示できる。候補を正式な要求や工程完了の判断へ自動昇格しない

## Capability Skill 連携

本スキルは次の Capability Skill を名レベルで参照する。

- `agentdev-phase-theme-collaboration`: テーマ一覧の導出・旧新対応の解決・未決連携（決定的処理 script）
- `agentdev-adopted-conventions`: 採用規約の解決（4状態の機械的解決）

## 共通制約

- 正規成果物（Decision、REQ、Design 等）を直接更新しない（テーマ正本は `.agentdev/phase/` 配下の domain state である）
- 参考候補を必須要求・工程完了判断へ自動昇格しない
- テーマと Issue・成果物の一対一対応を強制しない
- GitHub 版・Local 版のいずれの正規利用経路から起動された場合も、同じ契約で実行する（テーマ正本は両版共通の domain state 配置に保存する）
