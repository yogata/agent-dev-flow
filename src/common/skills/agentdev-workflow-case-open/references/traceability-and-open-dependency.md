## 未決依存の保留と試作の区別

実行契約候補（Definition Package 構成要素）の構成では、実装対象と未決事項との関係を意味的な依存関係に基づいて判断し、利用者の未決判断に依存する正式実装を当該判断が成立するまで保留として区別して記録する（不足している判断と対象範囲を明示）。未決事項の存在だけを理由に依存しない作業を実行契約候補から除外しない。利用者が明示的に許可した試作は、正式採用・正規成果物の確定・本番適用と区別して実行契約へ明示記録し、試作の実施、成果物の存在、試験の成功を当該候補の正式採用や未決事項の解決として扱わない。未決の設計候補について試作として実施するには利用者の明示的な指示または許可を要し、明示的な指示・許可がない試作を開始しない（明示的な指示・許可がない限り、当該部分は未決判断に依存する実装として保留する）。保留した判断の追跡は既存の未決事項管理（追跡Issue）を利用して接続し、新たな管理機構を設けない。

## 実行対象構成の採用根拠照合

実行対象構成（`operation_units`、`artifact_actions`、`realization_actions` から導出する Root Case・Definition Package・Case 構成）を確定する際も、正式な採用の根拠を、利用者の明示判断または有効な正規決定という既存の採用基準に照合して扱う。作業の継続指示、エージェントによる提案や具体化の存在、形式的に受理された採用指定を、利用者に留保された仕様判断の採用根拠として扱わない。明示採用された範囲を超えて関連する別候補や未決の設計事項を一括して確定せず、採用対象・内容・範囲が一意に解決できない部分は Root Case・Definition Package の確定対象から保留し、確認対象として報告する。根拠照合の不足による保留は、既存の停止終了経路（要件が曖昧で Root Case を確立できない場合）および req-define への差し戻し経路に接続する。

## 検証用一時資材の作成・回収義務の詳細

Root Case 確立に伴い検証用remote、clone、bare repository、退避ログ、補助スクリプト、専用server・process等の検証用一時資材を作成する場合、既存の配置規則と権限に従う標準的な一時領域・リポジトリ内の作業領域（`.agentdev/tmp/` 等の配置分類）・許可された外部環境で作成・利用し、利用終了時に安全条件（当該作業が作成した専用資材であることの確認、回収対象範囲の特定、正式な成果物・必要な証拠・他の作業や利用者が管理する資材の保護、既存の副作用・承認境界への適合）が成立する範囲で回収する。安全条件と配置規則の詳細は検証に伴う一時資材の取扱いと後片付け責任 Design が所有する（対応関係は repository top-level `traceability/` 配下 sidecar を参照）。作成を委譲する場合は委譲契約へ一時資材の作成・利用・回収義務を含める（delegation-contracts Design「検証用一時資材の作成・報告義務」節）。後片付けの実施結果、確認根拠、未処理事項（未回収・確認不能・引継ぎ）を既存の作業記録経路へ返す。
