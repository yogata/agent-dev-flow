# phase-tasks-update workflow スキル

phase-tasks-update command の workflow 実装本体である。
テーマの追加、具体化、分割、統合、廃止をテーマ正本（`.agentdev/phase/themes.md`）に対して独立して実行する制御構造を所有する。
テーマ一覧はテーマ正本から導出し、別の更新可能な恒久一覧を作らない。

phase-tasks-update command は公開 interface（入出力契約・ガードレール）と本スキルへの dispatch のみを持ち、本スキルが workflow 実装本体を提供する。

## 入力

- phase-tasks-update command から渡される更新指示（自然言語。更新種別〔追加・具体化・分割・統合・廃止〕、対象テーマ識別、更新内容、判断根拠を含む）
- 現在の会話コンテキスト

## 出力

- 更新の結果（更新適用のテーマ識別、変更理由、旧新対応、未決事項の引継ぎ結果）
- 外部検討中テーマの旧識別で結果が戻った場合の再接続の可否と保留の明示

## 副作用

- テーマ正本（`.agentdev/phase/themes.md`）と未決記録（`.agentdev/phase/pending.md`）への更新
- identity（`.agentdev/phase/identity.yaml`）の値の確定（操作実行時に正規状態から解決して確定する）

## workflow model（STEP model 対象外）

本スキルは対話操作完結型の workflow であり、STEP model の対象外である。
resume point / export / import を持たない。各更新操作が1完結単位であり、テーマ正本自体が durable state であるため、中断後の同一要求再実行ではテーマ正本の実ファイルから状態を再構成する。
工程一覧のラベルは順序ラベルであり resume point ではない。

| 工程 | 名称 | 内容 |
|---|---|---|
| 1 | 対象の特定 | 指示と正規状態から操作対象の取組・対象版・現在工程を特定する。特定できない場合は更新を実行せず、候補と不足を報告する |
| 2 | 既存テーマ・未決の読み取り | テーマ正本と未決記録の実ファイルを読む。一覧はテーマ正本から導出する（Capability Skill の決定的処理 script を利用できる） |
| 3 | 更新の適用 | 更新種別（追加・具体化・分割・統合・廃止）に従いテーマ正本を更新する（下記「更新種別ごとの規律」） |
| 4 | 未決の引継ぎ | 統合・廃止では、継続対象の未決を後継テーマへ引き継ぎ、対象外・不要とされた事項の判断根拠を未決記録に残す（下記「未決事項の引継ぎ」） |
| 5 | 旧新対応の保持 | 変更理由と旧新対応をセクション内に保持する。テーマ識別を再利用しない |
| 6 | 冪等の維持 | 実質的な変更がない同一入力の再実行では、セクションを不当に再編せず、変更報告を増やさない |
| 7 | 報告 | 更新結果と旧新対応を報告する。外部検討中テーマが対象の場合は旧識別との整合も報告する |

ファイル検索・内容検索・ディレクトリ列挙は実行基盤の内蔵ツール（ファイル検索、内容検索、読み取り）を使用し、bash 内蔵コマンド（grep、ls 等）を標準手順としない。ただしテーマ一覧の導出・旧新対応の解決・未決連携の照合は Capability Skill の決定的処理 script の呼出しであり、この限りではない。

## 更新種別ごとの規律

初回形成の前後を問わず、各更新種別は独立して実行できる。

| 種別 | 規律 |
|---|---|
| 追加 | 新しいテーマ識別でセクションを作成する。既存テーマの再編を伴わない |
| 具体化 | 対象テーマのセクション内容を具体化する。テーマ識別は変更しない |
| 分割 | 旧テーマを deprecated にし、分割先テーマを新識別で作成して旧新対応を保持する |
| 統合 | 統合先テーマを残し、統合対象を deprecated にして後継を統合先に向ける。継続対象の未決は統合先へ引き継ぐ |
| 廃止 | 対象テーマを deprecated にして後継を明示するか、廃止の判断根拠を残す。未決の自動解消は行わない |

テーマ識別の再利用は行わない。廃止・統合された識別を新規テーマに付け替えない。

## 採用主張の照合

テーマの追加・具体化で採用を示す主張を扱う場合は、対象内容が有効な利用者判断または正規決定によって裏付けられることを照合してから扱う。

- 参照先が存在することだけを根拠に採用を認定しない。有効な採用根拠がない内容を正式な採用済み要求として扱わず、根拠が不足する場合は正式採用の主張を維持せず確認不足または候補として記録する
- テーマと正規成果物で同一の判断対象の採用状態が異なる場合は不整合を検出し、根拠に基づく是正または未確認として扱う。テーマの記述だけを根拠に正規成果物の採用状態を書き換えない
- 採用判断の成立と正規成果物への反映の完了を区別し、反映が未完了の間は成果物反映まで完了したと扱わない
- 採用主張のない通常の参考テーマを根拠参照の不在だけで一律に無効にしない。機械的部分は Capability Skill `agentdev-phase-theme-collaboration` の採用状態照合（`src/themes.ts --assess-adoption`）を利用できる

## 未決事項の引継ぎ

統合・廃止に際して、未決事項は自動解消しない。

- 継続対象の未決事項は後継テーマへ引き継ぐ（未決記録で状態を carried に更新し、引継ぎ元と後継の双方を関連テーマに残す）
- 対象外・不要とされた事項は、その判断根拠を未決記録に残し追跡可能にする

## 外部検討中テーマの旧識別の再接続

外部検討中のテーマが改名・分割・統合された後に、旧テーマ識別で検討結果が戻った場合は、勝手に破棄・再割当てしない。

- 旧識別の後継チェーンを解決し（Capability Skill の決定的処理 script を利用）、独立識別と旧新関係および現行テーマを照合する
- 安全に対応できる部分だけを再接続し、対応関係を報告する
- 不一致・解決不能な部分は保留とし、保留の理由を報告する（循環・未知識別は解決せず報告する）

## 冪等の維持

- 実質的な変更がない同一入力の再実行では、セクションを不当に再編せず、変更報告を増やさない
- 導出結果の決定性（同一正本から同一 JSON）を基盤とし、変更報告は実際の差分に限定する

## Capability Skill 連携

本スキルは次の Capability Skill を名レベルで参照する。

- `agentdev-phase-theme-collaboration`: テーマ一覧の導出・旧新対応の解決・未決連携・carried 未決の抽出（決定的処理 script）

## 共通制約

- 正規成果物（Decision、REQ、Design 等）を直接更新しない（テーマ正本は `.agentdev/phase/` 配下の domain state である）
- 未決事項を自動解消済みとして扱わない
- テーマと Issue・成果物の一対一対応を強制しない
- GitHub 版・Local 版のいずれの正規利用経路から起動された場合も、同じ契約で実行する
