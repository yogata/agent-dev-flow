# phase-review workflow スキル

phase-review command の workflow 実装本体である。
現在の正規成果物群、既定要求、検証証拠を照合して独立レビューを実行し、区分付き所見を提示する制御構造を所有する。
本スキルは所見の生成と区分判定のみを行い、正規成果物の更新と工程完了の認定は行わない。

phase-review command は公開 interface（入出力契約・ガードレール）と本スキルへの dispatch のみを持ち、本スキルが workflow 実装本体を提供する。

## 入力

- phase-review command から渡されるレビュー対象の指示（自然言語。範囲指定、既知の懸念を含む）
- 現在の会話コンテキスト

## 出力

- 4区分に分けた所見（セッション内テキスト出力。各所見に照合根拠を伴う）

## 副作用

- なし（読み取りと所見の提示のみ。ファイルの作成・変更、状態領域への書込みを行わない）

## workflow model（STEP model 対象外）

本スキルは読み取りと所見提示のみの workflow であり、STEP model の対象外である。
resume point / export / import を持たない。工程一覧のラベルは順序ラベルであり resume point ではない。
中断時は同一指示から先頭から再実行でき、再実行で状態の整合性が崩れない（副作用がないため）。

| 工程 | 名称 | 内容 |
|---|---|---|
| 1 | 照合対象の解決 | レビュー対象の指示から、照合すべき既定要求・対象成果物・検証証拠を正規情報（REQ/Decision/Design、対象成果物、検証結果）から解決する |
| 2 | 照合と所見の抽出 | 解決した照合対象を読み、要求と成果物・証拠の間の不整合、根拠の欠落、推測の混入、改善の余地を抽出する |
| 3 | 所見の区分判定 | 抽出した所見を4区分に分類する（下記「所見区分の提示形式」） |
| 4 | 所見の提示 | 区分付きの所見を提示形式に従って出力する。工程完了の認定を行わず、完了判断をユーザーへ返す |

ファイル検索・内容検索・ディレクトリ列挙は実行基盤の内蔵ツール（ファイル検索、内容検索、読み取り）を使用し、bash 内蔵コマンド（grep、ls 等）を標準手順としない。

## 所見区分の提示形式

所見は次の4区分で区別し、混同して提示しない。

| 区分 | 定義 | 必要な根拠 |
|---|---|---|
| 確定違反 | 既定要求・正規成果物・検証証拠と照合して違反が確定した事項 | 何がどの要求・成果物・証拠に違反するかの参照。違反と判定できた照合根拠 |
| 証拠不足 | 主張の真偽を現時点の検証証拠では判定できない事項 | 判定に必要な証拠の種類と、現状で欠けている範囲 |
| 推測 | 確定根拠を持たない仮定・見立て。事実と区別された状態 | 推測の根拠となった観察と、確定のために必要な確認事項 |
| 未採用改善候補 | 違反ではないが改善の可能性がある提案。採用判断はユーザーに残る | 改善の内容と、現状との差で得られる効果の見立て根拠 |

提示の規則:

- 各所見は区分ラベルを伴い、区分ごとに分けて提示する。区分の判定に迷いがある場合は証拠不足として扱い、判定に必要な証拠を明示する（推測を確定違反として提示しない）
- 所見が0件の区分は、その旨を明示して提示する（空区分の省略により、区別が実行されたことを判断できない状態にしない）
- テーマ一覧に記載のない違反を発見した場合は除外せず、テーマ由来の所見と区別せず同様に区分して提示する
- レビューの深さは必須基準としない。浅いが採用範囲内の資料もレビュー対象とする。深さを理由に所見を省略しない
- 所見の総数・網羅性は本レビューの合格条件としない

## 完了認定の不在

本スキルは工程の完了を認定しない。テーマ一覧の解消状態、構造上の成立、所見の総数の少なさは、要求充足・工程完了の根拠としない。
所見の提示後に「問題なし」「完了」との判定を出さず、所見と次に確認できる事項（採否判断、証拠追加、遷移判断等）をユーザーへ返す。

## 所見の配置

所見はセッション内の提示にとどめる。intake inbox、learning、backlog の各状態領域へ自動投入しない。
ユーザーが所見の採用を明示した場合は、採否判断の根拠とともに当該所見を扱う正規経路（当該成果物を所有する ADF 能力への引き継ぎ等）へ接続する。

## 主要 Capability Skill 連携

本スキルは次の Capability Skill を名レベルで参照する。

- `agentdev-project-extensions`: project extension 読込（5セクション、fail-open）

## 共通制約

- 正規成果物（Decision、REQ、Design 等）を直接更新しない
- レビューを工程完了の必須ゲートとせず、レビューの深さの必須基準を設けない
- ユーザー合意が必要な設計判断を代理確定しない
- GitHub 版・Local 版のいずれの正規利用経路から起動された場合も、本スキルの照合対象は最新の正規情報であり、同じ所見区分の契約で実行する
