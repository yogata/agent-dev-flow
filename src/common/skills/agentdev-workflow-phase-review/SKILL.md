# phase-review workflow スキル

phase-review command の workflow 実装本体である。
現在の正規成果物群、既定要求、検証証拠を照合して独立レビューを実行し、区分付き所見を提示する制御構造、およびその時点で有効な正規成果物群から工程全体像を再構成して提示する制御構造を所有する。
本スキルは所見の生成・区分判定と閲覧像の導出のみを行い、正規成果物の更新と工程完了の認定は行わない。

phase-review command は公開 interface（入出力契約・ガードレール・dispatch）を持ち、本スキルが workflow 実装本体を提供する。

## 入力

- phase-review command から渡される指示（自然言語。レビュー対象の指定、または工程全体像の再構成の要求。範囲指定、既知の懸念を含む）
- 現在の会話コンテキスト

## 出力

- 独立レビュー: 4区分に分けた所見（セッション内テキスト出力。各所見に照合根拠を伴う）
- 工程全体像: 採用済み事項・必要な上流前提・未決事項を区別した閲覧像（セッション内テキスト出力。閲覧像は保存しない）

## 副作用

- なし（読み取りと所見・閲覧像の提示のみ。ファイルの作成・変更、状態領域への書込みを行わない）

## workflow model（STEP model 対象外）

本スキルは読み取りと提示のみの workflow であり、STEP model の対象外である。
resume point / export / import を持たない。工程一覧のラベルは順序ラベルであり resume point ではない。
中断時は同一指示から先頭から再実行でき、再実行で状態の整合性が崩れない（副作用がないため）。

指示がレビュー対象の照合を求める場合は独立レビューの工程へ、工程全体像の再構成を求める場合は全体像の工程へ進む。どちらの指示とも解釈できない場合は、照合対象の解決で不足を報告する。

| 工程 | 名称 | 内容 |
|---|---|---|
| 1 | 照合対象の解決 | 指示から、照合すべき既定要求・対象成果物・検証証拠、または全体像の導出対象となる有効な正規成果物群を正規情報から解決する |
| 2 | 独立レビュー（レビュー指示時） | 照合対象を読み、要求と成果物・証拠の間の不整合、根拠の欠落、推測の混入、改善の余地を抽出し、4区分に分類して提示する（下記「所見区分の提示形式」） |
| 3 | 工程全体像の再構成（全体像指示時） | 有効な正規成果物群と工程駆動の保存状態から、採用済み事項・必要な上流前提・未決事項を区別した閲覧像を導出して提示する（下記「工程全体像の再構成」） |
| 4 | 提示 | 区分付きの所見または閲覧像を出力する。工程完了の認定を行わず、完了判断をユーザーへ返す |

ファイル検索・内容検索・ディレクトリ列挙は実行基盤の内蔵ツール（ファイル検索、内容検索、読み取り）を使用し、bash 内蔵コマンド（grep、ls 等）を標準手順としない。ただし工程駆動の保存状態（テーマ一覧・未決・受領記録）の導出は Capability Skill `agentdev-phase-theme-collaboration` の決定的処理 script の呼出しであり、この限りではない。

## 所見区分の提示形式

所見は次の4区分で区別し、混同して提示しない。

| 区分 | 定義 | 必要な根拠 |
|---|---|---|
| 確定違反 | 既定要求・正規成果物・検証証拠と照合して違反が確定した事項 | 何がどの要求・成果物・証拠に違反するかの参照。違反と判定できた照合根拠 |
| 証拠不足 | 主張の真偽を現時点の検証証拠では判定できない事項 | 判定に必要な証拠の種類と、現状で欠けている範囲 |
| 推測 | 確定根拠を持たない仮定・見立て。事実と区別された状態 | 推測の根拠となった観察と、確定のために必要な確認事項 |
| 未採用改善候補 | 違反ではないが改善の可能性がある提案。採用判断はユーザーに残る | 改善の内容と、現状との差で得られる効果の見立て根拠 |

提示の規則:

- 各所見は区分ラベルを伴い、区分ごとに分けて提示する。区分の判定に迷いがある場合は証拠不足として扱い、判定に必要な証拠を明示する（推測を確定違反として提示しない）
- 所見が0件の区分は、その旨を明示して提示する（空区分の省略により、区別が実行されたことを判断できない状態にしない）
- テーマ一覧に記載のない違反を発見した場合は除外せず、テーマ由来の所見と区別せず同様に区分して提示する
- レビューの深さは必須基準としない。浅いが採用範囲内の資料もレビュー対象とする。深さを理由に所見を省略しない
- 所見の総数・網羅性は本レビューの合格条件としない

## 工程全体像の再構成

工程全体像の再構成では、その時点で有効な工程全体の正規成果物群から、採用済み事項・必要な上流前提・未決事項を区別した一貫した閲覧像を導出する。

| 区分 | 定義 | 導出元 |
|---|---|---|
| 採用済み事項 | 利用者の明示判断または有効な正規決定を根拠に採用が確定した内容と、変更駆動経路で確定した正規成果物 | 正規成果物群、受領記録の採用記録 |
| 必要な上流前提 | 対象工程が依存する前置工程の既知義務・採用済み規約・有効な合意 | 前置工程の正規成果物、採用規約の解決 |
| 未決事項 | 未決記録に残る未決（unresolved・carried）と、採否が確定していない事項 | 未決記録、テーマ正本の未決参照 |

導出の規律:

- 閲覧像はその時点の正規情報から導出する。導出した閲覧像をファイルへ保存せず、第二の更新可能な正本として管理しない
- テーマ一覧はテーマ正本から導出する（Capability Skill の決定的処理 script を利用できる）
- 次工程の初回テーマ形成の参考として閲覧像を利用する場合は、既知の必須事項と新しい参考候補を区別して提示する。候補を要求や工程完了判断へ自動昇格しない
- 別セッションでは、正規成果物群と工程駆動の保存状態の実ファイルから閲覧像を再構成する。受領済み知見は受領情報から再取得し、未受領の外部検討内容を復元したと扱わない

## 完了認定の不在

本スキルは工程の完了を認定しない。テーマ一覧の解消状態、構造上の成立、所見の総数の少なさ、閲覧像の一貫性は、要求充足・工程完了の根拠としない。
所見・閲覧像の提示後に「問題なし」「完了」との判定を出さず、提示内容と次に確認できる事項（採否判断、証拠追加、遷移判断等）をユーザーへ返す。

## 所見の配置

所見と閲覧像はセッション内の提示にとどめる。intake inbox、learning、backlog の各状態領域へ自動投入せず、閲覧像をファイルへ保存しない。

## 採用所見の成果物修正への引き継ぎ

ユーザーが所見の採用を明示した場合は、採否判断の根拠とともに、当該所見を扱う正規経路へ引き継ぐ。
引き継ぎ先は、成果物更新の反映受理を所有する `agentdev-workflow-phase-artifacts-update` と、当該成果物を所有する成果物管理 Capability Skill である。新しい承認段階を一律に要求せず、本スキル自身は正規成果物を更新しない。

引き継ぎの規律:

- 引き継ぐ対象は、利用者が明示的に採用した所見のみである。未採用・採否不明の所見は採否判断が確定するまで引き継がず、修正確定済みの要求として扱わない
- 採用範囲（どの範囲を適用するか）と判断根拠（なぜ採用したか）を維持して引き継ぐ。所見の一部だけが採用された場合は、採用された範囲だけを引き継ぐ
- 対象成果物、参照する要求、元の指摘内容、判断根拠を誤転記や意味変更なく引き継ぐ
- 対象箇所の特定は、見出し・文言・文書内の構造上の位置など複数の特定情報で行い、行番号だけを依存条件としない
- 引き継ぎ先での修正前の最新照合、反映結果の実際の成果物変更との照合、中断後の残修正継続は、受け先の `agentdev-workflow-phase-artifacts-update` の規律に従う

## 主要 Capability Skill 連携

本スキルは次の Capability Skill を名レベルで参照する。

- `agentdev-phase-theme-collaboration`: 工程駆動の保存状態の導出（テーマ一覧・未決・受領記録。決定的処理 script）
- `agentdev-project-extensions`: project extension 読込（5セクション、fail-open）

## 共通制約

- 正規成果物（Decision、REQ、Design 等）を直接更新しない
- レビューを工程完了の必須ゲートとせず、レビューの深さの必須基準を設けない
- 閲覧像を第二の正本として保存しない
- ユーザー合意が必要な設計判断を代理確定しない
- GitHub 版・Local 版のいずれの正規利用経路から起動された場合も、本スキルの照合対象は最新の正規情報であり、同じ所見区分・閲覧像の契約で実行する
