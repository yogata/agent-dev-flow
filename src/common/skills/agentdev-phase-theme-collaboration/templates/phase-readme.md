# 工程駆動ドメイン状態（phase/）

工程駆動コラボレーションが使用するテーマ正本と最小識別状態の保存領域。
工程駆動の4操作（phase-tasks-create、phase-tasks-update、phase-artifacts-update、phase-review）、利用者判断による工程遷移（phase-transition）と、操作をまたぐ別セッション再開が読み書きする。

## 保存モデル

| Path | 保存内容 | 様式 |
|---|---|---|
| `identity.yaml` | 取組・対象版・現在工程の最小識別状態 | YAML |
| `themes.md` | 検討テーマの正本 | Markdown（テーマ1件を1セクション） |
| `pending.md` | 未決事項と判断根拠 | Markdown（未決1件を1セクション） |
| `received/` | 受領済み途中検討知見の受領記録（1受領1ファイル） | Markdown |
| `adoptions/` | 直接採用の採否記録（1採用1ファイル） | JSON（採否記録生成の決定的処理 script 出力） |
| `transitions/` | 工程遷移の遷移記録（1遷移1ファイル） | 遷移記録の操作契約（`agentdev-workflow-phase-transition`）が所有する物理形式 |

保存状態は書込対象の解決、再開、受領済み検討知見の継続に必要な最小情報に限る。
進行度・完了率・残作業を記録する恒久台帳を設けない。

## 導出規則

- テーマ一覧は `themes.md` のテーマセクションから導出する。一覧を恒久保存する別ファイルを作らない。
- 工程全体像（閲覧像）は、その時点で有効な正規成果物群と本領域の保存状態から導出して提示する。閲覧像を本領域へ保存しない。閲覧像を第二の正本として管理しない。

## identity.yaml の様式

フィールドは次の3つとする（空文字の初期状態で配置する）。

```yaml
undertaking: ""
target_version: ""
current_phase: ""
```

- 操作実行時に既存の正規状態から対象の取組、対象版、現在工程を解決して確定し、同一取組の再開時に復元する。
- 別取組へ、別版の工程や未決テーマを無条件に引き継がない。
- 対象を一意に解決できない場合は、正規成果物への変更を保留し、候補と不足を報告する。

## themes.md の様式

テーマ1件を1セクションで記録する。

```markdown
## THEME-{NNN}: テーマ名

- 状態: active | merged | deprecated
- 後継: （merged / deprecated 時に継承先テーマの識別）
- 具体化: テーマの内容、参照元の正規成果物
- 未決: （pending.md の未決エントリ識別。存在しない場合は省略）
```

- 統合・廃止では状態と後継を更新し、旧新対応をセクション内に保持する。テーマ識別を再利用しない。
- 分割は旧テーマを deprecated にし、分割先テーマを新識別で作成して旧新対応を保持する。
- 初回形成は、更新操作が先行していた場合でも、既存のテーマセクション、手修正、未決参照を保存し、必要な参考候補だけを追加する。
- 実質的な変更がない同一入力の再実行では、セクションを不当に再編せず、変更報告を増やさない。

## pending.md の様式

未決1件を1セクションで記録する。

```markdown
## PEND-{NNN}: 未決事項の要約

- 状態: unresolved | carried | resolved
- 関連テーマ: （テーマ識別。carried の場合は引継ぎ元と後継の双方）
- 判断根拠: （未決とした理由、対象外・不要と判断した根拠）
```

- 未決事項を自動解消済みとして扱わない。統合・廃止に際して、継続対象の未決事項は後継テーマへ引き継ぎ（状態を carried に更新）、対象外・不要とされた事項は判断根拠をこのファイルに残す。

## received/ の様式

受領済み途中検討知見を、1受領を1ファイルで保存する。

```
received/YYYY-MM-DD-{テーマ識別}.md
```

ファイルには受領情報（受領日時、対象テーマ識別、持出し時の目的と問い、参照元）と、採用・不採用・保留の各内容を記録する。

- 採用・不採用の記録は明示採用件数に比例する量にする。受領内容全体を複写する恒久複本を作らない。
- 採用根拠は利用者の明示判断または有効な正規決定であり、外部AIの自己申告を採用証拠として記録しない。
- 不正または曖昧な内容は不採用・保留として記録し、確定済みとして扱わない。
- 別セッションでは受領情報から受領済み知見を再取得する。一度も受領していない内容を復元したと扱わない。

## adoptions/ の様式

直接採用の採否記録を、1採用を1ファイルで保存する。

```
adoptions/YYYY-MM-DD-{採用対象の識別}-{連番}.json
```

1ファイルは1件の明示採用指示に対応する採否記録（採用レコード）を記録する。
採用対象の識別はテーマ識別または反映対象の成果物識別等であり、同日の複数採用は連番で区別する。

- 採否記録の様式と機械生成は `agentdev-phase-theme-collaboration` の決定的処理 script（戻り入力の受理・採否記録生成）が所有し、保存先への書込みは保存する操作（成果物反映）の責務である
- 受領記録と同じ証跡規律を適用する。内容の由来（provenance）と正式な採用根拠（adoptionBasis）を区別して記録し、由来だけを採用済みと扱わない
- 不正または曖昧な入力は不採用・様式不備として残し、採用記録へ確定しない（fail-closed）
- 採用・不採用の記録は明示採用件数に比例する量にする。採用内容本文を複写する恒久複本を作らない
- 同日の複数採用は連番で区別し、既存の記録を上書き・消失させない

## 終端遷移後の保存状態の保持

採用済みの工程関係に後続工程が存在しない終端の遷移は、架空の後続工程を作らない記録形式で遷移記録へ保存される。記録の物理形式は `agentdev-workflow-phase-transition` の決定的処理 script が所有する schema が定め、保存された記録から終端であることを再構成できる。

終端の遷移後、当該工程の工程駆動の保存状態（テーマ正本、識別状態、遷移記録）は参照専用として保持する。

- 参照専用の保持は、別セッション再開と過去工程の参照を保障するものであり、保存状態を再編・削除する根拠ではない
- 参照専用の保持は、完了済み過去工程の正規改訂と変更駆動経路による作業を妨げない
- テーマ正本のテーマ状態（active、merged、deprecated）に完了状態を追加せず、テーマの消化をもって工程の完了を記録・証明しない

## 別セッション再開

再開は本領域の実ファイル（`identity.yaml`、`themes.md`、`pending.md`、`received/`、`adoptions/`、`transitions/`）から行う。
外部検討の結果の到着や正規成果物への反映がなくても、実ファイルだけから、確定済みの対象版・現在工程・テーマ・未決・受領済み知見・採否記録・遷移記録を復元できる。
値が変わらない再開では、実ファイルを再編せず、変更報告を生まない。
