# 構造再編操作（分割・統合・項目移動）

本ファイルは `agentdev-req-file-manager` SKILL.md の補助資料であり、正規成果物の構造再編（分割・統合・項目移動）のうち REQ ファイルに対する操作手順を扱う。
専用の再編モードを新設せず、CREATE/APPEND/UPDATE と同じ採番・配置・照合・インデックス更新の規則を適用し、不足する操作のみを定める。
再編を要求しない初回作成・増分更新の利用経路は本ファイルの対象外であり、既存の操作モードを変更しない。

## 許可条件

- 再編は、利用者が再編対象（どの REQ ファイル、どの要件行）と実施（分割・統合・移動の別）を明示した範囲でのみ実行する
- 会話の流れからの推論で再編対象を確定しない。対象や許可範囲が特定できない場合は対象部分の変更を保留し、再編候補と不足している判断材料を報告する
- 構造変更と実質的な内容変更を区別する。構造だけの再編では、対象要求の振る舞い・成立条件・適用範囲・受け入れ条件の文言を保持し、内容変更が併せて許可されている場合のみ移動と同時に内容を修正する

## 再編操作の種類と既存モード構成

| 操作 | 内容 | 既存モードでの構成 |
|---|---|---|
| 分割 | 1 REQ ファイルの要件行集合を複数 REQ ファイルへ分離する | 後継 REQ の CREATE + 分離される要件行の項目移動 + 旧 REQ の本文内メタデータ更新（Supersedes / Superseded by、Status） |
| 統合 | 複数 REQ ファイルを 1 REQ ファイルへ統合する | 統合先への要件行の項目移動 + 旧 REQ の本文内メタデータ更新（Status と Superseded by） |
| 項目移動 | 要件行を別 REQ ファイルへ移動する | 移動元 REQ の該当行削除 + 移動先 REQ への行追加 |

- 分割・統合で生じる後継 REQ ファイルは、CREATE の採番（最大番号+1、欠番埋め禁止）、テンプレート適用、README インデックス追加、ドキュメントハブ更新の既存規則に従う
- REQ-ID は安定 ID である。再編で生じる新規 REQ ファイルは新規 REQ-ID を採番し、旧 REQ の本文内メタデータ（Supersedes / Superseded by、Status）で旧新対応を確認できる形にする
- 統合・分割で内容が後継へ移った旧 REQ の識別子を、過去と異なる要求を指す形で再利用しない（REQ番号採番ルールの欠番再利用禁止に従う）

## 要件行移動の識別子規則

- 要件行 ID は移動先 REQ ファイルの既存行連番との衝突を避けるため、移動先で既存の採番規則（最大行番号+1、欠番再利用禁止）に従って再採番する
- 移動元で生じた行連番の欠番は埋めず、欠番記録表（numbering-and-validation.md「要件行の既知欠番の記録」）へ理由と後継行の所在を同一変更で記録する
- 旧行 ID と後継行 ID の対応は、当該 REQ 本文内メタデータと欠番記録表から必要な範囲で確認できる。恒久的な旧新対応表の保存義務と独立した識別子履歴管理は設けない
- 衝突する行 ID を移動先にそのまま複写しない。別要求を指す識別子の衝突は、トレーサビリティ対応宣言の別要求への誤対応を生む

## 適用前検証

再編の適用前に次を検出し、検出時は対象部分の適用を保留して報告する。

| 検出対象 | 判定 | 保留時の報告 |
|---|---|---|
| 識別子衝突 | 移動・統合後の行 ID が移動先の既存行 ID と衝突しないこと。REQ-ID の新規採番は番号空間衝突チェック（numbering-and-validation.md「移行・統合時の番号空間衝突チェック（前置）」）を前置する | 衝突する識別子と該当ファイル一覧 |
| 移動先不明 | 移動先・統合先・分割後の配置先が一意に解決しないこと | 解決不能な対象と候補一覧 |
| 項目重複 | 同一内容の要件行を複数箇所へ適用していないこと。部分失敗からの再開時の重複適用検出を含む | 重複する対象行と適用済み位置 |

## 適用後検証

再編の適用後、再編全体を完了とする前に次を確認する。

| 確認 | 内容 |
|---|---|
| 内容保全の機械的突合 | 再編対象の全要件行について、再編前後の識別子・件数・行内容の突合を行う |
| 内容上の同等性確認 | 機械的突合に加えて、再編前の各対象要求の振る舞い・成立条件・適用範囲・受け入れ条件が再編後も保持されていることを確認する。項目数の一致だけを根拠に再編全体を完了としない |
| 参照整合 | 旧識別子（REQ-ID、要件行 ID）への現在有効な参照を docs 全体、トレーサビリティ sidecar、`.agentdev/extensions` 配下から特定し、必要な参照更新を行う。更新が必要な参照が未更新のまま残っていないことを確認する |
| インデックス整合 | README インデックス、ドキュメントハブ、欠番記録表を同一変更で更新する |

参照の影響判断（更新必要・更新不要・作成・未確認）は、差分・変更影響と増分更新の正規契約に従う。配置変更と要求内容の変更を区別し、構造だけの再編を理由に下流成果物の内容変更を自動確定しない。再編前の REQ に依拠する下流には、既存の伝播規律を適用する。

## 部分失敗からの再開

- 保存操作が部分的に失敗した場合、または検証途中で中断した場合は、再実行時に実際に成立した変更を正規成果物の実ファイルから確認する
- 成立済みの部分を重複適用せず、未成立部分だけを継続する
- 成立済み変更の重複適用による内容の重複・消失・誤改番を検出した場合は、当該部分の適用を停止し、成立状態と差分を報告する
