# サブエージェント調査委譲スコープ絞り込み

req-define の変更影響候補抽出および横断探索において、調査スコープの絞り込み（キーワード抽出、ファイル列挙・検索の前処理）と複数の読込や検索を伴う探索を読取専用の探索サブエージェントが実行し、判断主体へ構造化サマリを返却する手順。

## 目的と位置付け

実績 ses_10c29a13 で req-define のサブエージェント調査委譲に全体の約 34% の時間を消費した。
入力スコープが広すぎたことが主因であるため、決定的前処理で優先調査対象を事前特定して探索効率を高めつつ、複数の読込や検索を伴う前処理と横断探索自体を読取専用の探索サブエージェントへ委譲し、判断主体の会話コンテキストへ生の本文全文や大量の検索結果を持ち込まない。

**ヒントでありハードフィルタではない**: 絞り込み結果は探索サブエージェント内の調査優先対象リスト（priority targets）として扱う。
探索サブエージェントはこのリストを優先調査の目安とし、リスト外のファイルを調査対象から除外してはならない。
実ファイル完全列挙と全件存在確認（機械処理）の要求は、前処理を探索サブエージェントが実行する場合も維持する。

## 前処理フロー

### 1. RU からの対象領域キーワード抽出

入力 RU（`.agentdev/backlog/req-units/RU-*.md`）の frontmatter と本文から、調査すべき対象領域を示すキーワードを抽出する。

**抽出対象**:

| 抽出元 | キーワード種別 | 例 |
|--------|---------------|-----|
| frontmatter | `source_artifact`, `target_artifact`, `area` 等の対象示唆フィールド | `REQ`, `req-define`, `agentdev-req-analysis` |
| 本文見出し | 対象 command/skill/文書名 | `case-run`, `agentdev-issue-management` |
| 本文 | 既存 REQ/Decision/Design の参照 ID（`REQ-NNNN`, `DEC-NNN`, Design パス） | `REQ`, `DEC`, `<command Design>` |
| 本文 | ドメイン用語、対象機能名 | `委譲`, `I/O 境界`, `soft-contract` |

抽出キーワードは正規化（大小区別しない、`agentdev-` 等のプレフィクス揺れの吸収）した上で重複排除する。

**除外キーワード**: 汎用語（「対応」「実装」「確認」等）はノイズになるため抽出対象外とする。
command/skill 名、REQ/Decision/Design ID、固有名詞に限定する。

### 2. glob/grep による関連 REQ/Decision/Design 事前特定

抽出したキーワードでリポジトリ内の文書群を検索し、関連候補を事前特定する。

**検索対象とコマンド**:

```
# 関連 REQ 候補
glob docs/requirements/<REQ-*>.md
grep -l "<keyword>" docs/requirements/<REQ-*>.md

# 関連 Decision 候補
glob docs/decisions/<DEC-*>.md
grep -l "<keyword>" docs/decisions/<DEC-*>.md

# 関連 Design 候補
grep -rl "<keyword>" `docs/designs/`
```

REQ/ADR は ID 直接参照（`REQ-NNNN`, `ADR-NNNN`）が含まれる場合は当該ファイルを確実に含める。
Design はパス参照（docs 配下の Design 文書パス）と用語参照の双方で検索する。

**完全列挙の維持**: 上記 glob は関連候補の事前特定に用いるが、REQ/Decision の実ファイル完全列挙自体は別途 `agentdev-req-analysis` の「既存REQ/Decisionの定量的照合」で実施する。
本前処理が完全列挙を代替、省略することはない。
完全列挙の結果（全 REQ/Decision ファイル一覧）と事前特定結果（キーワード一致ファイル）は独立に保持し、サブエージェント調査委譲へ両方を渡す。

### 3. 調査優先対象リストの構築

事前特定した関連候補を優先度付きリストとして整理する。

**リスト要素**:

- `high`: キーワード一致 + ID 直接参照の文書（最優先）
- `medium`: キーワード一致のみの文書
- `unscoped`: 完全列挙結果のうちキーワード不一致の文書（REQ の完全性担保のため調査対象に含むが優先度は低い）

サブエージェント調査委譲は `high` → `medium` → `unscoped` の順で調査効率を高める。
`unscoped` を飛ばしてはならない（完全性維持）。

## 探索サブエージェントからの返却（構造化サマリ）

探索サブエージェントは、委譲契約（delegation-contracts Design の親セッション向け委譲結果サマリ）の読取専用委譲向け上限目安に従う構造化サマリを判断主体へ返却する。
含める項目は次の 7 項目に限定する（実装や検証にだけ該当する項目は省略する）:

1. 判定要約
2. 関連ファイルパス（行・節を含む）
3. 正規所有責務
4. 制約と矛盾点
5. 変更候補
6. 未確認事項
7. 副作用なしの旨

生の本文全文や大量の検索結果は返却本文に含めず、判断主体の会話コンテキストへ持ち込まない。取得不能、切断、文字化け、未確認を成功として扱わない。
判断主体（req-define）はサマリ記載の参照のうち判断に必要な、対象パスが確定している単一ファイルの限定的確認だけを直接実行する。

### 全文の機械抽出と取得物の引き継ぎ

探索およびサブエージェント間・後続担当への引き継ぎにおける全文の取り扱い規律。

- 調査対象ファイルの全文は既存の機械的手段で抽出し、委譲指示で既存本文や全索引の大量逐語再出力を要求しない。取得物への参照（`full_text_refs`）と、モデルによる判断・要約を分けて渡す
- 調査結果は原文参照（パス・範囲）と判断結果（判定、差異、根拠箇所）を分離して返す。必要な周辺文脈を含む原文を後続担当が実際に読めるように引き継ぎ、逐語再出力を原文参照の代替にしない
- `full_text_refs` は実行担当が実際に読める形で引き継ぐ。参照は実在する対象に向ける。取得不能、切断、文字化けを完全な抽出として扱わず、参照不能を黙過しない
- 大量の全文を委譲応答へ逐語再出力させない。原文参照と判断結果を分離し、応答には判断・結論と根拠位置を記録する
- 全件の存在確認と完全列挙は機械処理で維持する。優先対象リストや調査要約で列挙結果を置き換えない
- 優先対象外も含め追加探索を行い、priority_targets は探索範囲を制限するフィルターとして扱わない
- 手段の具体（ツール名、シェル、起動 API）は実行基盤側の操作規律に委譲し、本前処理で固定しない
- キーワード不一致だけを根拠に調査対象外を確定しない。完全列挙を維持した上で、直接参照、依存関係、矛盾候補から追加探索し、優先対象リストを閉じた検索範囲として扱わない

## 制約

- **決定的処理**: キーワード抽出、glob/grep は機械的、決定的処理であり、LLM 推論に依存しない。結果は再現可能であること
- **ヒント扱い**: 絞り込み結果をハードフィルタとして扱わない。前処理を探索サブエージェントが実行する場合も、`unscoped` を調査対象から除外することを禁止する
- **完全列挙の維持**: 実ファイル完全列挙と全件存在確認（機械処理）の要求を本前処理で省略、代替せず、完全列挙をキーワード検索で代替しない
- **全文の機械抽出と生本文持ち込み禁止**: 調査対象全文をモデルに逐語再生成させない。機械的手段による取得結果の参照を引き継ぎ、生の本文全文や大量の検索結果を判断主体の会話コンテキストへ持ち込まない
- **責務境界と直接実行範囲**: 探索・前処理は読取専用の探索サブエージェントが担い、判断主体が直接実行するのは対象パスが確定している単一ファイルの限定的確認だけとする。探索結果のドラフト反映と最終判断は親エージェント（req-define）が保持する（delegation-contracts Design）
