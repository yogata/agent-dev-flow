# 入力・部分反映・記録

`phase-artifacts-update` の所見処理、再投入、工程記録の詳細。入力の決定的処理は `agentdev-phase-theme-collaboration` が所有する。

## 入力と採用根拠

- 貼付・指定ファイル・直接提示に同じ改行正規化を適用し、同じ意味の入力は同じ確定 JSON を得る。入力は単一の線形走査で処理する。不正・曖昧な入力は不採用として残し、採用記録に確定しない。
- 対象 identity は操作時に正規状態から解決する。旧テーマ識別の後継解決、受領済み照会には Capability Skill の公開処理を使う。ファイル検索・読み取りは実行基盤の内蔵ツールを使う。
- 明示採用は `accepted` / `user-explicit` とする。テーマ正本と採否記録、正規成果物の不整合は Capability Skill の採用状態照合に接続する。実行境界側で照合される実ファイル・記録と一致させる。
- 独立レビューは利用者が明示採用した所見のみ受理する。対象成果物、参照する要求、元の指摘、判断根拠と採用範囲をそのまま保持する。最新の成果物で成立を確認し、見出し・文言・構造上の位置を併用する。誤り・解消済み・対象不明は保留し、理由と確認事項を返す。

## 部分反映と再投入

複数の項目がある場合は安全な独立事項を反映し、衝突・未確認・保存失敗を区別する。完了は実際の変更で確認し、修正指示、作業開始、保存成功だけで判断しない。同一要求の再投入では受領・採否記録と実ファイルを読み直し、決定的処理の重複検出を利用して未成立部分だけを続ける。

## 記録

- 外部戻りがある場合は受領日時、テーマ識別、目的、問い、参照元、採否を Capability Skill の契約に沿って記録する。別セッションでは保存済み情報から再取得し、未受領の内容は復元したと扱わない。
- 直接採用の記録は同日の連番で区別し、上書きしない。由来 `provenance` と正式な採用根拠 `adoptionBasis` を区別し、由来を採用証拠にしない。様式は領域契約文書の `decision-log/` の項を参照する。
- 証跡量は明示採用件数に比例させ、受領内容全体の恒久複本を作らない。所見の反映状況は元の所見、採用判断、実際の変更から再構成し、別の進捗台帳を設けない。
