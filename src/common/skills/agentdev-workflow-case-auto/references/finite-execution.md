# 有限実行の詳細

case-auto の v5 モードの明示指定時に読む。実行記録でモードを区別し、正式切替は crosswalk の処遇を伴う正規改訂で行う。運用実績だけで標準経路や棚卸し行を書き換えない。

| 責務 | 既存の正規経路 |
|---|---|
| 要求確定 | req-define の壁打ち合意と draft 確定 |
| 設計確定 | case-open の実変更判定・設計PR と case-ready の受入・確定 |
| 実装・検証 | case-run 委譲と case-close QG-4 |
| Issue 協調 | case-open の Root Case、case-ready の実行構造、case-auto の stage 制御 |
| 後処理 | case-close の統合・終了・Capture・永続化 |

- **小規模連続実行**: 単一対象の要求・設計確認から実装、検証、報告までを一続きに進める。Root Case / Epic / Child Issue を生成しない。権限と実行範囲を確認し、case-run の4状態 result・worktree 隔離・3点ゲート・PR 本文の検証差分を再利用する。PR マージや Issue 終了のみで完了としない。Capture を既存の intake / learning / backlog 循環へ引き継ぐ。
- **設計確定**: 確定済み要件から設計形成し、設計確定で独立終了する。正規 Design・Decision を永続化し、要求充足とは区別する。
- **確定済み設計からの接続**: 正規 REQ・Decision・Design と有限な範囲、既存検証条件を入力とし、最新の実装対象・依存・証拠を確認する。小規模経路または利用者が指定した Root Case を使う。工程駆動の成果物も参照専用入力として利用でき、変更駆動に工程駆動の操作・遷移を必須としない。追跡・委譲・分割・再開に Issue の価値がある作業は標準経路を使う。
- **正規状態と再開**: 上流の要求・設計を再所有しない。上流問題は無断変更せず req-define の再合意と影響再評価へ接続する。再開は正規入力と worktree・branch・PR・commit から復元する。未検証を成功と報告しない。Local 版はローカル記録と実 Git 取り込み結果を独立に突合する。
- **継承する制約**: 依存未充足の後続を開始せず、実装委譲の共有5枠、外部副作用の境界、隔離、再開、検証を維持する。単独工程と連続実行、工程駆動、GitHub・Local の代表事例では操作結果・正規成果物・Git 履歴・検証証拠を確認する。
