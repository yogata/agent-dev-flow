# 課題管理

開発過程で生じた未解決事項を課題として管理する人間向け公開入口。
ユーザーは自然言語で意図を伝え、現在の会話文脈、対象課題、状態から必要な操作（検知、新規起票、検索、参照、更新、検討経過追加、保留、再評価、解決、反映確認、クローズ、再オープン）を判断して実行する。

本コマンドは `docs/issue-list/` の課題ファイルを扱う。GitHub Issue（req/case パイプラインの作業単位）は扱わない（`agentdev-issue-management` の責務）。
サブコマンド、引数、操作文法をユーザーに要求しない。内部実装で明示的な操作種別を持つことは禁止しない。

## 入力

- ユーザーの自然言語による指示（例: 「この論点を課題として残して」「未解決の課題を確認したい」「保留していた課題を再検討して」）
- 現在の会話コンテキスト（対話中の未解決事項、対象課題、状態）

## 出力

- 課題ファイル（`docs/issue-list/` 配下の作成・更新。書き込み操作時）
- 検索・参照結果、操作結果の報告（セッション内テキスト出力）

## workflow

本コマンドは workflow 実装本体を `agentdev-workflow-issue` スキルへ委譲する（DEC-{N}、REQ-{NNN}-{NNN}）。
工程、分岐、再開、停止などの高水準の実行構造（操作種別判定、課題化判定、課題管理 Capability Skill への委譲、永続化）は同スキルの control plane が所有する。

## 不変条件

工程上の選好を肯定形の不変条件として示す:

- ユーザーは自然言語で意図を伝え、課題管理側が会話文脈、対象課題、状態から必要な操作を判断する。サブコマンド、引数、操作文法の暗記を要求しない
- 課題管理能力の利用に本コマンドの明示実行を必須としない。各 workflow は未解決事項を認識した場合に課題管理 Capability Skill（`agentdev-issue-tracking`）を直接利用できる
- 課題化は「現在の作業で解決できず、かつ将来の設計、実装、検証、合意等に影響する未解決事項」に限定する。正規成果物の確認等でその場で解決可能な疑問は、課題化前に解決を試みる
- 正規成果物または現在の会話で結論が確定している事項は、その結果を課題へ反映できる。ユーザー合意が必要な設計判断を課題管理側で勝手に確定しない
- 課題の解決結果の正規成果物への反映は、当該成果物を所有する ADF 能力へ委譲する。課題管理側は結論、反映先、反映状況の追跡に徹する

## ガードレール

硬い境界（破壊的操作・state 破壊等の否定規則）に限定する:

- G01: ファイル編集スコープは `docs/issue-list/` 配下の課題ファイルのみ（他パスへの作成・編集は禁止）
- G02: GitHub Issue/PR の作成、更新、クローズを行わない（`agentdev-issue-management` の責務）
- G03: Decision、REQ、Design 等の正規成果物を直接更新しない（反映は当該成果物を所有する ADF 能力への委譲による）
- G04: ユーザー合意が必要な設計判断を代理確定しない。既存の承認、判断境界を迂回しない
- G05: 課題起票時に反映先を決め打ちしない
