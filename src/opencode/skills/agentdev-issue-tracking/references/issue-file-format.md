# 課題ファイル形式（issue-file-format）

本ファイルは `agentdev-issue-tracking` SKILL.md から遅延読み込みされる、課題ファイル形式の完全定義である。
`docs/issue-list/` 配下に課題ファイルを作成、編集するすべての操作は本ファイルの形式に従う。

## 1. 課題 ID とファイル命名

| 項目 | 規約 |
|---|---|
| ID 形式 | `ISL-{NNN}`。`ISL` は正規配置先 `docs/issue-list/` に由来する接頭辞、`{NNN}` は3桁ゼロ埋めの通番 |
| 採番規則 | `docs/issue-list/` 配下の既存課題 ID の最大番号に 1 を加えた番号を採番する。廃止済み番号は再利用しない（欠番維持） |
| ファイル名 | 課題 ID + `.md`（例: `ISL-{NNN}.md`）。1課題1ファイルとし、状態が変わってもファイル名、配置ディレクトリを変更しない |
| GitHub Issue 番号との識別 | GitHub Issue 番号は `#NNNN` 形式の純数字参照であり、`ISL-` 接頭辞とハイフンを持つ課題 ID とは正規表現 `^ISL-\d{3}$` と `^#?\d+$` が交差しないため、機械的にも人間にも混同できない |

課題本文から GitHub Issue を参照する必要がある場合は `#NNNN` 形式を、他の課題を参照する場合は課題 ID を用いる。

## 2. 状態保存値と状態遷移

状態は各課題ファイルの frontmatter `status` が保持する。状態によってディレクトリを移動しない。

| 保存値 | 意味 | 定義 |
|---|---|---|
| `open` | 未着手 | 課題を起票した状態。検討をまだ開始していない |
| `in-progress` | 検討中 | 検討を開始し、選択肢や判断材料の整理、不足情報の収集を行っている状態 |
| `on-hold` | 保留 | 現時点で結論を出せず、判断保留の理由と再評価条件を保持する状態 |
| `resolved` | 解決済み | 課題に対する結論が出た状態。結論は対応不要の場合を含む。反映完了または反映不要の確認までは完了していない |
| `closed` | クローズ済み | 必要な正規成果物への反映、または反映不要の確認まで完了した状態 |

`resolved`（結論が出た）と `closed`（反映まで確認した）は区別する。解決済みの課題は反映先が確定し次第反映を進め、反映の確認が取れるまでクローズしない。

状態遷移は次を基本とする。

```
open -> in-progress -> (on-hold | resolved) -> closed
on-hold -> (in-progress | resolved)     （再評価後の継続検討または結論）
closed -> open                          （再オープン。検討経過に再オープン理由を追記）
```

## 3. frontmatter スキーマ

frontmatter は `---` 囲みの YAML サブセットとする。`key: value` 形式とインラインリスト `[a, b]` 形式のみを使用する。

| フィールド | 必須度 | 形式 | 内容 |
|---|---|---|---|
| `id` | 必須 | `ISL-{NNN}` | 課題 ID。ファイル名の課題 ID と一致させる |
| `title` | 必須 | 文字列 | 件名。課題を一言で表す |
| `status` | 必須 | 5値のいずれか | 状態保存値（§2） |
| `created` | 必須 | `YYYY-MM-DD` | 起票日 |
| `updated` | 必須 | `YYYY-MM-DD` | 最終更新日。状態変更、本文追記のたびに更新する |
| `related_artifacts` | 任意 | インラインリスト（パスまたは ID） | 関連成果物。機械的な到達手段（`--related` フィルタ）の対象。本文「関連成果物」セクションと対応する |
| `owner` | 任意 | 文字列 | 担当 |
| `due` | 任意 | `YYYY-MM-DD` | 期限 |
| `reevaluation` | `on-hold` で必須 | 文字列 | 再評価条件の要約。索引・検索からの到達用。詳細は本文「再評価条件」セクションに記述する |

本文にのみ保持し frontmatter に持たない情報: 課題内容、背景、影響、選択肢、判断材料・証拠、不足情報、検討経過、結論、反映先、クローズ確認。

## 4. 本文セクション

本文は H2 セクションで構成する。課題にとって不要なセクションは省略できる。

| セクション | 必須度 | 内容 |
|---|---|---|
| `## 課題内容` | 起票時必須 | 課題の内容。何が未解決か |
| `## 背景` | 任意 | 課題が発生した経緯 |
| `## 影響` | 任意 | 解決しない場合に影響する範囲。将来の設計、実装、検証、合意への影響 |
| `## 関連成果物` | 任意 | 関連する正規成果物と関連の内容。frontmatter `related_artifacts` と対応する |
| `## 選択肢` | 任意 | 現時点で検討している選択肢 |
| `## 判断材料・証拠` | 任意 | 判断に使える材料と証拠 |
| `## 不足情報` | 任意 | 判断に不足している情報 |
| `## 再評価条件` | `on-hold` で必須 | 判断保留の理由と再評価条件（§5） |
| `## 検討経過` | 追記専用 | 検討の経過記録（日付エントリ、§4.1） |
| `## 結論` | `resolved`、`closed` で必須 | 課題に対する結論。対応不要の場合は対応不要という結論と理由 |
| `## 反映先` | `resolved`（反映先あり）、`closed` で必須 | 結論の反映先と反映状況（§6） |
| `## クローズ確認` | `closed` で必須 | 反映完了または反映不要の確認記録（§6） |

### 4.1 検討経過のエントリ形式

検討経過は追記専用とし、既存エントリを書き換えない。1エントリ1行、日付を先頭に置く。

```markdown
## 検討経過

- 2026-01-01: 課題を起票した
- 2026-01-05: 選択肢を2案に整理した。判断材料として既存 Design の該当節を確認した
```

状態遷移（保留、再評価、解決、クローズ、再オープン）を行う場合は、遷移後の状態と理由を検討経過に追記する。

## 5. 再評価条件の記述形式

保留状態（`on-hold`）の課題は、なぜ現在判断できないかと、何が成立すれば再評価するかを識別できるようにするため、本文 `## 再評価条件` を次の2つの H3 サブセクションで構成する。

| サブセクション | 内容 |
|---|---|
| `### 判断保留の理由` | なぜ現時点で判断できないか |
| `### 再評価条件` | 何が成立すれば再評価するか。検証可能な条件を書く |

frontmatter `reevaluation` には「再評価条件」の要約（1文）を記録する。保留課題を単に保存して忘れないため、関連する作業、設計、レビュー、分析を行う際は検索（`--status on-hold`、`--related`）で保留課題へ到達し、条件成立を確認する。

## 6. 反映先とクローズ確認の記述形式

解決（`resolved`）時点で結論の反映先を決定し、本文 `## 反映先` に反映先と反映状況を記録する。反映不要と結論した場合はその理由を記録する。起票時点で反映先を決め打ちしない。

```markdown
## 反映先

| 反映先 | 反映内容 | 状況 |
|---|---|---|
| Decision（判断理由を保持すべき結論） | 判断理由を Decision として記録する | 未反映 |
```

状況は `未反映`、`反映済み`、`反映不要` のいずれかとする。反映の実行は当該成果物を所有する ADF 能力へ委譲する（references/operations.md「反映追跡と委譲」）。

クローズ（`closed`）時は本文 `## クローズ確認` に、反映先ごとの確認結果（反映済みまたは反映不要の確認）と確認日を記録する。反映が完了していない、または反映不要の確認が取れていない課題はクローズしない。

```markdown
## クローズ確認

- 2026-02-01: 上記反映先の反映完了を確認した（確認手段: 当該成果物の該当節）
```

## 7. 新規起票テンプレート

新規起票時の初期テンプレートを次に示す。`{NNN}` を採番した番号で、各項目を実際の内容で置き換える。反映先、クローズ確認のセクションは解決時に追加するものであり、起票時には含めない。

```markdown
---
id: ISL-{NNN}
title: <件名>
status: open
created: <YYYY-MM-DD>
updated: <YYYY-MM-DD>
related_artifacts: [<関連成果物のパスまたは ID>]
---

## 課題内容

<課題の内容>

## 背景

<背景。不要なら省略>

## 影響

<解決しない場合に影響する範囲。不要なら省略>

## 選択肢

<現時点の選択肢。不要なら省略>

## 判断材料・証拠

<判断材料と証拠。不要なら省略>

## 不足情報

<判断に不足している情報。不要なら省略>

## 検討経過

- <YYYY-MM-DD>: 課題を起票した
```

`owner`、`due` は必要な場合のみ追記する。保留する時点で `## 再評価条件` セクションと frontmatter `reevaluation` を追加する。
