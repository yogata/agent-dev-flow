## 対象と役割

本プロトコルの対象は、要件案、設計案、規格案、計画案を標準対象とする。完成済み文書に限定せず、ドラフト、構造化提案、検討中の選択肢を含む。

審議は、対象案側、批判側、親エージェント（合意管理）の3論理的役割で構成する。

| 役割 | 責務 |
|------|------|
| 対象案側 | 提起された批判を分類し、妥当な批判を受容し、妥当でない批判には根拠付き反論を返す |
| 批判側 | 対象案の具体的破綻、欠落、矛盾、影響を根拠付きで提起し、反論を確認して再検討状態を選択する |
| 親エージェント | 審議状態を管理し、争点の統合、合意の確定、ユーザー質問への移行判断、完了判断を行う |

本プロトコルの結果は助言であり、ユーザー承認、実装実行、強制的な統制判定にはならない。

## 審議上の論理的役割

審議上の状態は、争点の提起、反論、再検討、合意、撤回、限定、修正、ユーザー質問への移行、回答後再開、完了を扱う。各状態の遷移は「争点状態」で定義する。

## 批判と反論の往復

### 批判の提起

批判は可能な限り、次の要素を明示する。

| 要素 | 内容 |
|------|------|
| 批判対象 | 対象案のどの部分、要件、設計、判断に対する批判か |
| 批判内容 | 何が問題かの具体的な指摘 |
| 前提 | 批判が依存する前提条件 |
| 具体的破綻/欠落/矛盾/影響 | 問題の種類と具体例 |
| 根拠 | 批判の妥当性を支える証拠、参照先 |
| 反証条件 | どのような条件が示されれば批判が撤回されるか |

反証条件を持たない抽象的懸念は、原則として本質的争点とならない（「本質的争点と非本質的批判の判定」参照）。

### 対象案側の吟味と分類

対象案側は批判ごとに、根拠の確認可能性、前提の妥当性、目的/制約/対象外との整合、充足済か、修正しない場合の影響、好み/理想論/過剰要求/スコープ外でないか、他の批判との重複を吟味する。

対象案側は批判を次の6分類のいずれかに分類する。

| 分類 | 意味 |
|------|------|
| 全面受容 | 批判が妥当であり、対象案を修正して全面的に取り込む |
| 部分受容 | 批判の一部が妥当であり、該当部分を取り込む |
| 根拠付き反論 | 批判が前提、解釈、対象範囲の誤り等により妥当でなく、根拠を示して反論する |
| 充足済 | 批判が指摘する事項は既に対象案で満たされている |
| 他争点との重複 | 同一の本質的争点が別の批判でも扱われており、同一争点へ統合する |
| ユーザー判断が必要 | 関連コンテキストからは解決できず、ユーザーの判断を必要とする |

妥当な批判を対象案を守ることだけを目的として拒否しない。妥当でない批判をレビュー結果であることだけを理由に受け入れない。

### 批判側の再検討

反論を受けた批判側は、反論と根拠を確認し、次の6状態のいずれかを選択する。

| 状態 | 意味 |
|------|------|
| 撤回 | 反論により批判が妥当でなかったと確認し、批判を取り下げる |
| 維持 | 反論によっても批判が妥当であることを確認し、批判を維持する |
| 限定 | 批判の適用範囲を限定し、限定された範囲で批判を維持する |
| 修正再提示 | 批判の内容、前提、対象範囲を修正して再提示する |
| 部分合意 | 反論の一部を受容し、残る部分で批判を維持する |
| 解決不能 | 反論と批判のいずれも妥当と確定できず、自律審議では解決できない |

## 争点状態

争点は次の状態を持つ。

| 状態 | 意味 |
|------|------|
| 提起 | 批判が提示され、対象案側の分類待ち |
| 審議中 | 対象案側の分類、反論、批判側の再検討が進行中 |
| 合意 | 修正合意、撤回、限定合意、ユーザー判断反映後の合意のいずれかで争点が閉じた |
| 撤回 | 批判側が批判を取り下げ、争点を閉じた |
| 限定合意 | 適用範囲を限定した上で合意し、争点を閉じた |
| ユーザー質問中 | ユーザー判断を必要とし、質問を提示した状態 |
| 回答待ち | ユーザー質問に対する回答待ち |
| 完了 | ユーザー判断を反映し、再検証を経て争点を閉じた |

重複する批判は同一争点へ統合する。解決済み争点は、新しい証拠または異なる具体的破綻条件が提示されない限り再開しない。

## 本質的争点と非本質的批判の判定

次のいずれかに該当する指摘は、原則として本質的争点としない。

- 具体的破綻/実害を示せない指摘
- 目的/制約/対象範囲と無関係な改善
- 好み/理想論のみの指摘
- 過剰要求
- スコープ外
- 解決済みの再提出
- 表現変更のみの同一批判
- 反証条件を持たない抽象的懸念
- 継続目的化した指摘

対象案側が一方的に本質的でないと確定せず、反論と批判側の再検討を経て争点を閉じる。

## 自律審議継続

関連コンテキストから判断可能な限り、自律審議を継続する。ユーザー質問への移行は、関連コンテキストから解決できない場合に限定する（「ユーザー質問への移行」参照）。

継続時、次の8手続きを順不同で試みる。

| 手続き | 内容 |
|--------|------|
| 前提確認 | 批判と反論の前提を確認し、前提の相違を特定する |
| 根拠確認 | 批判と反論の根拠を再確認し、根拠の強度と適用範囲を比較する |
| 誤解解消 | 誤解、解釈の相違、情報の欠落があれば明示的に解消する |
| 適用範囲の限定 | 批判の適用範囲、対象案の適用範囲を限定し、爾余の範囲で合意可能か確認する |
| 部分合意の探索 | 批判と反論のうち合意可能な部分を切り出し、合意済み範囲を確定する |
| 代替案の比較 | 対立する選択肢の代案を比較し、共通の目的を満たす代替があるか確認する |
| 追加証拠による再評価 | 利用可能な関連コンテキストから追加証拠を取得し、争点を再評価する |
| 批判内容の再構成 | 批判と反論を整理し直し、真の対立点を抽出する |

## ユーザー質問への移行

### 移行条件

関連コンテキストから解決できない場合に限定して、未解決争点をユーザーへ返す。移行条件は次の6項目のいずれかに該当する場合とする。

| 移行条件 | 内容 |
|----------|------|
| 技術的同等選択肢間の優先判断 | 技術的に同等と見なされる選択肢間で、ユーザーの優先判断が必要な場合 |
| トレードオフ | 複数の要件、制約間にトレードオフがあり、優先順位の判断が必要な場合 |
| ユーザー固有の目的/要件/対象範囲/価値判断 | ユーザー固有の目的、要件、対象範囲、価値観に依存する判断の場合 |
| 両立不能要求 | 複数の要求が両立できず、いずれを優先するかの判断が必要な場合 |
| 事実/外部情報不足 | 関連コンテキストに事実、外部情報が不足し、ユーザーへの確認が必要な場合 |
| 膠着 | 批判と反論が自律審議の8手続きを尽くしても解決せず、膠着状態の場合 |

### 質問出力契約

質問は次の8項目を明確にする。

| 項目 | 内容 |
|------|------|
| 未解決争点 | ユーザー判断を必要とする争点の内容 |
| エージェント間で解決できない理由 | 自律審議では解決できなかった理由、試みた8手続きの結果 |
| 合意済み範囲 | 当該争点に関連する合意済みの範囲 |
| 対立選択肢 | ユーザー判断を要する対立する選択肢 |
| 選択肢ごとの差異/影響 | 各選択肢の差異と対象案へ与える影響 |
| 推奨案と根拠 | 親エージェントが推奨する案とその根拠 |
| ユーザーに確定してほしい判断 | ユーザーに確定を求める具体的な判断内容 |
| 回答後に再開する争点 | ユーザー回答後に再開し、再検証を行う争点 |

## 回答後の再開

ユーザー回答を対象争点の判断として反映し、影響を受ける争点から議論を再開する。

- 局所的影響の場合は解決済み全争点を再審議しない
- 基礎前提変更時は影響範囲を再評価し、必要な範囲を再レビューする

回答後に再開した争点は、修正版への再検証を経て完了状態へ遷移する。

## 合意条件と完了条件

### 合意条件

合意は形式的全会一致ではなく、本質的争点単位で判断する。争点は次のいずれかで閉じる。

| 閉じ方 | 内容 |
|--------|------|
| 修正合意 | 対象案を修正した上で合意した |
| 撤回 | 批判が撤回され、修正なしで合意した |
| 限定合意 | 適用範囲を限定した上で合意した |
| ユーザー判断反映後の合意 | ユーザー判断を反映した上で合意した |

### 完了条件

審議全体の完了は、形式的全会一致や固定観点全PASSではなく、次の8項目の本質的合意条件で判断する。固定観点全PASSや形式同一判定を完了条件としない。

1. 本質的争点がすべて閉じていること
2. 妥当と合意した批判が対象案へ反映されていること
3. 撤回/棄却された批判が対象案へ混入していないこと
4. 部分合意の採用範囲と非採用範囲が明確であること
5. ユーザー判断事項が残っていないこと
6. 修正版への再検証が完了していること
7. 再検証後に新たな本質的争点が残っていないこと
8. 批判を継続すること自体を目的とした議論だけが残っていないこと

## 出力契約

審議完了時の出力は次の7項目を含む。

| 項目 | 内容 |
|------|------|
| 合意済最終案 | 合意済みの対象案の最終版 |
| 採用した主要な批判と理由 | 採用した主要な批判とその採用理由 |
| 撤回/棄却した主要な批判と理由 | 撤回または棄却した主要な批判とその理由 |
| 部分合意内容 | 部分合意に至った内容、採用範囲、非採用範囲 |
| ユーザー判断内容 | ユーザー判断を反映した場合はその内容 |
| 残留リスク | 合意後も残るリスク、前提条件、不確実性 |
| 未解決時の再開可能質問 | 未解決争点がある場合、再開可能な質問 |

## 副作用境界

本スキルは次の副作用を行わない。

| 禁止 | 内容 |
|------|------|
| ファイル保存 | 対象案、審議状態、出力結果をファイルへ保存しない |
| commit | git commit を行わない |
| push | git push を行わない |
| Issue・PR更新 | Issue、PR の作成、更新、コメント追加を行わない |
| その他の外部状態変更 | データベース、外部サービス、実行環境の状態を変更しない |

ユーザー承認を代行しない。

## 読み取り専用の委譲契約

批判側、対象案側の各役割をサブエージェントへ委譲する場合、委譲は読み取り専用契約に従う。

委譲の実行方法、起動主体、実行モデル、実行基盤は固定しない。具象は AGENTS.md および `references/<harness>.md` 参照。

| 契約要素 | 内容 |
|----------|------|
| inputs | 対象案、関連コンテキスト、読み取り可能なソース、担当役割、前提となる争点状態 |
| side_effect_boundary | ファイル編集、commit、push、Issue/PR 作成、ユーザー承認の主張を行わない。修正を適用しない |
| output_contract | 担当役割の結果（批判、分類、反論、再検討状態）、根拠、参照したソース、前提 |
| capture_handoff | 親エージェントが各報告を受け取り、争点状態へ反映する。サブエージェントは対象案、争点状態へ直接反映しない |

親エージェントは各報告を統合し、合意、ユーザー質問への移行、完了を判断する。親エージェントが合意管理の最終権限を持つ。

## 審議状態の保存形式（実装詳細）

審議状態の物理的保存形式、スキーマ、最大ラウンド数、並列数、タイムアウトは SPEC 所有対象外とし、配布スキル実装へ委譲する。

本プロトコルは次の実装詳細を規定しない:

- 審議状態の保存先（インメモリ、ファイル、データベース等）
- 争点、批判、反論、合意のデータスキーマ
- 審議の最大ラウンド数、最大争点数
- 批判側、対象案側の並列起動数
- 各手続きのタイムアウト

これらは配布スキルの実装が AGENTS.md、`references/<harness>.md`、実行環境の制約に従い決定する。
